12

포인터

1장부터 scanf에 &를 붙여 왔고, 10장에서는 함수가 바꾼 값이 왜 밖에 전해지지 않는지 숙제로 남겼다. 두 질문의 답이 같다. 변수에는 값뿐 아니라 주소가 있다.

학습 목표

  • &(주소 연산자)와 *(역참조 연산자)의 역할을 구분할 수 있다
  • 포인터 변수를 선언하고 초기화하며, 크기가 항상 8바이트임을 안다
  • 주소를 넘겨 함수가 호출한 쪽의 값을 바꾸게 할 수 있다
  • swap 함수를 포인터로 구현하고 값 전달 버전과 비교할 수 있다
  • scanf의 &가 무엇이었는지 설명할 수 있다
  • 널 포인터와 초기화하지 않은 포인터가 왜 위험한지 안다

01 — 도입 문제

두 변수를 바꾸는 함수

10장 연습 8번에서 확인한 코드다.

CODE
void swap_bad(int a, int b)
{
    int t = a; a = b; b = t;
}

int x = 3, y = 7;
swap_bad(x, y);
printf("x=%d y=%d\n", x, y);
OUTPUT
x=3 y=7

함수 안에서는 분명히 바뀌었는데 밖은 그대로다. a와 b가 x, y의 복사본이기 때문이었다(10.3절).

그런데 생각해 보면 이상하다. 1장부터 우리는 함수가 바깥 변수를 바꾸는 것을 매번 보고 있었다.

scanf도 함수다. 그런데 a가 바뀐다. 차이는 하나뿐이다. &가 붙어 있다.

이 장이 답할 질문 ① &a는 무엇인가?
② 그것을 넘기면 왜 원본이 바뀌는가?
③ 그렇다면 우리가 만든 함수도 그렇게 만들 수 있는가?
02 — 개념 정리

개념 정리

12.1변수에는 주소가 있다

변수는 메모리의 어딘가에 자리를 잡는다. 그 자리의 번호가 주소이고, &로 알아낸다.

CODE
int a = 10;
printf("%d\n", a);
printf("%p\n", (void*)&a);
OUTPUT (한 예)
10
0x7ffdd01ed56c

주소는 실행할 때마다 달라진다. 값 자체를 외울 필요는 없고, "a라는 상자가 놓인 자리 번호"라고만 이해하면 된다. 출력할 때는 %p를 쓰고 (void*)로 변환한다.

8장의 배열로 비유하면
인덱스 = 자리 번호 = 주소
a[3]   = 그 자리의 값
변수에서는
&a = 자리 번호
 a = 그 자리의 값

12.2포인터 변수와 역참조

주소를 담는 변수가 포인터다. 선언할 때 *를 붙인다.

표기읽는 법값
aa의 값10
&aa의 주소0x7ffd…56c
pp의 값 (= a의 주소)0x7ffd…56c
*pp가 가리키는 곳의 값10
*의 두 가지 의미를 구분한다 선언할 때의 *는 "이 변수는 포인터다"라는 표시다. 식에서의 *는 "가리키는 곳으로 가라"는 명령이다. 같은 글자지만 역할이 전혀 다르다.
int *p = &a; ← 선언. *p = 99; ← 명령.

*p = 99;를 실행하면 a가 99가 된다. p를 통해 a를 건드린 것이다. 이것이 포인터의 전부다.

12.3포인터의 크기는 항상 같다

CODE
printf("%zu %zu %zu\n",
    sizeof(char*),
    sizeof(int*),
    sizeof(double*));
OUTPUT
8 8 8

가리키는 대상이 1바이트든 8바이트든 주소의 크기는 똑같다. 주소는 "몇 번지"라는 번호일 뿐이기 때문이다. 10장 오류 5에서 함수 안의 sizeof(a)가 8로 나왔던 이유가 바로 이것이다.

12.4주소를 넘기면 원본이 바뀐다

도입 문제의 답이다. 값 대신 주소를 넘긴다.

값을 넘긴다 — 안 된다
void swap_bad(int a, int b)
{
    int t = a;
    a = b;
    b = t;
}
swap_bad(x, y);
주소를 넘긴다 — 된다
void swap(int *a, int *b)
{
    int t = *a;
    *a = *b;
    *b = t;
}
swap(&x, &y);

주소도 복사본이다. a는 &x의 복사본이다. 그러나 복사된 주소가 가리키는 곳은 여전히 원본 x다. 그래서 *a로 접근하면 진짜 x를 건드리게 된다.

비유 값을 넘기는 것은 집 사진을 주는 것이다. 사진에 낙서해도 집은 그대로다.
주소를 넘기는 것은 집 주소를 적은 쪽지를 주는 것이다. 쪽지는 복사본이지만, 그 주소로 찾아가면 진짜 집이 있다.

12.5값을 여러 개 돌려주기

10장에서 "return은 하나뿐이라 값 두 개를 돌려줄 수 없다"고 했다. 포인터가 그 제약을 푼다.

읽을 값은 값으로, 쓸 자리는 주소로 받는다. 매개변수만 봐도 어느 것이 입력이고 어느 것이 출력인지 드러난다.

12.61장의 숙제 — scanf의 &

이제 답할 수 있다. scanf는 읽은 값을 우리 변수에 써 넣어야 한다. 값을 받으면 복사본만 고치게 되므로, 써 넣을 자리의 주소를 받아야 한다.

함수하는 일필요한 것
printf("%d", a)a의 값을 읽어서 출력값이면 충분
scanf("%d", &a)a에 값을 써 넣음주소가 필요

1장에서 "읽을 때는 &, 쓸 때는 안 붙임"으로 외웠던 규칙의 근거가 이것이다. 그리고 3장 오류 3에서 scanf("%s", &s)가 경고를 내면서도 대개 동작했던 이유도 이제 보인다. 배열 이름은 그 자체가 이미 주소이기 때문이다(12.8절).

12.7널 포인터와 초기화

포인터도 변수다. 초기화하지 않으면 아무 주소나 들어 있다. 그 주소로 값을 쓰면 어디가 망가질지 모른다.

초기화하지 않은 포인터
int *p;      // 쓰레기 주소
*p = 5;      // 어디에 쓰는지 모른다
경고
warning: 'p' is used
uninitialized [-Wuninitialized]

가리킬 곳이 아직 없으면 NULL을 넣어 둔다. NULL은 "아무 데도 가리키지 않는다"는 약속된 값이다.

CODE
int *p = NULL;
fprintf(stderr, "%p\n", (void*)p);
fprintf(stderr, "%d\n", p == NULL);
fprintf(stderr, "%d\n", *p);   // 죽는다
OUTPUT
(nil)
1
Segmentation fault

NULL을 역참조하면 확실하게 죽는다. 이것이 장점이다. 쓰레기 주소는 우연히 동작해 버그를 숨기지만, NULL은 즉시 드러난다. 쓸 수 없는 포인터는 NULL로 두고, 쓰기 전에 if (p != NULL)로 확인한다.

죽으면 printf 출력이 사라진다 위 코드를 printf로 바꾸면 앞의 두 줄도 화면에 나오지 않는다. 출력이 버퍼에 모였다가 한꺼번에 나가는데, 그 전에 죽어 버리기 때문이다.
그래서 디버깅 메시지는 stderr로 보낸다(3장). fprintf(stderr, ...)는 버퍼에 쌓지 않고 바로 나간다. "어디까지 실행됐는지" 추적할 때 반드시 이렇게 쓴다.

12.8포인터 연산과 배열

포인터에 1을 더하면 1바이트가 아니라 가리키는 자료형 하나만큼 이동한다.

CODE
int v[5] = {10,20,30,40,50};
int *q = v;
printf("%p %d\n", (void*)q,   *q);
printf("%p %d\n", (void*)(q+1), *(q+1));
OUTPUT
0x7ffd…5a0 10
0x7ffd…5a4 20

주소가 4만큼 늘었다. int가 4바이트이기 때문이다. 그래서 *(q+2)는 세 번째 원소가 된다.

세 표기는 모두 같다
v[2]
*(v + 2)
q[2]
배열 이름의 정체
v == &v[0]

배열 이름은
첫 원소의 주소다.

이것으로 10장의 두 번째 숙제가 풀린다. 함수에 배열을 넘기면 통째로 복사되는 것이 아니라 첫 원소의 주소가 넘어간다. 그래서 함수 안에서 고친 것이 밖에 전해졌고, sizeof는 8이 나왔다.

13장으로 이어진다 배열과 포인터의 관계는 다음 장에서 본격적으로 다룬다. 지금은 "배열 이름 = 첫 원소의 주소" 한 줄만 확실히 해 두면 된다.
03 — 표준 코드

표준 코드: swap과 minmax

요소읽는 법
void swap(int *a, int *b)매개변수가 주소다. 받는 쪽도 포인터로 선언한다.
int t = *a;값을 꺼내 임시 변수에 담는다. int t = a;로 쓰면 주소를 담게 되어 틀린다.
*a = *b;양쪽 모두 *를 붙인다. 한쪽만 붙이면 컴파일 오류다.
swap(&x, &y);호출할 때 &를 붙인다. swap(x, y)로 쓰면 경고가 난다.
minmax의 매개변수앞의 둘은 읽을 값이라 그냥 int, 뒤의 둘은 쓸 자리라 포인터다.
INPUT
3 7
OUTPUT
7 3
3 7
& 와 * 를 붙이는 자리를 외운다 호출하는 쪽 — 변수에 &를 붙여 주소를 만든다.
선언하는 쪽 — 매개변수에 *를 붙여 포인터로 받는다.
쓰는 쪽 — 함수 안에서 *를 붙여 값에 접근한다.
셋 중 하나만 빠져도 동작하지 않는다. 이 세 자리를 한 묶음으로 익힌다.

05 — 흔한 오류

흔한 오류 여섯 가지

오류 1호출할 때 &를 빠뜨렸다
swap(x, y);      // &가 없다

warning: passing argument 1 of 'swap' makes pointer
         from integer without a cast [-Wint-conversion]

값 3을 주소 3번지로 해석한다. 실행하면 대개 Segmentation fault다. 3장 오류 6(scanf의 & 누락)과 완전히 같은 구조다.

고치는 법 — 포인터를 받는 함수에는 반드시 &를 붙여 부른다. 경고 메시지에 makes pointer from integer가 보이면 이 실수다.
오류 2함수 안에서 *를 빠뜨렸다
void swap(int *a, int *b)
{
    int t = a;      // 주소를 담았다
    a = b;          // 주소만 바꿨다
    b = t;
}

컴파일은 경고와 함께 통과하고, 실행하면 아무 일도 일어나지 않는다. swap_bad와 똑같은 결과다. 포인터로 고쳐 놓고도 *를 빠뜨리면 원점이다.

고치는 법 — 함수 안에서 값을 다룰 때는 전부 *를 붙인다. *a, *b가 몇 번 나오는지 세어 본다.
오류 3초기화하지 않은 포인터에 썼다
un.c:2:28: warning: 'p' is used uninitialized [-Wuninitialized]
    2 | int *p; *p = 5;
      |         ~~~^~~

경고는 나온다. 그런데 실행해 보면 아무 일 없이 5가 출력되기도 한다. 우연히 쓸 수 있는 주소가 들어 있었던 것뿐이고, 다른 환경에서는 죽는다.

고치는 법 — 선언과 동시에 초기화한다. 가리킬 곳이 정해지지 않았으면 int *p = NULL;.
오류 4NULL을 역참조했다
int *p = NULL;
printf("%d\n", *p);      // Segmentation fault

경고가 없다. 문법상 완벽한 코드이기 때문이다. 다만 반드시 죽는다는 점이 오히려 다행이다. 조용히 틀린 답을 내는 것보다 낫다.

고치는 법 — 역참조 전에 if (p != NULL)로 확인한다. PART 3의 연결 리스트·트리에서는 이 검사가 거의 모든 함수의 첫 줄이 된다.
오류 5사라진 지역 변수의 주소를 돌려주었다
int *make(void)
{
    int t = 5;
    return &t;       // t는 함수가 끝나면 사라진다
}

warning: function returns address of local variable
         [-Wreturn-local-addr]

함수가 끝나면 t의 자리는 다른 호출에 재사용된다. 돌려받은 주소로 읽으면 엉뚱한 값이 나오거나 죽는다. 11장에서 본 호출 스택이 풀리는 것과 같은 이야기다.

고치는 법 — 값을 돌려주거나(return t;), 호출한 쪽이 만든 자리를 주소로 받아 거기에 쓴다(12.5절). 전역 배열을 쓰는 것도 방법이다.
오류 6포인터와 값을 헷갈려 출력했다
printf("%d\n", p);     // 주소를 %d로
printf("%p\n", *p);    // 값을 %p로

warning: format '%d' expects argument of type 'int',
         but argument 2 has type 'int *' [-Wformat=]

3장에서 배운 서식 지정자 불일치다. 주소는 %p와 (void*), 값은 %d로 출력한다.

고치는 법 — printf("%p", (void*)p)와 printf("%d", *p). 경고가 어느 쪽을 지적하는지 읽으면 바로 보인다.
이 장의 가장 중요한 교훈 포인터 오류는 죽거나(오류 1·4·5) 아무 일도 안 하거나(오류 2) 우연히 동작한다(오류 3). 셋 다 원인을 찾기 어렵다. 그래서 &와 *가 붙는 세 자리(호출·선언·사용)를 한 묶음으로 외우고, 포인터를 선언할 때마다 "이것이 가리키는 곳이 확실히 존재하는가"를 묻는다.

void add_one(int a)

07 — 확인 평가 해설

정답과 해설

※ 이 절은 교사용 통합본에만 수록한다. 학생 배부용에서는 제거한다.

01
printf("%p\n", (void*)&a); — 주소는 실행할 때마다 달라진다. 운영체제가 보안을 위해 매번 다른 자리에 올리기 때문이다. 값을 외우는 것이 의미 없다는 점을 체감시킨다.
02
int *p = &a; *p = *p * 2; 후 printf("%d\n", a); — a를 직접 건드리지 않았는데 바뀌는 것이 요점이다.
03
모두 8. 주소는 "몇 번지"라는 번호이고, 가리키는 대상이 무엇이든 번호의 크기는 같기 때문이다. int**(포인터를 가리키는 포인터)도 마찬가지다.
04
예제 2와 동일. 두 버전을 순서대로 호출해 3 7과 7 3이 나오는 것을 확인시킨다. 10장 연습 8번의 완결편이다.
05
void double_it(int *p) { *p = *p * 2; }, 호출은 double_it(&a);. 흔한 오답 — double_it(a)(오류 1) 또는 함수 안에서 p = p * 2(오류 2).
06
예제 3과 동일. -17 5에서 -3 -2. 4장 표에서 확인한 "나머지의 부호는 a를 따른다"가 그대로 나온다.
07
minmax(a, b, &mn, &mx); 후 minmax(mn, c, &mn, &t1);, minmax(mx, c, &t2, &mx); 식으로 두 번 더 호출한다.
지도 포인트 — 같은 변수를 입력과 출력으로 동시에 쓰는 것이 가능한지 토론시킨다. 이 함수는 먼저 비교하고 나중에 쓰므로 안전하지만, 일반적으로는 위험하다(9장 오류 4와 같은 구조).
08
p == NULL은 1, *p는 Segmentation fault로 죽는다. 종료 코드는 139다(1장). NULL이 "확실하게 죽는다"는 점이 장점이라는 설명을 덧붙인다.
09
if (a > b) { swap(&a, &b); }
if (b > c) { swap(&b, &c); }
if (a > b) { swap(&a, &b); }
5장 연습 12번에서 임시 변수를 직접 쓰던 것이 함수 호출 한 줄이 됐다. PART 3 버블 정렬이 정확히 이 모양임을 예고한다.
10
swap(&a[i], &a[n-1-i]); — 배열 원소에도 &를 붙여 주소를 만든다는 것이 핵심이다. 루프 조건은 i < n/2(8장 예제 3).
지도 포인트 — a는 이미 주소지만 a[i]는 값이므로 &가 필요하다. 이 구분을 분명히 한다.
11
*sum, *mx, *mn을 각각 초기화한 뒤 루프를 돈다. *mx = a[0]; *mn = a[0];로 시작해야 음수에서 틀리지 않는다(8장 오류 5).
흔한 오답 — 함수 안에서 지역 변수에 누적한 뒤 *sum에 넣는 것을 잊는다.
12
*h = s / 3600; *m = s / 60 % 60; *sec = s % 60; — 3장 연습 3번을 함수로 만든 것이다. 매개변수 이름을 s와 sec로 구분한 이유도 설명한다.
13
int find(int a[], int n, int t, int *pos)
{
    for (int i = 0; i < n; i++) {
        if (a[i] == t) { *pos = i; return 1; }
    }
    return 0;
}
설계의 요점 — "성공 여부"는 반환값, "결과"는 포인터로 나눈다. 못 찾았을 때 *pos를 건드리지 않는 것도 약속의 일부다. 호출하는 쪽은 반드시 반환값을 먼저 확인한다. 이 패턴은 PART 3·4의 탐색 함수에서 계속 쓰인다.
14
int면 주소가 4씩, double이면 8씩 늘어난다. 포인터 연산의 단위가 가리키는 자료형의 크기라는 것을 눈으로 확인하는 문제다.
15
if (b == 0) { return 0; } *result = a / b; return 1;. 호출하는 쪽은 if (!safe_div(a, b, &r)) { printf("divide by zero\n"); return 1; }.
지도 포인트 — 5장 연습 15번을 함수로 만든 것이다. 4장의 단락 평가, 5장의 거르기 먼저, 이 장의 출력 매개변수가 한 함수에 모인다.
16
① printf로 찍으면 메시지가 화면에 나오지 않는다. ② fprintf(stderr, ...)로 찍으면 메시지가 나온 뒤 죽는다.
이유 — stdout은 버퍼에 모았다가 한꺼번에 내보내는데, 그 전에 프로그램이 죽으면 버퍼 내용이 사라진다. stderr는 버퍼에 쌓지 않는다.
지도 포인트 — "코드가 분명히 거기까지 갔는데 출력이 없다"는 상황의 정체다. 3장에서 배운 두 스트림의 구분이 디버깅 도구가 되는 자리이므로 반드시 체험시킨다.
17
실수는 세 군데다.
① 선언 자리 — void add_one(int a)가 값을 받는다. 포인터로 고쳐야 한다. → void add_one(int *a)
② 사용 자리 — 함수 안에서 a = a + 1이 아니라 *a = *a + 1이어야 한다.
③ 출력 — printf("%d %d", x, p)에서 p는 포인터인데 %d로 찍었다. 게다가 p는 초기화되지 않았다.
경고 — passing argument 1 of 'add_one' makes integer from pointer without a cast, format '%d' expects argument of type 'int', but argument 3 has type 'int *', 'p' is used uninitialized.
지도 포인트 — 12.4절의 "세 자리"가 모두 등장한다. 호출은 맞았는데 선언과 사용이 틀린 경우다.
18
경고 — warning: function returns address of local variable [-Wreturn-local-addr]
실행 결과는 환경마다 다르다. 5가 나오기도 하고 쓰레기값이 나오기도 하며 죽기도 한다. 어느 쪽도 "맞는 동작"이 아니다.
왜 위험한가 — 11장에서 본 대로 함수가 끝나면 그 호출의 스택 자리가 풀린다. 다음 함수 호출이 같은 자리를 덮어쓰므로, 돌려받은 주소가 가리키는 곳의 내용이 언제 바뀔지 알 수 없다.
안전한 방법 두 가지 — ⑴ 값을 돌려준다(return t;). ⑵ 호출하는 쪽이 자리를 만들고 그 주소를 넘긴다(void make(int *out) { *out = 5; }). 전역 배열을 쓰는 세 번째 방법도 받아 준다.
19
① a의 주소다. scanf는 읽은 값을 a에 써 넣어야 하므로 쓸 자리를 알아야 한다.
② printf는 값을 읽기만 하므로 복사본으로 충분하다.
③ 배열 이름은 그 자체가 첫 원소의 주소이므로 &가 이미 필요 없다.
④ &s는 "배열 전체를 가리키는 포인터"로 자료형이 다르지만, 주소값 자체는 s와 같다. 그래서 경고는 나오되 실행 결과는 대개 같다. 자료형이 다른 것을 넘기는 것은 여전히 잘못이다.
지도 포인트 — 1장·3장에서 "외워라"고 했던 것이 모두 설명되는 자리다. 학생이 스스로 네 문장을 쓰게 하는 것이 목적이다.

모범 구성 예. 
void divmod(int a, int b, int *q, int *r);
    입력 a,b / 출력 q,r / b==0 이면 호출 금지 (safe_div 사용)
int  safe_div(int a, int b, int *result);
    반환 1=성공 0=0으로 나눔 / 경계: b=0

    입력 a,b / 출력 mn,mx / 경계: a==b

    입력 s / 출력 h,m,sec / 경계: s=0, s=86399

    반환 1=찾음 / 출력 pos / 경계: 없을 때 pos 미변경

설계 원칙 정리 — 읽을 것은 값으로, 쓸 것은 주소로. 실패 가능성은 반환값으로. 실패했을 때 출력 매개변수는 건드리지 않는다.
지도 포인트 — 10장 20번의 함수 모음이 이 장을 거치며 한 단계 성장한다. PART 2에서 이 파일을 계속 쓰게 하므로, 이름과 매개변수 순서를 이때 확정시킨다.
08 — 마무리

이 장을 마치기 전 점검

  • &는 주소를 만들고 *는 그 주소로 찾아간다는 것을 구분한다
  • 선언의 *와 식의 *가 다른 역할임을 안다
  • 호출·선언·사용 세 자리에 &와 *를 빠짐없이 붙인다
  • 읽을 값은 값으로, 쓸 자리는 주소로 받는다
  • 포인터를 선언할 때 반드시 초기화하거나 NULL을 넣는다
  • 역참조 전에 NULL인지 확인한다
  • 지역 변수의 주소를 돌려주지 않는다
  • 디버깅 메시지는 stderr로 보낸다
다음 장 예고 — 13장 포인터·배열·함수의 연결 배열 이름이 첫 원소의 주소라는 것을 확인했다. 다음 장에서는 그 관계를 끝까지 파고든다. 배열을 함수에 넘기는 정확한 의미, 2차원 배열을 넘기는 법, 그리고 포인터로 여러 값을 한꺼번에 돌려받는 설계를 다룬다.
