04

연산자와 형변환

C의 연산자는 수학 기호처럼 생겼지만 규칙이 다르다. 정수끼리 나누면 소수가 사라지고, 음수의 나머지는 음수가 되며, 연산 순서는 괄호 없이는 눈에 보이는 대로 가지 않는다.

학습 목표

  • 정수 나눗셈과 나머지의 규칙을 설명하고 음수가 섞인 경우를 예측할 수 있다
  • 음수 나머지를 0 이상으로 보정하는 표준 공식을 쓸 수 있다
  • 형변환을 올바른 위치에 넣어 의도한 값을 얻을 수 있다
  • 관계·논리 연산자의 결과가 0과 1이라는 것을 알고 단락 평가를 활용할 수 있다
  • 비트 연산으로 홀짝 판정과 2의 거듭제곱을 처리할 수 있다
  • 연산자 우선순위 때문에 생기는 대표적인 함정 세 가지를 피할 수 있다

01 — 도입 문제

시계를 거꾸로 돌리면

12시간제 시계가 지금 3시를 가리킨다. 20시간 전은 몇 시인가?

손으로 풀면 쉽다. 20시간 전은 12시간 전보다 8시간 더 전이니까, 3시에서 거꾸로 8칸 가면 7시다. 이제 이것을 C로 옮겨 보자.

자연스러워 보이는 코드
int h = 3, d = -20;
printf("%d\n", (h + d) % 12);
실제 출력
-5

−5시라는 시각은 없다. 수학 시간에 배운 나머지는 항상 0 이상이었는데, C의 %는 그렇지 않다. 이 차이가 올림피아드에서 모듈러 연산을 쓰는 거의 모든 문제의 첫 번째 함정이다.

또 하나. 2장과 3장에서 (double)sum / cnt라는 표현을 여러 번 썼다. 왜 괄호가 하필 저기에 붙는지, 아래 네 가지는 왜 결과가 다른지 이 장에서 정리한다.

x = 7, y = 2 일 때
x / y
(double)x / y
(double)(x / y)
x / (double)y
출력
3
3.500
3.000
3.500
이 장이 답할 질문 ① C의 %는 왜 음수를 내놓는가? 그리고 어떻게 고치는가?
② 형변환은 왜 위치가 중요한가?
③ 1 << 2 + 3은 7일까 32일까?
02 — 개념 정리

개념 정리

4.1산술 연산자와 정수 나눗셈

C의 산술 연산자는 + - * / % 다섯 개다. 앞의 셋은 수학과 같고, 뒤의 둘이 다르다.

정수끼리 나누면 결과도 정수다. 소수 부분은 반올림이 아니라 버린다. 7 / 2는 3.5가 아니라 3이고, 1 / 2는 0.5가 아니라 0이다.

가장 흔한 사고 printf("%.2f", (a + b) / 2); — 괄호 안이 정수끼리의 나눗셈이므로 소수점 아래가 이미 사라진 뒤에 실수로 출력된다. 5와 6의 평균이 5.00으로 나온다.

4.2나머지 연산과 음수

%는 나눗셈의 나머지다. C의 규칙은 "몫을 0 쪽으로 버린다"이며, 나머지는 다음 항등식을 만족하도록 정해진다.

C가 지키는 항등식
(a / b) * b + (a % b) == a
따라오는 성질
a % b 의 부호는
항상 a 의 부호를 따른다
aba / ba % b부호
7231a가 양수 → 양수
−72−3−1a가 음수 → 음수
7−2−31b의 부호는 영향 없음
−7−23−1a가 음수 → 음수

수학에서 −7을 2로 나눈 나머지는 보통 1이라고 배운다(몫을 −4로 잡는 방식). C는 몫을 −3으로 잡으므로 나머지가 −1이 된다. 둘 다 항등식은 만족하지만 약속이 다를 뿐이다.

0 이상으로 보정하는 표준 공식

배열 인덱스나 시계처럼 0 이상이어야만 하는 나머지가 필요할 때는 한 번 더 감싼다.

a (m = 5)a % m((a % m) + m) % m설명
−7−23−2 + 5 = 3
−6−14−1 + 5 = 4
−5000 + 5 = 5 → 다시 %5 → 0

바깥쪽 % m이 필요한 이유는 세 번째 줄에 있다. 나머지가 이미 0이면 + m 때문에 m이 되어 버리므로 한 번 더 걸러 준다.

4.3형변환 — 위치가 전부다

서로 다른 자료형이 섞이면 C는 자동으로 넓은 쪽에 맞춘다(암시적 형변환). int + double은 double이 된다. 문제는 양쪽이 모두 int일 때다. 이때는 아무도 넓혀 주지 않으므로 우리가 직접 지정해야 한다(명시적 형변환).

식 (x = 7, y = 2)결과계산 순서
x / y3int ÷ int → int
(double)x / y3.500x가 먼저 double → y도 자동으로 double
x / (double)y3.500한쪽만 바꿔도 된다
(double)(x / y)3.000나눗셈이 끝난 뒤 바꿔서 늦었다

2장의 오버플로 형변환과 완전히 같은 원칙이다. 망가지기 전에 바꾼다. 2장에서는 "넘치기 전", 여기서는 "소수가 사라지기 전"이다.

정수 승격 char와 short는 연산에 쓰이는 순간 자동으로 int로 넓혀진다. char c1 = 100, c2 = 100;일 때 c1 + c2는 200이고 크기도 4바이트다. 그런데 그 결과를 다시 char에 담으면 범위를 넘어 −56이 된다(2장의 되감기).

4.4관계·논리 연산자

관계 연산자 < <= > >= == !=와 논리 연산자 && || !의 결과는 항상 0 또는 1인 int 값이다. 참·거짓이라는 별도의 자료형이 있는 것이 아니다.

CODE
printf("%d %d %d %d %d\n",
   3 > 2, 3 < 2, !5, 1 && 0, 1 || 0);
OUTPUT
1 0 0 0 1

C에서 0이 거짓, 0이 아닌 모든 값이 참이다. 그래서 !5는 0이다. 5가 참이므로 그 부정은 거짓이다.

단락 평가

&&는 왼쪽이 거짓이면 오른쪽을 아예 계산하지 않는다. ||는 왼쪽이 참이면 오른쪽을 계산하지 않는다. 이것을 단락 평가라고 하며, 안전장치로 쓴다.

b가 0이면 왼쪽이 거짓이므로 10 / b가 실행되지 않는다. 순서를 바꿔 10 / b > 1 && b != 0으로 쓰면 0으로 나누어 프로그램이 죽는다. 검사를 왼쪽에 둔다는 것이 규칙이다.

4.5비트 연산자

정수를 2진수로 보고 비트 단위로 처리한다. 올림피아드에서는 집합 표현과 빠른 연산에 쓰인다.

연산자이름a=12, b=10일 때쓰임새
&ANDa & b = 8특정 비트 검사, 홀짝 판정
|ORa | b = 14특정 비트 켜기
^XORa ^ b = 6특정 비트 뒤집기
~NOT~a = −13모든 비트 반전
<<왼쪽 시프트a << 1 = 242배씩 곱하기, 2k 만들기
>>오른쪽 시프트a >> 1 = 62로 나누기

12는 2진수로 1100, 10은 1010이다. 자리마다 AND를 하면 1000 = 8이 된다. 직접 자리를 맞춰 써 보면 바로 보인다.

자주 쓰는 관용구뜻비고
n & 1홀수면 1, 짝수면 0맨 끝 비트만 본다
1 << k2k1 << 10 = 1024
n | (1 << k)k번 비트 켜기집합에 원소 추가
n & ~(1 << k)k번 비트 끄기집합에서 원소 제거
n ^ (1 << k)k번 비트 뒤집기토글
시프트의 함정 두 가지 ① 1 << 31은 int에서 음수가 된다(2장). 큰 값이 필요하면 1LL << k로 쓴다.
② 음수의 >>는 부호 비트가 유지된다. -1 >> 1은 0이 아니라 −1이다.

4.6복합 대입과 증감

sum = sum + x를 sum += x로 줄여 쓸 수 있다. -= *= /= %= &= |= ^= <<= >>=도 모두 같은 방식이다.

i = 10에서 차례로
i += 5;   →  15
i -= 3;   →  12
i *= 2;   →  24
i /= 4;   →   6
i %= 4;   →   2
증감 연산자
n = 5;
v = n++;   →  v=5, n=6  (쓰고 나서 증가)
k = 5;
v = ++k;   →  v=6, k=6  (증가하고 나서 씀)
한 문장에 같은 변수를 두 번 건드리지 않는다 printf("%d %d", n++, n); 같은 코드는 결과가 정해져 있지 않다. gcc도 operation on 'n' may be undefined라고 경고한다. 증감은 한 문장에 한 번만 쓴다.

05 — 흔한 오류

흔한 오류 여섯 가지

오류 1정수 나눗셈으로 소수를 날렸다

경고도 오류도 없다. 결과만 조용히 틀린다.

printf("%.2f\n", (a + b) / 2);        // 5와 6의 평균 → 5.00
printf("%.2f\n", (a + b) / 2.0);      // → 5.50

2를 2.0으로 바꾸기만 해도 된다. 한쪽이 실수면 나머지가 자동으로 따라오기 때문이다.

고치는 법 — 나눗셈이 들어간 식을 쓸 때마다 "여기 양쪽이 다 정수인가"를 확인한다.
오류 2음수 나머지를 보정하지 않았다

배열 인덱스로 쓰면 음수 인덱스가 되어 프로그램이 죽거나 엉뚱한 값을 읽는다.

int idx = (cur - k) % n;        // cur < k 이면 음수
int idx = ((cur - k) % n + n) % n;   // 올바름

양수만 들어오는 테스트로는 발견되지 않는다. 음수 입력을 직접 만들어 시험해야 한다.

고치는 법 — 뺄셈이 섞인 %를 보면 반사적으로 ((… ) % m + m) % m으로 감싼다.
오류 3형변환이 늦었다

2장의 오버플로 형변환과 똑같은 실수의 실수 버전이다.

printf("%.3f\n", (double)(x / y));   // 3.000  — 이미 늦음
printf("%.3f\n", (double)x / y);     // 3.500  — 올바름
고치는 법 — 형변환은 연산자의 피연산자에 붙인다. 식 전체를 감싸면 소용없다.
오류 4== 를 = 로 썼다

=는 대입이고 ==는 비교다. 대입식의 값은 대입된 값이므로, if (x = 0)은 항상 거짓이 된다.

if (x = 5) { ... }   // x에 5를 넣고, 5는 참이므로 항상 실행

gcc는 suggest parentheses around assignment used as truth value로 경고한다. 5장 조건문에서 본격적으로 만나므로 지금 익혀 둔다.

고치는 법 — 비교는 ==. 경고를 흘려보내지 않는다.
오류 5괄호 없이 우선순위를 믿었다

<<가 +보다 낮고, &가 ==보다 낮다는 것은 직관과 반대다.

ex4.c:7:26: warning: suggest parentheses around '+' inside '<<'
    7 |     printf("%d\n", 1 << 2 + 3);
      |                         ~~^~~
고치는 법 — 비트 연산자가 다른 연산자와 섞이면 무조건 괄호를 친다. 괄호는 공짜다.
오류 6한 문장에서 같은 변수를 두 번 바꿨다
c.c:26:55: warning: operation on 'n' may be undefined [-Wsequence-point]
   26 |     printf("%d %d\n", n++, n);
      |                       ~^~

C 표준이 평가 순서를 정해 두지 않아서, 컴파일러와 최적화 옵션에 따라 결과가 달라진다. 집에서 맞던 코드가 채점 서버에서 틀릴 수 있다.

고치는 법 — 증감은 한 문장에 한 번만. 헷갈리면 줄을 나눠 쓴다. v = n; n++;
이 장의 가장 중요한 교훈 오류 1·2·3은 경고조차 나오지 않는다. 컴파일러가 도와주지 않는 영역이므로, 식을 쓸 때마다 스스로 두 가지를 묻는 수밖에 없다. "양쪽이 다 정수인가?" 그리고 "음수가 들어올 수 있는가?"

17

항등식 검증 — 네 가지 부호 조합 (7,2) (−7,2) (7,−2) (−7,−2)에 대해 (a/b)*b + a%b를 계산해 모두 a와 같은지 출력으로 확인하라. 그리고 C가 몫을 0 쪽으로 버린다는 규칙이 이 항등식에서 어떻게 나오는지 설명하라.

18

우선순위 진단 — 아래 네 식의 값을 먼저 손으로 예측하고, 실행해 확인한 뒤, gcc가 어떤 경고를 내는지 적어라. 그리고 의도대로 동작하도록 괄호를 넣어 고쳐라. (x = 2)

(가) 1 << 2 + 3
(나) x & 2 == 2
(다) 2 + 3 * 4
(라) 100 / 3 * 3
19

단락 평가의 순서 — 아래 두 식을 b = 0으로 실행하면 하나는 정상 종료하고 하나는 죽는다. 어느 쪽인지 예측하고 실제로 확인하라. 그리고 "검사를 왼쪽에 둔다"는 규칙을 한 문장으로 정리하라.

(가) b != 0 && 10 / b > 1
(나) 10 / b > 1 && b != 0

※ 조건문은 5장이지만, 식의 값만 변수에 담아 출력해도 같은 현상을 볼 수 있다.

20

세 장의 함정 통합 — 아래 코드는 N개의 수의 평균을 구하려는 것이다. 숨어 있는 결함을 세 가지 이상 찾아 각각 어느 장의 내용인지 밝히고, 모두 고친 코드를 제시하라. (N ≤ 106, 각 수의 절댓값 ≤ 109)

int n, x;
int sum = 0;
scanf("%d", &n);
while (scanf("%d", &x) != EOF) {
    sum += x;
}
printf("%.2f\n", sum / n);
07 — 확인 평가 해설

정답과 해설

※ 이 절은 교사용 통합본에만 수록한다. 학생 배부용에서는 제거한다.

01
printf("%d %d\n", a / b, a % b); — 3장 연습 9번과 같은 코드다. 여기서는 부호 규칙을 묻기 위한 준비 문제다.
02
출력은 -3 -2. 수학에서는 −17 = 5×(−4) + 3으로 보아 나머지를 3이라 하지만, C는 몫을 0 쪽으로 버려 −3으로 잡으므로 나머지가 −2가 된다. 두 약속 모두 (a/b)*b + a%b == a는 만족한다.
03
printf("%.2f\n", (a + b) / 2.0); — / 2로 쓰면 5.00이 나온다. 흔한 오답 1위이므로 반드시 틀려 보게 한 뒤 고치게 한다.
04
printf("%d\n", n & 1); — n % 2도 양수에서는 같지만, 음수에서는 −1이 나온다. n & 1은 음수에서도 0 또는 1이므로 이쪽이 안전하다. 이 차이를 꼭 짚는다.
05
printf("%d %d %d %d\n", a & b, a | b, a ^ b, ~a); — 12와 10을 2진수로 써 놓고 자리를 맞춰 확인시킨다.
06
printf("%lld\n", 1LL << k); — 1 << k로 쓰면 K가 31 이상일 때 깨진다. 1은 int라서 시프트도 int로 수행되기 때문이다. 지도 포인트 — 2장의 "형변환은 연산 전에"가 시프트에도 똑같이 적용된다.
07
printf("%d %d %d\n", a > b, a == b, a < b); — 관계 연산자의 결과가 그대로 출력 가능한 정수라는 것을 체감시킨다.
08
100 → 120 → 70 → 210 → 30 → 0. 마지막 %= 10에서 30 % 10 = 0. /= 7에서 210/7 = 30이 정확히 나누어떨어지는 것도 확인시킨다.
09
printf("%d\n", ((a % m) + m) % m); — 바깥쪽 % m을 빠뜨린 답안이 많다. a = -5, m = 5를 넣으면 5가 출력되어 틀린다는 것을 보여 준다.
10
printf("%d\n", ((h + d) % 24 + 24) % 24);
지도 포인트 — D의 절댓값이 109이고 H가 23 이하이므로 h + d는 int 범위 안이다. 2장의 습관대로 최악의 경우를 먼저 계산하게 한 뒤 "이번에는 int로 충분하다"는 결론까지 내리게 한다.
11
printf("%d\n", (n + k - 1) / k); — 올림 나눗셈의 표준 관용구다.
원리: 나누어떨어지면 k-1을 더해도 몫이 그대로이고, 나머지가 있으면 k-1이 그 부족분을 메워 몫이 1 늘어난다.
주의 — N과 K가 모두 109이면 n + k - 1이 약 2×109으로 INT_MAX를 넘는다. (long long)n + k - 1로 쓰거나 long long으로 받는다. 2장의 중간값 점검이 또 나온다.
12
printf("%d\n", a + (b - a) / 2); — 2장 연습 16번의 재등장이다. 차이 b - a는 범위를 넘지 않으므로 int만으로 안전하다. PART 3 이분 탐색에서 쓰는 형태임을 다시 예고한다.
13
printf("%d %d %d\n", n | (1 << k), n & ~(1 << k), n ^ (1 << k)); — N=12(1100), K=1이면 1번 비트가 원래 0이므로 켜기와 토글이 둘 다 14, 끄기는 변화 없이 12다. K=2로도 시험시켜 결과가 달라지는 것을 확인시킨다.
14
printf("%d\n", n / 100 % 10); — 순서가 중요하다. n % 10 / 100으로 쓰면 0이 나온다. 지도 포인트 — "원하는 자리를 맨 끝으로 끌어내린 뒤 10으로 나눈 나머지"라는 절차로 외우게 한다.
15
long long으로 받아 printf("%lld\n", ((s % 86400) + 86400) % 86400); — 입력 서식도 %lld. 3장과 2장과 이 장이 한 줄에 모두 들어간다.
16
① 200 ② −56. 연산은 정수 승격으로 int에서 수행되어 200이 되지만, 그 200을 char(−128~127)에 담으면 범위를 넘어 되감긴다. sizeof(c1 + c2)가 4로 나오는 것을 함께 보여 주면 설득력이 커진다.
17
네 경우 모두 항등식이 성립한다(출력은 1 1 1 1).
설명 — 몫을 정하면 나머지는 a - (a/b)*b로 자동으로 결정된다. C는 몫을 0 쪽으로 버리므로 -7/2 = -3이고, 따라서 나머지는 -7 - (-3)*2 = -1이 된다. 수학의 약속처럼 몫을 −4로 내림하면 나머지는 -7 - (-4)*2 = 1이 된다. 나머지의 부호는 몫을 어느 쪽으로 버리느냐가 결정한다.
18
(가) 32 — 1 << (2+3). 경고 suggest parentheses around '+' inside '<<'. 의도대로면 (1 << 2) + 3 = 7.
(나) 0 — x & (2==2) = 2 & 1 = 0. 경고 suggest parentheses around comparison in operand of '&'. 의도대로면 (x & 2) == 2 = 1.
(다) 14 — 곱셈이 먼저. 경고 없음. 직관과 일치한다.
(라) 99 — (100/3)*3 = 33*3. 경고 없음. 정수 나눗셈이 먼저 일어나 1이 사라진다.
지도 포인트 — (다)와 (라)는 경고가 없다는 점이 핵심이다. 컴파일러가 잡아 주는 함정과 스스로 조심해야 하는 함정을 구분시킨다.
19
(가)는 정상 종료, (나)는 0으로 나누어 죽는다(대개 Floating point exception).
&&는 왼쪽이 거짓이면 오른쪽을 평가하지 않는다. (가)는 b != 0이 거짓이므로 10 / b에 도달하지 않는다. (나)는 나눗셈이 먼저 평가된다.
정리 문장 예시 — "위험한 연산을 보호하는 검사는 &&의 왼쪽에 둔다."
20
결함은 네 가지다.
① int sum — 최악의 합이 106×109 = 1015로 넘친다. 2장 → long long sum.
② != EOF — 숫자가 아닌 입력에서 무한 루프. 3장 → == 1.
③ sum / n — 정수 나눗셈으로 소수가 사라진다. 4장 → (double)sum / n.
④ 첫 scanf의 반환값 미검사. 3장 → if (scanf("%d", &n) != 1) return 1;
고친 코드: 
int n, x;
long long sum = 0;
if (scanf("%d", &n) != 1) return 1;
while (scanf("%d", &x) == 1) {
    sum += x;
}
printf("%.2f\n", (double)sum / n);
지도 포인트 — 네 장을 한 코드에서 동시에 점검하는 문제다. PART 2의 오답 유형 분류(개념·구현·시간·경계)로 각 결함을 분류시키면 다음 파트로 자연스럽게 이어진다.
08 — 마무리

이 장을 마치기 전 점검

  • 정수끼리의 나눗셈은 소수를 버린다는 것을 식을 쓸 때마다 의식한다
  • a % b의 부호가 a를 따른다는 것을 안다
  • ((a % m) + m) % m을 외워서 쓸 수 있다
  • 형변환을 연산 전에, 피연산자에 붙인다
  • 관계·논리 연산의 결과가 0 또는 1이라는 것을 안다
  • 위험한 연산을 보호하는 검사를 &&의 왼쪽에 둔다
  • 비트 연산자가 섞이면 괄호를 친다
  • n & 1이 n % 2보다 안전한 이유를 설명할 수 있다
다음 장 예고 — 05장 조건문 이 장에서 만든 0과 1이 드디어 쓰인다. if는 식의 값이 0인지 아닌지만 본다. 경우를 빠짐없이 겹치지 않게 나누는 방법과, ==를 =로 잘못 쓰는 사고를 다음 장에서 다룬다.
