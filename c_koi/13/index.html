13

포인터·배열·함수의 연결

12장에서 "배열 이름은 첫 원소의 주소"라는 한 줄을 확인했다. 이 장은 그 한 줄이 만드는 모든 결과를 끝까지 따라간다. 배열을 함수에 넘기는 정확한 의미, 2차원 배열을 넘기는 법, 그리고 결과를 여러 개 돌려받는 함수 설계가 여기서 완성된다.

학습 목표

  • 배열 이름이 함수에 넘어갈 때 포인터로 바뀐다는 것을 설명할 수 있다
  • int a[], int *a, int a[5]가 매개변수로서 모두 같음을 안다
  • 배열의 일부만 함수에 넘길 수 있다
  • 2차원 배열을 함수에 넘길 때 열 크기를 반드시 적는 이유를 안다
  • const로 "읽기만 하는 배열"을 표시할 수 있다
  • 최댓값과 최솟값을 한 번의 호출로 함께 돌려받는 함수를 쓸 수 있다

01 — 도입 문제

두 번 훑을 것인가, 한 번에 받을 것인가

배열의 최댓값과 최솟값이 둘 다 필요하다. 10장까지의 방법으로는 함수를 두 개 만들어야 했다.

답은 맞다. 그런데 배열을 두 번 훑는다. N이 100만이면 200만 번이다. 한 번 지나가면서 둘 다 구할 수 있는데도.

12장에서 포인터로 값을 여러 개 돌려받는 법을 배웠다. 그것을 배열에 적용하면 된다.

원하는 모양
int mn, mx;
arr_minmax(a, n, &mn, &mx);
얻는 것
· 배열을 한 번만 훑는다
· 호출도 한 줄
· 무엇이 결과인지 보인다

그런데 여기서 의문이 하나 생긴다. a에는 &를 붙이지 않았는데 mn, mx에는 붙였다. 왜 다른가?

이 장이 답할 질문 ① 배열을 함수에 넘길 때 정확히 무엇이 넘어가는가?
② 배열의 일부만 넘길 수 있는가?
③ 2차원 배열은 어떻게 넘기는가?
02 — 개념 정리

개념 정리

13.1배열 이름은 함수에 넘어가면서 포인터가 된다

배열 이름은 대부분의 식에서 첫 원소의 주소로 취급된다. 함수 호출도 그중 하나다.

main 에서
int v[5] = {10,20,30,40,50};
sizeof(v)        → 20
sizeof(v)/sizeof(v[0]) → 5
v == &v[0]       → 참
함수 안에서
void f(int a[], int n)
{
    sizeof(a)    → 8
}

같은 배열인데 sizeof가 20에서 8로 바뀐다. 함수가 받은 것은 배열 전체가 아니라 주소 하나이기 때문이다. 8은 포인터의 크기다(12.3절).

gcc가 경고해 준다 warning: 'sizeof' on array function parameter 'a' will return size of 'int *' [-Wsizeof-array-argument]
10장 오류 5에서 만난 그 경고다. 이제 이유를 안다. 그래서 배열을 넘길 때는 크기 n을 함께 넘긴다.

이것으로 10장과 12장의 숙제가 모두 풀린다. 배열을 넘겨도 복사가 일어나지 않으니 함수 안에서 고치면 원본이 바뀌고, 100만 개짜리 배열을 넘겨도 전혀 느리지 않다.

13.2매개변수의 세 가지 표기는 모두 같다

세 가지 선언
void f(int a[],  int n)
void f(int *a,   int n)
void f(int a[5], int n)
함수 안에서의 sizeof(a)
8
8
8

세 번째가 특히 중요하다. int a[5]라고 써도 컴파일러는 5를 무시한다. 크기가 5인 배열만 받는 것이 아니고, 크기 검사도 하지 않는다.

표기권장도
int a[]권장 — "배열을 받는다"는 의도가 드러난다
int *a가능 — 실제 정체에 충실하다. 원소 하나를 가리킬 때는 이쪽
int a[5]피한다 — 크기를 검사한다고 오해하게 만든다

이 교재는 int a[]를 표준으로 쓴다. 다만 받는 쪽이 포인터라는 사실은 잊지 않는다.

13.3배열의 일부만 넘기기

주소를 넘기는 것이므로 시작 위치를 바꿔 넘길 수 있다.

v = {10,20,30,40,50} 일 때
f(v,     5);   // 전체
f(v + 2, 3);   // 30,40,50
f(&v[2], 3);   // 같은 뜻
함수 안에서 a[0]은
10
30
30

v + 2와 &v[2]는 완전히 같다. 둘 다 "세 번째 원소의 주소"다. 길이를 3으로 함께 넘기는 것을 잊으면 안 된다.

이 기법은 PART 3의 분할 정복에서 핵심이 된다. 병합 정렬이 배열을 반으로 쪼개 재귀 호출할 때 정확히 이 방식을 쓴다.

13.4const — 읽기만 한다는 약속

배열을 넘기면 함수가 원본을 고칠 수 있다. 고칠 생각이 없다면 const를 붙여 실수로 고치는 것을 컴파일러가 막게 한다.

CODE
void f(const int a[], int n)
{
    a[0] = 999;
}
컴파일 결과
error: assignment of
read-only location '*a'

경고가 아니라 오류라서 반드시 걸린다. 함수의 선언만 봐도 "이 함수는 배열을 읽기만 한다"는 것이 드러나는 것도 큰 장점이다.

쓰는 기준 배열을 읽기만 하는 함수(arr_sum, arr_max, find)에는 const를 붙인다. 고치는 함수(arr_reverse, sort)에는 붙이지 않는다. 올림피아드에서 필수는 아니지만, 함수의 의도를 드러내므로 이 교재에서는 쓴다.

13.52차원 배열 넘기기

2차원 배열도 넘어갈 때 포인터가 된다. 그런데 1차원과 달리 열 크기를 반드시 적어야 한다.

올바른 선언
#define M 4

void show(int a[][M], int n)
void show(int (*a)[M], int n)   // 같은 뜻
열을 빼면 오류
void show(int a[][], int n)

error: array type has
incomplete element type 'int[]'

오류 메시지가 이유를 알려 준다. must have bounds for all dimensions except the first — 첫 번째 차원을 뺀 나머지는 크기를 밝혀야 한다.

왜 열 크기가 필요한가

9장에서 2차원 배열이 메모리에 한 줄로 놓인다고 배웠다. 행 우선이므로 a[i][j]를 찾으려면 "i번째 행의 시작"을 계산해야 하고, 그러려면 한 행이 몇 칸인지 알아야 한다.

컴파일러가 하는 계산
a[i][j] 의 자리
 = a 의 시작 + (i × M + j) × 4바이트
크기 확인 (int a[3][4])
sizeof(a)       = 48  (전체)
sizeof(a[0])    = 16  (한 행)
a + 1 은 16바이트 이동

M을 모르면 이 계산을 할 수 없다. 반면 행 수는 몰라도 된다. 그래서 첫 번째 차원만 비울 수 있다.

더 유연한 방법 — 1차원처럼 다루기

7장 연습 13번에서 손으로 계산했던 i*N + j가 여기서 다시 나온다. 코드가 번거로워지므로 보통은 int a[][M] 형태를 쓰고, 배열 크기를 #define으로 고정한다.

올림피아드에서의 실용 지침 2차원 배열은 전역으로 선언하고 함수에 넘기지 않는 것이 가장 간단하다(9·10장). board, n, m을 전역으로 두면 매개변수가 사라진다. 넘겨야 할 때만 int a[][M] 형태를 쓴다.

05 — 흔한 오류

흔한 오류 여섯 가지

오류 1함수 안에서 sizeof로 크기를 구했다
void f(int a[]) {
    int n = sizeof(a) / sizeof(a[0]);   // 8 / 4 = 2
    for (int i = 0; i < n; i++) { ... } // 두 칸만 돈다
}

warning: 'sizeof' on array function parameter 'a'
         will return size of 'int *' [-Wsizeof-array-argument]

경고는 나오지만 실행된다. 배열이 100개여도 앞의 두 개만 처리하고 끝난다.

고치는 법 — 크기를 매개변수로 받는다. void f(int a[], int n). 예외 없는 규칙이다.
오류 2배열 원소에 &를 빠뜨렸다
swap(a[i], a[j]);     // 값을 넘겼다
swap(&a[i], &a[j]);   // 올바름

a는 주소지만 a[i]는 값이다. 헷갈리기 쉬운 지점이다. 12장 오류 1과 같은 경고가 나온다.

고치는 법 — "배열 전체는 a, 원소 하나는 &a[i]". 두 경우를 나란히 외운다.
오류 32차원 배열의 열 크기를 뺐다
void show(int a[][], int n) { ... }

error: array type has incomplete element type 'int[]'
note: declaration of 'a' as multidimensional array must have
      bounds for all dimensions except the first

오류라서 반드시 걸린다. 메시지가 해결 방법까지 알려 준다. 행 수는 비울 수 있고 열 수는 비울 수 없다.

고치는 법 — void show(int a[][M], int n). M은 #define으로 정한 상수여야 한다.
오류 4넘긴 배열 크기와 선언한 크기가 다르다
#define M 4
void show(int a[][M], int n);

int b[3][5];        // 열이 5다
show(b, 3);         // 컴파일 경고만 나고 실행된다

컴파일러가 계산하는 자리와 실제 자리가 어긋나 완전히 엉뚱한 값을 읽는다. 죽지 않고 틀린 답만 낸다.

고치는 법 — 배열 선언과 함수 선언에 같은 #define 이름을 쓴다. 숫자를 직접 쓰지 않는다.
오류 5(*p)++ 의 괄호를 빠뜨렸다
*cnt++;      // 포인터를 증가시킨다 (값은 그대로)
(*cnt)++;    // 가리키는 값을 증가시킨다 (올바름)

경고가 없다. ++가 *보다 먼저 묶이기 때문이다(4장 우선순위). 카운터가 늘지 않아 결과가 항상 0이거나, 포인터가 엉뚱한 곳을 가리키게 된다.

고치는 법 — 포인터가 가리키는 값을 증감할 때는 항상 괄호. 또는 *cnt = *cnt + 1;로 명확하게 쓴다.
오류 6배열을 복사한 줄 알았다
void f(int a[], int n) {
    a[0] = 999;          // 원본이 바뀐다
}

int v[5] = {1,2,3,4,5};
f(v, 5);
printf("%d\n", v[0]);    // 999

경고도 오류도 없다. "함수 안에서만 바꾸고 싶었는데" 원본이 망가진다. 정렬 함수를 호출한 뒤 원래 순서가 필요해져서 발견되는 경우가 많다.

고치는 법 — 원본을 지키려면 호출 전에 복사본을 만든다. 읽기만 하는 함수에는 const를 붙여 의도를 분명히 한다.
이 장의 가장 중요한 교훈 배열을 함수에 넘기면 복사되지 않는다. 이것이 장점(빠르다)이자 함정(원본이 바뀐다)이다. 함수를 만들 때마다 "이 함수는 배열을 읽는가 고치는가"를 정하고, 읽기만 하면 const를 붙인다. 그러면 오류 6이 컴파일 단계에서 걸린다.

07 — 확인 평가 해설

정답과 해설

※ 이 절은 교사용 통합본에만 수록한다. 학생 배부용에서는 제거한다.

01
예제 1과 동일. main에서 20, 함수 안에서 8. 함수가 받은 것은 배열이 아니라 주소이기 때문이다. gcc 경고도 함께 확인시킨다.
02
void arr_print(const int a[], int n) — 읽기만 하므로 const. 끝의 공백 처리는 3장 출력 형식 점검표를 적용한다.
03
합이 4×109이므로 반환형이 long long이어야 한다(2장). 흔한 오답 — int 반환, 또는 함수 안에서 int s로 누적.
04
표준 코드와 동일. n = 1이면 42 42. 모두 음수면 mx가 음수로 나오는지 확인시킨다. *mx = 0으로 초기화한 답안이 여기서 걸린다(8장 오류 5).
05
const를 붙이면 error: assignment of read-only location으로 컴파일이 되지 않는다. 고치는 함수에는 붙이지 않는다는 기준을 몸으로 익히는 문제다.
06
printf("%lld\n", arr_sum(a + L, R - L + 1));
길이가 R - L + 1인 것이 핵심이다. 양끝을 포함하므로 +1(6장 반복 횟수 세기). 지도 포인트 — 새 함수를 만들지 않고 호출 방식만 바꿔 해결하는 경험이 13.3절의 목적이다.
07
8장 연습 4번의 함수 버전. 지도 포인트 — 8장에서 "배열에 담을 필요 없다"고 했던 문제다. 여기서는 함수 인터페이스를 연습하는 것이 목적이므로 배열을 쓴다.
08
#define M 5와 void show(int a[][M], int n). 전역 배열도 int a[100][M]처럼 같은 M을 쓴다(오류 4 예방).
09
예제 5의 변형. 합이 0으로 나오는 예제를 넣은 것은 "0이니까 틀렸나" 의심을 유도하기 위해서다.
흔한 오답 — *neg_cnt++(오류 5). 반드시 (*neg_cnt)++.
10
int arr_equal(const int a[], const int b[], int n, int *pos)
{
    for (int i = 0; i < n; i++) {
        if (a[i] != b[i]) { *pos = i; return 0; }
    }
    return 1;
}
두 배열 모두 const다. 12장 13번 find와 같은 설계(성공 여부는 반환값, 위치는 포인터)임을 짚는다.
11
arr_copy(a, b, n); 후 arr_reverse(b, n);. 원본 a는 그대로다.
지도 포인트 — 8장에서 "배열은 =로 복사할 수 없다"고 배웠다. 그 복사를 함수로 만들어 두면 매번 루프를 쓰지 않아도 된다. 19번의 해법이기도 하다.
12
행별 합은 out[i]에, 열별 합은 out[j]에 누적한다. 출력 배열도 매개변수로 받는 것이 요점이다. 반환할 수 없으므로(배열은 반환 불가) 이 방식뿐이다.
주의 — out[]은 고치므로 const를 붙이지 않는다. 입력 a에는 붙인다. 한 함수에 두 종류가 섞이는 첫 사례다.
13
9장 표준 코드를 함수로 분리한 것. 10장 15번과 비교하면, 거기서는 전역을 썼고 여기서는 매개변수로 넘긴다.
지도 포인트 — 두 방식을 모두 써 본 뒤 올림피아드에서는 전역이 간단하다는 결론을 학생이 스스로 내리게 한다(13.5절 실용 지침).
14
*first = *second = a[0];   // 또는 INT_MIN
for (int i = 0; i < n; i++) {
    if (a[i] > *first)  { *second = *first; *first = a[i]; }
    else if (a[i] > *second) { *second = a[i]; }
}
핵심 — 1위가 바뀔 때 기존 1위를 2위로 밀어내는 순서다. 반대로 쓰면 2위가 사라진다. 8장 13번(두 번째로 큰 값)과 달리 중복을 허용하므로 5 5 3 9 9의 답이 9 9다.
15
arr_minmax(a + L, R - L + 1, &mn, &mx); 후 mx만 출력. 06번과 같은 기법이다.
반복 횟수 — 최악 Q × N = 106으로 통과한다. 8장 15번처럼 N, Q가 10만이면 불가능해지고, 그때 필요한 것이 PART 3의 세그먼트 트리임을 예고한다.
16
① *cnt++; — ++가 먼저 묶여 포인터가 다음 칸으로 이동한다. 값은 그대로이고, 이후 역참조하면 엉뚱한 자리를 본다.
② (*cnt)++; — 가리키는 값이 1 늘어난다. 의도대로다.
4장 우선순위표에서 ++(단항, 1순위)가 *(역참조, 역시 단항)와 같은 순위지만 후위 ++가 더 강하게 묶인다. 괄호로 명시하는 것이 유일한 해법이다.
17
세 경우 모두 sizeof(a)가 8이다.
int a[5]로 선언한 함수에 크기 3짜리 배열을 넘겨도 경고 없이 컴파일된다.
뜻하는 바 — 매개변수의 [5]는 컴파일러가 완전히 무시하는 장식이다. 크기 검사를 해 줄 것이라 기대하면 안 된다. 그래서 이 교재는 int a[]를 쓰고 크기를 항상 따로 넘긴다.
18
① 48 / 16 / 4.
② a, a[0], &a[0][0]은 모두 같은 주소. a+1은 +16, a[0]+1은 +4.
③ a는 "한 행을 가리키는 포인터"라 1을 더하면 행 하나(16바이트)를 건너뛴다. a[0]은 "int를 가리키는 포인터"라 4바이트를 건너뛴다. 같은 주소를 가리켜도 자료형이 다르면 더하기의 보폭이 다르다.
④ 함수가 a[i][j]를 찾으려면 "i번째 행의 시작"을 계산해야 하고, 그 보폭이 바로 한 행의 크기 = M × 4바이트다. M을 모르면 보폭을 모르므로 계산할 수 없다. 그래서 열 크기를 선언에 적어야 한다.
지도 포인트 — 9장의 "메모리는 한 줄이다"와 이 장의 "열 크기 필수"가 여기서 하나로 연결된다. 이 문제를 풀고 나면 int a[][M]을 외우지 않아도 된다.
19
① 배열이 복사되지 않으므로 정렬 함수가 원본을 바꿔 버렸다. 호출 후의 a는 이미 정렬된 상태라 원래 순서가 남아 있지 않다.
② const를 붙이면 정렬 함수 안에서 대입하는 줄이 error: assignment of read-only location으로 막힌다. 즉 "이 함수는 고치는 함수"라는 것이 컴파일 단계에서 드러난다. (정렬 함수에는 const를 붙이면 안 된다. 이 실험의 목적은 const가 무엇을 막는지 보는 것이다.)
③ ⑴ 호출 전에 arr_copy로 복사본을 만들어 복사본을 정렬한다. ⑵ 원본을 출력한 뒤 정렬한다(순서를 바꾼다).
지도 포인트 — PART 3에서 "정렬하면 원래 인덱스가 사라진다"는 문제를 계속 만난다. 값과 인덱스를 함께 묶어 정렬하는 기법(구조체, 15장)이 그 해법임을 예고한다.
20
모범 구성 예. 
void arr_print  (const int a[], int n);
    입력만 / 실패 없음 / 경계: n=0 이면 빈 줄
long long arr_sum(const int a[], int n);
    입력만 / 경계: n=0 → 0
void arr_minmax (const int a[], int n, int *mn, int *mx);
    출력 mn,mx / n>=1 필요 / 경계: n=1, 모두 같은 값, 모두 음수

    고침 / 경계: n=0,1 (아무 일 없음)

    src 입력, dst 출력 / 겹치면 안 됨

    입력만 / 반환이 개수

    반환 1=찾음 / 못 찾으면 pos 미변경
설계 원칙 정리 — 읽기만 하면 const, 고치면 안 붙인다. 크기는 항상 함께 넘긴다. 결과가 둘 이상이면 포인터, 하나면 반환값. 실패 가능성이 있으면 반환값으로 알린다.
지도 포인트 — PART 1에서 만든 세 번째이자 마지막 함수 모음이다(10장 수학 함수, 12장 출력 매개변수, 13장 배열 함수). PART 2 첫 시간에 이 파일을 열어 놓고 시작하게 한다.
08 — 마무리

이 장을 마치기 전 점검

  • 배열을 함수에 넘기면 주소만 넘어간다는 것을 안다
  • 배열을 받는 함수는 크기를 함께 받는다
  • 함수 안에서 sizeof로 배열 크기를 구하지 않는다
  • 배열 전체는 a, 원소 하나는 &a[i]
  • 읽기만 하는 배열 매개변수에 const를 붙인다
  • 2차원 배열 매개변수에 열 크기를 적고 #define으로 통일한다
  • 포인터가 가리키는 값을 증감할 때 (*p)++로 괄호를 친다
  • 원본을 지켜야 하면 복사본을 만들어 넘긴다
다음 장 예고 — 14장 문자열과 문자 처리 문자열은 C에 따로 있는 자료형이 아니라 char 배열이다. 그래서 이 장에서 배운 모든 규칙이 그대로 적용된다. 여기에 "끝을 알리는 특별한 문자" 하나가 더해지는데, 그 한 칸을 잊어서 생기는 사고가 문자열 문제 오답의 대부분이다.
