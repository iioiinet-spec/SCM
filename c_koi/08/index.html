08

1차원 배열

지금까지는 입력을 읽고 계산한 뒤 버렸다. 값을 모아 두고 여러 번 들여다봐야 하는 순간부터 배열이 필요하다. 그리고 배열의 인덱스를 값 자체로 쓰는 발상 하나가 올림피아드에서 가장 자주 쓰이는 도구가 된다.

학습 목표

  • 배열을 선언·초기화하고 인덱스로 접근할 수 있다
  • 인덱스 범위를 넘는 접근이 왜 위험한지 설명할 수 있다
  • 배열을 순회하며 합·최댓값·조건에 맞는 개수를 구할 수 있다
  • 값을 인덱스로 쓰는 카운팅 배열로 분포를 집계하고 최빈값을 찾을 수 있다
  • 큰 배열을 어디에 선언해야 하는지 알고 메모리 한계를 계산할 수 있다

01 — 도입 문제

두 번 들여다봐야 하는 문제

N명의 점수를 입력받아 평균보다 높은 사람이 몇 명인지 세는 문제다. 지금까지의 방법으로 시도해 보자.

평균은 모든 입력을 다 읽은 뒤에야 알 수 있다. 그런데 비교하려면 각 점수가 다시 필요하다. 이미 지나간 값들은 x에 덮어써져 사라졌다.

해결책은 둘 중 하나다. 입력을 두 번 읽거나(채점 환경에서는 불가능하다), 읽은 값을 전부 저장해 두는 것이다. 후자가 배열이다.

또 하나의 문제 N명의 점수(0~100)에서 가장 많이 나온 점수를 찾으려면? 각 점수가 몇 번 나왔는지 세야 하는데, 101개의 변수를 만들 수는 없다. 이 문제의 답이 이 장의 핵심인 카운팅 배열이다.
이 장이 답할 질문 ① 같은 종류의 값 여러 개를 어떻게 한 이름으로 다루는가?
② 인덱스를 "몇 번째"가 아니라 "값 그 자체"로 쓰면 무엇이 가능해지는가?
③ 배열을 100만 개 만들면 어디에 선언해야 하는가?
02 — 개념 정리

개념 정리

8.1선언과 초기화

배열실제 내용주의
a[5]쓰레기 5개초기화하지 않으면 0이 아니다
b[5]1 2 3 4 5
c[5]1 2 0 0 0부분 초기화하면 나머지는 0
d[5]0 0 0 0 0{0}은 전부 0을 만드는 관용구
e[]7 8 9원소 수 = sizeof(e)/sizeof(e[0])

인덱스는 0부터 시작한다. 크기가 5면 쓸 수 있는 인덱스는 0, 1, 2, 3, 4이고 a[5]는 없다. 6장에서 표준형으로 외운 for (int i = 0; i < n; i++)가 바로 이 범위와 정확히 맞아떨어진다.

8.2인덱스 범위를 넘으면

C는 인덱스를 검사하지 않는다. 범위를 넘어도 그냥 그 자리의 메모리를 읽거나 쓴다.

CODE
int a[5] = {1,2,3,4,5};
for (int i = 0; i <= 5; i++) {
    printf("%d ", a[i]);
}
OUTPUT (한 예)
1 2 3 4 5 32766

마지막 값은 실행할 때마다 달라진다. 읽기는 이렇게 이상한 값이 나오는 정도지만, 쓰기는 다른 변수를 망가뜨리거나 프로그램을 죽인다. 배열 오류가 찾기 어려운 이유는, 망가진 곳과 증상이 나타나는 곳이 다르기 때문이다.

-O2를 켜면 경고가 나온다 warning: array subscript 5 is above array bounds of 'int[5]' [-Warray-bounds=]
warning: iteration 5 invokes undefined behavior [-Waggressive-loop-optimizations]
다만 인덱스가 변수일 때는 컴파일러가 알 수 없으므로 경고가 나오지 않는다. 범위 검사는 결국 사람이 한다.

8.3배열 순회의 기본 네 가지

목적핵심 코드주의
합sum += a[i];누적 변수는 long long을 고려(2장)
최댓값if (a[i] > mx) { mx = a[i]; }초기값을 a[0]으로
개수 세기if (조건) { cnt++; }cnt = 0 초기화
찾기if (a[i] == t) { pos = i; break; }없을 때의 값을 −1로
최댓값의 초기값을 0으로 두지 않는다 int mx = 0;으로 시작하면 모든 값이 음수일 때 0이 답으로 나온다. mx = a[0]으로 시작하고 i = 1부터 비교하거나, 2장의 INT_MIN을 쓴다. 6장 연습 13번에서 이미 만난 문제다.

8.4카운팅 배열 — 값을 인덱스로

이 장에서 가장 중요한 절이다. 지금까지 인덱스는 "몇 번째"였다. 이제 인덱스를 값 그 자체로 쓴다.

보통의 배열
a[0] = 90   ← 0번 학생의 점수
a[1] = 85
a[2] = 90
카운팅 배열
cnt[90] = 2  ← 90점이 2명
cnt[85] = 1
cnt[0..100] 전부 준비

값 x를 읽을 때마다 cnt[x]를 1 늘린다. 입력을 한 번만 훑으면 모든 값의 등장 횟수가 완성된다. N번의 반복으로 끝난다.

이것이 왜 강력한지는 비교해 보면 안다. 최빈값을 배열 저장 방식으로 구하면 모든 쌍을 비교해 N²번이 필요하다. 카운팅 배열은 N + 101번이면 끝난다. 7장에서 본 "N이 10만이면 이중 루프는 불가능"이라는 벽을 자료구조 하나로 넘는 것이다.

쓸 수 있는 조건쓸 수 없는 경우이유
값의 범위가 좁고 정수값이 109까지배열을 그만큼 만들 수 없다
점수 0~100, 나이 0~150값이 실수인덱스는 정수여야 한다
알파벳 26개값이 음수일 수 있음인덱스가 음수가 된다

값이 음수를 포함하면 옮겨서 쓴다. −100 ~ 100이면 cnt[x + 100]으로 0 ~ 200에 담는다. 이 수법을 오프셋이라고 하며, PART 3의 좌표 압축으로 이어진다.

8.5배열은 통째로 대입할 수 없다

하면 오류
int a[5], b[5];
b = a;
컴파일 결과
error: assignment to
expression with array type

경고가 아니라 오류라서 바로 걸린다. 복사하려면 반복문으로 한 칸씩 옮긴다. 배열 이름이 왜 그냥 값이 아닌지는 13장 포인터에서 밝혀진다.

8.6큰 배열은 어디에 선언하는가

올림피아드 문제는 N이 100만까지 가는 경우가 흔하다. 그런데 함수 안에 큰 배열을 선언하면 프로그램이 죽는다.

선언크기실측 결과이유
main 안 int a[1000000]3.8 MB정상스택은 보통 8 MB까지
main 안 int a[2000000]7.6 MB정상
main 안 int a[10000000]38 MBSegmentation fault스택 초과
전역 int a[10000000]38 MB정상스택이 아닌 별도 영역
규칙 두 가지 ① 원소가 10만 개를 넘으면 전역으로 선언한다. 함수 밖, main 위에 쓴다.
② 전역 배열은 자동으로 0으로 초기화된다. 카운팅 배열을 전역으로 두면 {0}을 쓸 필요도 없다.

메모리 계산도 해 둔다. int는 4바이트이므로 100만 개 = 약 4 MB다. 문제의 메모리 제한이 256 MB라면 int 배열을 6천만 개까지 쓸 수 있다.

03 — 표준 코드

표준 코드: 점수 분포와 최빈값

N명의 점수(0~100)를 읽어 분포를 집계하고 가장 많이 나온 점수를 출력한다.

요소설계 의도
int cnt[101];점수가 0부터 100까지이므로 크기는 101이다. 100으로 쓰면 만점자에서 범위를 넘는다.
전역 선언자동 0 초기화. 지역에 두려면 int cnt[101] = {0};로 쓴다.
cnt[x]++;이 한 줄이 집계의 전부. 입력을 한 번만 훑는다.
cnt[s] > cnt[best]같을 때 갱신하지 않으므로 동점이면 작은 점수가 답이 된다. 문제가 요구하는 기준에 맞춰야 한다.
반복 횟수입력 N번 + 탐색 101번. N이 100만이어도 즉시 끝난다.
INPUT
10
90 85 90 100 85 90 70 85 85 60
OUTPUT
85 4
분포 전체를 찍어 보면
60:1  70:1  85:4  90:3  100:1
검산
1+1+4+3+1 = 10 = N
모든 칸의 합이 N과 같아야 한다.
동점 처리를 문제에서 확인한다 "가장 많이 나온 점수가 여럿이면 작은 것을 출력"인지 "큰 것"인지에 따라 비교 연산자가 달라진다. >는 작은 쪽, >=는 큰 쪽을 남긴다. 한 글자 차이로 오답이 되므로 문제 서술을 반드시 다시 읽는다.

05 — 흔한 오류

흔한 오류 여섯 가지

오류 1배열 크기를 1 모자라게 잡았다

값의 범위가 0 ~ 100이면 서로 다른 값이 101개다.

int cnt[100];   // 100점 입력에서 cnt[100] → 범위 밖
int cnt[101];   // 올바름

만점자가 없는 테스트로는 발견되지 않는다. 범위의 양 끝 값을 반드시 넣어 본다.

고치는 법 — 크기는 최댓값 + 1. 오프셋이 있으면 최댓값 − 최솟값 + 1. 넉넉하게 잡는 것이 안전하다.
오류 2지역 배열을 초기화하지 않았다
int main(void) {
    int cnt[101];        // 쓰레기값
    cnt[x]++;            // 쓰레기 + 1
}

6장 오류 2의 배열 버전이다. 실행할 때마다 결과가 달라지거나, 우연히 0이 들어 있어 집에서는 맞고 채점에서는 틀린다.

고치는 법 — int cnt[101] = {0};로 쓰거나, 전역으로 선언한다. 전역은 자동으로 0이다.
오류 3큰 배열을 함수 안에 선언했다
int main(void) {
    int a[10000000];     // 38 MB → Segmentation fault
}

컴파일은 되고 실행하자마자 죽는다. 메시지에 배열 이야기가 전혀 없어서 원인을 찾기 어렵다. 스택 한계는 보통 8 MB, 즉 int 약 200만 개다.

고치는 법 — 원소가 10만 개를 넘으면 전역으로 옮긴다. main 위, 함수 밖에 쓴다.
오류 4인덱스가 범위를 넘었다
oob.c:4:5: warning: array subscript 5 is above array bounds
          of 'int[5]' [-Warray-bounds=]        (-O2 에서만)

상수 인덱스는 -O2에서 잡아 주지만, 변수 인덱스는 아무도 잡아 주지 못한다. 특히 위험한 두 가지:

코드문제
for (i = 0; i <= n; i++) a[i]a[n]은 범위 밖
cnt[x]++ (x가 범위 밖 입력)입력 검증을 안 했다
고치는 법 — 표준형 i < n을 쓴다. 카운팅할 값이 범위 안인지 의심되면 if (0 <= x && x <= 100)로 거른다(5장의 "거르기 먼저").
오류 5최댓값 초기값을 0으로 두었다
int mx = 0;
for (int i = 0; i < n; i++) { if (a[i] > mx) { mx = a[i]; } }
// 입력이 전부 음수면 답이 0으로 나온다

양수만 들어오는 테스트에서는 완벽히 동작한다. 음수 입력이 있는 문제에서만 틀린다.

고치는 법 — int mx = a[0];로 시작한다. 또는 INT_MIN(2장). 최솟값은 a[0] 또는 INT_MAX.
오류 6배열을 = 로 복사하려 했다
cp.c:2:47: error: assignment to expression with array type
    2 | int b[5]; b = a;
      |             ^

이것은 오류라서 바로 걸린다. 다행이다. 13장에서 포인터를 배우면 int *p = a;는 통과하는데, 그것은 복사가 아니라 같은 배열을 가리키게 만드는 것이라 더 위험하다.

고치는 법 — 반복문으로 한 칸씩 옮긴다. for (i = 0; i < n; i++) { b[i] = a[i]; }
이 장의 가장 중요한 교훈 배열 오류는 망가진 곳과 증상이 나타나는 곳이 다르다. 엉뚱한 변수의 값이 바뀌거나, 한참 뒤에 죽는다. 그래서 선언한 크기와 실제로 쓰는 인덱스 범위를 선언할 때 한 번, 쓸 때 한 번 두 번 확인하는 수밖에 없다.

두 방식의 속도 비교 — N개의 정수(0 ~ 1,000) 중 최빈값을 ① 모든 쌍을 비교하는 이중 루프 ② 카운팅 배열 두 가지로 구현하라. N을 1,000 / 10,000 / 50,000으로 바꿔 가며 각각의 실행 시간을 stderr로 측정해 표로 만들고, 7장의 복잡도 판단과 비교해 설명하라.

18

경계값 사냥 — 표준 코드(최빈값)에 대해 다음을 각각 시험하고 결과를 적어라. ① 모든 점수가 0점 ② 모든 점수가 100점 ③ N = 1 ④ 배열 크기를 101에서 100으로 바꾸고 100점 입력. ④에서 무슨 일이 일어나며, 왜 그 증상이 바로 나타나지 않을 수도 있는지 설명하라.

19

오프셋 설계 — 값의 범위가 ⑴ −105 ~ 105 ⑵ 1 ~ 109 ⑶ 실수 0.0 ~ 100.0(소수 첫째 자리까지) 세 경우에 대해, 카운팅 배열을 쓸 수 있는지 판정하고 쓸 수 있다면 배열 크기와 오프셋을 정하라. 쓸 수 없다면 그 이유와 대안의 방향을 적어라.

20

범위 밖 쓰기의 실제 피해 — 아래 코드를 작성해 실행하고, before와 after의 값이 어떻게 되는지 관찰하라. 왜 이런 일이 생기는지 메모리 배치로 설명하고, 이런 오류를 조기에 발견하는 방법을 두 가지 이상 제시하라.

int before = 111;
int a[5] = {0};
int after = 222;

for (int i = 0; i <= 7; i++) { a[i] = 9; }

printf("before=%d after=%d\n", before, after);

※ 결과는 컴파일러와 최적화 옵션에 따라 달라진다. 자신의 환경에서 관찰한 것을 그대로 적는다.

07 — 확인 평가 해설

정답과 해설

※ 이 절은 교사용 통합본에만 수록한다. 학생 배부용에서는 제거한다.

01
for (int i = n-1; i >= 0; i--) { printf("%d ", a[i]); } — 6장 역순 루프와 같다. 인덱스가 n-1부터라는 점을 짚는다.
02
합이 최대 105 × 109 = 1014이므로 long long(2장). 평균은 (double)sum / n(4장). 흔한 오답 — int sum 또는 sum / n.
03
int mx = a[0], pos = 0;
for (int i = 1; i < n; i++) {
    if (a[i] > mx) { mx = a[i]; pos = i; }
}
printf("%d %d\n", mx, pos + 1);
처음 나온 위치이므로 >를 쓴다. >=면 마지막 위치가 된다. 전부 음수인 예제로 mx = 0 오답을 반드시 걸러 낸다.
04
배열에 저장할 필요도 없다. 읽으면서 if (x == t) cnt++;로 끝난다. 지도 포인트 — "배열을 배웠으니 무조건 배열에 담는다"는 습관을 여기서 경계시킨다. 두 번 봐야 할 때만 저장한다.
05
예제 3의 방법 B. i < n/2가 핵심이다. i < n으로 쓰면 원래대로 돌아오는 것을 직접 실행해 보게 한다.
06
cnt[x]++ 후 0~100 순회하며 if (cnt[s] > 0). 카운팅 배열이 자동으로 정렬된 순서를 준다는 점이 중요하다. 12번의 복선이다.
07
표준 코드와 동일. 입력 70 90 70 90에서 >면 70, >=면 90이 나온다.
이유 — >=는 같은 값을 만나도 갱신하므로 뒤쪽(큰 점수)이 남는다. 문제가 요구하는 기준을 반드시 확인하라는 교훈.
08
예제 4와 동일. cnt[c - 'a']++. 입력은 scanf(" %c", &c)를 == 1로 반복(3장). 대문자나 공백이 섞일 수 있으면 if로 거른다.
09
예제 1과 동일. N ≤ 105이므로 배열 크기는 넉넉히 100,005 정도. 10만 개는 400 KB로 지역에 두어도 되지만, 습관상 전역으로 두는 것을 권한다.
10
예제 5와 동일. 크기 201, 오프셋 100. 흔한 오답 — 크기 200. -100과 100을 모두 넣어 확인시킨다.
11
int seen[1001] = {0};
for (int i = 0; i < n; i++) {
    if (seen[a[i]] == 0) { printf("%d ", a[i]); seen[a[i]] = 1; }
}
카운팅 배열을 0/1 표시로만 쓰는 형태다. 이것이 PART 3에서 그래프 탐색의 visited 배열로 그대로 이어진다. 반드시 짚어 둔다.
12
for (int v = 0; v <= 10000; v++) {
    for (int k = 0; k < cnt[v]; k++) { printf("%d ", v); }
}
반복 횟수 — 입력 N번 + 출력 (10,001 + N)번. 즉 N + 값의 범위에 비례하며, 비교 정렬의 N log N보다 빠르다.
지도 포인트 — 안쪽 루프가 있어도 전체 출력 횟수는 N이므로 이중 루프가 아니다. "루프가 겹쳤다 = N²"이 아니라는 것을 여기서 가르친다. 값의 범위가 좁을 때만 쓸 수 있다는 제약도 함께 강조한다.
13
최댓값을 찾고, 최댓값이 아닌 것 중 최댓값을 다시 찾는다(두 번 훑기). 또는 mx1, mx2를 한 번에 갱신한다. 값의 범위가 좁다면 카운팅 배열로 위에서 두 번째로 cnt[v] > 0인 v를 찾는 방법이 가장 간단하다.
경계 — 모든 값이 같으면 두 번째가 존재하지 않는다. 문제에서 이 경우의 처리를 정해야 한다.
14
cnt 배열 크기가 1,000,001이므로 약 4 MB다. 지역에 두면 위험하니 전역으로 선언한다. 집계 후 cnt[v] == 1인 v를 작은 것부터 출력한다.
지도 포인트 — 입력 N도 106이므로 입력 배열까지 두면 8 MB다. 사실 이 문제는 입력 배열이 필요 없다. 읽으면서 바로 cnt[x]++만 하면 된다. 4번과 같은 교훈이다.
15
단순 풀이는 질의마다 L~R을 더하므로 최악 Q × N = 106번으로 N, Q ≤ 1,000에서는 통과한다.
N, Q가 10만이면 1010번으로 불가능하다. 미리 누적합을 만들어 두면 질의 하나를 뺄셈 한 번으로 끝낼 수 있다(PART 3 누적합 단원). 여기서는 "단순 풀이의 한계를 체감하는 것"까지가 목표다.
16
⑴ 4 MB — 통과, 지역도 가능(8 MB 이내).
⑵ 8 × 107 = 80 MB — 256 MB 이내라 통과, 그러나 지역은 불가(전역 필수).
⑶ 1 × 108 = 100 MB — 통과, 전역 필수.
⑷ 4 × 108 = 400 MB — 메모리 초과. 자료형을 줄이거나(char·short) 알고리즘을 바꿔야 한다.
지도 포인트 — 2장의 자료형 크기와 이 장의 배열이 만나 메모리 제한이라는 새 제약을 만든다. 시간과 메모리를 모두 계산하는 습관으로 넘어간다.
17
이중 루프는 N², 카운팅은 N + 1001번이다. N = 50,000이면 25억 대 5만으로 약 5만 배 차이다. 실측하면 이중 루프는 수 초, 카운팅은 측정이 어려울 만큼 빠르게 나온다.
지도 포인트 — 7장에서 "N이 크면 이중 루프 불가"라고 배웠고, 여기서 그 벽을 자료구조로 넘는 첫 경험을 한다. 알고리즘 공부의 동기가 되는 자리이므로 시간을 들여 체감시킨다.
18
① 0 N ② 100 N ③ 입력된 그 점수와 1 ④ cnt[100]이 배열 밖을 건드린다.
④의 증상이 바로 안 나타나는 이유 — cnt[100]은 배열 바로 다음 메모리이고, 거기에 마침 다른 변수가 있으면 그 변수가 망가진다. 아무것도 없으면 아무 일도 일어나지 않은 것처럼 보인다. 프로그램이 죽지 않는다고 해서 맞는 것이 아니다.
지도 포인트 — 전역 배열의 경우 뒤에 다른 전역 변수가 올 수 있고, 지역이면 스택의 다른 값을 덮는다. 20번으로 이어진다.
19
⑴ 가능 — 크기 200,001, 오프셋 100,000. 약 800 KB로 전역 선언.
⑵ 불가능 — 배열 크기 109는 4 GB. 값의 개수는 많아야 N개이므로, 값을 정렬해 순서로 바꾸는 좌표 압축이나 해시가 필요하다(PART 3).
⑶ 변형하면 가능 — 소수 첫째 자리까지이므로 ×10해 정수로 만들면 0 ~ 1000의 1001칸이 된다. 다만 실수 입력을 10배 한 뒤 반올림할 때 오차에 주의한다(2장).
지도 포인트 — ⑶의 "실수를 정수로 바꿔 다루기"는 계산 기하(PART 4)에서도 쓰는 표준 수법이다.
20
결과는 환경과 옵션에 따라 전혀 다르게 나온다. 교재 집필 환경(gcc 13.3.0, 리눅스)에서 실제로 관찰한 것은 다음과 같다. 
$ gcc -std=c11 -Wall -o q20 q20.c
$ ./q20
*** stack smashing detected ***: terminated
Aborted

$ gcc -std=c11 -O2 -Wall -o q20 q20.c
q20.c:6:41: warning: iteration 5 invokes undefined behavior
$ ./q20
before=111 after=222
최적화를 끄면 프로그램이 죽고, 켜면 멀쩡히 돌아간다. -O2에서는 a를 읽는 곳이 없다고 판단해 루프 자체를 없애 버렸기 때문이다. 다른 환경에서는 after만 9로 바뀌는 결과가 나오기도 한다. 어느 쪽도 "정상 동작"이 아니다.
(stack smashing detected는 컴파일러가 배열 뒤에 심어 둔 감시값이 망가진 것을 실행 중에 발견한 것이다. 항상 잡아 주지는 않는다.)
설명 — 지역 변수들은 스택에 나란히 놓인다. a[5], a[6], a[7]은 배열 바깥이지만 그 자리에 다른 변수가 있을 수 있고, 그 변수가 덮어써진다. 컴파일러가 변수를 어떤 순서로 배치할지는 정해져 있지 않으므로 결과를 예측할 수 없다.
조기 발견 방법 — ① -O2 -Wall로 컴파일해 -Warray-bounds 경고 확인 ② 루프 조건을 i < n 표준형으로 통일 ③ 배열 크기를 상수로 정의해 선언과 루프에서 같은 이름을 쓰기 ④ 가능하면 -fsanitize=address 옵션으로 실행해 즉시 잡기.
지도 포인트 — "실행이 되니까 맞다"는 가장 위험한 판단이다. 이 장의 교훈을 여기서 마무리한다.
08 — 마무리

이 장을 마치기 전 점검

  • 인덱스는 0부터 n-1까지라는 것을 쓸 때마다 확인한다
  • 카운팅 배열의 크기는 최댓값 − 최솟값 + 1로 잡는다
  • 지역 배열은 = {0}으로 초기화하거나 전역으로 선언한다
  • 원소가 10만 개를 넘으면 전역에 선언한다
  • 최댓값의 초기값을 0이 아니라 a[0]으로 둔다
  • 두 번 봐야 할 때만 배열에 저장한다
  • cnt[x]++ 한 줄이 N번의 훑기로 분포를 완성한다는 것을 안다
  • 시간뿐 아니라 메모리도 계산한다
다음 장 예고 — 09장 2차원 배열과 델타 이동 7장에서 좌표로 계산했던 격자를 이제 저장한다. 그리고 상하좌우 네 방향을 dx, dy 배열 두 개로 표현하는 수법을 배우는데, 이것이 PART 3 격자 BFS의 뼈대가 된다.
