16

동적 메모리·디버깅·테스트

PART 1의 마지막 장이다. 크기를 미리 모를 때 메모리를 얻는 방법을 배우고, 지금까지 열다섯 장에서 쌓인 모든 함정을 제출 전에 스스로 걸러 내는 절차를 완성한다. 틀린 코드를 자동으로 잡아내는 도구가 이 장의 진짜 주제다.

학습 목표

  • malloc·calloc·free로 크기가 정해지지 않은 배열을 만들 수 있다
  • 할당 실패와 메모리 누수, free 후 사용의 위험을 안다
  • 올림피아드에서 전역 배열과 동적 할당 중 무엇을 쓸지 판단할 수 있다
  • freopen으로 테스트 입력을 파일에서 읽어 반복 검증할 수 있다
  • -fsanitize=address와 valgrind로 메모리 오류를 자동 검출할 수 있다
  • 기준 정답과 대조하는 스트레스 테스트로 반례를 스스로 찾을 수 있다

01 — 도입 문제

크기를 미리 모를 때

8장부터 배열을 쓸 때마다 "최대 크기"를 미리 잡아 왔다.

대부분의 문제에서는 이것으로 충분하다. 하지만 두 가지 경우에 곤란해진다.

상황문제
최댓값이 매우 클 때N ≤ 108이면 전역 배열이 400 MB로 메모리 초과
크기가 입력에 따라 달라질 때N×M 격자인데 N과 M의 곱만 제한되는 경우

이럴 때는 입력을 읽은 뒤 필요한 만큼만 메모리를 얻는다. 그것이 동적 할당이다.

그리고 이 장에는 더 중요한 주제가 하나 있다. 지금까지 열다섯 장 동안 "경고 없는 오류"를 수없이 만났다. 오버플로, 범위 밖 접근, 초기화 누락, 정렬 기준 실수. 이것들을 사람 눈으로 찾는 것은 한계가 있다.

이 장이 답할 질문 ① 크기를 모를 때 어떻게 배열을 만드는가?
② 범위 밖 접근을 자동으로 잡아낼 수 있는가?
③ 내 코드가 틀렸다는 것을 컴퓨터가 알려 주게 할 수 있는가?
02 — 개념 정리

개념 정리

16.1malloc과 free

항목설명
sizeof(int) * n바이트 수를 넘긴다. 개수가 아니다.
(int *)malloc은 void*를 돌려주므로 받을 자료형으로 바꾼다(15장 qsort와 같다).
반환값실패하면 NULL이다. 반드시 검사한다(12장).
free(a)돌려준다. 안 하면 누수다.

malloc과 calloc의 차이

두 번째 malloc 직후
1645166323 5 0 0 115
← 앞서 쓰던 값이 남아 있다
calloc 직후
0 0 0 0 0
← 항상 0으로 채워진다

malloc으로 받은 자리에는 쓰레기값이 들어 있다. 위 출력은 같은 자리를 free했다가 다시 받은 결과인데, 이전에 쓴 값이 그대로 보인다. 8장 오류 2(초기화 누락)가 동적 할당에서도 똑같이 적용된다.

카운팅 배열처럼 0부터 시작해야 하면 calloc을 쓴다. 0으로 채우는 시간이 들지만 안전하다.

16.2할당은 실패할 수 있다

CODE
size_t huge = (size_t)1000000000 * 1000;
int *p = (int *)malloc(huge);
printf("%s\n", p == NULL ? "NULL" : "성공");
OUTPUT
NULL

메모리가 모자라면 NULL을 돌려준다. 검사하지 않고 쓰면 NULL 역참조로 즉시 죽는다(12장). 다행히 확실히 죽으므로 원인을 찾기는 쉽다.

16.3누수와 free 후 사용

메모리 누수

free하지 않고 끝내면 그 메모리는 회수되지 않는다. valgrind로 확인할 수 있다.

올림피아드에서 누수는 보통 문제가 안 된다 프로그램이 끝나면 운영체제가 전부 회수하기 때문이다. 다만 반복해서 할당하는 코드에서는 실행 중에 메모리가 계속 늘어 초과가 날 수 있다. 습관적으로 free를 쓰되, 못 썼다고 당황할 필요는 없다.

free 후 사용

이쪽이 훨씬 위험하다. free한 자리를 계속 쓰는 것이다.

free 뒤에는 p = NULL;을 넣어 두면 실수로 썼을 때 확실히 죽는다. 조용히 틀린 값을 쓰는 것보다 낫다.

16.4전역 배열과 동적 할당 — 무엇을 쓸까

상황권장이유
최댓값이 적당함
(N ≤ 106 정도)		전역 배열코드가 짧고 자동으로 0이며 실수할 여지가 없다
최댓값이 너무 큼동적 할당전역으로는 메모리 초과
크기가 입력에 따라 결정동적 할당최악의 경우로 잡으면 낭비가 크다
연결 리스트·트리동적 할당노드를 필요할 때마다 만든다(PART 3)
솔직한 지침 PART 2에서 푸는 문제의 대부분은 전역 배열로 충분하다. 동적 할당은 코드가 길어지고 free·NULL 검사 같은 실수 지점이 늘어난다.
그럼에도 이 장에서 배우는 이유는 PART 3의 연결 리스트와 트리 때문이다. 거기서는 동적 할당이 필수다. 지금은 원리만 익혀 둔다.

16.5freopen — 테스트를 반복하기 쉽게

터미널에 매번 입력을 치는 것은 느리고 오타가 난다. 입력을 파일에 적어 두고 읽게 하면 한 번의 실행으로 끝난다.

집에서 — 파일에서 읽는다
$ gcc -DLOCAL -o sol sol.c
$ ./sol
60
제출용 — 표준 입력
$ gcc -o sol sol.c
$ echo "2
5 7" | ./sol
12

-DLOCAL을 붙여 컴파일하면 freopen 줄이 살아나고, 안 붙이면 사라진다. 같은 소스를 고치지 않고 두 방식으로 쓸 수 있다.

물론 1장에서 배운 ./sol < input.txt로도 같은 일을 할 수 있다. 통합 개발 환경에서 실행 버튼만 누르는 경우에 freopen이 편하다.

16.6디버깅 도구 네 가지

도구잡아내는 것쓰는 법
-Wall (1장부터)서식 불일치, 초기화 누락, 우선순위, 반환 누락항상 켠다
-O2 -Wall범위 밖 상수 인덱스, 루프 밖 접근제출 전 한 번 더
-fsanitize=address실행 중의 범위 밖 접근, free 후 사용버그가 안 보일 때
valgrind메모리 누수, 초기화 안 된 값 사용동적 할당을 쓸 때

몇 번째 줄에서 났는지 정확히 알려 준다. -g를 함께 붙여야 줄 번호가 나온다. 변수 인덱스라도 잡아내므로, -Wall이 못 잡는 것을 메운다.

sanitizer는 느리다 실행 속도가 몇 배 느려지므로 제출용 빌드에는 쓰지 않는다. 버그를 찾을 때만 켜고, 찾은 뒤에는 끈다.

그리고 12장에서 배운 것 하나. 디버깅 출력은 stderr로 보낸다. 프로그램이 죽어도 메시지가 남고, 채점 결과에 섞이지 않는다.

16.7스트레스 테스트 — 반례를 자동으로 찾기

이 장에서 가장 중요한 절이다. 느리지만 확실히 맞는 코드와 빠르지만 의심스러운 코드를 만들어, 무작위 입력으로 둘을 비교한다.

준비물설명
gen무작위 입력을 만드는 프로그램. 작은 크기로 만든다
sol확실히 맞는 코드(느려도 됨)
bad검사할 코드
비교 스크립트둘의 출력이 다르면 멈추고 그 입력을 보여 준다

실제로 돌려 보자. 최댓값을 구하는 코드에서 mx = 0으로 시작한 것(8장 오류 5)을 bad로 두었다.

이것이 PART 2의 핵심 기술이다 "어디가 틀렸는지 모르겠다"는 상황에서 구체적인 반례를 손에 쥐는 것만큼 강력한 도구는 없다. 반례가 작으면(원소 3개) 손으로 추적할 수 있다. 입력을 작게 만드는 것이 요령이다.
PART 2·3에서 빠른 알고리즘을 배울 때마다 "느린 완전탐색"을 기준으로 삼아 이 방법으로 검증한다.

05 — 흔한 오류

흔한 오류 여섯 가지

오류 1malloc에 개수를 넘겼다
int *a = (int *)malloc(n);               // n 바이트 — 너무 작다
int *a = (int *)malloc(sizeof(int) * n); // 올바름

경고가 없다. n이 10이면 10바이트, 즉 int 두 개 반밖에 안 된다. 나머지 칸을 쓰는 순간 범위 밖이다.

고치는 법 — malloc은 항상 바이트 수를 받는다. sizeof(자료형) * 개수로 쓴다.
오류 2NULL 검사를 생략했다
int *a = (int *)malloc(sizeof(int) * n);
a[0] = 1;        // 실패했으면 NULL 역참조

대부분의 경우 할당이 성공하므로 평소엔 문제가 없다. 큰 메모리를 요구하는 문제에서만 Segmentation fault가 난다.

고치는 법 — if (a == NULL) { return 1; }를 바로 다음 줄에 둔다. 한 줄이면 된다.
오류 3malloc 받은 메모리를 초기화하지 않았다
int *cnt = (int *)malloc(sizeof(int) * 101);
cnt[x]++;        // 쓰레기 + 1

8장 오류 2의 동적 할당 버전이다. 전역 배열은 자동으로 0이지만 malloc은 아니다. 운 좋게 0이 들어 있어 통과하다가 어느 날 틀린다.

고치는 법 — 0부터 시작해야 하면 calloc을 쓴다. 또는 루프로 직접 채운다.
오류 4free한 포인터를 다시 썼다
warning: pointer 'p' used after 'free' [-Wuse-after-free]
AddressSanitizer: heap-use-after-free

gcc가 간단한 경우는 잡아 주지만, 함수를 건너뛰면 못 잡는다. 그때는 sanitizer가 필요하다. 이미 다른 용도로 쓰이는 메모리를 건드리므로 엉뚱한 곳이 망가진다.

고치는 법 — free(p); p = NULL;을 한 묶음으로 쓴다. 두 번 free하는 사고도 함께 막힌다.
오류 5freopen을 #ifdef 없이 남겨 두었다
freopen("input.txt", "r", stdin);     // 제출 코드에 그대로

채점 서버에는 그 파일이 없다. freopen이 실패하면 stdin이 쓸 수 없는 상태가 되어 입력을 하나도 못 읽는다. 모든 테스트가 틀린다.

고치는 법 — #ifdef LOCAL로 감싼다. 제출 직전 -DLOCAL 없이 한 번 실행해 확인한다.
오류 6큰 입력으로만 테스트했다

07 — 확인 평가 해설

정답과 해설

※ 이 절은 교사용 통합본에만 수록한다. 학생 배부용에서는 제거한다.

01
int *a = (int*)malloc(sizeof(int) * (size_t)n); 후 NULL 검사, 입력, 출력, free(a). 네 단계를 한 묶음으로 익히게 한다.
02
표준 코드와 동일. 모두 음수 입력에서 mx가 음수로 나오는지가 핵심이다. mx = 0으로 시작한 답안은 여기서 걸린다(8장 오류 5). N = 1도 확인시킨다.
03
예제 1과 동일. malloc의 내용은 실행할 때마다 다를 수 있다. 운영체제가 새 메모리를 줄 때는 0으로 채워 주기도 해서, 처음 한 번은 0이 나올 수도 있다. 그래서 더 위험하다는 점을 강조한다.
04
malloc((size_t)1000000000 * 1000) → NULL. 검사 없이 a[0] = 1;을 하면 Segmentation fault로 죽는다(종료 코드 139). 12장의 NULL 역참조와 같다.
05
-DLOCAL이면 input.txt에서, 없으면 표준 입력에서 읽는다. 지도 포인트 — #ifdef를 빼고 제출했을 때 어떤 일이 생기는지(오류 5) 실제로 재현시킨다. input.txt를 지우고 실행하면 입력을 못 읽는다.
06
① 그냥 실행 → 아무 일 없이 쓰레기값 출력(또는 운 나쁘면 죽음)
② -O2 -Wall → 상수 인덱스면 array subscript ... is above array bounds 경고
③ sanitizer → 실행 중에 정확한 줄 번호와 함께 중단
지도 포인트 — 세 결과를 나란히 놓고 보면 도구를 왜 여러 개 쓰는지 바로 이해한다.
07
free 없으면 definitely lost: 400 bytes, 넣으면 ERROR SUMMARY: 0 errors. 보충 — 올림피아드에서는 누수가 보통 문제가 되지 않지만, 반복 할당하는 코드에서는 실행 중 메모리가 계속 늘어난다는 점을 짚는다.
08
p = NULL을 넣으면 확실히 죽는다(NULL 역참조). 안 넣으면 엉뚱한 값이 나오거나 우연히 멀쩡해 보인다. "확실히 죽는 것이 낫다"는 판단을 설명한다 — 조용히 틀리는 것보다 즉시 드러나는 편이 디버깅에 유리하다.
09
int *g = (int*)malloc(sizeof(int) * (size_t)n * (size_t)m);
// 접근: g[i * m + j]
주의 — sizeof(int) * n * m에서 n * m이 int로 계산되면 넘칠 수 있다. (size_t) 변환을 앞에 둔다(2장 형변환 위치).
지도 포인트 — 7장 연습 13번에서 손으로 계산한 i*M+j가 여기서 실제로 쓰인다.
10
int *cnt = (int*)calloc((size_t)v + 1, sizeof(int)); — 크기는 V+1(8장 오류 1), calloc으로 0 초기화(오류 3). 두 함정이 한 줄에 모여 있다.
malloc을 썼다면 루프로 0을 채워야 한다. 안 채우면 쓰레기값에 ++를 한다.
11
15장 예제 5의 cmp_int를 쓴다. 절댓값 2×109이므로 뺄셈을 쓰면 틀린다. 동적 배열이라는 점만 다르고 나머지는 15장 그대로다.
12
예제 5의 gen.c. srand(시드)로 시작해야 같은 시드에 같은 입력이 나와 재현이 가능하다. 재현성이 없으면 반례를 다시 만들 수 없다는 점을 강조한다.
13
교재 환경에서는 seed 3에서 3 / -5 -2 -10이 나왔다. 기준은 −2, 버그 코드는 0.
이유 — mx = 0으로 시작했는데 모든 값이 음수라 한 번도 갱신되지 않았다. 0은 입력에 없는 값인데도 답으로 나왔다.
지도 포인트 — 학생마다 시드와 반례가 다를 수 있다. 중요한 것은 "모두 음수"라는 패턴을 무작위 생성기가 알아서 만들어 냈다는 점이다.
14
오버플로 버그를 고를 경우 — 생성기가 109 근처의 값을 만들어야 한다. rand() % 20 - 10 같은 작은 값으로는 영원히 반례가 안 나온다.
비교 함수 뺄셈 버그 — 양수와 음수 모두 20억 근처가 나와야 한다.
최댓값 초기값 버그 — 음수만 나오는 경우가 필요하므로 값 범위를 음수 쪽으로 치우치게 한다.
지도 포인트 — 이것이 이 문제의 핵심 교훈이다. 생성기가 버그를 드러낼 수 있는 입력을 만들어야 한다. 작은 값만 만드는 생성기는 오버플로를 절대 못 잡는다. 테스트 설계도 설계라는 것을 가르친다.
15
다섯 파일과 기대 출력 예: t1(N=1) → 그 값 두 번, t2(모두 음수) → 음수 최댓값, t3(모두 같은 값), t4(최댓값 109 여러 개) → 합이 int를 넘음, t5(N=0) → 0.
스크립트는 for f in t*.txt; do ./sol < $f; done 형태면 충분하다.
지도 포인트 — 한 번 만들어 두면 코드를 고칠 때마다 1초 만에 전부 재검증된다. 이 투자 대비 효과를 체감시키는 것이 목적이다.
16
⑴ 400 KB — 전역으로 충분. 전역 권장.
⑵ 400 MB — 256 MB 초과. 전역도 동적도 불가능하다. int 대신 더 작은 자료형을 쓰거나, 배열에 다 담지 않고 읽으면서 처리하는 방식으로 알고리즘을 바꿔야 한다.
⑶ 전역으로 106×106을 잡을 수는 없다. 동적 할당 필수. 실제 필요한 것은 N·M ≤ 106이므로 4 MB면 된다.
⑷ 105 × 28 = 2.8 MB — 전역 권장.
지도 포인트 — ⑵처럼 둘 다 안 되는 경우가 있다는 것이 중요하다. 그때는 자료구조가 아니라 알고리즘을 바꿔야 한다.

교재 환경 기준 정리.
버그-Wall-O2 -Wallsanitizervalgrind
⑴ 상수 인덱스 범위 밖못 잡음잡음잡음잡음
⑵ 변수 인덱스 범위 밖못 잡음대개 못 잡음잡음잡음
⑶ free 후 사용간단하면 잡음잡음잡음잡음

지도 포인트 — 원소 8개짜리 반례보다 2~3개짜리가 훨씬 낫다. 손으로 추적할 수 있기 때문이다. PART 3·4의 복잡한 알고리즘에서 이 기법이 실제로 필요해진다.

정답이 없는 문제다. 다만 반드시 쓰게 한다. 학생마다 자주 틀리는 유형이 뚜렷하게 다르며, 본인이 그것을 인식하는 것만으로 오답률이 크게 줄어든다.
교사용 운영법 — 수업에서 수집해 반 전체의 빈도표를 만들면, PART 2 초반에 어느 장을 복습해야 할지가 데이터로 나온다. 개인 점검표는 PART 2 내내 갱신하게 한다.
20
⑴ 최악의 경우 — 합은 105 × 100 = 107로 int로도 되지만 long long을 쓴다. 정렬은 N log N ≈ 1.7×106으로 여유.
⑵ 자료형·크기 — char name[21](14장 +1), int score, age. 구조체 28바이트.
⑶ 메모리 — 105 × 28 = 2.8 MB. 전역 배열로 충분하다.
⑷ 경계 입력 — N=1 / 모두 같은 점수(정렬 2·3순위 확인) / 모든 점수가 100 / 평균과 정확히 같은 점수가 있는 경우 / 이름이 20자인 경우.
⑸~⑼ — 평균 비교는 (double)sum / n(4장). "평균 이상"이므로 >=를 쓴다. 비교 함수는 15장 표준 코드 그대로.
지도 포인트 — 이 문제는 난이도가 높지 않다. 목적은 절차를 밟는 연습이다. 코드를 먼저 쓰고 나중에 점검하는 학생과, 절차대로 간 학생의 소요 시간을 비교해 보면 후자가 더 빠르다는 것을 알게 된다. PART 2의 작업 방식을 여기서 정착시킨다.
08 — 마무리

PART 1을 마치며

  • malloc은 바이트 수를 받고, NULL을 검사하고, free로 돌려준다
  • 0부터 시작해야 하면 calloc을 쓴다
  • freopen은 #ifdef LOCAL로 감싼다
  • 버그가 안 보이면 -fsanitize=address -g로 돌려 본다
  • 동적 할당을 썼으면 valgrind로 한 번 확인한다
  • 경계 입력 다섯 가지를 코드 쓰기 전에 만든다
  • 의심스러우면 기준 코드와 대조하는 스트레스 테스트를 돌린다
  • 제출 전에 점검표의 해당 줄을 확인한다
PART 1에서 얻은 것 문법 열여섯 장을 지나며 도구 다섯 가지를 손에 넣었다. 수학 함수(10장), 출력 매개변수(12장), 배열 함수(13장), 문자열 함수(14장), 구조체와 비교 함수(15장). 그리고 그것들을 검증하는 절차(16장).
