구조체와 사용자 정의 자료형

13장에서 "정렬하면 원래 인덱스가 사라진다"는 문제를 남겨 두었다. 서로 관련된 값들을 한 덩어리로 묶으면 그 문제가 사라진다. 그리고 구조체 배열을 qsort로 정렬하는 형태가 PART 2·3의 거의 모든 정렬 문제에서 쓰인다.

학습 목표

  • 구조체를 정의하고 .으로 멤버에 접근할 수 있다

01 — 도입 문제

이름과 점수가 따로 놀 때

학생 N명의 이름과 점수를 받아 점수가 높은 순으로 출력하는 문제다. 14장까지의 방법으로는 배열을 두 개 쓴다.

점수를 정렬하면 score 배열의 순서가 바뀐다. 그런데 name 배열은 그대로다. 이름과 점수의 짝이 깨진다.

정렬 전
name:  minjun  jisoo  hyun
score:     90     95    88
score만 정렬하면
name:  minjun  jisoo  hyun
score:     95     90    88
            ↑ minjun이 95점?

해결하려면 두 배열을 함께 옮겨야 한다. 멤버가 셋, 넷으로 늘어나면 교환할 때마다 모두 옮겨야 하고, 한 줄이라도 빠뜨리면 조용히 틀린다.

근본적인 해법 애초에 이름과 점수를 한 덩어리로 묶어 두면, 덩어리 하나를 옮기는 것으로 끝난다. 그 묶음이 구조체다.
이 장이 답할 질문 ① 서로 다른 자료형의 값을 어떻게 한 덩어리로 묶는가?
② 구조체는 배열처럼 "복사되지 않는" 것인가?
③ 점수가 같으면 나이순, 그것도 같으면 이름순 — 이런 정렬을 어떻게 쓰는가?
02 — 개념 정리

개념 정리

15.1구조체 정의와 멤버 접근

배열은 같은 자료형을 여러 개 모으지만, 구조체는 다른 자료형을 묶는다. 멤버는 .으로 접근한다.

이름 멤버는 char 배열이므로 =로 대입할 수 없다(8장). strcpy를 쓴다.

초기화

선언과 동시에
struct Student s = {"minjun", 95, 15};
전부 0으로
struct Student s = {0};

배열과 같은 규칙이다(8장). 전역으로 선언하면 자동으로 0이 된다.

15.2구조체는 = 로 복사된다

여기가 배열과 결정적으로 다른 점이다.

CODE
struct Student t = s;      // 통째로 복사
strcpy(t.name, "jisoo");
t.score = 88;
OUTPUT
s: minjun 95
t: jisoo  88

t를 고쳐도 s는 멀쩡하다. 안에 들어 있는 배열 멤버까지 함께 복사된다. 8장에서 배열은 b = a가 오류였는데, 구조체로 감싸면 복사가 된다.

동작배열구조체
=로 복사오류된다
함수에 넘기기주소만 간다통째로 복사된다
return으로 돌려주기불가능된다
함수에 넘기면 복사되므로 못 고친다 void move(Point p) { p.x += 100; }는 아무 일도 하지 않는다. 10장의 swap_bad와 같은 상황이다. 고치려면 포인터로 받는다.
또 하나, 큰 구조체를 값으로 넘기면 매 호출마다 복사 비용이 든다. 그래서 읽기만 해도 const 포인터로 넘기는 경우가 많다.

15.3구조체 포인터와 화살표

두 표기는 같다
struct Student *p = &s;

(*p).score      // 괄호 필수
p->score        // 같은 뜻, 이쪽을 쓴다
왜 괄호가 필요한가
*p.score 로 쓰면
.이 *보다 먼저 묶여
*(p.score) 가 된다 (4장)

->는 "가리키는 구조체의 멤버"를 뜻한다. (*p).를 짧게 쓴 것이고, 실무에서는 거의 ->만 쓴다.

포인터로 받았으므로 p->score = 100;으로 고치면 원본이 바뀐다(12장).

15.4typedef — 이름을 짧게

매번 struct를 쓰기 번거롭다
struct Student s;
struct Student a[100];
typedef를 쓰면
typedef struct {
    char name[20];
    int  score;
} Student;

Student s;
Student a[100];

이 교재는 typedef 형태를 표준으로 쓴다. 코드가 짧아지고 읽기 쉽다.

15.5enum — 상수에 이름을

값을 지정하면 그 값부터, 안 하면 직전 값 + 1이다. 9장의 델타 배열에 이름을 붙이는 데 특히 유용하다.

9장의 델타 배열
int dy[4] = {-1, 1, 0, 0};
int dx[4] = { 0, 0,-1, 1};

dy[2], dx[2]   // 무슨 방향?
enum을 쓰면
enum { UP, DOWN, LEFT, RIGHT };

dy[LEFT], dx[LEFT]   // 명확하다

숫자 2가 왼쪽이라는 것을 코드가 직접 말해 준다. 주석이 필요 없어진다.

15.6구조체의 크기와 패딩

구조체의 크기는 멤버 크기의 합보다 클 수 있다.

구조체멤버 합실제 크기
struct { char c; int i; }58
struct { int i; char c; }58
struct { char a; char b; int i; }68
struct { char name[20]; int s; int a; }2828

CPU가 값을 빠르게 읽을 수 있도록 빈 칸을 끼워 넣기 때문이다. 이것을 패딩이라고 한다.

올림피아드에서 알아 둘 점 메모리 계산에 영향을 준다. 10만 개짜리 구조체 배열을 만들 때 "멤버 합 × 10만"으로 계산하면 실제보다 작게 나온다. sizeof로 직접 재는 것이 정확하다.
큰 멤버부터 선언하면 패딩이 줄어드는 경우가 많다. 메모리가 빠듯할 때만 신경 쓰면 된다.

15.7qsort — 표준 정렬 함수

C는 정렬 함수를 표준으로 제공한다. <stdlib.h>의 qsort다.

비교 함수의 규칙

반환값뜻
음수x를 앞에 놓는다
0순서 상관없음
양수y를 앞에 놓는다

p->score - q->score이면 오름차순, q->score - p->score이면 내림차순이다. 순서만 바꾸면 된다.

뺄셈 방식은 오버플로에 걸린다 값이 20억 근처면 a - b가 넘쳐 부호가 뒤집힌다(2장). 실제로 {2000000000, -2000000000}을 뺄셈 방식으로 정렬하면 정렬되지 않는다.
안전한 형태는 다음과 같다. 
return (a > b) - (a < b);        // 오름차순
if (a != b) { return (a > b) ? 1 : -1; }
값의 범위가 작다고 확신할 때만 뺄셈을 쓴다.

다중 기준

1순위가 같을 때 2순위를 보는 것은 if를 차례로 쓰면 된다.

앞의 기준이 다르면 거기서 결정되고, 같으면 다음으로 넘어간다. 마지막 기준은 if 없이 바로 반환한다. strcmp가 이미 음수·0·양수를 돌려주므로 그대로 쓸 수 있다(14장).

05 — 흔한 오류

흔한 오류 여섯 가지

오류 1구조체 정의 끝에 세미콜론을 안 붙였다
struct Student {
    int score;
}            // ← 세미콜론 없음

int main(void) { ... }

error: expected identifier or '(' before 'int'

오류 메시지가 다음 줄을 가리킨다. 1장 오류 1(세미콜론 누락)과 같은 구조다. 구조체 정의가 끝났다는 것을 알리는 세미콜론이 없어 int main을 구조체 변수 선언으로 읽는다.

고치는 법 — 구조체 정의의 닫는 중괄호 뒤에는 항상 세미콜론. 함수와 다른 점이다.
오류 2점과 화살표를 바꿔 썼다
Student *p = &s;
p.score = 100;      // error: invalid type argument of '->'
s->score = 100;     // error: invalid type argument of '->'

오류라서 반드시 걸린다. 구조체 변수는 ., 구조체 포인터는 ->로 외운다.

고치는 법 — *가 붙어 선언됐으면 ->. 함수 매개변수로 받은 것은 대개 포인터이므로 ->다.
오류 3값으로 넘기고 고치려 했다
void init(Student s) { s.score = 0; }    // 아무 일도 안 한다
void init(Student *s) { s->score = 0; }  // 올바름

경고가 없다. 10장 오류 3, 12장 오류 2와 같은 함정이 구조체에서 반복된다. 게다가 큰 구조체면 복사 비용까지 든다.

고치는 법 — 고치는 함수는 포인터로 받는다. 읽기만 해도 구조체가 크면 const Student *로 받아 복사를 피한다.
오류 4비교 함수에서 뺄셈을 썼다
int cmp(const void *x, const void *y)
{
    return *(const int*)x - *(const int*)y;   // 오버플로
}

경고가 없다. 값이 작을 때는 완벽히 동작한다. {2000000000, -2000000000}을 넣으면 정렬되지 않은 채로 나온다. 2장의 오버플로가 여기서 다시 나온다.

고치는 법 — return (a > b) - (a < b);. 값의 범위가 작다고 확인했을 때만 뺄셈을 쓴다.
오류 5qsort에 원소 크기를 잘못 넘겼다
qsort(a, n, sizeof(a), cmp);       // 배열 전체 크기
qsort(a, n, sizeof(Student), cmp); // 올바름 — 원소 하나의 크기

경고가 없다. qsort가 엉뚱한 간격으로 자료를 옮겨 데이터가 망가진다. 멤버 합으로 직접 계산해 넘기는 것도 패딩 때문에 틀린다(15.6절).

고치는 법 — 세 번째 인자는 언제나 sizeof(원소자료형). sizeof(a[0])으로 써도 좋다.
오류 6다중 기준에서 앞 조건을 검사하지 않았다
return (q->score - p->score) + (p->age - q->age);   // 두 기준을 더했다

점수 차이와 나이 차이가 상쇄되어 엉뚱한 순서가 나온다. 1순위가 같을 때만 2순위를 봐야 한다.

고치는 법 — if (p->score != q->score) { return ...; }로 먼저 다른지 확인하고 반환한다. 마지막 기준만 if 없이 반환한다.
이 장의 가장 중요한 교훈 오류 3·4·5·6은 경고가 전혀 없다. 특히 4번과 6번은 작은 테스트에서 정상 동작한다. 정렬 결과는 눈으로 확인한다. 1순위가 같은 자료를 일부러 여러 개 넣어, 2·3순위가 제대로 작동하는지 보는 테스트를 반드시 만든다.

07 — 확인 평가 해설

정답과 해설

※ 이 절은 교사용 통합본에만 수록한다. 학생 배부용에서는 제거한다.

01
scanf("%20s %d", s.name, &s.score) — 이름에는 &가 없고 점수에는 있다. 배열 멤버와 정수 멤버의 차이다(12장). 이 구분을 반드시 짚는다.
02
a[i].name, &a[i].score — 인덱스가 먼저, 점이 나중이다. a.name[i]로 쓰는 오답이 종종 나온다.
03
int best = 0;으로 시작해 if (a[i].score > a[best].score) { best = i; }. 인덱스를 기억하는 방식이 가장 간단하다.
동점이면 먼저이므로 >를 쓴다. >=면 나중 학생이 남는다(8장 표준 코드와 같은 기준).
04
구조체는 =로 복사되고 안의 배열 멤버까지 함께 복사된다. 배열은 =가 컴파일 오류였다(8장 오류 6). 구조체로 감싸면 복사가 가능해진다는 점이 핵심이다.
05
좌표가 109이면 차이가 2×109, 제곱이 4×1018로 long long이 꼭 필요하다. 
long long dx = a.x - b.x;      // 먼저 long long에 담는다
long long dy = a.y - b.y;
return dx * dx + dy * dy;
흔한 오답 — (long long)((a.x-b.x)*(a.x-b.x) + ...). 괄호 안이 이미 int로 넘친다(2장 오류 2).
06
예제 3과 동일. 값으로 받은 버전은 아무 일도 하지 않는다. 10장 swap_bad, 12장 오류 2와 같은 함정이 세 번째로 반복되는 자리다.
07
return (a > b) - (a < b);. 절댓값이 2×109이면 뺄셈이 넘친다.
지도 포인트 — 문제에서 범위를 크게 준 이유가 이것이다. 뺄셈으로 제출하면 특정 입력에서만 틀린다.
08
예제 4와 동일. 지도 포인트 — 입력 명령이 0~3 숫자로 들어와도, 코드 안에서는 dy[d]처럼 변수로 쓰이므로 enum의 이점은 상수를 직접 쓰는 자리에서 나온다. 예: if (d == LEFT).
09
if (p->score != q->score) { return q->score - p->score; }
return strcmp(p->name, q->name);
점수는 0~100이라 뺄셈이 안전하다. 95점 두 명이 hyun, jisoo 순으로 나오는지 확인시킨다.
10
표준 코드와 동일. 교재의 6명 입력을 그대로 쓰면 세 기준이 모두 검증된다. 학생이 직접 만든 입력도 18번에서 점검한다.
11
typedef struct { int value; int idx; } Item;

int cmp(const void *x, const void *y)
{
    const Item *p = x, *q = y;
    if (p->value != q->value) { return (p->value > q->value) - (p->value < q->value); }
    return p->idx - q->idx;      // 동점이면 원래 순서
}
13장 19번의 답이다. 값과 인덱스를 묶으면 정렬해도 원래 위치를 잃지 않는다.
지도 포인트 — 2순위로 idx를 넣으면 동점의 원래 순서가 보장된다(안정 정렬의 효과를 손으로 만든 것). qsort는 안정 정렬이 아니므로 이 한 줄이 필요하다. PART 3 정렬 단원에서 다시 다룬다.
12
좌표가 109이므로 뺄셈을 쓰면 안 된다. (p->x > q->x) - (p->x < q->x) 형태로 쓴다. 07번과 같은 이유다.
13
끝점이 1순위, 시작점이 2순위다. 예제에서 끝점 3인 둘이 시작점으로 갈려 0 3, 2 3 순이다.
지도 포인트 — "끝나는 시각이 빠른 순"으로 정렬하는 것이 회의실 배정 그리디의 핵심이다. PART 3에서 이 정렬 하나로 문제가 풀리는 것을 보게 된다고 예고한다.
14
{char c; int i; char d;}는 12바이트, {int i; char c; char d;}는 8바이트가 나온다(환경에 따라 다를 수 있다).
10만 개면 1.2 MB 대 0.8 MB로 0.4 MB 차이다.
지도 포인트 — 메모리 제한이 빠듯한 문제에서만 신경 쓰면 된다. 다만 멤버 합으로 계산하면 틀린다는 것은 반드시 알아야 한다(오류 5와 연결).
15
make와 add는 결과를 return하므로 값으로 받아도 된다. dist2는 읽기만 하므로 값으로 받아도 되지만, 구조체가 커지면 const Point *가 낫다. equal도 마찬가지다.
지도 포인트 — Point는 8바이트라 값으로 넘기는 비용이 거의 없다. 구조체 크기를 보고 판단한다는 기준을 세운다.
16
합을 long long으로 구한 뒤 (double)sum / n과 비교한다(4장). 정렬은 점수 내림차순. 평균이 75이므로 90, 80 두 명이 나온다.
17
① 뺄셈 방식은 정렬되지 않은 채 2000000000 -2000000000으로 나오고, 안전한 방식은 -2000000000 2000000000으로 정상이다.
② 2000000000 - (-2000000000)은 40억으로 INT_MAX를 넘어 음수가 된다(실제 −294967296). 음수를 돌려주므로 qsort는 "x가 앞"이라고 판단한다. 즉 큰 수를 앞에 놓는다.
③ 두 값의 차이가 int 범위 안이면 안전하다. 실무 기준으로는 모든 값이 10억 미만의 양수이거나, 값의 범위가 231보다 좁다고 확인된 경우다. 점수(0~100)나 나이는 안전하다.

=로 복사오류된다
함수에 넘겨 고치기된다(주소가 감)안 된다(복사됨)
return으로 돌려주기불가능된다
함수 안 sizeof8(포인터)실제 크기

⑤에 대해 — 구조체끼리 ==는 error: invalid operands to binary ==로 막힌다. 패딩의 쓰레기값 때문에 바이트 비교가 의미 없을 수 있어서다. 멤버를 하나씩 비교하는 함수를 만들어야 한다.
지도 포인트 — 배열과 구조체가 거의 정반대로 동작한다는 것이 이 표의 핵심이다. 벽에 붙여 두고 PART 2 내내 참고하게 한다.

최종 라이브러리 구성 예. 
/* 자료형 */
typedef struct { int x, y; } Point;
typedef struct { int a, b; } Interval;     // 구간 [a,b]
typedef struct { int value, idx; } Item;   // 값 + 원래 위치

/* 비교 함수 — 모두 qsort용 */
int cmp_int      (const void*, const void*);  // 오름차순, 오버플로 안전
int cmp_int_desc (const void*, const void*);  // 내림차순
int cmp_point    (const void*, const void*);  // x 오름 → y 오름
int cmp_interval (const void*, const void*);  // 끝점 b 오름 → 시작 a 오름
int cmp_item     (const void*, const void*);  // value 오름 → idx 오름(원래순 유지)

/* 10장 수학 */  is_prime, gcd, lcm, digit_sum, digital_root, my_abs, mod
/* 12장 출력매개변수 */ swap, divmod, minmax, to_hms, safe_div
/* 13장 배열 */  arr_print, arr_sum, arr_minmax, arr_reverse, arr_copy, find
/* 14장 문자열 */ trim_newline, str_reverse, is_palindrome, count_char, str_find
동점 처리 기준 — 모든 비교 함수에 "동점이면 무엇으로 갈리는가"를 주석으로 명시한다. 특히 cmp_item의 idx 2순위는 안정 정렬 효과를 만드는 핵심이므로 이유까지 적게 한다.
지도 포인트 — PART 1의 결산이다. 다음 수업 첫머리에 이 파일을 열고 "지난 16장 동안 만든 도구"로 소개한 뒤 PART 2를 시작한다.
08 — 마무리

이 장을 마치기 전 점검

  • 구조체 정의 끝에 세미콜론을 붙인다
  • 구조체 변수는 ., 포인터는 ->
  • 구조체는 =로 복사되고 함수에 넘기면 복사된다 — 고치려면 포인터
  • qsort의 세 번째 인자는 sizeof(원소자료형)
  • 비교 함수에서 뺄셈 대신 (a>b)-(a<b)를 쓴다
  • 다중 기준은 if (다르면) return을 차례로 쌓는다
  • 값과 인덱스를 묶으면 정렬 후에도 원래 위치를 안다
  • 정렬 결과는 동점 자료를 넣은 입력으로 눈으로 확인한다
다음 장 예고 — 16장 동적 메모리·디버깅·테스트 PART 1의 마지막 장이다. 크기를 미리 모를 때 메모리를 얻는 방법, 그리고 지금까지 열다섯 장에서 쌓인 모든 함정을 제출 전에 걸러 내는 절차를 정리한다. 스스로 테스트를 만들고 기준 정답과 대조하는 습관이 PART 2의 출발점이 된다.
