05

조건문

프로그램이 갈림길을 만나는 곳이다. 문법은 하루면 외우지만, 경우를 빠짐없이 겹치지 않게 나누는 일은 올림피아드 내내 따라다닌다. 이 장은 문법보다 경우 나누기에 더 많은 분량을 쓴다.

학습 목표

  • if의 조건이 "0인가 아닌가"만 본다는 것을 알고 4장의 0·1과 연결할 수 있다
  • else if 체인의 순서가 결과를 바꾼다는 것을 설명할 수 있다
  • 성립하지 않는 경우를 먼저 거르는 구조로 조건을 배치할 수 있다
  • 중괄호를 생략했을 때 생기는 else 결합 문제를 피할 수 있다
  • switch의 break 누락이 만드는 fall-through를 이해하고 의도적으로도 쓸 수 있다
  • =와 ==, 연쇄 비교, 실수 비교의 세 가지 함정을 피할 수 있다

01 — 도입 문제

삼각형이 되기는 하는가

세 변의 길이 a, b, c를 입력받아 삼각형의 종류를 판정하는 문제다. 종류는 정삼각형·이등변삼각형·부등변삼각형 셋이다. 많은 학생이 이렇게 쓴다.

세 경우를 빠짐없이 겹치지 않게 나눴다. 그런데 입력 1 2 10을 넣으면 부등변삼각형이라고 답한다. 길이 1, 2, 10으로는 삼각형을 만들 수 없는데도.

빠진 것 분류 자체는 맞다. 문제는 분류하기 전에 확인했어야 할 것을 건너뛴 데 있다. 세 변이 삼각형을 이루려면 가장 긴 변이 나머지 두 변의 합보다 짧아야 한다.

올림피아드 문제는 거의 항상 이런 구조를 가진다. "성립하지 않는 입력"이 먼저 있고, 그다음에 분류가 온다. 조건문을 배치하는 순서가 정답과 오답을 가른다.

이 장이 답할 질문 ① 거르는 조건을 어디에 두어야 하는가?
② else if 체인의 순서를 바꾸면 무엇이 달라지는가?
③ x가 50일 때 0 < x < 10은 참일까 거짓일까?
02 — 개념 정리

개념 정리

5.1if의 조건은 숫자다

4장에서 관계·논리 연산의 결과가 0 또는 1인 정수라는 것을 배웠다. if는 그 값을 받아 0이면 건너뛰고, 0이 아니면 실행한다. 참·거짓이라는 별도의 개념이 있는 것이 아니다.

그래서 if (n % 2)는 "n이 홀수면"과 같고, if (n)은 "n이 0이 아니면"과 같다. 간결하지만 의도가 흐려지므로, 교재에서는 if (n % 2 != 0)처럼 비교를 명시하는 쪽을 권한다.

5.2else if 체인은 위에서부터 걸러진다

else if는 새로운 문법이 아니라 else 뒤에 if를 붙인 것이다. 중요한 성질은 하나다. 위의 조건이 참이면 아래는 쳐다보지도 않는다.

올바른 순서
if (s >= 90) printf("A\n");
else if (s >= 80) printf("B\n");
else if (s >= 70) printf("C\n");
else printf("F\n");
뒤집힌 순서 — 전부 C
if (s >= 70) printf("C\n");
else if (s >= 80) printf("B\n");
else if (s >= 90) printf("A\n");
else printf("F\n");

오른쪽은 95점도 C로 찍는다. 95는 70 이상이므로 첫 조건에서 걸려 버리기 때문이다. 범위를 나눌 때는 좁은 쪽(또는 극단)부터 쓴다.

이 성질 덕분에 아래쪽 조건은 위쪽이 모두 거짓이라는 전제를 공짜로 얻는다. else if (s >= 80)은 사실상 "80 이상 90 미만"을 뜻하므로, s >= 80 && s < 90이라고 쓸 필요가 없다.

5.3경우 나누기의 세 가지 원칙

원칙뜻어기면
빠짐없이모든 입력이 어느 한 가지에 반드시 해당한다아무것도 출력하지 않는 입력이 생긴다
겹치지 않게한 입력이 두 가지에 동시에 해당하지 않는다두 번 출력되거나, 순서에 따라 답이 바뀐다
거르기 먼저성립하지 않는 입력을 맨 앞에서 쳐낸다도입 문제의 1 2 10처럼 엉뚱한 답이 나온다

"빠짐없이"는 마지막을 else로 닫으면 자동으로 보장된다. 조건이 있는 분기로 끝내지 말고 항상 else로 마무리하는 습관을 들인다.

"거르기 먼저"에는 또 하나의 이유가 있다. 4장에서 배운 단락 평가처럼, 위험한 계산을 보호해 준다. 0으로 나누는 코드 앞에 b != 0을 두는 것과 같은 구조다.

5.4중괄호와 else의 결합

실행할 문장이 하나면 중괄호를 생략할 수 있다. 그러나 생략하면 두 가지 사고가 난다.

사고 ① 두 번째 줄이 조건과 무관해진다

의도
if (x > 0)
    printf("양수\n");
    printf("확인\n");   ← 항상 실행된다
들여쓰기는 거짓말을 한다
C는 들여쓰기를 보지 않는다.
if에 묶이는 것은
바로 뒤의 문장 하나뿐.

사고 ② else가 엉뚱한 if에 붙는다

들여쓰기만 보면 else가 바깥 if에 붙은 것 같다. 그러나 C의 규칙은 else는 가장 가까운, 아직 짝이 없는 if에 붙는다이다. 따라서 안쪽 if (b == 1)의 짝이다. 실행하면 메시지가 출력된다.

gcc가 잡아 준다 warning: suggest explicit braces to avoid ambiguous 'else' [-Wdangling-else]
해결책은 하나다. 문장이 하나뿐이어도 중괄호를 쓴다. 이 교재의 모든 코드는 중괄호를 생략하지 않는다.

5.5삼항 연산자

조건 ? A : B는 조건이 참이면 A, 거짓이면 B라는 값이 된다. if는 문장이고 삼항 연산자는 식이라는 점이 다르다. 그래서 printf 안에 바로 넣을 수 있다.

CODE (a=7, b=3, n=-7)
printf("%d %d\n", a>b?a:b, a<b?a:b);
printf("%d\n", n < 0 ? -n : n);
printf("%d\n", a>10 ? 1 : (a>5 ? 2 : 3));
OUTPUT
7 3
7
2

최댓값·최솟값·절댓값처럼 짧고 명백한 선택에 쓴다. 세 겹 이상 중첩하면 읽기 어려워지므로 그때는 if로 쓴다.

5.6switch와 fall-through

하나의 값을 여러 상수와 비교할 때 쓴다. 조건은 정수나 문자여야 하고, 범위 비교는 할 수 없다.

n출력이유
1one two threecase 1로 들어가 break까지 쭉 흐른다
2two threecase 2부터 흐른다
3three바로 break를 만난다

case는 들어가는 지점을 고르는 표지판일 뿐 블록의 경계가 아니다. break를 만날 때까지 아래로 계속 흐르는 이 성질을 fall-through라고 한다.

사고의 원인이지만, 여러 값을 묶을 때는 일부러 활용한다.

5.7조건문의 세 가지 함정

함정 ① 연쇄 비교

x = 50 일 때
0 < x < 10        → 1 (참!)
(0 < x) && (x < 10) → 0
왜
왼쪽부터 묶인다.
(0 < 50) → 1
1 < 10   → 1
수학 기호와 모양만 같다.

gcc는 comparisons like 'X<=Y<=Z' do not have their mathematical meaning으로 경고한다. 범위 조건은 반드시 &&로 두 개를 잇는다.

함정 ② = 와 ==

CODE
int x = 0;
if (x = 5) printf("실행됨, x=%d\n", x);
else       printf("실행 안 됨\n");
OUTPUT
실행됨, x=5

x = 5는 x에 5를 넣고 그 값 5가 된다. 5는 0이 아니므로 항상 참이다. 거꾸로 if (y = 0)은 항상 거짓이 된다. gcc 경고는 suggest parentheses around assignment used as truth value다.

함정 ③ 실수 비교

CODE
double d = 0.1 + 0.2;
printf("%d\n", d == 0.3);
OUTPUT
0

2장에서 본 그대로다. 실수는 ==로 비교하지 않고 차이가 충분히 작은지로 판단한다.

03 — 표준 코드

표준 코드: 삼각형 판정

도입 문제의 답이다. 거르기를 맨 앞에 두는 구조를 그대로 보여 준다.

분기설계 의도
1번 — 삼각형 성립 검사거르기 먼저. 세 부등식 중 하나라도 어기면 삼각형이 아니다. 어느 변이 가장 긴지 찾을 필요 없이 세 개를 모두 검사하면 된다.
2번 — 세 변이 같은가가장 좁은 조건을 먼저 둔다. 정삼각형은 이등변 조건도 만족하므로 순서를 바꾸면 영원히 걸리지 않는다.

4번 — else빠짐없이를 보장한다. 나머지는 전부 부등변이다.

05 — 흔한 오류

흔한 오류 여섯 가지

오류 1== 를 = 로 썼다
eq.c:4:9: warning: suggest parentheses around assignment
          used as truth value [-Wparentheses]
    4 |     if (x = 5) printf("실행됨, x=%d\n", x);
      |         ^

if (x = 5)는 항상 참이고 덤으로 x의 값까지 바꾼다. if (x = 0)은 항상 거짓이다. 둘 다 컴파일은 된다.

고치는 법 — 경고를 보면 즉시 멈추고 확인한다. 의도적으로 대입을 쓰는 경우는 이 수준에서는 없다.
오류 2범위를 수학 기호처럼 썼다
m.c:18:61: warning: comparisons like 'X<=Y<=Z' do not have
           their mathematical meaning [-Wparentheses]
m.c:18:65: warning: comparison of constant '10' with boolean
           expression is always true [-Wbool-compare]

0 < x < 10은 (0 < x) < 10으로 묶인다. 앞이 0이나 1이 되고 그것은 언제나 10보다 작으므로 x가 무엇이든 참이다.

고치는 법 — (0 < x) && (x < 10). 두 번째 경고가 "항상 참"이라고 직접 말해 준다.
오류 3중괄호를 생략해 else가 엉뚱한 곳에 붙었다
de.c:4:8: warning: suggest explicit braces to avoid
          ambiguous 'else' [-Wdangling-else]

else는 들여쓰기가 아니라 가장 가까운 짝 없는 if에 붙는다. 눈으로 본 구조와 실제 구조가 달라서, 코드를 아무리 읽어도 원인이 보이지 않는다.

고치는 법 — 문장이 하나여도 중괄호를 쓴다. 예외 없이.
오류 4else if 순서가 뒤집혔다

경고가 없다. 컴파일러 입장에서는 완벽히 정상인 코드다.

if (s >= 70) printf("C\n");        // 95점도 여기서 걸린다
else if (s >= 80) printf("B\n");   // 영원히 실행되지 않음
else if (s >= 90) printf("A\n");   // 영원히 실행되지 않음
고치는 법 — 범위 분기는 극단부터 쓴다. 작성 후 각 분기에 해당하는 값을 하나씩 대입해 확인한다.
오류 5switch에서 break를 빠뜨렸다

경고가 없다. 의도적 fall-through와 실수를 컴파일러가 구별할 수 없기 때문이다.

switch (n) {
    case 1: printf("one ");      // break 없음 → 아래로 흐른다
    case 2: printf("two ");
    case 3: printf("three "); break;
}
// n=1 일 때 출력: one two three
고치는 법 — case를 쓸 때 break를 먼저 쓰고 그 위에 내용을 채운다. 일부러 흘릴 때는 주석으로 표시한다.
오류 6거르기를 뒤에 두었다

도입 문제와 예제 5가 그대로 이 오류다. 더 위험한 형태는 계산이 먼저 일어나는 경우다.

if (a / b > 2) { ... }         // b가 0이면 여기서 죽는다
else if (b == 0) { ... }       // 도달하지 못한다

4장의 단락 평가와 같은 원리다. 보호하는 검사가 보호받는 계산보다 먼저 와야 한다.

고치는 법 — 조건을 나열하기 전에 "이 입력이 애초에 유효한가"를 먼저 묻는 분기를 둔다.
이 장의 가장 중요한 교훈 오류 4·5·6은 경고가 나오지 않는다. 조건문의 정확성은 컴파일러가 아니라 테스트 입력이 보증한다. 분기를 하나 만들 때마다 그 분기에만 해당하는 입력을 하나씩 준비해 전부 통과시킨다.

else는 누구의 짝인가 — 아래 코드를 a=1, b=0으로 실행한 결과를 예측하고 확인하라. gcc 경고를 적고, ① else가 바깥 if에 붙도록 ② 안쪽 if에 붙도록 각각 중괄호를 넣어 두 가지 버전을 만들어라.

    if (b == 1)

07 — 확인 평가 해설

정답과 해설

※ 이 절은 교사용 통합본에만 수록한다. 학생 배부용에서는 제거한다.

01
if (a > b) { printf("%d\n", a); } else { printf("%d\n", b); } — 같을 때 else로 떨어져 b가 출력되는데, a와 b가 같으므로 문제없다. 이 점을 학생에게 확인시킨다.
02
세 분기. if (n > 0) … else if (n < 0) … else …. 지도 포인트 — 0을 else로 처리하는 것이 "빠짐없이"의 전형이다. else if (n == 0)으로 끝내면 else가 없어 원칙에 어긋난다.
03
if (n % 2 != 0) 또는 if (n & 1). 흔한 오답: if (n % 2 == 1) — 음수에서 -7 % 2가 −1이라 홀수인데도 even이 나온다. 4장 연습 4번의 재확인이다.
04
int mx = a; if (b > mx) { mx = b; } if (c > mx) { mx = c; } — else를 붙이면 안 된다는 점을 짚는다. 두 비교는 독립적이다.
05
(y % 4 == 0 && y % 100 != 0) || (y % 400 == 0) — 1900→0, 2000→1, 2100→0. 괄호를 빼면 &&가 ||보다 우선순위가 높아 결과는 같지만(4장 우선순위표), 가독성을 위해 괄호를 쓰게 한다.
06
거르기 먼저: if (x == 0 || y == 0) { printf("axis\n"); } 그다음 네 사분면.
지도 포인트 — 축 검사를 뒤로 미루면 (0, 5)가 2사분면으로 잘못 판정된다. 표준 코드와 같은 구조다.
07
예제 3에 D 분기를 추가한 형태. 범위 검사(s < 0 || s > 100)가 맨 앞이다. 경계값 0, 60, 70, 80, 90, 100, 101, −1을 전부 시험시킨다.
08
printf("%d\n", n < 0 ? -n : n); — 보충 — INT_MIN의 절댓값은 int로 표현할 수 없다(2장). 입력 범위가 주어지지 않으면 이런 구멍이 생긴다는 것을 언급해 둔다.
09
if (a + b <= c || b + c <= a || c + a <= b) { printf("NO\n"); } else { printf("YES\n"); } — 등호 포함이 핵심이다. <만 쓰면 1 2 3에서 YES가 나온다.
10
분기 순서가 이 문제의 전부다. 좁은 조건부터 내려간다. 
삼각형 아님
→ 정삼각형 (a==b && b==c)
→ 직각이등변 (이등변 AND 직각)
→ 이등변
→ 직각 (a*a+b*b==c*c 등 세 경우)
→ 부등변 (else)
주의 — 직각 판정은 어느 변이 빗변인지 모르므로 세 조합을 모두 검사한다. 변의 길이가 크면 a*a가 넘칠 수 있으므로 (long long)a*a로 쓴다(2장).
지도 포인트 — 정삼각형은 직각일 수 없으므로 순서를 어떻게 두어도 무방하지만, 직각이등변은 이등변보다 반드시 위에 와야 한다.
11
예제 4와 동일. case를 줄줄이 붙이는 것이 fall-through의 의도적 활용임을 다시 확인시킨다. default: printf("invalid\n");로 마무리한다.
12
세 번의 비교·교환으로 정렬된다. 
if (a > b) { int t = a; a = b; b = t; }
if (b > c) { int t = b; b = c; c = t; }
if (a > b) { int t = a; a = b; b = t; }
printf("%d %d %d\n", a, b, c);
지도 포인트 — 세 번째 비교가 왜 또 필요한지 7 2 5로 추적시킨다. 이것이 PART 3 버블 정렬의 축소판이다.
13
c >= 'A' && c <= 'Z' / c >= 'a' && c <= 'z' / c >= '0' && c <= '9' / else. 입력은 scanf(" %c", &c)로 받는다(3장). 숫자 문자 '7'과 정수 7이 다르다는 것을 반드시 짚는다.
14
겹치지 않는 경우는 b < c 이거나 d < a, 두 가지뿐이다. 따라서 
if (b < c || d < a) { printf("NO\n"); } else { printf("YES\n"); }
지도 포인트 — 겹치는 경우를 직접 나열하면 네다섯 가지가 되어 빠뜨리기 쉽다. 여집합이 더 단순하면 여집합을 쓴다는 발상은 PART 2 이후에도 계속 쓰인다.
15
if (b == 0) { printf("divide by zero\n"); return 1; } printf("%d\n", a / b); — return 1로 끝내면 뒤쪽 코드에 도달하지 않으므로 else가 없어도 안전하다. 1장의 종료 코드와 연결해 echo $?로 확인시킨다.
16
double diff = a - b; if (diff < 1e-9 && -diff < 1e-9) { printf("equal\n"); } else { printf("different\n"); } — 0.1+0.2와 0.3은 ==로는 다르지만 이 방식으로는 equal이 된다.
17
출력은 Y. 경고는 suggest explicit braces to avoid ambiguous 'else' [-Wdangling-else].
else는 안쪽 if (b == 1)의 짝이다. a가 1이라 바깥 조건은 통과하고, b가 0이라 안쪽이 거짓이므로 else가 실행된다.
① 바깥에 붙이려면: if (a == 1) { if (b == 1) { printf("X\n"); } } else { printf("Y\n"); } → a=1이면 아무것도 출력되지 않는다.
② 안쪽에 붙이려면: if (a == 1) { if (b == 1) { printf("X\n"); } else { printf("Y\n"); } } → 현재 동작과 같다.
지도 포인트 — 같은 글자 배열이 중괄호 위치에 따라 전혀 다른 프로그램이 된다는 것을 보여 주는 문제다.
18
(가) 항상 참 — 대입식의 값 5가 0이 아니다. 경고 suggest parentheses around assignment used as truth value.
(나) 항상 참 — (0 < x)가 0이나 1이 되고 둘 다 100보다 작다. 경고 두 개: comparisons like 'X<=Y<=Z' do not have their mathematical meaning, comparison of constant '100' with boolean expression is always true.
(다) 항상 참 — x가 1이면 x != 2가 참, x가 2면 x != 1이 참, 나머지는 둘 다 참. 의도는 &&였을 것이다.
(다)에 경고가 없는 이유 — (가)와 (나)는 문법 모양만 보고 기계적으로 잡아낼 수 있는 패턴이지만, (다)는 각 비교가 그 자체로 완전히 정상이고 둘을 합쳤을 때의 의미를 따져야 알 수 있다. 컴파일러는 프로그래머의 의도까지 추론하지 않는다.
19
① D가 출력된다. ② 95는 60 이상이므로 맨 위 조건에서 걸리고, else if이므로 아래는 평가되지 않는다. ③ 각 조건이 문법적으로 완전히 정상이고, 도달 불가능한 분기인지 판단하려면 값의 범위를 추론해야 하는데 컴파일러는 그렇게까지 하지 않는다. ④ 각 분기에 정확히 하나씩 해당하는 입력을 준비해 전부 시험한다. 95, 85, 75, 65, 50을 넣으면 전부 D가 나와 즉시 발견된다.
20
모범 테스트 표(입력 → 기대 출력).
1 2 10 → 삼각형 아님 · 3 3 3 → 정삼각형 · 1 1 1.414…는 정수가 아니므로 5 5 7 → 이등변삼각형 · 3 4 5 → 직각삼각형 · 6 7 8 → 부등변삼각형 · 직각이등변은 정수 변으로 불가능하므로 그 분기는 도달할 수 없다는 것을 발견하는 것이 이 문제의 함정이다.
경계값 — 1 2 3(합이 정확히 같음) → 삼각형 아님, 0 1 1(길이 0) → 삼각형 아님.
지도 포인트 — 분기를 만들었는데 도달 가능한 입력이 존재하지 않는 경우가 있다는 발견이 핵심이다. 정수 변에서는 직각이등변삼각형이 존재할 수 없다(√2가 무리수). 문제 조건이 실수 입력이었다면 달라진다. 이 토론을 꼭 거친다.
08 — 마무리

이 장을 마치기 전 점검

  • 성립하지 않는 입력을 거르는 분기를 맨 앞에 둔다
  • 범위 분기는 극단부터 쓰고 else로 마무리한다
  • 문장이 하나여도 중괄호를 생략하지 않는다
  • 범위 조건을 0 < x < 10처럼 쓰지 않는다
  • switch의 case마다 break를 확인한다
  • 실수는 ==로 비교하지 않는다
  • 분기마다 그 분기에만 해당하는 테스트 입력을 하나씩 만든다
  • 등호가 들어가야 하는 경계인지 따로 생각한다
다음 장 예고 — 06장 반복문 지금까지 미뤄 둔 for와 while을 드디어 다룬다. 2장의 "틀리는 N 찾기"와 3장의 "입력 끝까지 읽기"에서 읽기만 했던 코드를 직접 쓰게 된다. 그리고 이 장의 조건문이 반복의 종료 조건으로 다시 등장한다.
