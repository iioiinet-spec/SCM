06

반복문

2장에서 "틀리는 N 찾기", 3장에서 "입력 끝까지 읽기" 코드를 읽기만 하고 넘어갔다. 이 장에서 그것을 직접 쓴다. 반복문은 알고리즘의 몸통이며, 여기서부터 코드의 속도를 따지기 시작한다.

학습 목표

  • while·for·do-while의 구조를 알고 상황에 맞게 고를 수 있다
  • 초기화·조건·갱신 세 가지를 빠짐없이 점검해 무한 루프를 막을 수 있다
  • break와 continue의 작용 범위를 정확히 안다
  • 중첩 루프의 반복 횟수를 계산하고 실행 시간을 가늠할 수 있다
  • 한 자리가 될 때까지 자릿수 합을 반복하는 과정을 추적 출력할 수 있다

01 — 도입 문제

한 자리가 될 때까지

어떤 수의 각 자리 숫자를 모두 더한다. 결과가 여전히 두 자리 이상이면 또 더한다. 한 자리가 될 때까지 반복한다.

987654 의 경우
987654
 → 9+8+7+6+5+4 = 39
 → 3+9 = 12
 → 1+2 = 3
원하는 출력
987654 -> 39 -> 12 -> 3

이 문제는 반복이 두 겹이다. 바깥쪽은 "한 자리가 될 때까지", 안쪽은 "자릿수를 하나씩 떼어내며". 그리고 두 반복의 성격이 다르다.

반복몇 번 도는가어떤 반복문이 맞는가
바깥미리 알 수 없다조건이 거짓이 될 때까지 → while
안쪽자릿수만큼 — 역시 미리 모른다수가 0이 될 때까지 → while

지금까지 쓴 for는 "몇 번 돌지 아는" 반복이었다. 이 문제처럼 횟수를 모르는 반복이 올림피아드에서는 오히려 더 많다.

이 장이 답할 질문 ① 세 가지 반복문 중 무엇을 언제 쓰는가?
② 반복이 반드시 끝난다는 것을 어떻게 보장하는가?
③ 1,000,000,000번 도는 반복문은 몇 초나 걸리는가?
02 — 개념 정리

개념 정리

6.1while — 조건이 참인 동안

5장의 if와 모양이 같다. 차이는 몸통을 실행한 뒤 다시 조건으로 돌아간다는 것뿐이다. 조건이 처음부터 거짓이면 몸통은 한 번도 실행되지 않는다.

6.2for — 횟수가 정해진 반복

while로 쓰면 세 부분이 코드 여기저기에 흩어진다. for는 그것을 한 줄에 모아 빠뜨리기 어렵게 만든 문법이다.

while 버전
int i = 0;          // 초기화
while (i < n) {     // 조건
    ...
    i++;            // 갱신
}
for 버전 — 완전히 같다
for (int i = 0; i < n; i++) {
    ...
}

for (int i = 0; ...)처럼 안에서 선언한 변수는 그 반복문 안에서만 존재한다. 밖에서 쓰려면 밖에서 선언한다.

표준형을 하나만 외운다 for (int i = 0; i < n; i++) — 0부터 시작해 n 미만까지, 정확히 n번. 배열을 배우는 8장부터 이 형태가 거의 전부가 되므로, 다른 모양을 쓰고 싶을 때마다 한 번 더 생각한다.

6.3do-while — 일단 한 번은 실행

n = 0으로 세 반복문을 돌려 보면 차이가 한눈에 보인다.

n = 0 일 때
for   : (끝)
while : (끝)
do    : 0 (끝)
쓰임새
"적어도 한 번은 해야 하는" 일.
자릿수 분해에서 0을 입력받아도
"0"을 출력하려면 do-while이 맞다.

올림피아드에서는 for와 while로 대부분 해결되므로 do-while은 자주 쓰지 않는다. 다만 0이 입력될 때의 동작을 설계할 때 떠올릴 수 있어야 한다.

6.4반복문 설계: 세 가지를 반드시 확인

반복문을 쓸 때마다 아래 세 질문에 답한다. 하나라도 빠지면 무한 루프이거나 off-by-one이다.

점검질문어기면
초기화누적 변수와 반복 변수가 올바른 값에서 시작하는가쓰레기값부터 더해진다
조건몇 번 도는가. <인가 <=인가한 번 모자라거나 한 번 더 돈다
갱신조건에 쓰인 변수가 몸통에서 반드시 변하는가무한 루프

반복 횟수 세는 법

for 문횟수비고
i = 0; i < n; i++n표준형
i = 1; i <= n; i++n1부터 셀 때
i = 1; i < 10; i++910이 아니다
i = 1; i <= 10; i++10
i = a; i <= b; i++b − a + 1양끝 포함

6.5break와 continue

키워드하는 일예: 1~10에서
break반복문을 즉시 끝낸다i==5에서 break → 1 2 3 4
continue이번 회차만 건너뛰고 다음 회차로짝수에서 continue → 1 3 5 7 9
break는 가장 안쪽 반복문 하나만 끝낸다 중첩된 for 안에서 break를 쓰면 안쪽 반복만 끝나고 바깥 반복은 계속 돈다. 아래 코드의 출력은 (1,1) (2,1) (3,1)이다. 
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 3; j++) {
        if (j == 2) { break; }
        printf("(%d,%d) ", i, j);
    }
}
바깥까지 빠져나가려면 깃발 변수를 쓰거나, 10장에서 배울 함수로 분리해 return하는 방법을 쓴다.

continue는 for에서 갱신식을 건너뛰지 않는다. 그러나 while에서는 갱신을 몸통에서 직접 하므로, continue가 갱신을 건너뛰어 무한 루프가 되는 사고가 자주 난다.

6.6반복 횟수와 실행 시간

2장에서 자료형의 범위를 따졌듯, 이제부터는 반복 횟수를 따진다. 아래는 덧셈 한 번만 하는 가장 단순한 반복문의 실측값이다.

반복 횟수실측 시간판단
1,000,000 (106)0.003 초여유롭다
10,000,000 (107)0.027 초여유롭다
100,000,000 (108)0.266 초가능하지만 몸통이 무거우면 위험
1,000,000,000 (109)2.646 초대부분 시간 초과
1초 ≈ 1억 번 위 실측에서 1억 번이 0.27초였지만, 그것은 몸통이 덧셈 하나뿐이기 때문이다. 실제 문제의 몸통은 조건 검사·배열 접근·함수 호출이 섞여 몇 배 무겁다. 그래서 "1초에 1억 번"을 기준으로 잡는다. 넉넉히 잡아 두면 틀릴 일이 없다.

중첩 루프는 곱해진다

NN² 반복 횟수실측 시간판단
1,0001,000,0000.002 초문제없음
10,000100,000,0000.121 초경계선
30,000900,000,0001.206 초위험

여기서 올림피아드의 가장 중요한 판단 기준이 나온다. 문제의 N을 보고 어떤 알고리즘이 허용되는지 먼저 결정한다. N이 10만인데 이중 루프를 쓰면 100억 번이 되어 어떤 코드를 짜도 통과할 수 없다.

N의 크기허용되는 반복예
N ≤ 1,000삼중 루프 N³까지완전탐색
N ≤ 10,000이중 루프 N²모든 쌍 비교
N ≤ 1,000,000단일 루프 또는 N log N정렬, 한 번 훑기
N ≥ 109루프 없이 공식 또는 log N수식, 이분 탐색

6.7무한 루프와 종료 보장

반복이 끝나려면 조건에 쓰인 값이 종료 쪽으로 반드시 움직여야 한다. 세 가지 전형적인 사고가 있다.

코드왜 끝나지 않는가
while (i < n) { sum += i; }i++가 없다. 갱신 누락
while (n != 1) { n = n / 2; }n = 0으로 시작하면 영원히 0
while (scanf("%d",&x) != EOF)3장의 그 사고. 글자가 섞이면 계속 0

일부러 무한 루프를 만들고 break로 빠져나오는 형태도 쓴다. 이때는 break에 반드시 도달한다는 근거가 있어야 한다.

03 — 표준 코드

표준 코드: 자릿수 합 반복

도입 문제의 답이다. 바깥 while과 안쪽 while의 역할이 다르다는 점에 집중한다.

요소읽는 법
while (n >= 10)바깥 반복. "두 자리 이상인 동안". 한 자리가 되면 끝난다.
int sum = 0;매 회차마다 0으로 초기화한다. 바깥에 선언하면 이전 결과가 누적되어 틀린다.
sum += n % 10;맨 끝 자리를 떼어 더한다(4장의 나머지).
n /= 10;맨 끝 자리를 버린다. 이것이 안쪽 반복의 갱신이다. 빠뜨리면 무한 루프.
n = sum;바깥 반복의 갱신이다. 이것이 있어야 n이 작아져 언젠가 10 미만이 된다.
INPUTOUTPUT확인 사항
987654987654 -> 39 -> 12 -> 3세 번 반복
98759875 -> 29 -> 11 -> 2
100100 -> 10이 섞여도 정상
55처음부터 한 자리 — 반복 0회
999999999999999999 -> 81 -> 9int 최대 근처
반복 0회가 경계값이다 입력 5는 바깥 while을 한 번도 돌지 않는다. 그래서 처음에 printf("%d", n)으로 원래 수를 먼저 찍어 두는 설계가 필요했다. 반복문을 쓸 때는 0회 도는 경우를 항상 따로 시험한다.

05 — 흔한 오류

흔한 오류 여섯 가지

오류 1off-by-one — 한 번 더, 또는 한 번 덜

경고가 없다. 반복 횟수가 1만큼 어긋나므로 대부분의 입력에서는 비슷한 답이 나와 발견이 늦다.

쓴 것횟수의도
i = 1; i < n; i++n − 1n번 돌려던 것
i = 0; i <= n; i++n + 1n번 돌려던 것
고치는 법 — 표준형 for (int i = 0; i < n; i++)를 기본으로 쓰고, 벗어날 때는 n = 1과 n = 0을 넣어 횟수를 손으로 센다.
오류 2누적 변수를 초기화하지 않았다
int sum;              // 쓰레기값
for (int i = 1; i <= n; i++) { sum += i; }

지역 변수는 자동으로 0이 되지 않는다. 실행할 때마다 다른 값이 나오거나, 우연히 0이 들어 있어 집에서는 맞고 채점에서는 틀리는 최악의 형태가 된다.

반대 방향의 실수도 있다. 표준 코드의 int sum = 0;을 바깥 while 밖으로 빼면 매 회차 누적이 겹쳐 틀린 답이 나온다.

고치는 법 — 누적 변수는 선언과 동시에 초기화한다. 그리고 "어느 반복 바깥에 두어야 하는가"를 따로 생각한다.
오류 3갱신을 빠뜨려 무한 루프
while (n > 0) {
    sum += n % 10;
    // n /= 10;  을 빠뜨리면
}

프로그램이 멈추지 않는다. 채점 결과는 시간 초과로 나오므로, 알고리즘이 느린 줄 알고 엉뚱한 곳을 고치게 된다.

while에서 continue를 쓸 때 특히 조심한다. 갱신이 continue 아래에 있으면 건너뛰어진다.

고치는 법 — while을 쓸 때마다 "조건에 쓰인 변수가 몸통의 모든 경로에서 변하는가"를 확인한다. 가능하면 갱신이 눈에 보이는 for를 쓴다.
오류 4for 뒤에 세미콜론을 찍었다
y.c:4:5: warning: this 'for' clause does not guard...
          [-Wmisleading-indentation]
    4 |     for (int i = 1; i <= n; i++);
      |     ^~~
    5 |     {
      |     ^

세미콜론 하나가 빈 몸통이 되어, 아래 블록은 반복과 무관하게 한 번만 실행된다. n이 5여도 결과는 1이다.

고치는 법 — for와 while의 괄호 뒤에는 세미콜론을 찍지 않는다. gcc가 잡아 주므로 경고를 흘리지 않는다.
오류 5실수를 루프 변수로 썼다
for (double x = 0.0; x != 1.0; x += 0.1) { ... }   // 끝나지 않는다

0.1을 열 번 더한 값은 1.0이 아니라 0.99999999999999988898이다(2장). x != 1.0은 영원히 참이다.

고치는 법 — 루프 변수는 정수로 쓴다. 실수가 필요하면 for (int i = 0; i < 10; i++) { double x = i * 0.1; }처럼 정수에서 계산해 낸다.
오류 6중첩 루프에서 break가 바깥까지 나갈 줄 알았다

경고가 없다. 코드만 보면 "찾으면 끝낸다"처럼 읽히지만 실제로는 바깥 반복이 끝까지 돈다.

for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        if (조건) { break; }   // 안쪽만 끝난다
    }
}
고치는 법 — 깃발 변수를 두고 바깥 조건에도 넣는다. int found = 0; … for (int i = 0; i < n && !found; i++). 10장 이후로는 함수로 분리해 return하는 쪽이 깔끔하다.
이 장의 가장 중요한 교훈 오류 1·2·3·6은 경고가 없다. 반복문의 정확성은 세 가지 점검(초기화·조건·갱신)과 경계 입력 시험으로만 확인된다. 특히 0회 도는 입력과 1회만 도는 입력을 반드시 넣어 본다.

07 — 확인 평가 해설

정답과 해설

※ 이 절은 교사용 통합본에만 수록한다. 학생 배부용에서는 제거한다.

01
for (int i = 1; i <= n; i++) { printf("%d ", i); } 후 printf("\n"); — 끝에 공백이 남는 것이 문제되면 printf("%d%c", i, i==n?'\n':' ')로 처리한다(3장 출력 형식).
02
for (int i = n; i >= 1; i--) — 역순 루프의 세 부분이 모두 뒤집힌다는 것을 짚는다. 조건이 i > 0이어도 같다.
03
long long sum = 0; for (int i = 1; i <= n; i++) { sum += i; } — 2장 표준 코드의 반복 버전. 누적 변수만 long long이면 된다는 점을 재확인한다.
04
printf("%d x %d = %d\n", n, i, n * i); — 서식 문자열에 변수를 세 개 넣는 연습이다.
05
int s = 0; while (n > 0) { s += n % 10; n /= 10; } — 흔한 오답: n /= 10; 누락 → 무한 루프. 입력 0을 넣으면 0이 출력되는지도 확인시킨다.
06
long long f = 1; for (int i = 1; i <= n; i++) { f *= i; } — 2장 연습 18번에서 20!까지가 한계임을 확인했으므로 N ≤ 20이 조건이다. N = 21을 넣어 음수가 나오는 것을 보여 주면 좋다.
07
이중 루프. for (int i = 1; i <= n; i++) { for (int j = 1; j <= i; j++) { printf("*"); } printf("\n"); } — 안쪽 조건이 j <= i로 바깥 변수에 의존하는 첫 경험이다.
08
continue 버전: if (i % 2 == 0) { continue; } sum += i;
미사용 버전: if (i % 2 != 0) { sum += i; } 또는 for (int i = 1; i <= n; i += 2).
지도 포인트 — 세 번째 방법이 가장 빠르다(반복 횟수 절반). continue는 읽기 쉬울 때만 쓰는 것이 좋다는 판단 기준을 세운다.
09
표준 코드와 동일. 5 → 5(반복 0회), 100 → 100 -> 1. sum 선언 위치를 바깥 while 밖으로 옮겨 틀려 보게 한 뒤 되돌리면 오류 2가 몸에 남는다.
10
예제 3과 동일. 반복 횟수는 √(109) ≈ 31,623번으로 여유롭다.
주의 — i * i에서 i가 약 31,623이면 i*i는 약 109로 int 범위 안이다. 다만 N이 1018까지 커지는 문제에서는 (long long)i * i가 필요하다.
경계값 — 1(not prime), 2(prime), 4(not prime).
11
int cnt = 0; long long sum = 0;
for (int i = 1; (long long)i * i <= n; i++) {
    if (n % i == 0) {
        cnt += 2; sum += i + n / i;
        if ((long long)i * i == n) { cnt--; sum -= i; }
    }
}
36의 약수는 1,2,3,4,6,9,12,18,36으로 9개, 합은 91. 6×6=36이므로 6이 중복되는 것을 빼는 처리가 핵심이다. 이 중복 처리를 빠뜨리면 10개, 97이 나온다.
12
while (b != 0) { int t = a % b; a = b; b = t; }
printf("%d\n", a);
48, 18 → 6. 종료 보장 — b가 매 회 반드시 작아지고 0 이상이므로 유한 번에 끝난다. 이것이 6.7절의 "종료 쪽으로 움직인다"의 모범 사례다. PART 2에서 다시 다룬다.
13
첫 값을 읽어 mx와 mn의 초기값으로 삼는 것이 핵심이다. mx = 0으로 시작하면 모든 입력이 음수일 때 틀린다. 
int x, mx, mn, first = 1;
while (scanf("%d", &x) == 1) {
    if (first) { mx = mn = x; first = 0; }
    else { if (x > mx) { mx = x; } if (x < mn) { mn = x; } }
}
지도 포인트 — INT_MIN/INT_MAX로 초기화하는 방법도 있다(2장의 limits.h). 두 방법을 모두 보여 준다.
14
while (n > 0) { r = r * 10 + n % 10; n /= 10; } — 12300 → 321. 앞의 0이 자동으로 사라지는 이유(r * 10 + 0이 0에서 시작)를 추적시킨다. 주의 — 뒤집은 수가 int를 넘을 수 있으므로 큰 입력에서는 long long.
15
위쪽 절반과 아래쪽 절반을 나눠 쓰는 것이 가장 단순하다. i번째 줄의 공백은 n/2 - i개, 별은 2*i + 1개.
지도 포인트 — 공식을 먼저 세우고 코드를 쓰게 한다. 바로 코딩하면 1씩 어긋나 한참 헤맨다. 7장 격자 패턴의 예고 문제다.
16
측정값은 환경에 따라 다르지만 10배마다 약 10배라는 비례 관계는 반드시 나온다. 교재의 실측표(0.003 / 0.027 / 0.266 / 2.646초)와 비교해 자기 컴퓨터의 속도 감각을 갖게 하는 것이 목적이다. stderr로 출력하는 이유는 3장에서 배운 대로 채점 대상과 분리하기 위해서다.
17
0회 — 5 → 5. 1회 — 100 → 100 -> 1, 또는 19 → 19 -> 10이 아니라 19 -> 10 -> 1이므로 2회. 1회 도는 예는 10(→1), 23(→5) 등 자릿수 합이 바로 한 자리가 되는 수.
3회 이상 — 987654 → 3회.
printf("%d", n)을 빼면 — 반복이 0회 도는 입력(5)에서 아무것도 출력되지 않는다. 다른 입력에서는 맨 앞의 원래 수만 빠지므로 차이가 덜 눈에 띈다. 0회 경계가 왜 중요한지 보여 주는 문제다.
18
(가) 무한 — i++가 없다. 갱신 누락.
(나) 끝남, 5번 — 5,4,3,2,1.
(다) 무한 — i가 0,3,6,9,12…로 10을 건너뛴다. 조건의 문제. i < 10으로 쓰면 끝난다. 종료 조건은 !=보다 <가 안전하다는 교훈.
(라) 끝남, 4번 — 0.25는 2진수로 정확히 표현되므로 0.0, 0.25, 0.5, 0.75까지 돌고 1.0에서 멈춘다. 지도 포인트 — 오류 5에서 0.1은 실패했는데 0.25는 성공한다. 실수 루프가 "가끔 되는" 것이 더 위험하다는 점을 강조한다.
19
입력 10 12 → 2 6(i=1일 때 j는 12까지 못 가므로 i=2, j=6이 첫 쌍).
안쪽 break만 — 쌍을 찾아도 바깥 루프가 i=10까지 계속 돌아 최대 N²번 반복하고, 더 심각하게는 나중 쌍으로 답이 덮어써진다.
깃발 버전 — int found = 0; for (int i = 1; i <= n && !found; i++). 찾는 즉시 바깥도 멈추므로 반복 횟수가 크게 줄어든다.
지도 포인트 — "더 돌아도 답은 같다"와 "더 돌면 답이 바뀐다"는 전혀 다른 문제다. 후자는 정답 자체가 틀린다.
20
⑴ 106번 — 통과. 한 번 훑으면 된다.
⑵ 105 × 105 = 1010번 — 불가(약 100초). 정렬하거나 한 번 훑으며 누적하는 방식으로 N 또는 N log N으로 줄여야 한다. PART 3의 정렬·투 포인터가 이 자리를 메운다.
⑶ 단순 반복은 109번으로 불가. √N ≈ 31,623번으로 줄이면 통과.
⑷ 1012번 — 반복으로는 불가. 공식 N(N+1)/2로 반복 없이 끝낸다. 2장의 중간값 오버플로 점검이 필요하다.
지도 포인트 — 이 네 가지가 PART 2 이후 모든 문제에서 반복되는 판단 절차다. "코드를 쓰기 전에 횟수를 센다"를 습관으로 만든다.
08 — 마무리

이 장을 마치기 전 점검

  • 반복문마다 초기화·조건·갱신 세 가지를 확인한다
  • for (int i = 0; i < n; i++)를 표준형으로 쓴다
  • 반복이 0회 도는 입력을 반드시 시험한다
  • 누적 변수를 선언과 동시에 초기화하고, 어느 반복 바깥에 둘지 생각한다
  • break는 가장 안쪽 반복만 끝낸다는 것을 안다
  • 루프 변수로 실수를 쓰지 않는다
  • 코드를 쓰기 전에 반복 횟수를 세고 1억 기준으로 판단한다
  • 종료 조건은 !=보다 <를 쓴다
