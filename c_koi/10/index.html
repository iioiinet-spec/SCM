10

함수

지금까지 모든 코드를 main 하나에 몰아 넣었다. 문제가 조금만 복잡해지면 같은 코드를 두세 번 쓰게 되고, 고칠 때마다 전부 찾아 고쳐야 한다. 함수는 이름 붙은 재사용 단위이자, 6장에서 미뤄 둔 숙제의 해답이다.

학습 목표

  • 함수를 정의하고 호출할 수 있으며 프로토타입이 왜 필요한지 설명할 수 있다
  • 매개변수가 복사본이라는 것을 알고, 함수 안의 변경이 밖에 전해지지 않는 이유를 안다
  • 모든 경로에서 return하도록 함수를 작성할 수 있다
  • 지역 변수와 전역 변수의 유효 범위를 구분할 수 있다
  • return으로 중첩 반복문을 한 번에 빠져나올 수 있다
  • 소수 판정·최대공약수·자릿수 합을 함수로 분리해 재사용할 수 있다

01 — 도입 문제

같은 코드를 세 번 쓰게 될 때

"1부터 N까지의 수 중 소수인 것의 개수와 소수의 합, 그리고 가장 큰 소수를 출력하라." 6장에서 배운 소수 판정을 그대로 쓰면 이렇게 된다.

문제는 길이가 아니다. 판정 로직을 고쳐야 할 때 세 군데를 모두 고쳐야 하고, 한 군데를 빠뜨리면 발견되지 않는다. 실제로 이 코드에는 n = 1을 소수로 세는 버그가 있는데, 세 곳에 똑같이 들어 있다.

그리고 또 하나. 6장 연습 19번에서 "이중 루프를 한 번에 빠져나오기"를 깃발 변수로 해결하면서, 더 깔끔한 방법이 10장에 있다고 미뤄 두었다. 그 답도 이 장에 있다.

② 함수 안에서 바꾼 값이 왜 밖에 전해지지 않는가?

우리는 1장부터 int main(void)를 써 왔다. main도 함수다. 반환형이 int이고 매개변수가 없으며 return 0;으로 끝난다. 다른 점은 운영체제가 호출한다는 것뿐이다(1장 2.3절).

10.2프로토타입 — 미리 알려 두기

C는 위에서 아래로 읽는다. main보다 아래에 정의된 함수를 호출하면 컴파일러가 모른다.

문제의 코드
int main(void) {
    printf("%d\n", square(5));
}
int square(int x) { return x * x; }
경고
warning: implicit declaration
of function 'square'
[-Wimplicit-function-declaration]

1장 오류 5에서 본 그 경고다. 실행은 되지만 경고가 난다. 해결 방법은 두 가지다.

방법설명
함수를 main 위에 정의함수가 적을 때는 이것으로 충분하다
프로토타입을 맨 위에 선언int square(int x); — 몸통 없이 세미콜론으로 끝낸다

이 교재는 프로토타입을 맨 위에 모아 쓰는 방식을 표준으로 삼는다. 함수가 서로를 호출할 때 순서를 고민하지 않아도 되고, 파일 맨 위만 봐도 어떤 함수가 있는지 한눈에 보이기 때문이다.

10.3값에 의한 전달 — 매개변수는 복사본

C에서 함수에 값을 넘기면 복사본이 만들어진다. 함수 안에서 아무리 바꿔도 원본은 그대로다.

CODE
void swap_bad(int a, int b)
{
    int t = a; a = b; b = t;
}

int x = 3, y = 7;
swap_bad(x, y);
printf("x=%d y=%d\n", x, y);
OUTPUT
x=3 y=7

함수 안에서 a와 b는 분명히 바뀌었다. 그러나 그것은 x와 y의 복사본이었고, 함수가 끝나면서 사라졌다. 이름이 같아도 마찬가지다.

값을 돌려주려면 return을 쓴다 지금 단계에서 함수가 바깥에 결과를 전하는 방법은 return 하나다. 그래서 돌려줄 값이 두 개 이상이면 곤란해진다. 그 해결책이 12장 포인터이고, 교환 함수를 제대로 만드는 것도 그때다. 지금은 "복사본이라 안 된다"는 사실만 확실히 해 둔다.

10.4반환값 — 모든 경로에서 return

잘못된 코드
int f(int x)
{
    if (x > 0) return 1;
}
경고와 결과
warning: control reaches end
of non-void function
[-Wreturn-type]

f(5)  → 1
f(-5) → -551763613 (쓰레기)

x가 0 이하면 return 없이 함수가 끝난다. 그러면 아무 값이나 돌아온다. 5장에서 배운 "빠짐없이"가 여기서도 그대로 적용된다. 조건 분기로 끝내지 말고 마지막에 return을 둔다.

void 함수는 돌려줄 값이 없으므로 return;만 쓰거나 아예 생략한다. 중간에 끝내고 싶을 때 return; 한 줄을 쓸 수 있다.

10.5지역 변수와 전역 변수

종류선언 위치살아 있는 동안초기값
지역 변수함수(또는 블록) 안그 함수가 실행되는 동안쓰레기
전역 변수모든 함수 바깥프로그램 전체0
CODE
int cnt = 100;           // 전역

void f(void) { printf("%d\n", cnt); cnt++; }
void g(void) { int cnt = 5; printf("%d\n", cnt); }

int main(void) {
    f();   // 100
    f();   // 101
    g();   //   5
    printf("%d\n", cnt);
}
OUTPUT
100
101
5
102

g 안의 cnt는 전역 cnt를 가린다. 같은 이름이지만 전혀 다른 변수이고, g가 끝나면 사라진다. 전역은 102로 멀쩡하다.

올림피아드에서의 실용 지침 큰 배열과 N, M 같은 입력 크기는 전역으로 둔다(8·9장). 그러면 함수마다 넘겨 줄 필요가 없어 코드가 짧아진다. 대신 이름을 가리는 실수를 조심해야 하므로, 지역 변수에는 i, j, t 같은 짧은 이름을, 전역에는 board, visited 같은 긴 이름을 쓴다.

10.6return으로 중첩 루프 탈출

6장 오류 6과 연습 19번의 숙제다. break는 가장 안쪽 반복만 끝낸다. 깃발 변수를 쓰면 되지만 조건이 지저분해진다.

깃발 변수 방식 (6장)
int found = 0;
for (int i = 1; i <= n && !found; i++) {
    for (int j = 1; j <= n; j++) {
        if (i * j == k) {
            fi = i; fj = j;
            found = 1; break;
        }
    }
}
함수로 분리 (10장)
int find_pair(void)
{
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= n; j++) {
            if (i * j == k) {
                fi = i; fj = j;
                return 1;
            }
        }
    }
    return 0;
}

return은 함수 전체를 끝낸다. 몇 겹으로 중첩되어 있든 한 번에 빠져나온다. 게다가 "찾았는가"를 반환값으로 돌려주므로 깃발 변수도 필요 없다.

10.7함수로 나누는 기준

기준설명
두 번 이상 쓰인다가장 분명한 신호. 도입 문제의 소수 판정이 그렇다
이름을 붙일 수 있다"소수인지 판정한다"처럼 한 문장으로 말할 수 있으면 함수가 된다
중첩이 깊어진다루프 세 겹에 조건문이 들어가면 안쪽을 떼어 낸다
탈출이 필요하다10.6절처럼 return으로 끊고 싶을 때

반대로 나누지 않아야 할 때도 있다. 한 번만 쓰이고 이름 붙이기도 애매한 세 줄짜리 코드는 그냥 두는 편이 읽기 쉽다. 함수 개수가 많다고 좋은 코드가 아니다.

10.8배열을 넘기면 복사되지 않는다

값에 의한 전달에는 예외처럼 보이는 것이 하나 있다. 배열이다.

CODE
void touch(int a[], int n)
{
    a[0] = 999;
}

int v[5] = {1,2,3,4,5};
touch(v, 5);
printf("%d\n", v[0]);
OUTPUT
999

함수 안에서 바꾼 것이 밖에 전해졌다. 배열은 통째로 복사되지 않고 "어디에 있는지"만 전달되기 때문이다. 그 정체는 13장에서 밝혀진다.

함수 안에서는 sizeof가 통하지 않는다 sizeof(a)를 함수 안에서 쓰면 배열 전체 크기가 아니라 8이 나온다. gcc도 'sizeof' on array function parameter 'a' will return size of 'int *'로 경고한다.
그래서 배열을 넘길 때는 크기를 따로 넘긴다. void touch(int a[], int n)처럼 n이 항상 따라다니는 이유다.
03 — 표준 코드

함수읽는 법
is_primen < 2를 맨 앞에서 거른다(5장). 도입 문제의 버그가 여기서 한 번만 고쳐진다. (long long)i * i는 2장의 중간값 오버플로 대비.

최소공배수는 나누기를 먼저 한다 a * b / gcd(a,b)로 쓰면 a * b에서 넘칠 수 있다(2장). a / gcd(a,b) * b로 쓰면 중간값이 작아진다. gcd는 a의 약수이므로 나누어떨어져 정확도도 유지된다.

05 — 흔한 오류

흔한 오류 여섯 가지

오류 1프로토타입 없이 아래쪽 함수를 호출했다
p1.c:2:32: warning: implicit declaration of function 'square'
           [-Wimplicit-function-declaration]

1장 오류 5에서 pritnf 오타로 만났던 그 경고다. 이번에는 오타가 아니라 순서 때문이다. 경고만 나고 실행은 되므로 넘어가기 쉽다.

고치는 법 — 프로토타입을 파일 맨 위에 모아 쓴다. 몸통 없이 세미콜론으로 끝낸다.
오류 2모든 경로에서 return하지 않았다
rv.c:2:36: warning: control reaches end of non-void function
           [-Wreturn-type]

경고를 무시하면 쓰레기값이 돌아온다. 실행 결과가 1과 -551763613처럼 나온다. 조건이 복잡해질수록 빠뜨린 경로를 찾기 어려워진다.

고치는 법 — 함수의 마지막 줄에 항상 return을 둔다. 5장의 "빠짐없이"를 함수에 적용한 것이다.
오류 3함수가 바꾼 값이 전해질 줄 알았다
void swap_bad(int a, int b) { int t=a; a=b; b=t; }
swap_bad(x, y);   // x, y는 그대로

경고도 오류도 없다. 완벽히 정상인 코드이고, 단지 아무 일도 하지 않을 뿐이다. 함수 안에 printf를 넣어 보면 분명히 바뀌어 있어서 더 혼란스럽다.

고치는 법 — 지금은 return으로 값을 돌려받는다. 두 값을 바꾸려면 호출한 쪽에서 직접 교환한다. 제대로 된 해법은 12장 포인터.
오류 4지역 변수가 전역 변수를 가렸다
int cnt = 0;                    // 전역 — 전체 개수를 셀 생각

void f(void) {
    int cnt = 0;                // 같은 이름의 지역 변수
    ...
    cnt++;                      // 전역이 아니라 지역이 늘어난다
}

경고가 없다. 함수가 끝나면 지역 cnt는 사라지고 전역은 0 그대로다. 결과가 항상 0으로 나오는데 코드만 봐서는 멀쩡해 보인다.

고치는 법 — 전역에는 total_count, board처럼 긴 이름을, 지역에는 i, c, t처럼 짧은 이름을 쓴다. 이름이 겹치지 않으면 생기지 않는 사고다.
오류 5함수 안에서 sizeof로 배열 크기를 구하려 했다
arr.c: warning: 'sizeof' on array function parameter 'a'
       will return size of 'int *' [-Wsizeof-array-argument]

main 안    : sizeof(v) = 20
함수 안    : sizeof(a) =  8

8장에서 배운 sizeof(a)/sizeof(a[0])가 함수 안에서는 통하지 않는다. 결과는 8/4 = 2가 되어 배열을 두 칸만 훑는다.

고치는 법 — 배열을 넘길 때는 크기를 매개변수로 함께 넘긴다. void f(int a[], int n).
오류 6매개변수가 없는데 괄호를 비워 두었다
int f();        // 매개변수 정보가 없다는 뜻 (옛 문법)
int f(void);    // 매개변수가 없다는 뜻 (올바름)

f()로 선언하면 컴파일러가 인자 개수를 검사하지 않는다. f(1, 2, 3)처럼 잘못 불러도 경고가 나오지 않는다.

고치는 법 — 매개변수가 없으면 (void)로 명시한다. 1장부터 써 온 int main(void)가 그래서 그 모양이다.
이 장의 가장 중요한 교훈 오류 3·4는 경고가 전혀 나오지 않는다. 그리고 둘 다 "코드는 맞는데 아무 효과가 없는" 형태라서, 로직을 의심하며 한참을 헤매게 만든다. 함수를 쓸 때는 "이 함수가 바깥에 전하는 것은 반환값뿐인가?"를 매번 확인한다.

정답과 해설

※ 이 절은 교사용 통합본에만 수록한다. 학생 배부용에서는 제거한다.

01
long long cube(int x) { return (long long)x * x * x; } — 반환형이 long long이어야 하고, 곱하기 전에 형변환해야 한다(2장 연습 5). 둘 중 하나만 해도 틀린다.
02
max2(max2(a, b), c) — 함수를 중첩 호출하는 첫 경험이다. 안쪽이 먼저 계산되어 그 결과가 바깥의 인자가 된다는 것을 짚는다.
03
int my_abs(int x) { if (x < 0) { return -x; } return x; } — INT_MIN의 절댓값은 int로 표현할 수 없다(2장). -INT_MIN이 다시 INT_MIN이 되어 음수가 그대로 나온다. 실행해 확인시킨다.
04
표준 코드와 동일. n < 2 거르기가 맨 앞이어야 1이 소수로 나오지 않는다. 2는 루프가 한 번도 돌지 않고 바로 return 1이 되는 것도 확인시킨다.
05
gcd(100, 0)은 b == 0이라 루프를 돌지 않고 a인 100을 돌려준다. 수학적으로도 맞다. gcd(0, 0)은 0이 되는데, 문제에서 그 입력이 가능한지 확인하는 습관을 들인다.
06
출력은 39 987654. 함수 안에서 n /= 10으로 깎았지만 복사본이라 호출한 쪽은 멀쩡하다. 이 확인이 10.3절을 몸에 새기는 자리다.
07
void print_stars(int k) { for (int j = 0; j < k; j++) { printf("*"); } printf("\n"); } 후 for (int i = 1; i <= n; i++) { print_stars(i); }. 지도 포인트 — 7장의 이중 루프가 "루프 + 함수 호출"로 바뀌었다. 중첩이 한 겹 줄어 읽기 쉬워진다.
08
출력 예: 호출 전 3 7 / 함수 안 7 3 / 호출 후 3 7.
지도 포인트 — "안에서는 분명히 바뀌었는데 밖은 그대로"라는 체험이 핵심이다. 12장 포인터의 동기를 여기서 만들어 둔다.
09
예제 1과 동일. N = 20에서 소수는 2,3,5,7,11,13,17,19로 8개, 합 77, 최대 19.
반복 횟수 — N = 106이면 각 수마다 √n번이므로 대략 106 × 1000 = 109에 가깝다. 실제로는 합성수가 빨리 걸러져 훨씬 적지만 아슬아슬하다. PART 3의 에라토스테네스 체가 이 자리를 대체한다는 것을 예고한다.
10
(long long)a / g * b. a * b를 먼저 하면 1018로 간신히 들어가지만, 조금만 더 커지면 넘친다. 나누기를 먼저 하는 습관을 들인다.
예제에서 gcd(109, 109−1) = 1이고 lcm은 999999999000000000이다.
11
표준 코드의 digital_root에 추적 출력을 넣는다. 6장 표준 코드와 비교해 안쪽 while이 함수로 빠져 바깥 구조가 또렷해진 것을 보여 준다. 입력 5(반복 0회)도 다시 확인시킨다.
12
int is_palindrome(int n)
{
    int r = 0, t = n;
    while (t > 0) { r = r * 10 + t % 10; t /= 10; }
    return (r == n);
}
n을 그대로 쓰지 않고 t에 복사해 깎는 것이 요점이다. n을 깎으면 마지막 비교에서 쓸 원본이 없어진다. 복사본이라도 함수 안에서는 조심해야 한다는 교훈.
13
세 함수 모두 (int a[], int n) 형태다. arr_max의 초기값은 a[0](8장 오류 5). 합이 0으로 나오는 예제를 넣은 것은 "0이니까 틀렸나" 의심하는 학생을 걸러 내기 위해서다.
14
실제로 바뀐다. 8번과 다른 이유 — int a는 값이 복사되지만, 배열은 통째로 복사되지 않고 어디에 있는지만 전달되기 때문이다. 그래서 함수가 그 자리의 값을 직접 고친다.
지도 포인트 — 이 차이가 13장 포인터의 핵심 주제다. 지금은 "배열은 예외"로 외워 두되, 이유가 따로 있다는 것을 알려 둔다.
15
예제 5와 동일. 지도 포인트 — 9장 코드와 나란히 놓고 비교시킨다. 조건 네 개가 이름 하나로 바뀌면서 본체 루프가 짧아지고, n/m 혼동(9장 오류 2)을 확인할 곳이 한 군데로 줄었다.
16
예제 3과 동일. 10 12 → 2 6, 3 100 → none. 반환값으로 성공 여부를, 전역 변수로 결과를 전달하는 구조를 설명한다.
17
출력은 A 101 / C 100 / B 11 / D 100.
A — f의 매개변수 x는 지역 x(100)의 복사본. 101이 되지만 복사본이다.
C — main의 x는 그대로 100.
B — g에는 지역 x가 없으므로 전역 x(10)를 건드려 11이 된다.
D — main의 지역 x는 여전히 100. 전역이 바뀐 것과 무관하다.
매개변수 이름을 y로 바꾸면 — 결과는 달라지지 않는다. 이름은 사람이 읽기 위한 것이고, 어느 변수인지는 선언 위치가 정한다. 이름을 바꾸면 오히려 혼동이 줄어 읽기 좋아진다.
18
방법길이바깥 루프평가
깃발 변수조건이 길어짐즉시 멈춤조건식이 지저분
goto가장 짧음즉시 멈춤남용하면 흐름이 꼬임
함수 + return함수 선언이 추가즉시 멈춤재사용 가능, 의미가 드러남
이 교재의 표준은 함수 + return이다. 셋 다 정확히 동작하지만, 함수 방식만이 그 덩어리에 이름을 주고 다른 곳에서 다시 쓸 수 있게 한다. 다만 goto를 "쓰면 안 되는 것"으로 가르치지는 않는다. 중첩 루프 탈출 한 가지 용도로는 널리 쓰이며, 직접 써 보고 판단하게 하는 것이 이 문제의 목적이다.
19
과도한 분해의 예: read_board(), in_range(), count_neighbors(), print_board() 네 개. 각각 한 번씩만 쓰이고 전역 변수에 의존하므로, 이름만 붙었을 뿐 읽으려면 네 곳을 오가야 한다.
in_range 하나만 쓴 버전이 대체로 읽기 쉽다. 그 조건은 루프 안에서 반복해 쓰이고(기준 ①), 이름을 붙일 수 있으며(기준 ②), 9장 오류 2를 한 곳으로 모은다.
지도 포인트 — "함수를 많이 만들수록 좋다"는 오해를 깨는 자리다. 다만 count_neighbors는 다른 문제에서도 쓰일 가능성이 높아 분리할 가치가 있다는 반론도 받아 준다. 정답이 하나가 아닌 토론 문제로 운영한다.

모범 구성 예(여섯 개 이상이면 된다). 
int  is_prime(int n);        // n이 소수면 1      경계: 1→0, 2→1
int  gcd(int a, int b);      // 최대공약수        경계: (100,0)→100
long long lcm(int a, int b); // 최소공배수        주의: 나누기 먼저
int  digit_sum(int n);       // 자릿수 합         경계: 0→0
int  digital_root(int n);    // 한 자리까지 반복  경계: 5→5
int  my_abs(int x);          // 절댓값            주의: INT_MIN
int  max2(int a, int b);     // 큰 값
int  mod(int a, int m);      // 0 이상 나머지     경계: (-7,5)→3
int  in_range(int y, int x); // 격자 안이면 1     전역 n, m 사용
지도 포인트 — PART 2 첫 수업에서 이 파일을 꺼내 쓰게 한다. 자기가 만든 도구를 다시 쓰는 경험이 함수를 체득하는 가장 빠른 길이다. mod는 4장 표준 코드 ((a % m) + m) % m을 함수로 만든 것으로, PART 3·4에서 계속 쓰인다.
08 — 마무리

이 장을 마치기 전 점검

  • 프로토타입을 파일 맨 위에 모아 선언한다
  • 함수의 마지막 줄에 항상 return을 둔다
  • 매개변수가 복사본이라는 것을 알고, 바깥에 전하는 것은 반환값뿐임을 확인한다
  • 매개변수가 없으면 (void)로 명시한다
  • 전역과 지역의 이름이 겹치지 않게 짓는다
  • 중첩 루프 탈출은 함수와 return으로 처리한다
  • 배열을 넘길 때 크기를 함께 넘긴다
  • 두 번 이상 쓰이거나 이름 붙일 수 있는 덩어리만 함수로 뗀다
