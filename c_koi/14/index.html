14

문자열과 문자 처리

C에는 문자열이라는 자료형이 없다. 문자열은 char 배열이고, 13장에서 배운 규칙이 그대로 적용된다. 여기에 "끝을 알리는 문자" 하나가 더해지는데, 그 한 칸을 잊어서 생기는 사고가 문자열 문제 오답의 대부분이다.

학습 목표

  • 문자열이 널 종료 문자로 끝나는 char 배열임을 알고 배열 크기를 올바르게 잡는다
  • strlen·strcpy·strcmp·strcat의 동작과 위험을 안다
  • fgets로 공백이 섞인 한 줄을 읽고 개행을 제거할 수 있다
  • ctype.h의 판정·변환 함수를 쓸 수 있다
  • 아스키 코드 연산으로 문자와 숫자를 변환할 수 있다
  • 한 줄을 공백 기준으로 단어 분리하고 가장 긴 단어를 찾을 수 있다

CODE

입력 / 출력

%s는 공백에서 끊긴다(3장 3.3절). 문장 전체를 한 번에 읽을 방법이 필요하다.

그리고 또 하나. 읽어 온 뒤에는 어디까지가 한 단어인지를 직접 가려내야 한다. 문자열은 그냥 글자가 늘어선 배열일 뿐이므로, "단어"라는 개념은 우리가 만들어야 한다.

02 — 개념 정리

개념 정리

14.1문자열은 널 종료 문자로 끝난다

C의 문자열은 char 배열이고, 끝에 널 종료 문자 '\0'(값 0)이 들어 있다. 이 한 칸이 "여기가 끝"이라는 표시다.

char s[10] = "abc";
인덱스 0  1  2  3  4 ...
값     97 98 99  0  0 ...
글자   'a' 'b' 'c' \0
크기 두 가지
strlen(s) = 3   ← 글자 수
sizeof(s) = 10  ← 배열 칸 수

strlen은 '\0'을 만날 때까지 세는 함수다. 그래서 글자 수만 돌려주고 종료 문자는 포함하지 않는다. 반면 sizeof는 선언한 칸 수다(배열일 때만, 13장).

배열 크기는 "최대 길이 + 1" 문제가 "문자열의 길이는 최대 100"이라고 하면 char s[101];로 선언한다. 100칸은 글자, 한 칸은 종료 문자다. 이 +1을 빠뜨리는 것이 이 단원 오답 1위다.

종료 문자를 지우면

CODE
char u[10] = "abc";
u[3] = 'X';        // 종료 문자를 덮음
printf("%zu\n", strlen(u));
OUTPUT
4

길이가 4로 늘었다. '\0'이 사라져 그 뒤의 0을 만날 때까지 계속 세었기 때문이다. 운이 나쁘면 배열 밖까지 세러 간다. 문자열을 직접 만들 때는 반드시 '\0'을 넣는다.

14.3fgets로 한 줄 읽기

공백이 섞인 한 줄을 읽으려면 fgets를 쓴다.

인자뜻
line읽어 담을 배열
sizeof(line)배열 크기. 이것 때문에 넘치지 않는다
stdin표준 입력에서 읽는다(1장)
반환값실패하거나 입력이 끝나면 NULL(12장)

개행 문자가 따라온다

입력 "hello world" 후 Enter
strlen(line)   = 12
마지막 글자 코드 = 10   ← 개행
내용 = [hello world
]
제거하는 표준 관용구
line[strcspn(line, "\n")] = '\0';

→ strlen = 11
→ [hello world]

strcspn(line, "\n")은 "개행이 처음 나오는 위치"를 돌려준다. 개행이 없으면 문자열 길이를 돌려주므로, 어느 경우든 안전하게 동작한다. 이 한 줄을 통째로 외운다.

scanf와 fgets를 섞으면 밀린다 scanf("%d", &n) 다음에 fgets를 쓰면, scanf가 남긴 개행을 fgets가 읽어 빈 줄이 나온다. 3장의 %c 함정과 같은 구조다.
해결책은 scanf 뒤에 getchar();로 개행 하나를 버리거나, 입력 전체를 fgets로만 읽고 sscanf로 파싱하는 것이다.

14.4sscanf — 문자열에서 뽑아내기

sscanf는 입력 대신 문자열에서 읽는 scanf다. 서식 문자열 규칙은 3장 그대로다.

CODE
char line[] = "minjun 15 172.5";
char name[50]; int age; double h;
int r = sscanf(line, "%49s %d %lf",
               name, &age, &h);
결과
r = 3
name = "minjun"
age  = 15
h    = 172.5

반환값은 성공적으로 읽은 항목 수로 scanf와 같다(3장). "%d-%d-%d" 같은 서식도 그대로 쓸 수 있어 날짜 파싱에 편하다.

14.6문자열도 배열이다

13장의 모든 규칙이 그대로 적용된다.

13장에서 배운 것문자열에서는
배열 이름은 첫 원소의 주소scanf("%s", s)에 &가 없는 이유(12장)
함수에 넘기면 주소만 간다함수가 문자열을 고치면 원본이 바뀐다
함수 안에서 sizeof는 8크기를 따로 넘기거나 strlen을 쓴다
부분 배열은 a + kprintf("%s", s + 3)이면 네 번째 글자부터 출력
읽기만 하면 constint count_vowels(const char s[])

차이는 하나뿐이다. 문자열은 끝에 '\0'이 있으므로 크기를 따로 넘기지 않아도 끝을 알 수 있다. 그래서 strlen(s)만으로 루프를 돌 수 있다.

05 — 흔한 오류

흔한 오류 여섯 가지

오류 1배열 크기에 +1을 하지 않았다
// 문제: 길이가 최대 100인 문자열
char s[100];      // 100글자 + 종료 문자 = 101칸 필요
char s[101];      // 올바름

99글자까지는 멀쩡히 동작한다. 딱 100글자인 입력에서만 종료 문자가 배열 밖에 쓰인다. 예제로는 절대 발견되지 않는다.

고치는 법 — 문제의 최대 길이를 읽자마자 +1한 값을 #define으로 정한다. 넉넉하게 잡는 것이 더 안전하다.
오류 2strcmp를 참·거짓으로 썼다
if (strcmp(a, b)) { printf("같다\n"); }      // 정반대
if (strcmp(a, b) == 0) { printf("같다\n"); } // 올바름

경고가 없다. strcmp는 같으면 0을 돌려주는데, C에서 0은 거짓이다(5장). 그래서 "같을 때 거짓"이 되어 뜻이 뒤집힌다.

고치는 법 — strcmp를 쓸 때는 항상 == 0이나 != 0을 명시한다. 예외를 두지 않는다.
오류 3strcpy로 버퍼를 넘겼다
char small[5];
strcpy(small, "abcdefghij");

warning: '__builtin_memcpy' writing 11 bytes into a region
         of size 5 overflows the destination [-Wstringop-overflow=]

실행하면 *** stack smashing detected ***로 죽는다. 길이가 상수일 때는 gcc가 잡아 주지만, 입력받은 문자열을 복사할 때는 아무도 잡아 주지 못한다.

고치는 법 — 복사 대상의 크기를 먼저 확인한다. 길이가 보장되지 않으면 strlen으로 재어 보거나, 애초에 복사하지 않고 원본의 일부를 가리키는 방식을 쓴다(13.3절).
오류 4잘라낸 조각에 종료 문자를 안 붙였다
memcpy(best, line + start, wlen);
// best[wlen] = '\0';  을 빠뜨리면

best에 이전에 들어 있던 긴 단어의 꼬리가 남아 엉뚱한 글자가 따라 나온다. 전역 배열이면 처음엔 0이라 우연히 맞다가, 두 번째 단어부터 틀린다.

고치는 법 — 문자열을 직접 만들었으면 마지막에 반드시 '\0'을 넣는다. memcpy·strncpy는 붙여 주지 않는다.
오류 5scanf 뒤에 fgets를 썼다
scanf("%d", &n);
fgets(line, sizeof(line), stdin);   // 빈 줄이 들어온다

scanf가 숫자만 읽고 개행을 남긴다. fgets가 그 개행을 만나 바로 줄이 끝났다고 판단한다. 3장 오류 2(%c 앞 공백)와 완전히 같은 구조다.

고치는 법 — scanf 뒤에 getchar();를 넣거나, 처음부터 fgets만 쓰고 sscanf로 파싱한다(예제 5). 후자를 권장한다.
오류 6루프 조건에 strlen을 넣었다
for (int i = 0; i < strlen(s); i++) { ... }   // 매번 끝까지 센다

동작은 맞지만 strlen이 반복마다 호출된다. 길이 N이면 전체가 N²번이 된다. N이 10만이면 100억 번으로 시간 초과다(6장).

고치는 법 — int len = (int)strlen(s);로 미리 한 번만 구한다. 루프 안에서 문자열 길이가 바뀌지 않는다면 언제나 이렇게 쓴다.
이 장의 가장 중요한 교훈 문자열 오류는 종료 문자 한 칸에서 온다. 배열 크기(오류 1), 조각 만들기(오류 4), 복사(오류 3)가 모두 그렇다. 문자열을 다룰 때마다 묻는다. "이 배열에 종료 문자가 들어갈 자리가 있는가? 그리고 그 자리에 실제로 들어갔는가?"

정답과 해설

※ 이 절은 교사용 통합본에만 수록한다. 학생 배부용에서는 제거한다.

01
strlen은 글자 수, sizeof는 선언한 칸 수. 배열을 char s[101]로 선언했다면 5와 101이 나온다. 13장에서 배운 대로 함수 안에서는 sizeof가 8이 되므로 main에서 확인시킨다.

03
s[i] = (char)toupper((unsigned char)s[i]); — 알파벳이 아닌 글자는 toupper가 그대로 돌려주므로 조건 검사가 필요 없다. 쉼표와 느낌표가 유지되는지 확인시킨다.

공백을 건너뛰면서 양끝에서 좁혀 온다. 
int l = 0, r = len - 1;
while (l < r) {
    while (l < r && s[l] == ' ') { l++; }
    while (l < r && s[r] == ' ') { r--; }
    if (tolower(s[l]) != tolower(s[r])) { return 0; }
    l++; r--;
}
주의 — 공백 건너뛰기를 비교 앞에 두어야 한다. 또는 공백을 모두 제거한 새 문자열을 만든 뒤 판정하는 방법도 깔끔하다.

int k = ((K % 26) + 26) % 26;        // 4장 표준 코드

else if (isupper(c)) { c = (char)('A' + (c - 'A' + k) % 26); }
K가 음수이거나 26 이상일 수 있으므로 먼저 보정한다. 4장의 ((a%m)+m)%m이 여기서 또 쓰인다.

for (int i = 0; i + m <= n; i++) {

① s[3] = '\0' → strlen은 3, 출력은 abc. 뒤의 ef는 메모리에 남아 있지만 보이지 않는다.
② s[6] = 'X' → 원래 그 자리가 종료 문자였다. 덮어쓰면 strlen이 7이 되고 출력은 abcdefX. 배열이 char s[10]이라 나머지가 0으로 초기화되어 있어 7에서 멈춘 것이다.
③ 바이트를 찍으면 97 98 99 100 101 102 88 0 0 0으로, 88이 'X'이고 그다음 0에서 끝난다.

지도 포인트 — 겉보기에 똑같은 루프인데 한쪽만 시간 초과가 난다. "함수 호출 안에 루프가 숨어 있다"는 것을 의식하는 훈련이고, PART 2 이후 계속 필요하다.

08 — 마무리

이 장을 마치기 전 점검

  • 배열 크기를 최대 길이 + 1로 잡는다
  • 문자열을 직접 만들면 끝에 '\0'을 넣는다
  • strcmp는 항상 == 0을 명시해 쓴다
  • 공백이 섞인 줄은 fgets로 읽고 개행을 제거한다
  • scanf와 fgets를 섞지 않는다
  • strlen을 루프 조건에 넣지 않는다
  • ctype.h 함수에는 (unsigned char)를 씌운다
  • 단어 분리는 "공백 건너뛰기 → 단어 읽기" 두 단계로 쓴다
다음 장 예고 — 15장 구조체와 사용자 정의 자료형 13장에서 "정렬하면 원래 인덱스가 사라진다"는 문제를 남겨 두었다. 이름과 점수를 한 덩어리로 묶으면 그 문제가 사라진다. 구조체 배열을 qsort로 정렬하는 것이 PART 2·3의 거의 모든 정렬 문제에서 쓰이는 형태다.
