03

서식 입출력

서식 문자열은 입출력의 설계도다. 글자 하나가 어긋나면 컴파일은 되고 실행도 되지만 답이 틀린다. 이 장에서 1장에 미뤄 둔 scanf의 반환값과 -O2 경고까지 정리한다.

학습 목표

  • 자료형마다 맞는 서식 지정자를 골라 쓸 수 있다 — 특히 읽기와 쓰기가 다른 경우
  • 폭·정렬·정밀도 지정자로 출력 모양을 원하는 대로 맞출 수 있다
  • scanf가 공백을 건너뛰는 경우와 건너뛰지 않는 경우를 구분할 수 있다
  • scanf의 반환값을 읽어 입력 성공 여부를 판정하고 EOF를 감지할 수 있다
  • 개수를 모르는 입력을 끝까지 읽어 처리하는 표준형을 쓸 수 있다

01 — 도입 문제

개수를 모르는 입력

지금까지 푼 문제는 입력의 개수가 정해져 있었다. 두 수, 세 수. 그런데 올림피아드 문제는 이렇게 끝나는 경우가 많다.

문제의 입력 설명 "입력은 여러 개의 정수로 이루어진다. 입력의 끝까지 모든 정수의 합을 출력하라."
몇 개가 들어올지 알려 주지 않는다. 100개일 수도, 1,000,000개일 수도 있다.

이 문제를 풀려면 두 가지를 알아야 한다. 첫째, 입력이 끝났다는 것을 어떻게 아는가. 둘째, 끝날 때까지 반복하려면 무엇이 필요한가. 둘째는 6장 반복문의 몫이고, 이 장은 첫째를 책임진다.

답은 scanf가 돌려주는 값에 들어 있다. 우리는 1장부터 scanf를 써 왔지만 그 반환값을 한 번도 쳐다보지 않았다. 사실 scanf는 매번 "몇 개를 제대로 읽었는지"를 보고하고 있었다.

또 하나, 1장에서 남겨 둔 숙제가 있다. -O2를 붙여 컴파일하면 나오던 그 경고다.

"scanf의 반환값을 무시하고 있다"는 뜻이다. 두 문제의 답이 같은 곳에 있다는 것을 이 장에서 확인한다.

02 — 개념 정리

개념 정리

3.1서식 지정자 한눈에

서식 지정자는 값과 글자 사이의 변환 규칙이다. printf는 값을 글자로 바꾸고, scanf는 글자를 값으로 바꾼다. 방향이 반대이므로 지정자가 다른 경우가 생긴다.

자료형printfscanf주의
int%d%d같다
long long%lld%lld같다. %d를 쓰면 틀린다(2장)
unsigned int%u%u올림피아드에서는 쓰지 않는다
float%f%f정밀도가 낮아 쓰지 않는다
double%f%lf읽기와 쓰기가 다르다
char%c%c%d로 아스키 번호도 출력 가능
문자열(char[])%s%s&를 붙이지 않는다
sizeof의 결과%zu—2장에서 사용
글자 % 자체%%—
double만 비대칭이다 printf는 %f, scanf는 %lf. 이것만 따로 외운다. scanf("%f", &d)로 double을 읽으면 경고가 뜨고 값은 0.000000이 된다.

3.2출력 모양 다듬기 — 폭·정렬·정밀도

지정자 앞에 숫자를 넣어 출력 칸을 조절한다. 형식은 % + -(왼쪽 정렬) + 0(0으로 채움) + 폭 + .정밀도 + 지정자다.

서식출력의미
printf("[%d]", 42)[42]기본
printf("[%5d]", 42)[   42]폭 5, 오른쪽 정렬
printf("[%-5d]", 42)[42   ]폭 5, 왼쪽 정렬
printf("[%05d]", 42)[00042]빈칸을 0으로 채움
printf("[%f]", 3.14159)[3.141590]기본은 소수점 아래 6자리
printf("[%.2f]", 3.14159)[3.14]소수점 아래 2자리
printf("[%8.2f]", 3.14159)[    3.14]전체 폭 8, 소수 2자리
printf("[%8s]", "abc")[     abc]문자열도 폭 지정 가능
printf("%d:%02d", 3, 5)3:05시계 표기 — 2장 연습 12번의 숙제
%.0f의 반올림은 우리가 아는 반올림이 아니다 printf("%.0f", 2.5)는 2, printf("%.0f", 3.5)는 4를 출력한다. 0.5인 경우 가까운 짝수로 보내는 규칙을 쓰기 때문이다. 반올림이 중요한 문제에서는 출력 서식에 맡기지 말고 정수 연산으로 직접 처리한다.

3.3scanf의 공백 규칙

입력 파일에는 공백과 줄바꿈이 섞여 있다. scanf가 이것을 어떻게 처리하는지가 입력 코드의 거의 모든 버그를 만든다. 규칙은 두 줄이다.

지정자앞의 공백·줄바꿈읽는 범위
%d %lld %lf %s알아서 건너뛴다공백을 만날 때까지
%c건너뛰지 않는다딱 한 글자 — 공백도 글자다

그래서 %c만 사고가 난다. 입력 A B에서 문자 두 개를 읽어 보자.

scanf("%c") 두 번
c1 = [A] (65)
c2 = [ ] (32)   ← 공백!
scanf(" %c") 두 번
c1 = [A] (65)
c2 = [B] (66)   ← 정상

서식 문자열 안의 공백 한 칸은 "여기서 공백을 만나면 모두 건너뛰라"는 명령이다. 그래서 " %c"라고 쓰면 해결된다. %c를 쓸 때는 항상 앞에 공백을 붙인다고 외워 두면 된다.

%d 다음에 %c를 쓰는 경우도 같은 함정이다. %d가 숫자를 읽고 멈추면 그 뒤의 줄바꿈이 그대로 남아 있어서, 다음 %c가 그 줄바꿈을 읽어 버린다.

입력
7
A
결과 비교
scanf("%c", &g)  → g = 개행(10)
scanf(" %c", &g) → g = 'A'(65)

3.4scanf의 반환값

scanf는 성공적으로 읽어서 변수에 넣은 항목의 개수를 돌려준다. 입력이 완전히 끝났으면 EOF를 돌려주는데, 이 값은 −1이다.

입력반환값뜻
12 252두 개 모두 성공
12 ab1첫 번째만 성공
ab cd0하나도 못 읽음 — 입력은 그대로 남는다
(입력 없음)-1 (EOF)더 읽을 것이 없음
0과 EOF는 다르다 숫자가 와야 할 자리에 글자가 있으면 scanf는 0을 돌려주고 그 글자를 입력에서 치우지 않는다. 그래서 같은 자리를 다시 읽으면 또 0이다. 끝을 != EOF로 판정하면 영원히 끝나지 않는다. 반드시 "읽어야 할 개수와 같은가"로 판정한다.

3.51장의 숙제: -O2 경고의 정체

이제 그 경고를 읽을 수 있다. "scanf의 반환값을 무시했다"는 지적이고, 지적이 옳다. 반환값을 검사하도록 고치면 경고는 사라진다.

경고가 나는 코드
scanf("%d %d", &a, &b);
경고가 사라지는 코드
if (scanf("%d %d", &a, &b) != 2)
    return 1;

올림피아드 문제는 입력이 명세대로 들어온다고 보장하므로 검사를 생략해도 답은 맞는다. 다만 이 장부터는 반환값을 쓰는 습관을 들인다. 입력 개수를 모르는 문제에서는 선택이 아니라 필수이고, 디버깅할 때도 입력이 잘못됐는지 로직이 틀렸는지를 즉시 가려 준다.

03 — 표준 코드

표준 코드: 입력 끝까지 읽어 합하기

도입 문제의 답이다. 반복문은 6장에서 다루므로 지금은 while 줄의 조건에만 집중한다.

요소읽는 법

반환값 사용조건식에서 반환값을 썼으므로 -O2 경고도 나지 않는다.

두 입력의 모양이 전혀 다른데 코드는 그대로다. %d가 공백과 줄바꿈을 모두 건너뛰기 때문이다. 입력 데이터의 줄 구분에 맞춰 코드를 바꿀 필요가 없다.

키보드로 직접 시험할 때 터미널에서 값을 입력하다가 입력의 끝을 알리려면 Ctrl+D(윈도우는 Ctrl+Z 후 Enter)를 누른다. 또는 1장에서 배운 대로 ./eofsum < input.txt로 파일을 연결한다.

05 — 흔한 오류

흔한 오류 여섯 가지

메시지는 모두 gcc 13.3.0의 실제 출력이다. 이 장의 오류는 2장처럼 조용히 틀리는 쪽이다.

오류 1double을 %f로 읽었다

출력은 %f, 입력은 %lf. 이것 하나만 비대칭이라 계속 틀린다.

e1.c:6:13: warning: format '%f' expects argument of type 'float *',
            but argument 2 has type 'double *' [-Wformat=]
    6 |     scanf("%f", &d);
      |            ~^   ~~
      |             |   |
      |             |   double *
      |             float *
      |            %lf

실행하면 d에 입력값이 들어가지 않고 0.000000이 나온다. 4바이트만 채워 넣기 때문이다.

고치는 법 — scanf("%lf", &d). gcc가 %lf라고 답까지 적어 준다.
오류 2%c 앞에 공백을 안 붙였다

경고도 오류도 없다. 컴파일러 입장에서는 완전히 정상인 코드다.

scanf("%d", &n);
scanf("%c", &g);     // n 뒤의 줄바꿈을 읽어 버린다

g에는 개행 문자(아스키 10)가 들어간다. 입력이 밀렸다는 것을 알아채기까지 한참 걸린다.

고치는 법 — scanf(" %c", &g). %c를 쓸 때는 기계적으로 앞에 공백을 붙인다.
오류 3문자열에 &를 붙였다

1장에서 "읽을 때는 &"라고 외운 것이 여기서 역효과를 낸다.

e1.c:5:13: warning: format '%s' expects argument of type 'char *',
            but argument 2 has type 'char (*)[32]' [-Wformat=]
    5 |     scanf("%s", &s);
      |            ~^   ~~
      |             |   |
      |             |   char (*)[32]
      |             char *

이 경우는 주소값이 우연히 같아서 대개 정상 동작한다. 그래서 더 위험하다. 경고를 무시하는 습관이 붙는다.

고치는 법 — 배열 이름은 그 자체가 주소다. scanf("%s", s).
오류 4%s에 폭을 지정하지 않았다

char s[32];에 scanf("%s", s)로 50글자를 입력하면 배열 뒤의 메모리를 덮어쓴다. 경고는 없고, 운이 좋으면 멀쩡히 돌아가고 운이 나쁘면 Segmentation fault로 죽는다.

고치는 법 — 배열 크기가 N이면 %(N-1)s. 크기 32면 %31s. 문제의 최대 길이를 보고 배열을 넉넉히 잡는 것도 함께 한다.
오류 5끝 판정을 != EOF 로 했다

숫자 자리에 글자가 들어오면 scanf는 0을 돌려주고 그 글자를 치우지 않는다. 다음 번에도 같은 글자를 보고 또 0이다.

입력이 "abc"일 때 while (scanf("%d", &x) != EOF) 의 동작:

try 1: scanf 반환 0
try 2: scanf 반환 0
try 3: scanf 반환 0
...  영원히 끝나지 않는다

채점 결과는 시간 초과로 나온다. 알고리즘이 느린 줄 알고 엉뚱한 곳을 고치게 된다.

고치는 법 — while (scanf("%d", &x) == 1). 읽어야 할 항목이 두 개면 == 2. "기대한 개수와 같은가"로 판정한다.
오류 6출력에 군더더기를 넣었다

채점은 stdout의 글자를 정답 파일과 글자 단위로 비교한다(1장 2.4절). 다음은 모두 오답 처리된다.

코드문제
printf("합은 %d입니다\n", s);안내문이 섞였다
printf("%d ", s);끝에 불필요한 공백
printf("%d", s);줄바꿈 누락 — 문제에 따라 허용되기도 한다
printf("%.2f\n", (double)s);정수를 실수로 출력했다
고치는 법 — 문제의 출력 예시를 글자 그대로 재현한다. 안내문이 필요하면 fprintf(stderr, ...)로 보낸다.
이 장의 가장 중요한 교훈 서식 문자열의 글자 하나는 코드 한 줄과 같은 무게를 가진다. %f와 %lf, %c와 " %c", == 1과 != EOF. 전부 한 글자 차이인데 결과는 0.000000, 엉뚱한 문자, 시간 초과로 갈린다.

무한 루프 재현하기 — 아래 코드를 작성하고 입력으로 abc를 주어 실행하라. ① 무슨 일이 일어나는가 ② scanf의 반환값은 몇인가 ③ 왜 끝나지 않는가 ④ 한 글자만 고쳐 해결하라.

int x, sum = 0;
while (scanf("%d", &x) != EOF) {
    sum += x;
}
printf("%d\n", sum);

(가) printf("%d\n", v);
(나) scanf("%f", &d);
(다) scanf("%s", &s);
(라) scanf("%d", &v);

07 — 확인 평가 해설

정답과 해설

※ 이 절은 교사용 통합본에만 수록한다. 학생 배부용에서는 제거한다.

01
printf("[%d]\n[%5d]\n[%-5d]\n[%05d]\n", 7, 7, 7, 7); 한 줄로도 가능하다. 서식 문자열 안에 \n을 넣어 묶는 것을 보여 준다.
02
printf("%.1f%%\n", x); — % 하나만 쓰면 다음 글자를 지정자로 해석해 출력이 깨진다. 흔한 오답: printf("%.1f%\n", x).
03
printf("%02d:%02d:%02d\n", s/3600, s/60%60, s%60); — 2장 연습 12번에서 3:5로 끝냈던 것을 여기서 완성한다. 두 장의 연결을 짚어 준다.
04
scanf(" %c", &c); 후 printf("[%c](%d)\n", c, c); — 같은 변수를 두 서식으로 출력하는 것이 요점이다.
05
scanf(" %c %c", &a, &b); 또는 " %c" 두 번. printf("%c%c\n", b, a);. 흔한 오답: "%c %c" — 첫 번째 %c 앞 공백이 없어도 이 입력에서는 우연히 동작한다. 앞에 개행이 붙은 입력으로 시험시켜 차이를 보여 준다.
06
char s[101]; scanf("%100s", s); — 배열 크기 101, 폭 100. 종료 문자 한 칸을 왜 남기는지 설명한다(14장 예고).
07
double a, b; scanf("%lf %lf", &a, &b); printf("%.4f\n", a+b); — 읽기 %lf, 쓰기 %f. 흔한 오답: scanf("%f", ...) → 출력 0.0000.
08
scanf("%d-%d-%d", &y, &m, &d); — 서식 문자열의 -가 입력의 -와 맞춰진다. 보충 — scanf("%4d-%2d-%2d", ...)로도 되고, 구분자가 없는 20261012라면 %4d%2d%2d를 쓴다(예제 4).
09
최악의 합은 106 × 109 = 1015이므로 long long이 필요하다. 
int x;
long long sum = 0;
while (scanf("%d", &x) == 1) sum += x;
printf("%lld\n", sum);
지도 포인트 — 읽는 변수 x는 int로 충분하고 누적 변수만 long long이면 된다. 2장 표준 코드와 같은 구조다.
10
cnt와 sum을 함께 누적한 뒤 printf("%d %.2f\n", cnt, (double)sum / cnt);. 흔한 오답: sum / cnt — 정수 나눗셈이 되어 4.00이 나온다(2장 연습 15번과 같은 함정).
11
while (scanf("%99s %d", name, &score) == 2) printf("%-10s%5d\n", name, score); — 한 번의 scanf로 두 항목을 읽고 반환값을 2와 비교하는 것이 요점이다.
12
첫 줄의 T를 먼저 읽고 T번 반복한다. 
int T, a, b;
if (scanf("%d", &T) != 1) return 1;
for (int i = 0; i < T; i++) {
    if (scanf("%d %d", &a, &b) != 2) return 1;
    printf("%d\n", a + b);
}
지도 포인트 — 올림피아드에서 가장 흔한 입력 형식이다. 9~11번의 EOF 방식과 이 T 방식 두 가지가 입력 처리의 전부라고 정리해 준다.
13
scanf("%2d%2d%2d", &a, &b, &c); — 나눗셈 풀이를 쓴 답안도 정답이지만, 이 문제의 목적은 필드 폭의 존재를 체득하는 것이므로 서식 풀이를 요구한다.
14
scanf("%99s %d %lf", name, &age, &h); 후 printf("%s/%d/%.1f\n", name, age, h);
보충 실험 — 입력을 172.45로 바꾸면 172.5가 아니라 172.4가 나온다. %.20f로 찍어 보면 실제 저장된 값이 172.44999999999998863132이기 때문이다. 2장에서 배운 "double은 정확하지 않다"가 출력 자리에서 드러나는 사례다.
15
int a, b;
if (scanf("%d %d", &a, &b) != 2) {
    fprintf(stderr, "input error\n");
    return 1;
}
printf("%d\n", a + b);
return 0;
정상 입력이면 echo $?가 0, 잘못된 입력이면 1. 1장의 종료 코드와 이 장의 반환값이 만나는 지점이다.
16
출력은 0 2 2 4 4. 규칙은 0.5인 경우 가까운 짝수 쪽으로 보낸다(은행가 반올림). 일반적인 반올림이라면 1, 2, 3, 4, 5가 나와야 한다.
지도 포인트 — 평균·확률을 출력하는 문제에서 마지막 자리가 1 차이로 틀리는 원인이다. 정확한 반올림이 필요하면 정수 연산으로 처리한다.
17
① 프로그램이 멈추지 않는다(채점에서는 시간 초과). ② 반환값은 계속 0이다. ③ scanf가 %d로 읽는 데 실패하면 그 글자를 입력에서 치우지 않는다. 그래서 다음 호출도 같은 a를 보고 또 실패한다. 0은 EOF(−1)가 아니므로 조건이 끝나지 않는다.
④ != EOF를 == 1로 바꾼다.
지도 포인트 — 0과 EOF를 구분하는 것이 이 장의 핵심이다. 이 문제를 직접 겪게 한 뒤 3.4절로 돌아가 다시 읽힌다.
18
(가) %d에 long long — 경고 expects argument of type 'int', 출력은 하위 32비트인 1410065408. → %lld.
(나) %f에 double* — 경고 expects argument of type 'float *', d는 0.000000. → %lf.
(다) %s에 &s — 경고 has type 'char (*)[16]', 그러나 대개 정상 동작한다. → &를 뺀다.
(라) %d에 long long* — 경고 expects argument of type 'int *', 작은 수에서는 우연히 맞기도 한다. → %lld.
정리 — 네 경우 모두 컴파일은 성공한다. (다)와 (라)는 테스트에서 통과하고 채점에서 틀릴 수 있어 가장 위험하다.
19
%d·%lf·%s는 값을 읽기 전에 앞쪽의 공백과 줄바꿈을 모두 건너뛴다. 입력에서 공백과 줄바꿈은 똑같이 "구분자"로 취급되므로, 한 줄에 모여 있든 줄마다 나뉘어 있든 동일하게 읽힌다.
%c는 예외다. 한 글자를 있는 그대로 읽으므로 공백과 줄바꿈도 하나의 글자로 가져간다. 그래서 입력의 줄 구성이 바뀌면 결과가 달라지고, " %c"처럼 앞에 공백을 두어 명시적으로 건너뛰게 해야 같은 동작이 된다.
20
모범 답안 예시(항목 수와 표현은 달라도 된다).
출력 ① 안내문이 stdout에 섞이지 않았는가 → 틀림 ② 끝의 불필요한 공백 → 틀림 ③ 줄바꿈 처리 → 문제에 따라 틀림 ④ 정수를 실수로, 실수를 정수로 출력하지 않았는가 → 틀림 ⑤ 소수점 자릿수가 문제 요구와 같은가 → 틀림
입력 ⑥ double을 %lf로 읽는가 ⑦ %c 앞에 공백을 붙였는가 ⑧ 끝 판정을 == 1로 했는가 → 시간 초과
자료형(2장) ⑨ 최악의 경우 값을 계산했는가 ⑩ 중간값이 넘치지 않는가 ⑪ long long을 %lld로 출력하는가
공통 ⑫ 경고 0개인가(1장)
지도 포인트 — 이 점검표를 교실 벽에 붙이고 PART 2 내내 쓴다. 학생이 직접 만든 표라야 실제로 쓴다.
08 — 마무리

이 장을 마치기 전 점검

  • double은 읽기 %lf, 쓰기 %f라는 것을 안다
  • %c 앞에는 기계적으로 공백을 붙인다
  • 문자열에는 &를 붙이지 않고, 폭을 지정해 읽는다
  • scanf의 반환값이 무엇을 뜻하는지 설명할 수 있다
  • 끝 판정을 == 1로 하고 != EOF를 쓰지 않는 이유를 안다
  • 폭·정렬·정밀도로 출력 모양을 맞출 수 있다
  • 제출 전 출력 형식 점검표를 확인한다
다음 장 예고 — 04장 연산자와 형변환 이 장에서 (double)sum / cnt라는 표현이 여러 번 나왔다. 왜 괄호가 저기에 붙는지, 정수끼리의 나눗셈은 왜 소수가 사라지는지, 그리고 음수를 나눈 나머지가 왜 음수가 되는지를 다음 장에서 정리한다.
