05

약수·배수·소수와 유클리드 호제법

여기부터는 입력을 모으는 것이 아니라 수 자체의 성질을 묻는다. 그런데 이 유형의 코드는 대부분 한 줄만 바꾸면 3만 배 빨라진다. 어떤 한 줄인지, 왜 그런지를 2장의 복잡도 표로 계산해 결정한다.

학습 목표

  • 약수를 구할 때 √N까지만 돌면 되는 이유를 설명할 수 있다
  • 제곱수에서 약수를 두 번 세지 않도록 경계를 처리할 수 있다
  • 소수 판정의 경계값 0, 1, 2를 올바르게 처리할 수 있다
  • 여러 수를 판정할 때 에라토스테네스의 체로 바꿀 줄 안다
  • 유클리드 호제법을 세 줄로 쓰고 왜 빠른지 설명할 수 있다
  • 최소공배수에서 나누기를 먼저 해 오버플로를 피할 수 있다

01 — 도입 문제

한 줄을 바꾸면 3만 배

문제
N의 약수가 몇 개인지 출력하라.

제약
1 ≤ N ≤ 1,000,000,000
시간 제한 1초
정의 그대로 옮긴 코드
int c = 0;
for (long long i = 1; i <= n; i++)
    if (n % i == 0) c++;
printf("%d\n", c);

맞는 코드다. 작은 N으로 테스트하면 전부 통과한다. 그런데 N이 109이면 루프가 10억 번 돈다. 2장의 표에서 109은 "아슬아슬"이었다. 실제로 재 보면,

측정 (N = 1,000,000,000)
O(N)   약수 100개   3.5612초   ← 시간 초과
O(√N)  약수 100개   0.0001초

배수 = 31,515배
바뀐 것은 조건 한 줄
/* 전 */
for (i = 1; i <= n; i++)

/* 후 */
for (i = 1; i * i <= n; i++)
             ↑
         이것뿐이다
왜 √N까지면 충분한가 약수는 반드시 짝으로 나온다. i가 n의 약수이면 n/i도 약수다. 그리고 둘 중 작은 쪽은 반드시 √n 이하다. 둘 다 √n보다 크면 곱이 n보다 커지기 때문이다.
그러므로 1부터 √n까지만 돌면서 i를 찾을 때마다 n/i를 짝으로 함께 세면 빠짐없이 전부 구해진다. 100 = 1×100 = 2×50 = 4×25 = 5×20 = 10×10 — 왼쪽 수는 전부 10 이하다.

√(109) ≈ 31,623이므로 루프가 10억 번에서 3만 번으로 줄었다. 2장에서 만든 복잡도 표가 여기서 그대로 쓰인다 — N ≤ 109이면 O(N)은 불가능하고 O(√N)이나 O(log N)을 찾아야 한다.

이 장이 답할 질문 ① 약수·소수 문제에서 루프를 어디까지 돌려야 하는가?
② 수 하나가 아니라 100만 개를 판정해야 하면?
③ 최대공약수를 반복문 없이 구할 수 있는가?
02 — 개념 정리

개념 정리

5.1약수는 짝으로 — 그런데 제곱수가 문제다

i를 찾을 때마다 n/i를 함께 세면 된다. 단 i와 n/i가 같은 경우를 두 번 세면 안 된다.

약수의 개수O(√N)
int count_divisors(long long n) {
    int c = 0;
    for (long long i = 1; i * i <= n; i++) {
        if (n % i == 0) {
            c++;                      /* i 자신 */
            if (i != n / i) c++;      /* 짝꿍 — 같으면 세지 않는다 */
        }
    }
    return c;
}
n약수개수i == n/i 인 지점
1111 = 1/1
41, 2, 432 = 4/2
91, 3, 933 = 9/3
161, 2, 4, 8, 1654 = 16/4
361, 2, 3, 4, 6, 9, 12, 18, 3696 = 36/6
1001, 2, 4, 5, 10, 20, 25, 50, 100910 = 100/10
제곱수만 약수의 개수가 홀수다 표를 보면 제곱수(1, 4, 9, 16, 36, 100)의 약수 개수가 전부 홀수다. 짝이 하나 모자라기 때문이다. 이것이 "짝을 지을 수 없는 수는 제곱수뿐"이라는 성질이고, 사물함 문제·전구 문제 같은 유명한 문제의 답이 여기서 나온다.
if (i != n/i)를 빠뜨리면 제곱수에서만 답이 1 커진다. n = 36을 넣어야 걸린다. 제곱수가 이 유형의 표준 반례다.

n = 1부터 20,000까지 O(N)판과 O(√N)판을 전수 비교해 불일치 0건임을 확인했다.

5.2소수 판정도 같은 원리, 단 경계가 더 까다롭다

소수 판정O(√N)
int is_prime(long long n) {
    if (n < 2) return 0;              /* 0, 1, 음수는 소수가 아니다 */
    for (long long i = 2; i * i <= n; i++)
        if (n % i == 0) return 0;
    return 1;
}
경계값 확인
  0 → 소수 아님
  1 → 소수 아님   ← 가장 흔한 실수
  2 → 소수        ← 유일한 짝수 소수
  3 → 소수
  4 → 소수 아님
  9 → 소수 아님   ← i=3 에서 걸린다
 25 → 소수 아님
 97 → 소수
왜 n=2에서 루프가 안 도는가
n = 2 일 때
  i = 2 에서 i*i = 4 > 2
  → 루프를 한 번도 돌지 않고
    return 1

즉 2는 자동으로 소수가 된다.
따로 처리할 필요가 없다.
1을 소수로 처리하는 오류 if (n < 2) return 0;을 빼면 n = 1에서 루프가 돌지 않고 return 1이 되어 1이 소수가 된다. 그리고 n = 0에서도 1이 된다.
이 한 줄이 없어도 2 이상의 모든 입력에서는 정답이 나온다. 그래서 예제로는 안 걸린다. 소수 문제의 표준 반례는 0, 1, 2다.

n = 0부터 100,000까지 O(N)판과 O(√N)판을 전수 비교해 불일치 0건이었다. 109에 가까운 소수 999,999,937을 판정하면 O(√N)은 0.00011초, O(N)은 3.557초다.

5.3여러 개를 판정하면 체로 바꾼다

"1부터 N까지 소수가 몇 개인가"를 묻는다면 이야기가 달라진다. 수 하나마다 O(√N)이면 전체가 O(N√N)이다. N = 106이면 109으로 2장의 기준에서 위험하다.

에라토스테네스의 체O(N log log N) — 사실상 O(N)
char comp[1000001];                    /* 전역 — 0으로 자동 초기화 */

comp[0] = comp[1] = 1;                  /* 0과 1은 소수가 아니다 */
for (long long i = 2; i * i <= N; i++)     /* 여기도 √N 까지 */
    if (!comp[i])                        /* i가 아직 소수이면 */
        for (long long j = i * i; j <= N; j += i)  /* i*i 부터 */
            comp[j] = 1;                 /* 배수를 지운다 */
방법 (N = 1,000,000)결과시간판정
하나씩 O(√N) 판정78,498개0.2430초가능하지만 느리다
에라토스테네스의 체78,498개0.0022초111배 빠르다

N = 107에서도 체는 0.0335초에 664,579개를 찾는다.

두 가지 i * i 체에는 i * i가 두 번 나오는데 의미가 다르다.
① 바깥 루프 i * i <= N — √N보다 큰 수의 배수는 이미 작은 소수에게 지워졌다.
② 안쪽 시작 j = i * i — 2i, 3i… 는 이미 2, 3…에게 지워졌으므로 i²부터 시작하면 된다.
판별 기준 — 수 하나만 판정하면 is_prime, 범위 전체가 필요하면 체. 메모리는 char 배열로 N바이트다(107이면 10MB, 2장의 메모리 계산).

5.4소인수분해

작은 소인수부터 나누어떨어지는 동안 계속 나눈다. 역시 √n까지만 돌되, 남은 수가 1보다 크면 그것도 소인수라는 처리가 핵심이다.

factorize.cO(√N)
for (long long p = 2; p * p <= n; p++)
    while (n % p == 0) {              /* if 가 아니라 while */
        printf("%lld ", p);
        n /= p;
    }
if (n > 1) printf("%lld ", n);        /* 남은 것은 큰 소인수 하나 */
검증
     12 = 2 x 2 x 3
    100 = 2 x 2 x 5 x 5
     97 = 97
   1024 = 2 x 2 x ... x 2  (10개)
  30030 = 2 x 3 x 5 x 7 x 11 x 13
999999937 = 999999937
마지막 if 가 없으면
97 → (아무것도 출력 안 됨)
999999937 → (출력 없음)

√n 까지 돌아도 97의
약수를 못 찾기 때문이다.
소수를 입력하면 침묵한다.
while이어야 하는 이유, 마지막 if가 있어야 하는 이유 while — 12는 2로 두 번 나뉜다. if로 쓰면 2 x 6이 되어 6이 소인수로 남는다.
마지막 if — n이 소수이거나, 나누고 남은 몫이 √n보다 큰 소수인 경우다. 반드시 하나만 남는다(둘 이상이면 곱이 원래 n보다 커진다).
표준 반례 — 소수 자체를 입력하는 것. 97이나 999999937을 넣어 본다.

5.5유클리드 호제법

최대공약수를 구하는 데 반복문으로 1부터 훑을 필요가 없다. gcd(a, b) = gcd(b, a mod b)라는 성질 하나면 끝난다.

gcd(1071, 462)의 과정
1071 = 462 x 2 + 147
 462 = 147 x 3 +  21
 147 =  21 x 7 +   0
                   ↑
            나머지가 0이면
            직전 나누는 수가 답

→ gcd = 21
코드 (두 가지 다 외운다)
/* 반복판 */
while (b) {
    long long t = a % b;
    a = b;
    b = t;
}
return a;

/* 재귀판 — 한 줄 */
return b ? gcd(b, a % b) : a;

반복 횟수의 최악은 두 수가 연속한 피보나치 수일 때다. 직접 재 보면,

4 × 1017짜리 두 수를 84번 만에 long long이 담을 수 있는 거의 최대치의 두 수에서도 84회다. 복잡도로는 O(log min(a, b))다. 2장의 표에서 O(log N)은 N이 1018이어도 가능한 유일한 구간이었다.
그래서 최대공약수 문제에서는 제약을 볼 필요도 없다 — 호제법은 항상 통과한다.

5.7뺄셈으로 하면 안 되는 이유

gcd(a, b) = gcd(a−b, b)도 참이다. 그래서 나머지 대신 뺄셈으로 써도 답은 맞는다. 그런데,

측정: gcd(1,000,000,000, 1)
나머지판: 반복      1회  0.00000초
뺄셈판  : 반복 999,999,999회  0.51028초
무슨 일이 일어나는가
뺄셈판은
  10^9 - 1 → 999999999
  999999999 - 1 → 999999998
  ... 1씩 줄어든다

나머지판은
  10^9 % 1 = 0 → 한 번에 끝

나머지 연산은 뺄셈을 한 번에 몰아서 한 것이다. 그래서 O(N)이 O(log N)이 된다. 2장에서 "나머지는 덧셈보다 4배 비싸다"고 했지만, 여기서는 그 4배를 내고 10억 배를 산다.

5.8최소공배수 — 나누기를 먼저

lcm(a, b) = a × b ÷ gcd(a, b)다. 그런데 쓰는 순서에 따라 결과가 달라진다.

a = 4×10⁹, b = 6×10⁹, gcd = 2×10⁹
a * b / g
  a*b = 5553255926290448384
        ← long long도 넘침

a / g * b
  4000000000 / 2000000000 = 2
  2 * 6000000000 = 12000000000
        ← 정답
왜 나누어떨어지는가
g는 a의 약수다.
따라서 a % g == 0 이 항상 참.

→ a / g 는 정수 나눗셈이지만
  정보가 전혀 손실되지 않는다.

(4장의 "나눗셈을 먼저 하면
 정보가 사라진다"의 예외)
4장의 규칙과 반대로 보이지만 아니다 4장에서 "곱셈 먼저, 나눗셈 마지막"이라고 했다. 그 이유는 나눗셈이 소수점을 버려 정보가 사라지기 때문이었다. 여기서는 나누어떨어지는 것이 보장되므로 정보 손실이 없다.
정리 — 나누어떨어지는 것이 수학적으로 보장되면 먼저 나눠서 수를 작게 만든다. 보장되지 않으면 나눗셈은 마지막에.
03 — 표준 코드

표준 코드

numlib.c이 장의 함수 모음 — 외워서 쓴다
#include <stdio.h>

/* ① 소수 판정 — O(√N) */
int is_prime(long long n) {
    if (n < 2) return 0;
    for (long long i = 2; i * i <= n; i++)
        if (n % i == 0) return 0;
    return 1;
}

/* ② 약수의 개수 — O(√N) */
int count_divisors(long long n) {
    int c = 0;
    for (long long i = 1; i * i <= n; i++)
        if (n % i == 0) { c++; if (i != n / i) c++; }
    return c;
}

/* ③ 약수의 합 — long long 주의 */
long long sum_divisors(long long n) {
    long long s = 0;
    for (long long i = 1; i * i <= n; i++)
        if (n % i == 0) { s += i; if (i != n / i) s += n / i; }
    return s;
}

/* ④ 최대공약수 — O(log N) */
long long gcd(long long a, long long b) {
    return b ? gcd(b, a % b) : a;
}

/* ⑤ 최소공배수 — 나누기 먼저! */
long long lcm(long long a, long long b) {
    return a / gcd(a, b) * b;
}
이 다섯 개가 브론즈 수론의 전부다 05장에서 나오는 거의 모든 문제가 이 다섯 함수의 조합이다. 손으로 다섯 번씩 써 보고 외운다. 특히 ②④⑤의 한 줄짜리 요령 — if (i != n/i), b ? gcd(b, a%b) : a, a / gcd(a,b) * b — 는 토씨까지 외운다.
sieve.c범위 전체의 소수가 필요할 때
#include <stdio.h>
#define MAXN 1000000

char comp[MAXN + 1];              /* 전역 → 전부 0 */

int main(void) {
    int n;
    if (scanf("%d", &n) != 1) return 1;

    comp[0] = comp[1] = 1;
    for (long long i = 2; i * i <= n; i++)
        if (!comp[i])
            for (long long j = i * i; j <= n; j += i)
                comp[j] = 1;

    int cnt = 0;
    for (int i = 2; i <= n; i++)
        if (!comp[i]) cnt++;

    printf("%d\n", cnt);
    return 0;
}
j = i * i에서 long long을 빼면 i가 int이고 N이 109에 가까우면 i * i가 int 범위를 넘어 음수가 된다. 그러면 안쪽 루프가 아예 돌지 않거나 엉뚱한 곳을 건드린다. 3장의 "조건식 안의 오버플로"가 여기서도 나온다.
습관 — i * i를 쓰는 모든 자리에서 i를 long long으로 선언한다. 비용은 0이다.

예제 3최대공약수를 여러 개로 확장

세 수 이상의 gcd와 lcm은 앞에서부터 두 개씩 접으면 된다.

코드
long long g = a[0], l = a[0];
for (int i = 1; i < n; i++) {
    g = gcd(g, a[i]);
    l = l / gcd(l, a[i]) * a[i];
}
검증: 12, 18, 24
gcd = 6
  gcd(12,18)=6, gcd(6,24)=6

lcm = 72
  lcm(12,18)=36, lcm(36,24)=72
lcm을 접을 때가 오버플로의 단골 l이 매번 커지므로 수가 몇 개만 되어도 금방 넘친다. 반드시 long long이고, 반드시 나누기를 먼저다. 문제가 "나머지를 출력하라"고 했다면 중간마다 나머지를 취해야 한다.
초기값에도 주의한다. 4장의 원리대로 gcd와 lcm의 초기값은 a[0]이다. gcd를 0으로 시작해도 gcd(0, x) = x라 우연히 맞지만, lcm을 0으로 시작하면 항상 0이 된다.

05 — 흔한 오류

흔한 오류 여섯 가지

1
i <= n으로 끝까지 돈다
정의 그대로라 맞는 답이 나오지만, N = 109에서 3.56초다. 작은 예제로는 전부 통과한다.
대책 i * i <= n으로 바꾸고 짝꿍 n/i를 함께 센다. 측정값은 0.0001초, 3만 배 차이다.
2
제곱수에서 약수를 두 번 센다
if (i != n/i)를 빠뜨리면 n = 36의 약수가 10개로 나온다(정답 9개). 제곱수가 아닌 입력에서는 전부 맞는다.
대책 제곱수를 반례로 넣는다 — 1, 4, 9, 16, 36, 100.
3
1을 소수로 판정한다
if (n < 2) return 0;이 없으면 n = 1에서 루프가 돌지 않고 return 1이 된다. 0에서도 마찬가지다.
대책 소수 문제의 표준 반례는 0, 1, 2. 셋을 반드시 넣어 본다.
4
소인수분해에서 마지막 if (n > 1)을 빠뜨린다
97이나 999999937처럼 소수를 입력하면 아무것도 출력되지 않는다. 합성수에서는 전부 맞는다.
대책 소수 자체를 반례로 넣는다. 그리고 if가 아니라 while로 나누는지 확인한다(12 = 2×2×3).
5
최소공배수를 a * b / g로 쓴다
a, b가 4 × 109급이면 a * b가 long long도 넘는다. 측정 결과 5553255926290448384라는 쓰레기 값이 나왔다.
대책 a / gcd(a,b) * b. g는 a의 약수이므로 나누어떨어진다는 것이 근거다.
6
i * i를 int로 계산한다
int i로 쓰고 N이 109 근처면 i * i가 음수가 되어 루프 조건이 깨진다. 작은 N에서는 멀쩡하다.
대책 i * i가 나오는 자리의 i는 항상 long long으로 선언한다. 또는 i <= n / i로 쓴다.
이 장의 가장 중요한 교훈 오류 2·3·4는 딱 한 종류의 입력에서만 틀린다 — 제곱수 / 0·1 / 소수. 공통점은 "특별한 수"라는 것이다.
수론 문제의 테스트 입력 목록은 항상 이렇게 시작한다 — 0, 1, 2, 제곱수 하나, 소수 하나, 제약의 최댓값. 여섯 개면 이 장의 오류가 거의 전부 걸린다.

정답과 해설

01
본문 count_divisors. 검증 — 1→1, 4→3, 9→3, 16→5, 36→9, 100→9, 49→3.
지도 포인트 — i * i <= n에서 i가 long long인지 확인시킨다. N이 1012이면 i가 106까지 가므로 i*i는 1012로 int를 넘는다. 오류 6번이 여기서 실제로 발생한다.
02
√N 루프는 약수를 작은 것과 큰 것이 번갈아 나온다. 오름차순으로 출력하려면 작은 쪽은 바로, 큰 쪽은 배열에 모았다가 역순으로 출력한다. 
long long big[100]; int bc = 0;
for (i = 1; i * i <= n; i++)
    if (n % i == 0) {
        printf("%lld ", i);
        if (i != n / i) big[bc++] = n / i;
    }
for (int k = bc - 1; k >= 0; k--) printf("%lld ", big[k]);
검증 — 100 → 1 2 4 5 10 20 25 50 100.
지도 포인트 — 약수의 개수는 아무리 많아도 작다. 1012 이하에서 최대는 963761198400 = 26·34·52·7·11·13·17·19·23 의 6,720개이므로 배열 크기 걱정은 없다. 참고로 106 이하의 최대는 720720의 240개다. 그리고 출력 순서가 역순이라는 점에서 "구하는 순서와 출력 순서가 다를 수 있다"를 배운다.
03
본문 is_prime. 검증 — 0→NO, 1→NO, 2→YES, 97→YES, 999999937→YES.
복잡도 — 100 × √(1012) = 100 × 106 = 108. 2장의 기준으로 통과한다.
지도 포인트 — M과 √N을 곱해서 판단하는 것이 2장 오류 2의 적용이다. M이 105였다면 1011로 불가능하고, 그때는 체로 바꿔야 한다(값의 범위가 작다면).
04
하나씩 판정하면 N × √N = 107 × 3,163 ≈ 3 × 1010으로 불가능하다. 체는 O(N log log N)으로 사실상 O(N)이다.
측정 — N = 106: 하나씩 0.2430초 / 체 0.0022초(111배). N = 107: 체 0.0335초로 664,579개.
지도 포인트 — 78,498이라는 숫자를 외우게 할 필요는 없지만, 자신의 코드가 이 값을 내는지로 검산할 수 있다는 것은 알려 준다. 체의 메모리는 char 배열로 107바이트 = 9.5MB다(2장).
05
본문 5.4절. while로 나누고 마지막에 if (n > 1).
검증 — 12 → 2 2 3 / 100 → 2 2 5 5 / 97 → 97 / 1024 → 2가 10개 / 30030 → 2 3 5 7 11 13 / 1 → 출력 없음.
지도 포인트 — N = 1이 숨은 경계다. 루프가 돌지 않고 n > 1도 거짓이라 아무것도 출력되지 않는데, 그것이 정답이다. 그리고 소인수의 개수는 아무리 많아도 log₂(1012) ≈ 40개를 넘지 않는다(전부 2일 때 최대).
06
gcd는 한 줄 재귀, lcm은 a / gcd(a,b) * b. 검증 — 24, 18 → gcd 6, lcm 72.
지도 포인트 — A, B가 109이면 lcm은 최대 1018이다. long long 범위(9.2 × 1018)에는 들어가지만 a*b를 먼저 하면 1018이라 아슬아슬하다. 나누기를 먼저 하면 걱정할 필요가 없어진다는 것이 요점이다.
07
1071 = 462 x 2 + 147
 462 = 147 x 3 +  21
 147 =  21 x 7 +   0
→ gcd = 21
지도 포인트 — 학생에게 세 줄의 숫자가 어떻게 이동하는지를 화살표로 그리게 한다. 나누는 수 → 다음 줄의 나뉘는 수, 나머지 → 다음 줄의 나누는 수. 이 이동을 손으로 그려 보면 a = b; b = t; 두 줄이 그림과 똑같다는 것을 알게 된다. 주문이 아니라 절차로 만드는 것이 목적이다.
08
count_divisors에서 c++를 s += i로 바꾼 것. 반환형은 반드시 long long.
검증 — 1→1, 6→12, 12→28, 28→56, 496→992.
지도 포인트 — N이 1012이면 약수의 합은 N 자신보다 크다(최소한 N + 1). 개수는 int로 충분한데 합은 아니라는 점에서 4장의 "집계마다 자료형이 다르다"가 그대로 적용된다.
09
측정 — O(N) 3.5612초 / O(√N) 0.0001초 → 약 31,500배.
지도 포인트 — 3만 배라는 숫자를 직접 보게 하는 것이 전부다. 2장에서 "알고리즘을 바꾸면 100배, 상수를 줄이면 4배"라고 했는데, 여기서는 3만 배다. 루프 범위를 줄이는 것은 상수 최적화가 아니라 복잡도를 O(N)에서 O(√N)으로 바꾼 것이다.
10
각 n에 대해 sum_divisors(n) - n == n을 검사한다. 1,000 이하 → 6, 28, 496.
복잡도 — N × √N = 104 × 100 = 106으로 여유롭다.
지도 포인트 — "자기 자신을 제외한"을 빠뜨리면 아무것도 출력되지 않는다(약수의 합이 자기 자신인 수는 1뿐이고, 1의 진약수 합은 0이다). 문제 문장의 "제외"를 코드로 옮겼는지가 채점 포인트다. 1장의 "문제를 끝까지 읽는다"가 여기서 쓰인다.
11
예제 3의 접기. 초기값은 a[0].
검증 — 12, 18, 24 → gcd 6, lcm 72.
지도 포인트 — lcm의 초기값을 0으로 두면 항상 0이 나온다(4장의 "곱의 초기값은 1" 과 같은 종류의 오류). gcd는 0으로 둬도 gcd(0, x) = x라 우연히 맞는데, 우연히 맞는 것과 근거가 있는 것은 다르다는 점을 짚는다.
12
체를 B까지 만든 뒤 A부터 B까지 훑어 !comp[i]인 것을 출력. 검증 — 20~30 → 23, 29.
지도 포인트 — A가 1인 경우가 경계다. comp[1] = 1을 설정하지 않으면 1이 소수로 출력된다. 체를 쓸 때도 0과 1을 먼저 지우는 두 줄을 빠뜨리지 않는지 확인한다. 오류 3번이 체 버전으로 나타난 것이다.
13
복잡도 — gcd 한 번이 O(log N)이고 N번 부르므로 O(N log N) = 105 × 17 ≈ 1.7 × 106. 여유롭게 통과한다.
검증 — n=12 → 4(1, 5, 7, 11). n=7 → 6, n=10 → 4, n=11 → 10.
지도 포인트 — 소수 p에 대해서는 답이 p−1이라는 규칙이 보인다(7→6, 11→10). 학생이 표를 보고 규칙을 발견하게 한 뒤, 소인수분해로 더 빠르게 구하는 방법(오일러 피 함수)이 있다는 것만 알려 준다. 지금은 O(N log N)으로 충분하다는 판단이 더 중요하다.
14
sqrt()는 double을 반환하므로 1018 근처에서 오차가 생긴다(3장의 실수 문제).
보정법 — long long r = (long long)sqrt((double)n); 로 구한 뒤 r-2부터 r+2까지 훑으며 k*k == n인 k가 있는지 확인한다.
long long r = (long long)sqrt((double)n);
for (long long k = (r > 2 ? r - 2 : 0); k <= r + 2; k++)
    if (k * k == n) return 1;
return 0;
지도 포인트 — 실수로 어림한 뒤 정수로 확인하는 패턴이다. 실수를 아예 안 쓸 수는 없지만, 실수의 결과를 믿지 않고 정수로 검산하면 안전하다. k*k가 1018을 넘을 수 있으므로 r+2까지만 보는 것도 중요하다.

지도 포인트 — 나머지는 뺄셈을 몰아서 한 것이라는 설명을 여기서 한다. 10^9 % 1은 "1을 10억 번 빼는 일"을 한 번에 끝낸 것이다. 2장에서 "나머지 연산은 덧셈보다 4배 비싸다"고 했지만, 4배를 내고 10억 배를 산다는 것이 이 문항의 교훈이다.

a = 4000000000, b = 6000000000, gcd = 2000000000.
a*b/g → a*b가 5553255926290448384(넘침) → 결과도 쓰레기.
a/g*b → 2 * 6000000000 = 12000000000 (정답).
LLONG_MAX = 9223372036854775807. 실제 a*b는 2.4 × 1019로 2.6배 초과다.
지도 포인트 — 검산을 시킨다 — lcm × gcd = a × b 여야 한다. 12000000000 × 2000000000 = 2.4 × 1019이고 a × b도 2.4 × 1019로 일치한다. 수학적 관계로 답을 검산하는 습관을 만든다.
17
복잡도 — 각 수마다 √n 루프면 N√N = 106 × 103 = 109로 위험하다.
성질 — 약수 개수가 홀수인 수는 제곱수뿐이다. 따라서 답은 ⌊√N⌋. N = 100이면 10.
증명 — 약수 i마다 짝꿍 n/i가 있으므로 약수는 쌍으로 묶인다. 짝이 없는 경우는 i == n/i, 즉 i² == n일 때뿐이고 이것은 n이 제곱수라는 뜻이다. 제곱수가 아니면 모든 약수가 쌍을 이루므로 개수가 짝수다.
지도 포인트 — 5.1절의 표에서 이미 보인 성질을 스스로 증명하게 하는 문항이다. 그리고 O(109)가 O(1)이 되었다는 점 — 수학적 성질 하나가 알고리즘을 완전히 없앴다. 이것이 수론 문제의 본질이다.
18
l = 1;로 시작해 l = l / gcd(l, i) * i;를 i = 1..N에 반복한다.
N = 40까지의 값을 출력해 보면 N = 43에서 처음 long long을 넘는다(실제로는 N ≤ 40 제약 안에서는 안전하다). N = 40일 때 lcm(1..40) ≈ 5.34 × 1015다.
지도 포인트 — 초기값이 1이라는 점(4장: 곱의 초기값). 그리고 "넘치는 지점을 직접 찾아보라"는 2장 12번 문항과 같은 실험 구조다. 제약의 40이라는 숫자가 어디서 나왔는지를 학생이 역산하게 만드는 것이 목적이다.
19
발상 — "각 수의 약수를 찾는다"를 뒤집어 "각 수가 누구의 약수인지"를 센다. 
for (int i = 1; i <= N; i++)
    for (int j = i; j <= N; j += i)
        d[j]++;          /* i는 j의 약수다 */
복잡도 — 안쪽 루프가 N/1 + N/2 + N/3 + … + N/N = N × (조화수) ≈ N ln N. N = 106이면 약 1.4 × 107로 여유롭다.
N = 106에서 가장 약수가 많은 수는 720,720이고 약수가 240개다.
지도 포인트 — 체와 완전히 같은 구조다. 체가 "배수를 지운다"였다면 여기는 "배수의 개수를 올린다". 관점을 뒤집으면 복잡도가 바뀐다는 것이 이 문항의 핵심이고, 7장 카운팅 배열과 PART 3의 여러 기법으로 이어진다.

⑴ 질의별 복잡도
질의즉석 계산Q = 105일 때 전체
1 (소수)O(√x) = 1,000108 — 위험
2 (약수 개수)O(√x) = 1,000108 — 위험
3 (gcd·lcm)O(log x) ≈ 202 × 106 — 여유
⑵ 미리 계산할 것 — 1번과 2번은 x ≤ 106이므로 미리 표로 만들어 둔다. 체로 소수 표를, 19번의 방법으로 약수 개수 표를 만들면 전처리 O(N log N) ≈ 1.4 × 107, 질의마다 O(1)이다. 3번은 호제법이 이미 빠르므로 즉석 계산한다.
메모리 — char comp[106+1] 1MB + int d[106+1] 4MB = 5MB. 256MB 안이고, 둘 다 전역에 둔다(2장).
⑶ 반례 목록 — 1 1(1은 소수가 아니다) / 1 2(유일한 짝수 소수) / 2 1(약수 1개) / 2 36(제곱수) / 3 1 1(gcd=lcm=1) / 3 1000000 1000000(같은 수) / x = 106(최댓값).
⑷ 전체 복잡도 — 전처리 1.4 × 107 + 질의 105 × O(1 또는 log) ≈ 1.6 × 107. 통과.
지도 포인트 — 이 문제의 핵심은 "질의마다 계산"에서 "미리 표를 만들고 찾아보기"로 바꾸는 것이다. 2장 도입의 누적합과 정확히 같은 발상이다 — 질문이 많으면 답을 미리 준비해 둔다. 그리고 세 질의의 복잡도가 다르므로 전부 미리 계산할 필요는 없다는 판단(3번은 즉석)도 짚어 준다.
08 — 마무리

이 장을 마치기 전 점검

  • 약수·소수 루프는 i * i <= n까지만 돈다
  • i * i가 나오는 자리의 i는 long long으로 선언한다
  • 약수를 짝으로 셀 때 if (i != n / i)를 넣는다
  • 소수 판정은 if (n < 2) return 0;으로 시작한다
  • 범위 전체의 소수가 필요하면 체로 바꾼다 (111배)
  • 소인수분해는 while로 나누고 if (n > 1)로 끝낸다
  • 최대공약수는 b ? gcd(b, a % b) : a 한 줄
  • 최소공배수는 a / gcd(a, b) * b — 나누기 먼저
  • 반례 여섯 개 — 0, 1, 2, 제곱수, 소수, 최댓값
