04

누적·집계형 문제

합·최댓값·최솟값·개수·평균. 코드는 세 줄이면 끝나는데 오답이 가장 많은 유형이다. 원인은 거의 하나다 — 초기값. 이 장은 집계의 뼈대를 네 가지로 정리하고, 초기값을 무엇으로 두어야 하는지를 반례로 결정하는 법을 다룬다.

학습 목표

  • 합·최대·최소·개수의 네 가지 뼈대를 외워서 쓸 수 있다
  • 각 집계의 초기값을 근거를 대며 결정할 수 있다
  • "입력에 없는 값이 답으로 나온다"는 증상에서 초기값 버그를 찾아낼 수 있다
  • 테스트케이스마다 누적 변수를 초기화해야 하는 이유를 설명할 수 있다
  • 나눗셈과 곱셈의 순서를 정하고 오버플로를 피할 수 있다
  • 평균의 버림·반올림을 정수 연산으로 구현할 수 있다

01 — 도입 문제

입력에 없는 숫자가 답으로 나온다

문제
N개의 정수가 주어진다.
가장 큰 값을 출력하라.

제약
1 ≤ N ≤ 100,000
-1,000,000,000 ≤ A[i] ≤ 1,000,000,000
거의 모든 학생이 쓰는 코드
int mx = 0;
for (int i = 0; i < n; i++) {
    scanf("%d", &x);
    if (x > mx) mx = x;
}
printf("%d\n", mx);

예제 입력 3 9 2 9 5를 넣으면 9가 나온다. 맞다. 그런데 이 입력을 넣어 보자.

입력
5
-5 -3 -9 -1 -7
실행 결과
mx = 0      으로 시작 → 0   ← 오답
mx = INT_MIN으로 시작 → -1
mx = a[0]   으로 시작 → -1
증상을 알아보는 법 출력된 0은 입력 어디에도 없는 숫자다. 다섯 개 모두 음수인데 답이 0이라는 것은, 프로그램이 한 번도 갱신하지 않았다는 뜻이다. 즉 초기값이 그대로 나온 것이다.
이 증상은 모든 집계 문제에서 똑같이 나타난다. "입력에 없는 값이 답으로 나오면 초기값을 의심한다" — 이 한 줄이 이 장의 핵심이다.

최솟값도 똑같다. mn = 0으로 시작하면 입력이 5 3 9 1 7일 때 답이 0이 된다. 모두 양수인데 0이 최솟값일 수는 없다.

그런데 왜 이 버그가 끝까지 살아남을까. 예제 입력에는 양수와 음수가 섞여 있기 때문이다. 문제에 적힌 예시로는 절대 걸리지 않고, 채점에서만 틀린다. 3장에서 본 구조와 같다 — 드물어서 안전한 것이 아니라 드물어서 못 찾는 것이다.

이 장이 답할 질문 ① 집계의 초기값은 무엇을 기준으로 정하는가?
② 테스트케이스가 여러 개일 때 무엇을 다시 0으로 돌려야 하는가?
③ 평균을 구할 때 나눗셈을 언제 하는가?
02 — 개념 정리

개념 정리

4.1집계는 네 가지뿐이다

브론즈 구간의 집계 문제는 아래 네 뼈대의 조합이다. 외워서 손이 먼저 움직이게 한다.

① 합 / ② 개수
long long sum = 0;
int cnt = 0;
for (i = 0; i < n; i++) {
    sum += a[i];
    if (조건) cnt++;
}
③ 최대 / ④ 최소
int mx = a[0];
int mn = a[0];
for (i = 1; i < n; i++) {   /* 1부터 */
    if (a[i] > mx) mx = a[i];
    if (a[i] < mn) mn = a[i];
}

왼쪽은 0부터, 오른쪽은 1부터 시작한다는 점에 주목한다. 최대·최소는 첫 값을 이미 써 버렸으므로 두 번째부터 돌면 된다. 0부터 돌아도 결과는 같지만(자기 자신과의 비교는 무해하다), 1부터 쓰는 것이 의도를 더 잘 드러낸다.

4.2초기값 결정표

이 표가 이 장의 핵심이다. 근거 열을 반드시 같이 외운다.

집계초기값근거0으로 두면 틀리는 입력
합0아무것도 더하지 않은 상태— (0이 맞다)
곱1아무것도 곱하지 않은 상태모든 입력 (답이 항상 0)
개수0아직 센 것이 없다— (0이 맞다)
최대a[0] 또는 INT_MIN어떤 입력보다 작아야 갱신된다모두 음수
최소a[0] 또는 INT_MAX어떤 입력보다 커야 갱신된다모두 양수
a[0]과 INT_MIN 중 무엇을 쓸까 a[0]을 권한다. 이유는 셋이다.
① <limits.h>를 포함할 필요가 없다.
② 값의 범위가 int보다 크거나(long long) 실수여도 그대로 통한다.
③ 답이 반드시 입력 안의 값이 된다. 입력에 없는 값이 나올 수가 없으므로 도입 문제의 버그 자체가 생기지 않는다.
단 a[0]을 쓰려면 값을 배열에 저장하거나 첫 값을 먼저 읽어 두어야 한다. 배열 없이 읽으면서 처리할 때는 INT_MIN/INT_MAX가 편하다.
INT_MIN을 쓸 때의 주의 값의 범위가 long long이면 INT_MIN으로는 부족하다. LLONG_MIN을 쓴다. 그리고 "충분히 작은 값"이라며 -1000000 같은 숫자를 임의로 쓰면, 제약이 109인 문제에서 바로 틀린다. 직접 고른 숫자 대신 a[0]이나 limits.h의 상수를 쓴다.

4.3개수를 셀 때의 초기값은 조건 쪽에 있다

개수의 초기값은 언제나 0이라 안전해 보이지만, "무엇을 세는가"의 기준에서 틀린다. 평균보다 큰 사람의 수를 세는 문제가 대표적이다.

실수로 쓰면
double avg = (double)sum / n;
for (i = 0; i < n; i++)
    if (a[i] > avg) cnt++;

← 3장에서 본 실수 비교
정수로 바꾸면
/* a[i] > sum/n  의 양변에 n */
for (i = 0; i < n; i++)
    if ((long long)a[i] * n > sum)
        cnt++;

← 나눗셈이 사라진다

검증 결과 — 50 50 70 80 100(합 350, 평균 70) → 초과 2명, 40.000%. 100 95 90 80 70 60(합 495, 평균 82.5) → 초과 3명, 50.000%.

4.4케이스마다 초기화한다

1장에서 다룬 내용이지만, 집계 문제에서는 증상이 훨씬 교묘하다. 테스트케이스 세 개를 주고 초기화를 빠뜨린 코드와 올바른 코드를 비교했다.

입력
3
3
1 2 3
2
10 20
3
-1 -2 -3
출력 (합, 최댓값)
초기화 빠뜨림 │ 올바름
──────────────┼──────────
   6  3       │   6  3    ← 같다
  36 20       │  30 20
  30 20       │  -6 -1
첫 케이스는 반드시 맞는다 이것이 이 버그가 발견되지 않는 이유다. 문제의 예제가 케이스 하나뿐이거나, 학생이 첫 줄만 보고 "맞네" 하면 끝이다.
세 번째 케이스를 보라. 입력이 모두 음수인데 합이 30, 최댓값이 20이다. 둘 다 이전 케이스의 값이다.
대책 — 누적 변수를 케이스 루프 안에서 선언한다. 선언하는 자리가 곧 초기화하는 자리다. 밖에 두면 "초기화를 잊었나"를 매번 확인해야 한다.

4.5합은 long long, 최대·최소는 원래 자료형

2장의 자릿수 계산이 그대로 적용된다. 다만 집계마다 결론이 다르다.

집계자료형이유
합long longN × (최댓값)만큼 커진다. 105 × 109 = 1014
곱long long도 모자랄 수 있다값이 몇 개만 곱해져도 넘친다. 문제가 나머지를 요구하는지 확인한다
개수int최대 N개. N ≤ 109이면 long long
최대·최소입력과 같은 자료형답이 입력 안의 값이므로 더 커지지 않는다
평균합을 long long으로나누기 전에 넘치면 끝이다

4.6나눗셈은 맨 마지막에, 그러나 올림한 뒤에

정답률을 백분율로 구하는 상황을 보자. 순서를 바꾸면 두 가지 서로 다른 오류가 난다.

나눗셈을 먼저 하면
correct = 17, total = 20

(correct / total) * 100
 = (17/20) * 100
 = 0 * 100
 = 0        ← 정보가 사라진다
곱셈을 먼저 하면
correct = 10^8, total = 3*10^8

correct * 100 (int)
 = 1410065408   ← 넘친다

(long long)correct * 100 / total
 = 33           ← 정답
결론 한 줄 "long long으로 올리고, 곱셈을 먼저, 나눗셈을 마지막에."
correct * 100 / total은 맞고 correct / total * 100은 틀린다. C는 왼쪽부터 계산하므로 쓰는 순서가 곧 계산 순서다. 그리고 곱셈 결과가 커지므로 long long 캐스팅을 맨 앞에 붙인다.

4.7평균: 버림과 반올림

C의 정수 나눗셈은 내림이 아니라 0 쪽으로 자른다. 음수에서 차이가 난다.

측정
 7 / 2 =  3      -7 / 2 = -3
 7 % 2 =  1      -7 % 2 = -1

내림이라면 -7/2 = -4 여야 한다.
C는 -3이다.
반올림 공식 (s ≥ 0 전용)
(2 * s + n) / (2 * n)

s=7 n=2 → 4    (3.5 → 4)
s=9 n=2 → 5    (4.5 → 5)
s=5 n=3 → 2    (1.667 → 2)
s=10 n=3 → 3   (3.333 → 3)
이 공식은 음수에서 틀린다 s = -7, n = 2일 때 수학적 반올림은 −4인데 공식은 −3을 준다. 합이 음수일 수 있는 문제에서는 쓰지 않는다.
안전한 방법 — 문제가 "소수점 아래 버림"인지 "반올림"인지 먼저 확인한다. 대부분의 브론즈 문제는 버림이거나 %.2f 같은 실수 출력이다. 반올림을 요구하면서 음수가 가능한 문제는 드물다.

4.8한 번 훑으며 여러 개를 동시에

합도 구하고 최댓값도 구해야 한다면 루프를 두 번 돌 필요가 없다. 같은 루프 안에서 전부 처리한다.

한 번 훑기합·최대·최소·조건 개수를 동시에
long long sum = 0;
int mx = a[0], mn = a[0], cnt = 0;

for (int i = 0; i < n; i++) {
    sum += a[i];
    if (a[i] > mx) mx = a[i];
    if (a[i] < mn) mn = a[i];
    if (a[i] % 2 == 0) cnt++;
}
두 번 훑어야 하는 경우도 있다 평균보다 큰 수의 개수처럼 먼저 전체를 알아야 세기 시작할 수 있는 것은 두 번 훑는다. 첫 번째 루프에서 합을, 두 번째 루프에서 개수를 센다. O(2N)이고 이것도 O(N)이다(2장).
판별 질문 — "이 값을 구하는 데 뒤에 올 입력이 필요한가?" 필요하면 두 번 훑는다.
03 — 표준 코드

표준 코드

aggregate.c집계 뼈대 — 배열에 저장하는 판
#include <stdio.h>

int a[100001];                 /* 큰 배열은 전역 (2장) */

int main(void) {
    int n;
    if (scanf("%d", &n) != 1) return 1;
    for (int i = 0; i < n; i++)
        if (scanf("%d", &a[i]) != 1) return 1;

    long long sum = 0;        /* 합은 long long */
    int mx = a[0], mn = a[0];  /* 최대·최소는 첫 값으로 */

    for (int i = 0; i < n; i++) {
        sum += a[i];
        if (a[i] > mx) mx = a[i];
        if (a[i] < mn) mn = a[i];
    }

    printf("%lld %d %d\n", sum, mx, mn);
    return 0;
}
stream.c집계 뼈대 — 배열 없이 읽으면서 처리하는 판
#include <stdio.h>

int main(void) {
    int n, x;
    if (scanf("%d", &n) != 1) return 1;

    if (scanf("%d", &x) != 1) return 1;   /* 첫 값을 먼저 읽는다 */
    long long sum = x;
    int mx = x, mn = x;                     /* 그 값으로 초기화 */

    for (int i = 1; i < n; i++) {           /* 1부터 n-1까지 */
        if (scanf("%d", &x) != 1) return 1;
        sum += x;
        if (x > mx) mx = x;
        if (x < mn) mn = x;
    }

    printf("%lld %d %d\n", sum, mx, mn);
    return 0;
}
어느 쪽을 쓸까 값을 두 번 이상 봐야 하면 배열(평균보다 큰 개수 세기, 정렬, 구간 합), 한 번만 보면 되면 스트림(합·최대·최소만). 스트림판은 메모리를 전혀 쓰지 않으므로 N이 107을 넘을 때 유용하다.
스트림판의 핵심은 첫 값을 루프 밖에서 읽는 것이다. 그 값이 곧 mx와 mn의 초기값이 된다. 루프가 i = 1부터인 이유다.
above_avg.c평균보다 큰 수의 비율 — 두 번 훑기
#include <stdio.h>

int a[1001];

int main(void) {
    int T;
    if (scanf("%d", &T) != 1) return 1;

    for (int t = 0; t < T; t++) {
        int n;
        if (scanf("%d", &n) != 1) return 1;

        long long sum = 0;              /* 케이스 안에서 선언 = 매번 초기화 */
        for (int i = 0; i < n; i++) {
            if (scanf("%d", &a[i]) != 1) return 1;
            sum += a[i];
        }

        int cnt = 0;                     /* 두 번째 훑기 */
        for (int i = 0; i < n; i++)
            if ((long long)a[i] * n > sum)  /* a[i] > sum/n 의 양변에 n */
                cnt++;

        printf("%.3f%%\n", cnt * 100.0 / n);
    }
    return 0;
}

검증 — 50 50 70 80 100 → 40.000%, 100 95 90 80 70 60 → 50.000%, 1 1 1 1 1 1 1 1 1 10 → 10.000%.

마지막 출력만 실수를 쓴다 비교는 전부 정수로 하고, 출력 한 줄에서만 100.0을 곱해 실수로 만든다. 중간 계산에 double이 끼어들지 않으므로 3장의 실수 비교 함정이 생기지 않는다.
cnt * 100.0 / n에서 100.0이 실수라 cnt가 실수로 승격되고, 그 다음 나눗셈도 실수 나눗셈이 된다. cnt * 100 / n으로 쓰면 정수 나눗셈이 되어 소수점이 사라진다.

단계 예제

예제 1초기값을 반례로 결정한다

초기값을 고를 때 "느낌"으로 정하지 않는다. 그 초기값이 그대로 출력되는 입력을 만들어 본다.

초기값 후보그대로 출력되는 입력판정
mx = 0모두 음수 — -5 -3 -9탈락
mx = -1000000모두 −106보다 작음 — -2000000000탈락
mx = INT_MIN없음 (int 입력이면)통과
mx = a[0]없음 (답이 항상 입력 안의 값)통과 · 권장

이 절차를 거치면 "충분히 작은 값"을 임의로 고르는 습관이 사라진다. 반례를 만들 수 없는 초기값만 쓴다.

예제 2최댓값과 함께 위치도 구하기

"가장 큰 값과 그것이 몇 번째인지"를 함께 묻는 문제가 많다. 같은 루프에서 처리한다.

코드
int mx = a[0], pos = 0;
for (int i = 1; i < n; i++)
    if (a[i] > mx) {
        mx = a[i];
        pos = i;        /* 같이 갱신 */
    }
printf("%d %d\n", mx, pos + 1);
검증: 3 9 2 9 5
최댓값 9
첫 위치 0-기준 1 → 1-기준 2
최댓값의 개수 2

> 를 쓰면 첫 번째 위치
>= 를 쓰면 마지막 위치
> 와 >= 가 답을 바꾼다 같은 최댓값이 여러 개일 때, >는 처음 나온 위치를, >=는 마지막 위치를 남긴다. 문제가 "가장 먼저 나오는 위치"를 묻는지 확인하고 부등호를 고른다. 3장의 경계 판단과 같은 종류다.

예제 3개수 세기는 배열로

"어떤 값이 몇 번 나왔는가"를 셀 때, 값의 범위가 좁으면 배열 하나로 끝난다.

자릿수별 개수
char s[] = "3141592653589793";
int c[10] = {0};

for (int i = 0; s[i]; i++)
    c[s[i] - '0']++;      /* 문자를 인덱스로 */
결과
0:0  1:2  2:1  3:3  4:1
5:3  6:1  7:1  8:1  9:3

합 = 16 (문자열 길이와 일치)

이 기법이 카운팅 배열이다. 값을 인덱스로 쓴다는 발상이 핵심이고, 7장에서 본격적으로 다룬다. 지금 기억할 것은 "세는 문제에서 if를 열 개 쓰고 있으면 배열을 의심한다"이다.

예제 4최빈값

카운팅 배열을 만든 뒤, 그 배열에서 다시 최댓값을 찾는다. 집계 위의 집계다.

코드
int cnt[101] = {0};
for (i = 0; i < n; i++) cnt[a[i]]++;

int best = -1, bc = 0;
for (int v = 0; v <= 100; v++)
    if (cnt[v] > bc) { bc = cnt[v]; best = v; }
검증: 1 3 3 5 5 5 7
cnt[1]=1 cnt[3]=2 cnt[5]=3 cnt[7]=1

→ 최빈값 5 (3번)

작은 값부터 보므로
동점이면 가장 작은 값이 남는다
여기서는 bc = 0 초기화가 안전하다 4.2절의 표와 모순처럼 보이지만 아니다. 개수는 음수가 될 수 없고, N ≥ 1이면 반드시 어떤 값의 개수가 1 이상이므로 반드시 갱신된다. 초기값의 안전성은 "답이 그보다 작을 수 있는가"로 판정한다. 표를 외우는 것이 아니라 판정 기준을 외운다.

예제 5최대 연속 부분합

"연속한 구간을 골라 합을 최대로"는 브론즈 후반에 자주 나온다. 집계 변수 두 개로 한 번에 푼다.

코드
long long cur = a[0], best = a[0];
for (int i = 1; i < n; i++) {
    cur = (a[i] > cur + a[i])
          ? a[i] : cur + a[i];
    if (cur > best) best = cur;
}
검증
-2 1 -3 4 -1 2 1 -5 4
  → 6   (4 -1 2 1)

-5 -3 -9 -1 -7  (모두 음수)
  → -1  (한 개만 고른다)
여기서도 best = 0이 함정이다 best = 0으로 시작하면 모두 음수인 입력에서 0이 나온다. 문제가 "적어도 하나는 골라야 한다"고 했다면 오답이다. 도입 문제와 똑같은 버그가 다른 옷을 입고 나온 것이다.
cur의 의미는 "i번째로 끝나는 구간 중 최대 합"이다. 직전까지의 합에 이어 붙일지, 여기서 새로 시작할지를 매번 고른다. 이 발상은 PART 3의 동적 계획법으로 이어진다.
05 — 흔한 오류

흔한 오류 여섯 가지

1
최댓값을 0으로 시작한다
모두 음수인 입력에서 0이 나온다. 최솟값을 0으로 시작하면 모두 양수인 입력에서 0이 나온다. 예제 입력에는 양수와 음수가 섞여 있어 걸리지 않는다.
대책 a[0]으로 초기화한다. 답이 반드시 입력 안의 값이 된다.
2
"충분히 작은 값"을 임의로 고른다
mx = -1000000으로 썼는데 제약이 109이면 틀린다. -999999999로 써도 입력이 -1000000000이면 틀린다.
대책 a[0]이나 <limits.h>의 INT_MIN/LLONG_MIN. 직접 고른 숫자는 쓰지 않는다.
3
케이스마다 초기화하지 않는다
누적 변수를 케이스 루프 밖에 선언하면 이전 케이스의 값이 남는다. 첫 케이스는 반드시 맞고 두 번째부터 틀린다.
대책 케이스 루프 안에서 선언한다. 선언하는 자리가 초기화하는 자리다.
4
합을 int로 받는다
N = 105, 값 ≤ 109이면 합은 1014다(2장). 최댓값은 int로 충분한데 합만 넘친다. 그래서 최댓값은 맞고 합만 이상한 출력이 나온다.
대책 합·곱·누적은 long long, 최대·최소는 입력과 같은 자료형.
5
나눗셈을 먼저 한다
(correct / total) * 100은 17/20 = 0이 되어 0을 출력한다. 반대로 곱셈을 먼저 하면서 long long을 안 붙이면 넘친다.
대책 long long으로 올리고, 곱셈 먼저, 나눗셈 마지막.
6
평균을 실수로 만들어 비교한다
a[i] > (double)sum/n은 3장에서 본 실수 비교다. 평균이 정확히 경계에 걸리는 입력에서만 틀린다.
대책 양변에 n을 곱해 (long long)a[i] * n > sum으로 쓴다. 실수는 마지막 출력에서만 쓴다.
이 장의 가장 중요한 교훈 여섯 가지 중 1·2·3번은 모두 초기값 문제이고, 증상도 같다 — 입력 어디에도 없는 값이 답으로 나온다. 출력을 보고 "이 숫자가 입력에 있었나?"를 묻는 것만으로 세 가지가 동시에 걸린다.
그리고 1·3번은 예제 입력으로는 반드시 통과한다. 직접 반례를 만들어야 한다 — 모두 음수 / 모두 양수 / 케이스 두 개 이상, 이 셋이 집계 문제의 표준 반례다.

07 — 확인 평가

정답과 해설

01
본문 aggregate.c와 동일. 채점 포인트 — sum이 long long인가, mx·mn이 a[0]으로 초기화되었는가, 출력 서식이 %lld %d %d인가.
지도 포인트 — 합만 long long이고 최대·최소는 int라는 점을 반드시 짚는다. "전부 long long으로 하면 되지 않나"는 맞는 말이지만, 왜 그래도 되는지를 설명할 수 있어야 한다 — 최댓값은 입력 안의 값이므로 입력 자료형을 넘지 않는다.
02
정답 — -25 -1 -9.
mx = 0판 — -25 0 -9. 최댓값만 0이 된다.
지도 포인트 — 출력된 0이 입력 다섯 개 어디에도 없다는 것을 손가락으로 짚어 확인시킨다. 이 장 전체가 이 한 장면에서 출발한다. 그리고 합과 최솟값은 멀쩡하다는 점 — 한 변수만 틀리면 다른 값이 맞아서 더 안 보인다.
03
int mx = a[0], pos = 0; for (i=1;i<n;i++) if (a[i] > mx) { mx = a[i]; pos = i; } 출력은 pos + 1.
검증 — 3 9 2 9 5 → 9 2.
지도 포인트 — >=로 쓰면 9 4가 나온다. 부등호 하나가 "처음"과 "마지막"을 가른다. 문제 문장에 "가장 먼저"가 있는지 다시 읽게 한다. 그리고 mx와 pos를 같은 if 안에서 갱신해야 한다는 점 — 따로 쓰면 어긋난다.
04
루프 한 번 안에 if 세 개. -4 0 3 -7 8 0 → 짝수 4개(−4, 0, 8, 0), 음수 2개, 0이 2개.
지도 포인트 — 0은 짝수다. 0 % 2 == 0이므로 자동으로 세어진다. 그리고 음수의 나머지는 C에서 음수이므로(4.7절) a[i] % 2 == 1로 홀수를 판정하면 음의 홀수를 놓친다. -7 % 2는 -1이다. 홀수는 a[i] % 2 != 0으로 쓴다.
05
버림 — sum / n. 합 5, n = 3이므로 1.
반올림 — (2*sum + n) / (2*n) = (10+3)/6 = 2.
두 결과가 다른 입력은 나머지가 n/2 이상일 때다. 예 — 1 2 2(합 5, n 3): 버림 1, 반올림 2.
지도 포인트 — 문제가 "버림"인지 "반올림"인지 명시하지 않은 경우가 실전에서 가장 위험하다. 예제 입출력을 보고 역산해 확인한다. 1장의 "입출력 명세를 먼저 읽는다"가 여기서 쓰인다.
06
int c[10] = {0}; for (i=0; s[i]; i++) c[s[i]-'0']++;
검증 — 3141592653589793 → 0 2 1 3 1 3 1 1 1 3. 합이 16으로 문자열 길이와 일치한다.
지도 포인트 — s[i] - '0'이 문자를 숫자로 바꾸는 관용구다(14장에서 다시 다룬다). 개수의 합이 입력 길이와 같은지 확인하는 것이 이런 문제의 자체 검산법이다. 하나라도 빠졌으면 합이 모자란다.
07
올바른 출력 — 6 3 / 30 20 / -6 -1.
초기화 빠뜨린 판 — 6 3 / 36 20 / 30 20.
첫 줄이 같다는 것이 핵심이다. 두 번째 줄의 36은 6+30, 세 번째 줄의 30은 36+(−6)이다. 최댓값 20도 두 번째 케이스의 값이 그대로 남았다.
지도 포인트 — 세 번째 케이스가 모두 음수인데 답이 양수라는 점에서 02번과 같은 증상을 보인다. "입력에 없는 값" 점검이 여기서도 통한다는 것을 연결시킨다.
08
카운팅 배열 cnt[101]을 만든 뒤 cnt에서 최댓값을 찾는다. v를 작은 값부터 보고 >(>=가 아니라)로 비교하면 동점 시 가장 작은 값이 남는다.
검증 — 1 3 3 5 5 5 7 → 5(3번).
지도 포인트 — 이 문제는 집계를 두 번 한다. 첫 번째는 개수 세기, 두 번째는 그 개수의 최댓값 찾기. 두 번째 집계의 초기값 bc = 0이 안전한 이유(개수는 음수가 될 수 없다)를 예제 4의 판정 기준으로 설명하게 한다.
09
본문 above_avg.c와 동일. 핵심은 (long long)a[i] * n > sum.
검증 — 40.000% / 50.000%. 추가로 1 1 1 1 1 1 1 1 1 10(n=10, 합 19) → 10.000%.
지도 포인트 — 캐스팅을 a[i]에 붙이는 이유를 묻는다. a[i] * n이 먼저 int로 계산된 뒤 long long이 되면 이미 늦다. 캐스팅은 곱하기 전에 붙인다. 109 × 105 = 1014이므로 실제로 넘친다.
10
printf("%lld\n", (long long)c * 100 / t); — 17, 20 → 85.
(c/t)*100판 — 17/20 = 0이므로 0. 정수 나눗셈이 소수를 버려 정보가 사라진 뒤 100을 곱하므로 복구되지 않는다.
long long 없이 c*100만 쓰면 — c = 108에서 1410065408로 넘친다.
지도 포인트 — 두 오류가 정반대 방향이라는 점이 이 문제의 요령이다. 나눗셈을 먼저 하면 정보가 사라지고, 곱셈을 먼저 하면 넘친다. 해법은 하나 — long long으로 올린 뒤 곱셈 먼저.
11
예제 5의 코드. cur과 best 모두 a[0]으로 초기화하고 i = 1부터 돈다.
검증 — -2 1 -3 4 -1 2 1 -5 4 → 6(4 −1 2 1). -5 -3 -9 -1 -7 → −1.
지도 포인트 — best = 0으로 시작하면 두 번째 입력에서 0이 나온다. 도입 문제와 완전히 같은 버그다. 모양만 다를 뿐 "입력에 없는 값"이 나온다는 증상까지 같다는 것을 학생이 스스로 말하게 한다. 합이 105 × 109 = 1014까지 가므로 long long도 필요하다.
12
누적합 p[i] = p[i-1] + a[i]를 만든 뒤, 구간 합은 p[r] - p[l-1], 개수는 r - l + 1, 평균은 합 / 개수.
검증 — [2,4] 합 90, 개수 3, 평균 30. [1,5] 합 150, 개수 5, 평균 30.
지도 포인트 — 개수를 r - l + 1로 세는 것이 경계 실수의 단골이다. l = r이면 1개여야 한다. 그리고 2장에서 만든 누적합이 여기서 평균의 분자가 된다 — 도구가 쌓여 간다는 것을 보여 주는 문제다.
13
int m1 = a[0], m2 = INT_MAX;          /* m1 ≤ m2 */
for (i = 1; i < n; i++) {
    if (a[i] < m1) { m2 = m1; m1 = a[i]; }   /* 밀어낸다 */
    else if (a[i] < m2) m2 = a[i];
}
검증 — 7 3 9 3 5 → 3 3. 중복을 허용하므로 <=가 아니라 <와 else if 조합으로 충분하다.
지도 포인트 — 가장 작은 값이 갱신될 때 이전 1등을 2등으로 밀어내는 두 줄이 핵심이다. 순서를 바꿔 m1 = a[i]를 먼저 쓰면 이전 값이 사라진다. 3장의 "조건의 순서"가 대입문의 순서로 나타난 경우다.
14
mx = a[0]로 시작해 매 반복에서 갱신한 뒤 출력. 첫 값은 자기 자신이 최댓값이다.
검증 — 3 9 2 9 5 → 3 9 9 9 9.
지도 포인트 — 출력 형식이 공백 구분 한 줄이므로 1장의 관용구를 쓴다 — if (i > 0) printf(" "); printf("%d", mx); 뒤에 마지막 printf("\n"). 끝에 공백이 붙지 않게 하는 것이 포인트다.
15
long long prod = 1;로 시작. 2 3 4 5 → 120.
prod = 0으로 두면 — 어떤 입력에서도 0이 나온다. 0에 무엇을 곱해도 0이기 때문이다.
지도 포인트 — 합의 초기값 0과 곱의 초기값 1은 같은 원리다 — "아무것도 처리하지 않은 상태"의 값이다. 더하기에서 그 값은 0이고 곱하기에서는 1이다. 이 원리를 알면 외울 것이 없다. 값이 최대 10이고 N ≤ 18이므로 곱은 최대 1018이다. LLONG_MAX는 약 9.2 × 1018이므로 간신히 안전하다 — 제약의 18이라는 숫자가 여기서 나온 것이다.
16
7/2 = 3, -7/2 = -3, 7%2 = 1, -7%2 = -1.
내림이라면 -7/2는 −4여야 한다. C는 0 방향 절삭이다.
평균에 미치는 영향 — 합이 음수일 때 "버림한 평균"이 수학적 내림과 달라진다. 합 −7, n = 2면 C는 −3, 내림은 −4다.
지도 포인트 — 대부분의 브론즈 문제는 값이 0 이상이라 이 차이가 드러나지 않는다. 그래서 제약에 음수가 있는지 확인하는 습관이 중요하다. 음수가 가능하면 "버림"의 정의를 문제에서 다시 확인한다.
17
s = 0..100, n = 1..10의 1,010쌍 전부에서 공식과 lround가 일치한다(불일치 0쌍).
음수로 넓히면 어긋난다 — s = -7, n = 2: lround(-3.5) = -4, 공식 −3. s = -5, n = 3: lround(-1.667) = -2, 공식 −1.
지도 포인트 — 공식이 "반올림"하는 방향은 +∞ 쪽이고, lround는 0에서 먼 쪽이다. 양수에서는 둘이 같지만 음수에서 갈린다. 공식을 외우기 전에 적용 범위를 외운다는 것이 이 문항의 목적이다. 그리고 3장에서 배운 전수 비교가 여기서도 검증 도구로 쓰인다.
18
int g = s / 10; if (g == 10) g = 9; 또는 int g = (s == 100) ? 9 : s / 10;
검증 — 100 95 90 85 0 → 0번 구간 1개, 8번 구간 1개, 9번 구간 3개(100·95·90).
지도 포인트 — 나눗셈으로 구간 번호를 만드는 것이 이 문항의 기법이다. if 열 개가 한 줄이 된다(3장 예제 4의 "분기 대신 배열"의 변형). 그리고 100이 s/10 = 10이 되어 배열 범위를 벗어나는 것이 유일한 경계다 — 이것을 못 보면 런타임 에러가 난다.
19
⑴ 한 번 — 둘 다 지금까지의 값만으로 갱신된다.
⑵ 두 번 — 평균을 알려면 전체 합이 필요하다.
⑶ 한 번 — 13번처럼 변수 두 개로 밀어내면 된다.
⑷ 한 번 — 두 번이 필요해 보이지만, "최댓값이 갱신되면 개수를 1로 되돌리고, 같은 값이면 +1"로 처리하면 한 번에 된다.
⑸ 한 번 — 최솟값을 먼저 알아야 할 것 같지만, 구하는 값이 합 − 최솟값 × N이므로 합과 최솟값만 모으면 된다.
지도 포인트 — ⑷와 ⑸처럼 "두 번이 필요해 보이지만 식을 바꾸면 한 번"인 경우가 있다는 것이 이 문항의 핵심이다. 판별 질문("뒤에 올 입력이 필요한가")은 출발점이고, 그다음 식을 변형할 수 있는지를 한 번 더 묻는다. ⑸의 변형은 2장의 "나눗셈을 곱셈으로"와 같은 종류의 사고다.

⑶ 표준 반례 — ① 모두 음수(-1 -2 -3) ② 모두 양수 ③ 케이스 두 개 이상. 추가로 N = 1(평균초과개수가 0이 된다)과 모든 값이 같은 경우(역시 0).
⑷ 복잡도 — T × N = 100 × 105 = 107. 2장의 표로 O(T·N)은 여유롭게 통과.
⑸ 샘플 검산 — 3 9 2 9 5: 합 28, 평균 5.6, 초과는 9와 9 → 2. -1 -2 -3: 합 −6, 평균 −2, 초과는 −1 → 1.
지도 포인트 — 두 번째 케이스가 이 문제의 전부다. 모두 음수이고, 최댓값이 -1이며, 평균이 -2이고, 평균을 초과하는 수가 있다. mx = 0·cnt 초기화 누락·실수 비교 중 하나라도 어기면 여기서 틀린다. 이 장의 모든 오류가 한 줄의 입력에 모여 있다.
08 — 마무리

이 장을 마치기 전 점검

  • 최대·최소의 초기값은 a[0]로 둔다
  • "충분히 작은 값"을 직접 고르지 않는다
  • 합·곱은 long long, 최대·최소는 입력과 같은 자료형
  • 곱의 초기값은 1이다 (아무것도 곱하지 않은 상태)
  • 누적 변수는 케이스 루프 안에서 선언한다
  • 곱셈 먼저, 나눗셈 마지막, 캐스팅은 곱하기 전에
  • 평균 비교는 양변에 n을 곱해 정수로 한다
  • 출력된 값이 입력에 없는 숫자이면 초기값을 의심한다
  • 표준 반례 — 모두 음수 / 모두 양수 / 케이스 두 개
다음 장 예고 — 05장 약수·배수·소수와 유클리드 호제법 여기까지는 입력을 그대로 모으는 문제였다. 다음은 수 자체의 성질을 묻는다. 약수를 구할 때 왜 √N까지만 돌면 되는지, 소수 판정을 왜 2부터 하나씩 나누면 안 되는지를 2장의 복잡도 표로 계산해 결정한다. 최대공약수는 반복문 대신 세 줄짜리 호제법으로 끝난다.
