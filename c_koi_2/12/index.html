03 — 점검표

제출 전 2분 점검

코드를 다 쓴 뒤 제출 버튼을 누르기 전에 이 열두 줄을 읽는다. 2분이면 끝나고, 오답의 절반을 잡는다.

읽기 전에 (30초)
□ 예시 입력을 그대로 넣어
  예시 출력과 글자 단위로 같은가
  ($ ./a < in.txt | diff - out.txt)

□ 출력 줄 수가 예시와 같은가

□ 안내문·디버그 출력이 남아 있지 않은가
  (stderr로 보냈는가)
자료형 (30초)
□ 답의 최댓값이 10자리를 넘는가
  → long long

□ 중간 계산(합·곱·조건식)도 세었는가

□ long long 을 %lld 로 출력하는가

□ 실수 비교가 남아 있지 않은가
경계 (30초)
□ N = 1 을 넣어 봤는가

□ 값이 제약의 양 끝일 때 맞는가

□ 모두 음수 / 모두 같은 값은?

□ 최대·최소의 초기값이 a[0]인가

□ 배열 크기에 여유가 있는가 (+1, +2)
복잡도 (30초)
□ 제약을 전부 곱해 봤는가 (T × N)

□ 2장의 표에서 통과 구간인가

□ 최악의 입력을 만들어 time으로 쟀는가

□ 큰 배열이 함수 밖에 있는가
시험장에서 쓰는 순서 ① 문제를 받으면 입출력 명세 → 제약 → 조건 순으로 읽는다(1장).
② 종이에 체크리스트 일곱 줄을 적는다 — 입력 유형 / 한 케이스 / 출력 형식 / 범위 / 최악의 값 / 복잡도 / 경계 입력.
③ 코드를 쓴다.
④ 예시로 diff를 돌린다.
⑤ 위 열두 줄 점검.
⑥ 제출.
②를 건너뛰면 ⑤에서 걸리는 것이 많아지고, ⑤를 건너뛰면 채점에서 걸린다. 앞쪽에 쓰는 시간이 가장 싸다.

06 — 해설

모의고사 해설

각 문항이 어느 장의 어느 함정을 묻는지 표시했다. 틀렸다면 그 장으로 돌아간다.

A1
묻는 것 — 04장(집계 네 뼈대·초기값), 02장(자료형), 01장(케이스별 초기화)
핵심 세 가지
① 합은 105 × 109 = 1014이므로 long long, 출력은 %lld.
② 최대·최소의 초기값은 a[0]. 0으로 두면 둘째 케이스(모두 음수)에서 최댓값이 0으로 나온다.
③ 평균 초과는 (long long)a[i] * n > sum으로 정수 비교. 실수로 하면 경계에서 틀린다.
반례 — 둘째 케이스가 모두 음수, 셋째가 N = 1(평균 초과 개수가 0).
틀렸다면 → 4장 오류 1·4·6, 2장 오류 3·4.
A2
묻는 것 — 03장(경계·실수 금지), 02장(오버플로)
핵심 — "W ÷ U ≥ 2.5"를 양변에 2U를 곱해 2*W >= 5*U로 바꾼다. U가 109이므로 5*U는 5 × 109으로 int를 넘는다 → long long.
기본료 체인은 오름차순 <=로 쓰면 조건이 하나씩만 필요하다. 마지막은 else로 닫는다.
경계 검증 — U=100 W=250은 정확히 2.5라 할증(1000 × 1.5 = 1500). U=100 W=249는 할증 없음. U=100/101/300/301이 기본료 경계.
틀렸다면 → 3장 오류 2·3·5·6, 2장 오류 3.
A3
묻는 것 — 05장(약수), 02장(복잡도 판단)
핵심 — 각 수마다 √N 루프를 돌면 106 × 103 = 109으로 측정상 2.549초, 시간 초과다.
5장 19번의 약수 개수 체를 쓴다 — for (i=1..R) for (j=i; j<=R; j+=i) d[j]++; 복잡도 O(R ln R) ≈ 1.4 × 107, 측정 0.030초. 85배 차이다.
검산 — L=1, R=100, K=2면 소수의 개수 25, 가장 작은 수 2. K=3이면 소수의 제곱(4, 9, 25, 49) 4개. K=1이면 1뿐.
틀렸다면 → 5장 오류 1, 2장 오류 1·2. "약수 개수"를 보고 √N만 떠올렸다면 5장 19번을 다시 읽는다.
A4
묻는 것 — 09장(델타·경계 검사), 04장(연속 길이 집계)
핵심 세 가지
① 8방향 델타 16개를 검산한다(합이 0 / 3×3을 덮는가).
② 경계 검사 한 줄을 모든 이웃 탐색에 붙인다. 안 붙이면 격자 밖에서 0이 나와 조용히 틀린다.
③ 연속 길이는 run 변수를 쓰되 지뢰 칸에서도 끊어야 한다.
반례 — 1×1(답 0, 1), 1×5 지뢰 없음(답 0, 5), 2×2 전부 지뢰(답 0, 0).
틀렸다면 → 9장 오류 1·2·3, 4장 오류 1.
A5
묻는 것 — 11장(비교 함수·다중 기준·중복 제거)
핵심 — V가 ±2 × 109이므로 뺄셈 비교를 쓰면 정렬이 깨진다. (a>b) - (a<b)를 쓰고, V는 long long으로 받는다.
기준 네 개를 표로 먼저 그린다 — 무게 내림 / 값 오름 / 이름 사전순 / 입력 순. 방향이 번갈아 나오므로 표 없이 쓰면 반드시 헷갈린다.
서로 다른 V의 개수는 복사본을 따로 정렬해 구한다(원본을 날리면 안 된다).
검산 — 샘플에서 무게 3인 셋 중 beta(−2×109)가 먼저, alpha·delta는 값이 같아 이름순. 서로 다른 V는 −2×109, 5, 2×109로 3개.
틀렸다면 → 11장 오류 1·3·5.
A6
묻는 것 — 02장(누적합), 04장(버림 평균)
핵심 — 질의마다 더하면 Q × N = 1011로 불가능. 누적합으로 질의당 O(1)이 된다.
합의 최댓값이 106 × 109 = 1015이므로 p는 long long.
연속 K개의 합도 같은 누적합으로 p[i] - p[i-K] 한 줄이다. 최댓값의 초기값은 p[K](첫 구간).
측정 — N=K=106, 전부 109인 최악 입력에서 0.104초, 답은 1015.
틀렸다면 → 2장 도입, 4장 오류 4.
B1
묻는 것 — 01장(입력 유형 ④의 변형), 02장(자료형)
핵심 — 종료 조건이 둘이다 — 0 0이거나 EOF. while (scanf("%lld %lld", &a, &b) == 2) { if (a==0 && b==0) break; ... }로 둘 다 처리된다.
A + B가 4 × 109까지 가므로 long long이고 출력은 %lld다.
반례 — 0 0 뒤에 줄이 더 있어도 처리하지 않는다. 0 0이 아예 없으면 EOF까지.
틀렸다면 → 1장 오류 1, 2장 오류 3·4.
B2
묻는 것 — 06장 전부
핵심 네 가지
① N = 0 — 자릿수 개수가 1, B진법 표기가 "0"이어야 한다. while (n)이 안 돌기 때문에 둘 다 따로 처리한다.
② 음수 — 부호를 먼저 뗀다. long long으로 받아야 n = -n이 안전하다.
③ 역순 수 — 1000000003 → 3000000001로 int를 넘는다.
④ B ≥ 11 — 10 이상의 자릿수를 'A' + d - 10으로. -123의 16진법은 7B다.
버퍼는 80칸(1018의 2진법이 60자리).
틀렸다면 → 6장 오류 1·2·3·4·5.
B3
묻는 것 — 08장 전부
핵심 네 가지
① scanf("%d", &T) 뒤에 남은 개행을 비운다. 안 그러면 첫 줄이 빈 줄로 읽혀 전부 어긋난다.
② fgets로 읽고 개행을 제거한다. 배열은 105 + 2.
③ 단어 수는 in 상태 변수로. 앞뒤·연속 공백이 있어도 맞아야 한다.
④ 최빈 알파벳의 동점 처리와 mx > 0 검사. 샘플의 Mississippi가 동점(i와 s가 4번씩)이고, 123 !은 알파벳이 없어 -다.
틀렸다면 → 8장 오류 1·2·3.
B4
묻는 것 — 07장(카운팅 배열·초기화 비용), 02장(T × V)
핵심 — 값이 −106~106이므로 오프셋 106, 배열 크기 2,000,001(+1을 빠뜨리면 양 끝에서 터진다).
케이스마다 memset하면 T × V = 105 × 2 × 106 = 2 × 1011로 확실한 시간 초과다. n ≤ 10이므로 쓴 자리만 되돌린다 — 측정 0.233초.
두 수의 합은 n ≤ 10이라 이중 루프(최대 45쌍)로 충분하다. "서로 다른 두 개"이므로 j = i+1부터.
반례 — n = 1(합 불가), 모두 같은 값, K가 범위 밖.
틀렸다면 → 7장 오류 3·4·5, 2장 오류 2.
B5
묻는 것 — 10장(완전탐색·가지치기)
핵심 — N = 30이면 230으로 측정 5.772초, 시간 초과다. 값이 모두 양수이므로 if (s > S) return;이 유효하고, 같은 입력에서 0.002초가 된다.
"하나 이상"이라는 조건 때문에 고른 개수를 같이 들고 다닌다. 빈 집합을 세면 S = 0일 때만 틀리지만, ⑵에서는 항상 틀린다(아무것도 안 고르면 합이 0).
검산 — N=30, S=20, 값 1..30에서 답이 64이고, 가지치기 유무에 관계없이 같다. 호출 수는 21억 → 15,303.
틀렸다면 → 10장 오류 3·6, 2장 오류 1.
B6
묻는 것 — 09장(델타·회전·경계), 07장(방문 배열)
핵심 네 가지
① 방향이 0=상, 1=우, 2=하, 3=좌로 시계 방향이므로 본문의 델타를 그대로 쓴다.
② 왼쪽 회전은 (d+3)%4. (d-1)%4로 쓰면 d=0에서 −1이 되어 격자 밖을 읽는다.
③ 전진을 "무시"해야 하므로 패딩을 쓸 수 없다 — 밖인지 알아야 하기 때문이다.
④ 지나간 칸은 방문 배열로 중복을 거른다(7장의 체크 배열이 2차원으로). 점수 합도 처음 방문할 때만 더한다.
검산 — 3×3에서 (0,0),(0,1),(0,2),(1,2),(2,2) 다섯 칸, 합 1+2+3+6+9 = 21, 최종 2 2 1. 1×1이면 1칸·시작 점수·방향 유지. 회전 명령만 있으면 1칸.
틀렸다면 → 9장 오류 1·4, 7장 오류 1.
07 — 자가 진단

채점과 다음 단계

점수판정다음에 할 일
11~12브론즈 완성PART 3(실버)으로 진급. 90분에 여유가 있었다면 더 그렇다
9~10거의 완성틀린 문항의 해당 장만 다시 보고 그 장의 연습 20문항을 재점검
6~8도구는 있으나 점검이 부족제출 전 2분 점검을 몸에 붙인다. 오답 지도에서 자신의 묶음을 찾는다
3~5도구가 손에 안 붙었다각 장의 표준 코드를 손으로 베껴 쓴다. 특히 2·4·7·9·11장
0~2처음부터1장부터 다시. 단, 연습 문제를 먼저 풀고 막힐 때 본문을 본다
점수보다 중요한 것 — 틀린 이유의 분포 틀린 문항마다 오답 지도의 번호를 적어 본다. 그리고 02절의 네 묶음 중 어디에 몰려 있는지 센다.
① 자료형과 범위에 몰려 있다면 — 코드를 쓰기 전에 최악의 값을 종이에 계산하는 절차가 빠진 것이다. 1장 체크리스트 5번.
② 초기값과 경계에 몰려 있다면 — 반례 목록을 먼저 적는 습관이 없는 것이다. 각 장의 "표준 반례"를 외운다.
③ 형식과 순서에 몰려 있다면 — diff로 예시를 비교하지 않은 것이다. 1장으로 돌아간다.
④ 복잡도 판단에 몰려 있다면 — 2장의 표를 외우지 않은 것이다. 여섯 줄짜리 표다.
여섯 문제를 틀렸는데 원인이 전부 다르면 고칠 것이 여섯 개지만, 한 묶음에 몰려 있으면 고칠 것은 하나다. 대개 후자다.

08 — 마무리

PART 2를 마치며

  • 문제를 받으면 명세 → 제약 → 조건 순으로 읽는다
  • 코드를 쓰기 전에 체크리스트 일곱 줄을 종이에 적는다
  • 제약을 곱해서 복잡도를 계산한다
  • 답의 최댓값이 10자리를 넘으면 long long
  • 최대·최소의 초기값은 a[0]
  • 경계·반례를 먼저 적고 코드를 쓴다
  • 예시 입출력을 diff로 비교한다
  • 최악의 입력을 직접 만들어 시간을 잰다
  • 제출 전 2분 점검 열두 줄을 읽는다
  • 틀리면 오답 지도에서 번호를 찾아 공책에 적는다
PART 2의 한 줄 열두 장에서 반복된 말은 하나였다 — "출력이 나왔다는 것은 아무것도 보장하지 않는다."
1장의 T 오독, 3장의 윤년 순서, 4장의 초기값 0, 5장의 제곱수, 6장의 n = 0, 7장의 배열 밖, 9장의 격자 밖, 11장의 뺄셈 비교 — 전부 프로그램이 멀쩡히 끝나고 그럴듯한 답을 내는 오류였다. 그래서 PART 2는 도구를 늘리는 책인 동시에 검산 도구를 늘리는 책이었다.
PART 3에서 다루는 알고리즘은 훨씬 강력하지만, 그것을 맞게 쓰는 힘은 여기서 만들어진다.
