07

배열 카운팅과 체크 배열

4장에서 자릿수를, 5장에서 소수를 배열에 담아 세었다. 그 기법에 이름을 붙일 때가 되었다. 값을 인덱스로 쓴다는 한 줄의 발상이 O(N²)를 O(N)으로 바꾼다. 2장 예제 2에서 미뤄 둔 문제가 여기서 풀린다.

학습 목표

  • 값을 인덱스로 쓰는 발상을 설명하고 세 가지 용도로 구분할 수 있다
  • 체크 배열을 쓸 수 있는 조건(값의 범위)을 메모리로 계산할 수 있다
  • 음수가 포함된 값에 오프셋을 적용할 수 있다
  • 테스트케이스마다 전체를 지우면 안 되는 이유를 측정으로 설명할 수 있다
  • 카운팅 정렬을 작성하고 언제 qsort보다 유리한지 판단할 수 있다
  • 체크 배열이 안 되는 경우를 알아보고 다른 방법을 찾을 수 있다

01 — 도입 문제

이중 루프를 지우는 한 줄

문제
N개의 정수 중에서 두 개를 골라
합이 K가 되게 할 수 있는가?

제약
2 ≤ N ≤ 200,000
1 ≤ A[i] ≤ 1,000,000
시간 제한 1초
자연스러운 풀이
for (i = 0; i < n; i++)
    for (j = i+1; j < n; j++)
        if (a[i] + a[j] == K)
            found = 1;

→ 2 × 10^10 번
→ 2장의 표로 불가능

2장에서 N ≤ 200,000이면 O(N²)는 불가능하다고 판정했다. 그런데 어떻게 줄일 것인가. "짝꿍이 이미 지나갔는지"만 알면 된다는 것이 열쇠다.

체크 배열 풀이
char seen[1000001] = {0};

for (i = 0; i < n; i++) {
    int need = K - a[i];
    if (1 <= need && need <= 1000000
        && seen[need]) { found = 1; break; }
    seen[a[i]] = 1;        /* 지나갔다고 표시 */
}
측정 (N = 200,000)
O(N²)   8.450초    ← 시간 초과
O(N)    0.00082초

배수 = 10,267배
한 줄의 발상 seen[a[i]] = 1; — 값 a[i]를 배열의 인덱스로 썼다. 그 순간 "이 값이 있었나?"라는 질문이 배열 한 칸 읽기가 된다. 찾기 위해 훑을 필요가 없어진다.
안쪽 루프가 사라졌으므로 O(N²)가 O(N)이 되었다. 대가는 메모리 1MB다. 5장에서 "수학적 성질이 알고리즘을 없앴다"면, 여기서는 메모리가 시간을 샀다.
이 장이 답할 질문 ① 값을 인덱스로 쓰는 기법은 어디까지 쓸 수 있는가?
② 음수가 있거나 값이 10억까지 가면?
③ 테스트케이스마다 배열을 어떻게 지우는가?
02 — 개념 정리

개념 정리

7.1세 가지 용도

값을 인덱스로 쓰는 배열은 무엇을 저장하느냐에 따라 셋으로 나뉜다. 이름과 자료형이 다르다.

이름저장하는 것자료형대표 질문
체크 배열있었나 (0/1)char"이 값이 나온 적 있나?"
카운팅 배열몇 번 나왔나int"이 값이 몇 번 나왔나?"
위치 배열어디서 나왔나int (−1로 초기화)"이 값이 몇 번째에 있나?"
세 가지를 한눈에
/* 체크 */
seen[a[i]] = 1;

/* 카운팅 */
cnt[a[i]]++;

/* 위치 (처음 나온 자리) */
if (pos[a[i]] == -1) pos[a[i]] = i;
읽을 때
if (seen[x])      /* 있나? */
cnt[x]            /* 몇 개? */
pos[x]            /* 어디? */

모두 O(1) — 훑지 않는다
char를 쓰는 이유 0 또는 1만 저장한다면 int(4바이트) 대신 char(1바이트)로 충분하다. 메모리가 4분의 1이 된다. 범위가 106이면 4MB가 1MB가 되고, 108이면 400MB가 100MB가 되어 통과 여부가 갈린다.
5장의 에라토스테네스의 체도 char comp[]를 썼다. 같은 이유다.

7.2쓸 수 있는 조건은 값의 범위다

이 기법의 비용은 N(개수)이 아니라 V(값의 범위)다. N이 10개여도 값이 10억까지 갈 수 있으면 배열은 10억 칸이 필요하다.

값의 범위 Vchar 배열int 배열판정 (256MB)
1,0000.001MB0.004MB여유
1,000,0001.0MB3.8MB여유
2,000,001 (음수 포함)1.9MB7.6MB여유
100,000,00095.4MB381.5MBchar만 가능
1,000,000,000953.7MB3,814.7MB둘 다 불가
판단 순서 ① 제약에서 값의 범위를 찾는다 (N이 아니다).
② char로 몇 MB인지 계산한다.
③ 메모리 제한 안이면 체크 배열, 아니면 다른 방법(정렬 + 이분 탐색 — 11장).
브론즈 문제에서 "값 ≤ 1,000,000"이라고 적혀 있으면 출제자가 카운팅 배열을 쓰라고 말하는 것이다. 2장의 "제약은 힌트다"가 여기서도 통한다.

7.3음수는 오프셋으로 민다

배열 인덱스는 음수가 될 수 없다. 값의 범위가 −106 ~ 106이면 전부 106만큼 밀어서 0 ~ 2×106으로 만든다.

선언과 사용
#define OFF 1000000
#define SZ  2000001

int cnt[SZ];              /* 전역 */

cnt[a[i] + OFF]++;        /* 쓸 때 */
... cnt[x + OFF] ...      /* 읽을 때 */
검증
값 −10^6 → 인덱스 0
값      0 → 인덱스 10^6
값  10^6 → 인덱스 2×10^6

크기 2,000,001칸
int면 7.6MB
크기는 2*OFF + 1이다 −106부터 106까지는 0을 포함해서 2,000,001개다. 2000000으로 선언하면 맨 끝 값에서 배열 범위를 벗어난다. +1을 빠뜨리는 것이 이 기법의 단골 실수다.
OFF와 SZ를 #define으로 한 번만 쓰면 둘이 어긋나는 일이 없다.

7.4초기화 — 이 장에서 가장 비싼 실수

테스트케이스가 여러 개면 케이스마다 배열을 지워야 한다. 그런데 어떻게 지우느냐로 통과와 시간 초과가 갈린다.

방법T = 10,000T = 100,000판정
① 케이스마다 memset 전체0.221초2.284초시간 초과
② 쓴 자리만 되돌리기0.0001초0.0012초1,900배 빠르다
③ 타임스탬프 (지우지 않음)0.0000초0.0000초가장 빠르다
② 쓴 자리만 되돌리기
int used[MAXN], uc = 0;

for (i = 0; i < n; i++) {
    seen[a[i]] = 1;
    used[uc++] = a[i];    /* 기록 */
}
/* 케이스 끝 */
for (i = 0; i < uc; i++)
    seen[used[i]] = 0;    /* 쓴 것만 */
uc = 0;
③ 타임스탬프
int stamp[MAXV];   /* 전역 = 0 */
int now = 0;       /* 케이스 번호 */

/* 케이스 시작 */
now++;

stamp[a[i]] = now;        /* 쓸 때 */
if (stamp[x] == now) ...  /* 읽을 때 */

/* 지우지 않는다! */
왜 ①이 느린가 — 비용을 세어 본다 memset 한 번이 V바이트다. 케이스가 T개면 T × V. T = 105, V = 106이면 1011바이트를 지운다. 각 케이스의 데이터가 10개뿐이어도 그렇다.
반면 ②는 T × n이다. 실제로 쓴 만큼만 지우므로 105 × 10 = 106이다. 10만 배 적다.
③ 타임스탬프는 아예 지우지 않는다. "이번 케이스에서 쓴 것인가"를 케이스 번호를 적어 두는 것으로 판별한다. 가장 우아하지만 int 배열이 필요하다(메모리 4배).

7.5카운팅 정렬

카운팅 배열을 만든 뒤 인덱스를 작은 것부터 훑으며 개수만큼 출력하면 정렬이 된다. 비교를 한 번도 하지 않는다.

카운팅 정렬O(N + V)
int cnt[MAXV + 1];                 /* 전역 */

for (int i = 0; i < n; i++)
    cnt[a[i]]++;                   /* 세고 */

for (int v = 0; v <= MAXV; v++)
    while (cnt[v]--)               /* 개수만큼 */
        printf("%d\n", v);          /* 출력 */
방법 (N = 100,000, V = 106)시간복잡도비고
qsort0.0132초O(N log N)값의 범위와 무관
카운팅 정렬0.0045초O(N + V)약 3배 빠르다
항상 빠른 것은 아니다 카운팅 정렬의 비용에는 값의 범위 V를 훑는 시간이 포함된다. N = 10개인데 V = 106이면 10개를 정렬하려고 100만 칸을 훑는다. N이 V보다 충분히 클 때만 유리하다.
판단 기준 — N ≥ V 정도면 카운팅 정렬, N ≪ V이거나 V가 너무 크면 qsort(11장).

7.6체크 배열이 못 하는 것

상황체크 배열대안
값이 109까지메모리 초과정렬 + 이분 탐색 (11장)
값이 실수인덱스 불가정렬 후 처리
값이 문자열인덱스 불가정렬 후 비교 (14장)
"K번째로 작은 값"가능하지만 V를 훑어야N ≪ V이면 정렬
값은 크지만 개수가 적다낭비가 심하다좌표 압축 (PART 3)
마지막 줄이 다리를 놓는다 "값이 109까지지만 N은 105개뿐"이라면, 실제로 등장하는 값은 많아야 105종류다. 그 값들만 모아 0, 1, 2, …로 번호를 다시 매기면 체크 배열을 쓸 수 있다. 이것이 좌표 압축이고, 정렬이 전제가 되므로 11장 이후에 다룬다.
지금 기억할 것은 하나다 — "값의 범위가 크면 체크 배열을 포기한다"가 아니라 "범위를 줄일 수 있는지 본다".
03 — 표준 코드

표준 코드

twosum.c도입 문제 — 체크 배열의 기본형
#include <stdio.h>
#define MAXV 1000000

char seen[MAXV + 1];           /* 전역 → 전부 0 (2장) */

int main(void) {
    int n, K;
    if (scanf("%d %d", &n, &K) != 2) return 1;

    int found = 0;
    for (int i = 0; i < n; i++) {
        int x;
        if (scanf("%d", &x) != 1) return 1;

        int need = K - x;
        if (1 <= need && need <= MAXV && seen[need])  /* 범위 검사 먼저! */
            found = 1;

        seen[x] = 1;
    }
    printf("%s\n", found ? "YES" : "NO");
    return 0;
}
세 줄이 전부 중요하다 ① 범위 검사를 먼저 — need는 음수가 될 수도, MAXV를 넘을 수도 있다. seen[need]를 먼저 쓰면 배열 밖을 읽는다. 3장에서 배운 &&의 단축 평가가 여기서 안전장치다.
② 표시는 검사 뒤에 — 순서를 바꾸면 a[i] + a[i] == K인 경우에 자기 자신과 짝을 지어 답이 된다. 문제가 "서로 다른 두 개"를 요구하면 오답이다.
③ 배열은 전역 — 1MB를 지역 변수로 두면 스택이 터진다(2장 오류 5).
countlib.c카운팅 배열 활용 네 가지
#define OFF 1000000
#define SZ  2000001

int cnt[SZ];                      /* 전역 */

/* ① 세기 */
for (int i = 0; i < n; i++) cnt[a[i] + OFF]++;

/* ② 서로 다른 값의 개수 */
int uniq = 0;
for (int v = 0; v < SZ; v++) if (cnt[v]) uniq++;

/* ③ 최빈값 (동점이면 가장 작은 값) */
int best = 0, bc = 0;
for (int v = 0; v < SZ; v++)
    if (cnt[v] > bc) { bc = cnt[v]; best = v - OFF; }   /* > 이지 >= 가 아니다 */

/* ④ 정렬된 순서로 출력 */
for (int v = 0; v < SZ; v++)
    for (int k = 0; k < cnt[v]; k++)
        printf("%d\n", v - OFF);
stamp.c케이스가 많을 때 — 타임스탬프
int stamp[MAXV + 1];              /* 전역 → 전부 0 */

int main(void) {
    int T;
    if (scanf("%d", &T) != 1) return 1;

    for (int t = 1; t <= T; t++) {      /* t가 1부터! 0은 "안 쓴 것" */
        int n;
        if (scanf("%d", &n) != 1) return 1;

        for (int i = 0; i < n; i++) {
            int x;
            if (scanf("%d", &x) != 1) return 1;
            if (stamp[x] == t) { /* 이번 케이스에서 이미 봤다 */ }
            stamp[x] = t;
        }
        /* 지우지 않는다 — 다음 케이스는 t+1로 구분된다 */
    }
    return 0;
}
케이스 번호를 1부터 세는 이유 전역 배열은 0으로 초기화된다. 케이스 번호를 0부터 쓰면 "한 번도 안 쓴 칸"과 "0번 케이스에서 쓴 칸"이 구분되지 않는다. 1부터 세면 0이 "안 쓴 것"을 뜻하게 되어 깔끔하다.
이것은 4장의 "초기값은 답이 될 수 없는 값으로"와 같은 원리다.
04 — 단계 예제

단계 예제

예제 1존재 질의 — 선형 탐색을 지운다

"N개의 수 중에 Q개의 질의 값이 각각 있는가?"는 체크 배열의 가장 전형적인 쓰임이다.

선형 탐색 O(N×Q)
for (i = 0; i < q; i++)
    for (j = 0; j < n; j++)
        if (a[j] == query[i]) { ... break; }

N = Q = 100,000
→ 10^10 번
체크 배열 O(N+Q)
for (i = 0; i < n; i++) have[a[i]] = 1;
for (i = 0; i < q; i++)
    printf("%d\n", have[query[i]]);

→ 2 × 10^5 번

측정 결과 — 선형 탐색 4.138초, 체크 배열 0.0008초로 약 5,179배다. 두 방법 모두 9,480개를 찾아 결과는 같았다.

예제 2중복 제거와 서로 다른 값의 개수

세면서 처음 보는 것만 센다
int uniq = 0;
for (i = 0; i < n; i++)
    if (!seen[a[i]]) {
        seen[a[i]] = 1;
        uniq++;
    }
또는 다 센 뒤 비어 있지 않은 칸
for (i = 0; i < n; i++) cnt[a[i]]++;

int uniq = 0;
for (v = 0; v <= MAXV; v++)
    if (cnt[v]) uniq++;

왼쪽은 O(N), 오른쪽은 O(N + V)다. 개수만 필요하면 왼쪽이 낫고, 어떤 값들인지도 필요하면 오른쪽이 자연히 정렬된 순서를 준다. 측정 입력(무작위 10만 개, 값 범위 106)에서 서로 다른 값은 95,108개였다.

예제 3최빈값 — 동점 처리가 전부다

최빈값이 여러 개일 때 문제가 무엇을 요구하는지에 따라 코드가 달라진다. 세 가지 모두 한 줄 차이다.

요구코드이유
가장 작은 값if (cnt[v] > bc)작은 v부터 보므로 먼저 잡힌 것이 남는다
가장 큰 값if (cnt[v] >= bc)동점이면 나중 것으로 갱신된다
두 번째로 작은 값최댓값을 먼저 구한 뒤 다시 훑으며 두 번째를 센다한 번에는 안 된다

검증 — 1 3 8 -2 2는 모든 값이 한 번씩이므로 최빈 빈도가 1이고, 그중 두 번째로 작은 값은 1이다(정렬하면 −2, 1, 2, 3, 8).

3장의 부등호 판단이 그대로 쓰인다 >와 >= 한 글자가 "첫 번째"와 "마지막"을 가른다. 4장 예제 2에서 최댓값의 위치를 구할 때와 완전히 같은 구조다. 문제 문장에 "가장 작은"이 있는지 다시 읽는다.

예제 4카운팅 정렬로 나이순 정렬

값의 범위가 좁으면(나이 0~200) 카운팅 정렬이 가장 짧고 빠르다.

코드
int c[201] = {0};
for (i = 0; i < n; i++) c[age[i]]++;

for (v = 0; v <= 200; v++)

검증

출력 19 19 19 20 20 21 21

비교를 한 번도 하지 않았다.
while (c[v]--)의 동작 조건을 검사한 뒤 1을 뺀다. c[v]가 3이면 3, 2, 1에서 참이고 0에서 거짓이 되어 정확히 3번 돈다(끝나고 c[v]는 −1이 된다). 배열을 재사용할 거라면 for (k = 0; k < c[v]; k++)로 쓰는 편이 안전하다.

예제 5초기화 비용을 세어 본다

테스트케이스가 많은 문제에서 지우는 비용을 복잡도에 포함해야 한다. 2장의 "제약을 곱한다"가 여기에 적용된다.

T전체 memset 비용실측판정
100100 × 106 = 108약 0.002초문제없다
10,000104 × 106 = 10100.221초위험
100,000105 × 106 = 10112.284초시간 초과

같은 조건에서 쓴 자리만 되돌리면 0.0012초다. 각 케이스의 데이터가 10개뿐이기 때문이다.

판단 기준 한 줄 T × V 와 T × n 을 비교한다. n(케이스당 데이터 개수)이 V(값의 범위)보다 훨씬 작으면 반드시 쓴 자리만 되돌리거나 타임스탬프를 쓴다.
T가 작으면(100 이하) memset으로도 충분하다. 항상 타임스탬프를 쓰라는 뜻이 아니다 — 비용을 세어 보고 정한다.
05 — 흔한 오류

흔한 오류 여섯 가지

1
배열 범위를 벗어난다
seen[K - x]에서 K - x가 음수이거나 MAXV를 넘을 수 있다. 런타임 에러가 나거나, 더 나쁘게는 조용히 엉뚱한 값을 읽는다.
대책 if (0 <= v && v <= MAXV && seen[v]) — 범위 검사를 먼저. 3장의 단축 평가가 안전장치다.
2
N(개수)을 보고 배열 크기를 정한다
이 기법의 배열 크기는 값의 범위 V로 정해진다. N = 100개여도 값이 106까지면 106칸이 필요하다.
대책 제약에서 A[i]의 범위를 찾아 그것으로 크기를 정한다. N은 입력 배열의 크기일 뿐이다.
3
음수 오프셋에서 +1을 빠뜨린다
−106 ~ 106은 2,000,001개다. 2000000으로 선언하면 맨 끝 값에서 범위를 벗어난다.
대책 #define SZ (2*OFF + 1)로 한 번만 쓴다. 그리고 양쪽 끝 값(−106과 106)을 반드시 테스트한다.
4
케이스마다 전체를 memset한다
T = 105, V = 106이면 2.284초로 시간 초과다. 각 케이스의 데이터가 10개뿐이어도 그렇다.
대책 쓴 자리만 되돌리거나(0.0012초) 타임스탬프. T × V를 복잡도에 포함해 계산한다.
5
표시와 검사의 순서를 바꾼다
seen[x] = 1;을 먼저 하면 x + x == K일 때 자기 자신과 짝이 되어 YES가 나온다. 문제가 "서로 다른 두 개"를 요구하면 오답이다.
대책 검사를 먼저, 표시를 나중에. 반례는 n=1, a=[5], K=10이다.
6
카운팅 정렬을 아무 데나 쓴다
N = 10개를 정렬하려고 V = 106칸을 훑으면 느리다. 값이 실수이거나 109까지 가면 아예 불가능하다.
대책 N과 V를 비교한다. N ≪ V이면 qsort. 메모리를 먼저 MB로 계산한다.
이 장의 가장 중요한 교훈 오류 1·2·3·6은 전부 "범위"에 대한 것이다 — 인덱스의 범위, 값의 범위, 배열의 범위. 이 기법은 값과 인덱스를 같은 것으로 취급하기 때문에, 둘의 범위가 어긋나는 순간 조용히 깨진다.
코드를 쓰기 전에 종이에 적는다 — "값은 L부터 R까지, 오프셋은 −L, 배열 크기는 R−L+1". 세 줄이면 네 가지 오류가 사라진다.

07 — 확인 평가

정답과 해설

01
char have[1000001]를 전역에 두고, 입력을 받으며 have[x] = 1, 질의마다 have[q]를 출력한다.
복잡도 O(N + Q) = 2 × 105. 측정 — 선형 탐색 4.138초 / 체크 배열 0.0008초(5,179배).
지도 포인트 — 배열이 전역인지 확인시킨다. 1MB를 main 안에 두면 스택이 터진다(2장 오류 5). 그리고 char를 쓴 이유(1MB vs 4MB)도 묻는다.
02
int cnt[1000001]에 cnt[x]++. 질의는 cnt[q]를 출력.
검증 — 5 5 3 1 3 5에서 5는 3번, 2는 0번.
지도 포인트 — 01번과의 차이는 자료형 하나다(char → int). 저장하는 것이 "있나"에서 "몇 개"로 바뀌면 자료형도 바뀐다. 7.1절의 표를 다시 펴게 한다.
03
if (!seen[x]) { seen[x] = 1; uniq++; } — O(N).
검증 — 5 5 3 1 3 5 → 3. 무작위 10만 개(값 범위 106)에서는 95,108개였다.
지도 포인트 — 값 범위를 훑는 방법(O(N+V))도 맞지만 O(N)으로 끝낼 수 있다는 점이 중요하다. "개수만 필요한가, 어떤 값인지도 필요한가"로 방법이 갈린다(예제 2).
04
#define OFF 1000000, #define SZ 2000001, cnt[a[i]+OFF]++. 최빈값은 >로 갱신하고 출력은 v - OFF.
검증 — -1000000 3 -1000000 3 7 → 둘 다 2번이지만 작은 쪽인 −1000000.
지도 포인트 — SZ가 2,000,001인지 확인시킨다. 2,000,000으로 쓰면 값 106에서 범위를 벗어난다(오류 3). 그리고 출력할 때 - OFF를 빠뜨리면 1,000,000 큰 값이 나온다 — 양쪽 변환을 짝으로 기억한다.
05
cnt[a[i]]++ 후 for (v=1; v<=10000; v++) for (k=0; k<cnt[v]; k++) printf.
검증 — 21 21 20 19 20 19 19 → 19 19 19 20 20 21 21.
지도 포인트 — N이 107까지 가는데 값 범위는 104뿐이다. N ≫ V이므로 카운팅 정렬이 압도적으로 유리하다(7.5절 판단 기준). 그리고 출력이 107줄이므로 printf 호출 자체가 부담이다 — 2장에서 측정했듯 100만 줄에 0.047초이므로 107이면 약 0.5초다. 출력량도 복잡도에 포함해야 한다.
06
본문 twosum.c. 검사를 먼저, 표시를 나중에.
검증 — 3 1 7 9 4, K=10 → YES(1+9 또는 3+7). n=1, a=[5], K=10 → NO(자기 자신과는 안 된다).
지도 포인트 — 순서를 바꾼 코드를 일부러 돌려 n=1, a=[5], K=10에서 YES가 나오는 것을 보여 준다. 한 줄의 순서가 답을 바꾼다. 3장의 "조건의 순서"가 대입문의 순서로 나타난 또 하나의 예다(4장 13번과 같은 구조).
07
cnt[x]++ 후 for (v=1; v<=MAXV; v++) if (cnt[v] >= 2) printf("%d\n", v);
검증 — 5 5 3 1 3 5 → 3, 5. 오름차순은 저절로 된다(작은 인덱스부터 훑으므로).
지도 포인트 — "오름차순으로 출력하라"는 조건에 정렬 코드를 추가하는 학생이 있다. 카운팅 배열은 이미 정렬되어 있다는 것을 짚는다. 인덱스가 곧 값이고 인덱스는 순서대로이기 때문이다.

12
N = 105, V = 106 — qsort 0.0132초 / 카운팅 정렬 0.0045초(약 3배 빠름). 결과는 일치.
N = 100으로 줄이면 — qsort는 거의 0초가 되지만 카운팅 정렬은 여전히 V = 106칸을 훑어야 하므로 역전된다.
지도 포인트 — "더 빠른 정렬"이 아니라 "조건이 맞을 때 빠른 정렬"이다. 복잡도 O(N + V)에서 V가 상수처럼 보이지만 N보다 클 수 있다는 것을 숫자로 체감시킨다. 2장의 "상수를 버리지만 무시하지는 않는다"와 같은 교훈이다.
13
for (i=0;i<n;i++) { if (seen[a[i]]) { printf("%d\n", i+1); return 0; } seen[a[i]]=1; } 끝까지 가면 -1.
검증 — 5 3 1 3 5 1 → 4번째(값 3이 두 번째로 등장). 중복 없는 입력 → -1.
지도 포인트 — 06번과 같은 구조다 — 검사를 먼저, 표시를 나중에. "이미 본 적 있나"를 묻는 모든 문제가 이 형태다. 그리고 찾는 즉시 종료하므로 평균적으로 훨씬 빨리 끝난다.
14
배열 두 개(inA, inB)를 만든 뒤 값 범위를 한 번 훑는다.
if (inA[v] && inB[v]) 교집합++; / if (inA[v] && !inB[v]) A만++;
검증 — A = {1,2,3,4}, B = {3,4,5} → 교집합 2, A에만 2.
지도 포인트 — 배열 하나로도 된다 — A를 1로, B를 만나면 2를 더해 1/2/3으로 구분하는 방법. 학생이 떠올리면 칭찬하되, 읽기 쉬운 쪽이 배열 두 개라는 것도 말해 준다. 메모리가 2MB로 충분하기 때문이다.
15
범위 검사를 빼면 need가 음수일 때 seen[-5]를 읽는다. 보통은 아무 일도 없는 것처럼 보이고(배열 앞쪽 메모리를 읽을 뿐) 가끔 잘못된 YES가 나온다.
-fsanitize=address로 컴파일하면 global-buffer-overflow라는 명확한 메시지가 나온다.
지도 포인트 — "오류가 안 난다"가 "맞다"가 아니다. C는 배열 범위를 검사하지 않으므로 잘못된 접근이 조용히 지나간다. PART 1 16장에서 배운 sanitizer를 여기서 다시 쓴다 — 이상한 답이 나오면 먼저 sanitizer로 돌려 본다.
16
int acc = 0;
for (int v = 1; v <= MAXV; v++) {
    acc += cnt[v];
    if (acc >= K) { printf("%d\n", v); break; }
}
검증 — 5 3 1 3 2에서 3번째로 작은 값은 정렬하면 1, 2, 3, 3, 5이므로 3.
지도 포인트 — 카운팅 배열을 누적하며 훑는 발상이 핵심이고, 이것이 2장 누적합의 변형이다. 그리고 acc >= K에서 >가 아니라 >=인 이유를 묻는다 — K번째가 그 값의 마지막 중복일 수 있기 때문이다. 경계는 K = 1과 K = N이다.
17
⑴ O(N³) — 2,000³ = 8 × 109. 2장의 기준으로 불가능하다.
⑵ O(N²) 풀이 — 두 개를 이중 루프로 고르고, 세 번째는 체크 배열로 찾는다. 
for (i = 0; i < n; i++) have[a[i]] = 1;    /* 먼저 전부 표시 */
for (i = 0; i < n; i++)
  for (j = i+1; j < n; j++) {
    long long need = (long long)K - a[i] - a[j];
    if (1 <= need && need <= MAXV && have[need]) { /* 찾았다 */ }
  }
4 × 106번으로 통과한다.
지도 포인트 — "세 개 중 두 개는 직접 고르고 하나는 조회"라는 발상이 이 문항의 전부다. 도입 문제(두 개 중 하나를 조회)의 확장이다. 단, 서로 다른 세 개라는 조건 때문에 need가 a[i]나 a[j]와 같은 경우를 개수로 따져야 한다 — 여기서 체크 배열 대신 카운팅 배열이 필요해진다는 점까지 가면 더 좋다.
18
카운팅 배열을 만든 뒤 누적합을 취한다. p[v] = p[v-1] + cnt[v]. 질의는 p[R] - p[L-1] 한 줄.
검증 — 1 3 3 7 9에서 [3,7] → 3개(3,3,7), [1,2] → 1개(1).
복잡도 — 전처리 O(N + V) = 1.1 × 106, 질의마다 O(1). 전체 통과.
지도 포인트 — 2장 누적합과 7장 카운팅 배열의 결합이다. 2장에서는 "위치"로 누적했고 여기서는 "값"으로 누적한다. 도구가 조합되기 시작하는 지점이고, 5장 20번의 "미리 표를 만든다"와도 같은 발상이다. p의 자료형은 int로 충분하다(최대 N = 105).
19
⑴ 불가능한 이유 — char 배열이라도 109바이트 = 953.7MB로 256MB를 넘는다.
⑵ 정렬 풀이 — 수열을 정렬하면 같은 값이 붙어 있게 된다. 앞에서부터 훑으며 a[i] != a[i-1]인 개수를 세면 서로 다른 값의 개수다. 복잡도 O(N log N) = 105 × 17 ≈ 1.7 × 106.
지도 포인트 — 정렬은 "값이 같은 것끼리 모아 주는" 도구라는 관점을 심어 준다. 체크 배열이 "값을 인덱스로" 모았다면 정렬은 "값을 순서로" 모은다. 둘은 같은 일을 다른 방법으로 하는 것이고, 값의 범위가 크면 정렬이 답이다. 11장의 예고가 된다.
20
⑴ 범위와 배열 — 값은 −106 ~ 106이므로 OFF = 1000000, SZ = 2000001. 카운팅이 필요하므로 int cnt[SZ] = 7.6MB. 256MB 안이고 전역에 둔다.
⑵ 초기화 비용 — T = 105, V = 2 × 106이므로 전체 memset이면 2 × 1011로 확실한 시간 초과다. n ≤ 10이므로 쓴 자리만 되돌린다 — T × n = 106.
⑶ 반례 목록 — ① n = 1 (두 수의 합 불가, 서로 다른 값 1개) ② 모두 같은 값 ③ 값이 −106과 106 양쪽 끝 ④ K = 2×a[i]인데 그 값이 하나뿐 (자기 자신과 짝 금지) ⑤ K가 범위 밖 (need가 배열 밖)
⑷ 복잡도 — 케이스마다 O(n) 세 번 + 되돌리기 O(n). 전체 T × n = 106. 통과.
⑸ 샘플 검산 — 3 1 7 9 4: 서로 다른 값 5개, 모두 1번씩이라 최빈값은 가장 작은 1, 1+9 = 10이므로 YES. -5 -5 5: 서로 다른 값 2개, 최빈값 −5(2번), −5+5 = 0이므로 YES.
지도 포인트 — 이 문제는 이 장의 모든 요소가 한 번씩 나온다 — 오프셋, 카운팅, 체크, 동점 규칙, 초기화 비용, 범위 검사. 특히 ⑵의 판단이 통과와 시간 초과를 가르는 유일한 지점이다. 학생이 코드를 쓰기 전에 T × V를 계산했는지를 확인하는 것이 이 문항의 목적이다.
08 — 마무리

이 장을 마치기 전 점검

  • 배열 크기는 N이 아니라 값의 범위 V로 정한다
  • 0/1만 저장하면 char를 쓴다 (메모리 4분의 1)
  • 음수가 있으면 오프셋, 크기는 2*OFF + 1
  • 인덱스로 쓰기 전에 범위 검사를 먼저 한다
  • 검사를 먼저, 표시를 나중에 (자기 자신과 짝 금지)
  • 케이스가 많으면 쓴 자리만 되돌리거나 타임스탬프
  • 초기화 비용 T × V를 복잡도에 포함한다
  • 카운팅 정렬은 N ≥ V일 때만 유리하다
  • 값의 범위가 크면 정렬로 간다 (11장)
다음 장 예고 — 08장 문자열 기초 처리 이 장에서 값을 인덱스로 썼다. 다음 장에서는 문자를 인덱스로 쓴다. 알파벳은 26칸, 아스키 전체도 128칸이면 충분하므로 카운팅 배열이 가장 잘 맞는 자리다. 문자열의 길이를 재는 법, scanf로 공백을 포함해 읽는 법, 그리고 문자열 문제에서 가장 많이 틀리는 끝의 '\0'을 다룬다.
