11

qsort와 정렬 기반 문제

7장에서 "값의 범위가 크면 체크 배열을 포기한다"고 했고, 그때 미뤄 둔 답이 정렬이었다. 정렬은 같은 값을 모아 주고 순서를 만들어 준다. 그 두 가지만으로 풀리는 문제가 놀랄 만큼 많다. 다만 C의 qsort에는 조용히 틀리는 함정이 하나 있다.

학습 목표

  • qsort의 네 인자를 정확히 쓸 수 있다
  • 비교 함수를 뺄셈 없이 작성해야 하는 이유를 측정으로 설명할 수 있다
  • 구조체를 여러 기준으로 정렬할 수 있다
  • 문자열 정렬의 두 가지 형태를 구분할 수 있다
  • 정렬 뒤에 저절로 풀리는 문제 유형을 다섯 가지 말할 수 있다
  • 이분 탐색으로 정렬된 배열을 O(log N)에 조회할 수 있다

01 — 도입 문제

교과서에 나오는 비교 함수가 틀렸다

가장 널리 쓰이는 비교 함수
int cmp(const void *x, const void *y) {
    return *(int*)x - *(int*)y;
}

qsort(a, n, sizeof(int), cmp);
입력
2000000000
-2000000000
0
1500000000
-1500000000

(제약이 |값| ≤ 2×10^9)
실행 결과
뺄셈 비교:
  0 1500000000 2000000000
  -2000000000 -1500000000
  → 정렬되지 않았다

올바른 비교:
  -2000000000 -1500000000 0
  1500000000 2000000000
원인
2000000000 - (-2000000000)
  = 4000000000
  → int로는 -294967296

큰 수에서 작은 수를 뺐는데
결과가 음수다.
→ "앞이 더 작다"고 판정한다

우연이 아니다. 값이 ±2 × 109 범위인 1,000개짜리 배열을 200번 만들어 뺄셈 비교로 정렬해 보았다. 200번 모두 정렬이 깨졌다.

올바른 비교 함수 
int cmp(const void *x, const void *y) {
    int a = *(const int*)x, b = *(const int*)y;
    return (a > b) - (a < b);
}
a > b이면 1 - 0 = 1, a < b이면 0 - 1 = -1, 같으면 0 - 0 = 0이다. 뺄셈을 하지 않으므로 넘칠 수 없다.
조금 길지만 이 네 줄을 통째로 외운다. 값의 범위가 작은 문제에서는 뺄셈판도 통과하지만, 언제 범위가 커질지는 문제가 정한다.
이 장이 답할 질문 ① qsort의 네 인자는 각각 무엇인가?
② 여러 기준으로 정렬하려면?
③ 정렬해 두면 무엇이 쉬워지는가?
02 — 개념 정리

개념 정리

11.1qsort의 네 인자

qsort<stdlib.h>
qsort(배열, 원소개수, 원소하나의크기, 비교함수);

qsort(a, n, sizeof(int), cmp);        /* int 배열 */
qsort(p, n, sizeof(P), cmp);          /* 구조체 배열 */
qsort(w, n, 20, cmp);                 /* char w[N][20] */
인자무엇흔한 실수
첫째배열의 시작 주소&a가 아니라 a
둘째원소의 개수바이트 수가 아니다
셋째원소 하나의 바이트 수배열 전체 크기가 아니다
넷째비교 함수의 이름cmp()가 아니라 cmp
둘째와 셋째를 바꿔 쓰면 컴파일은 된다. 실행하면 엉뚱한 메모리를 정렬하거나 크래시한다. qsort는 void*를 받으므로 타입 검사가 전혀 없다.
외우는 법 — "어디에, 몇 개, 하나가 몇 바이트, 어떻게". 이 순서다.

11.2비교 함수의 규칙

반환값뜻결과
음수x가 y보다 앞오름차순이 된다
0순서 상관없음
양수x가 y보다 뒤
값이 아니라 부호만 쓰인다 8장의 strcmp와 같다. -1이든 -100이든 "앞"이라는 뜻은 같다. 그래서 (a>b) - (a<b)처럼 −1, 0, 1만 내보내는 것이 가장 안전하다.
strcmp를 그대로 반환해도 된다 — strcmp가 이미 이 규칙을 따르기 때문이다.

11.3구조체를 여러 기준으로

기준이 여러 개면 if로 쌓는다. 앞 기준이 같을 때만 다음 기준을 본다.

다중 기준 비교나이 오름차순, 같으면 입력 순
typedef struct { int age; char name[20]; int idx; } P;

int cmp(const void *x, const void *y) {
    const P *p = x, *q = y;
    if (p->age != q->age)
        return (p->age > q->age) - (p->age < q->age);   /* 1순위 */
    return (p->idx > q->idx) - (p->idx < q->idx);       /* 2순위 */
}
입력
21-Park 20-Kim 21-Lee
20-Choi 19-Jung
결과
나이↑, 같으면 입력순
  19-Jung 20-Kim 20-Choi
  21-Park 21-Lee

나이↓, 같으면 이름순
  21-Lee 21-Park 20-Choi
  20-Kim 19-Jung
내림차순은 두 항을 바꾼다 (p->age > q->age) - (p->age < q->age)에서 p와 q를 맞바꾸면 내림차순이 된다.
return -cmp(...)로 부호만 뒤집는 것은 위험하다 — 반환값이 INT_MIN이면 부호를 뒤집을 수 없기 때문이다(6장에서 본 -n의 함정). 항을 바꾸는 쪽을 쓴다.

11.4문자열 정렬 — 두 가지 형태

자료 구조원소 크기비교 함수
char w[N][20]20strcmp((const char*)x, (const char*)y)
char *wp[N]sizeof(char*) (보통 8)strcmp(*(const char**)x, *(const char**)y)
차이는 역참조 한 번이다 2차원 배열이면 x가 이미 문자열의 시작 주소다. 포인터 배열이면 x는 "문자열 주소를 담은 칸"의 주소이므로 한 번 더 따라가야 한다.
올림피아드에서는 2차원 배열 쪽이 안전하다 — 원소 크기를 sizeof(w[0])으로 쓰면 숫자를 직접 적을 필요도 없다.

검증 — banana apple fig cherry date kiwi를 사전순으로 정렬하면 두 방법 모두 apple banana cherry date fig kiwi다. 길이순, 같으면 사전순으로 바꾸면 fig date kiwi apple banana cherry가 된다.

11.5안정성 — 표준은 보장하지 않는다

안정적(stable)이란 값이 같은 원소들의 원래 순서가 유지된다는 뜻이다. C 표준은 qsort에 대해 이것을 보장하지 않는다.

측정 (이 환경의 glibc)
N=100      뒤집힌 쌍 0
N=2,000    뒤집힌 쌍 0
N=100,000  뒤집힌 쌍 0
N=1,000,000 뒤집힌 쌍 0
N=2,000,000 뒤집힌 쌍 0

→ 실제로는 안정적이었다
그래도 의존하면 안 된다
glibc의 qsort는 메모리가 넉넉하면
병합 정렬을 쓰므로 안정적이다.

그러나 다른 환경에서는
퀵 정렬을 쓸 수 있고,
그러면 깨진다.

표준이 보장하지 않는 것에
기대지 않는다.
순서가 중요하면 인덱스를 기준에 넣는다 "같은 점수면 먼저 들어온 순서대로"가 필요하면, 입력받을 때 idx를 저장하고 비교 함수의 마지막 기준으로 쓴다(11.3절의 코드). 그러면 어떤 환경에서도 같은 답이 나온다.
이것은 1장에서 다룬 "출력이 나왔다고 보장되는 것은 없다"의 또 다른 얼굴이다 — 내 컴퓨터에서 맞는 것과 보장된 것은 다르다.

11.6정렬하면 저절로 풀리는 다섯 가지

정렬이 해 주는 일은 둘뿐이다 — 같은 값을 모아 주고, 순서를 만들어 준다. 그 둘에서 다음이 나온다.

문제정렬 후 코드복잡도
서로 다른 값의 개수if (b[i] != b[i-1]) uniq++;O(N log N)
중복 제거if (b[i] != b[k-1]) b[k++] = b[i];O(N)
K번째로 작은 값b[K-1]O(1)
중앙값b[n/2]O(1)
가장 가까운 두 수min(b[i] - b[i-1])O(N)
검증: 5 3 9 3 1 9 5 5
정렬 : 1 3 3 5 5 5 9 9

서로 다른 값   4개
중복 제거      1 3 5 9
3번째로 작은 값 3
중앙값(b[4])    5
가장 가까운 차  2
좌표 압축 (7장의 숙제)
중복 제거한 배열에서
각 값의 위치를 찾으면
0부터의 번호가 된다.

5→2  3→1  9→3  3→1
1→0  9→3  5→2  5→2

값이 10^9까지여도
번호는 0..N-1 이다
→ 체크 배열을 쓸 수 있다
7장에서 미뤄 둔 답 7장 19번에서 "값이 109까지면 체크 배열이 953.7MB로 불가능하다"고 했다. 정렬하면 서로 다른 값이 많아야 N개이므로, 그 값들에 0부터 번호를 다시 매기면 배열 크기가 N으로 줄어든다. 이것이 좌표 압축이다.
번호를 찾는 데 다음 절의 이분 탐색을 쓴다.

11.7이분 탐색

이분 탐색정렬된 배열에서 O(log N)
int has(int *v, int n, int x) {
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;   /* (lo+hi)/2는 넘칠 수 있다 */
        if (v[mid] == x) return 1;
        if (v[mid] < x) lo = mid + 1;
        else            hi = mid - 1;
    }
    return 0;
}
N = 106, 질의 1,000개시간복잡도
정렬 한 번0.167초O(N log N)
선형 탐색0.420초O(N) × 1,000
이분 탐색0.00017초2,400배 빠르다

질의를 106개로 늘려도 이분 탐색은 0.181초다. 선형이면 1012번으로 불가능하다(2장).

mid = (lo + hi) / 2를 쓰지 않는다 lo와 hi가 둘 다 10억 근처면 합이 int를 넘는다. 3장에서 본 "조건식 안의 오버플로"와 같은 자리다.
lo + (hi - lo) / 2로 쓰면 뺄셈이 먼저라 넘치지 않는다. 배열 인덱스에서는 잘 안 생기지만, 값의 범위를 이분 탐색할 때(PART 3) 반드시 필요하다.
"x 이상이 처음 나오는 위치" (lower_bound) 
int lower_bound(int *v, int n, int x) {
    int lo = 0, hi = n;              /* hi가 n (n-1이 아니다) */
    while (lo < hi) {                /* < (<= 가 아니다) */
        int mid = lo + (hi - lo) / 2;
        if (v[mid] < x) lo = mid + 1;
        else            hi = mid;
    }
    return lo;
}
검증 — 1 3 3 5 7에서 x=0→0, x=1→0, x=2→1, x=3→1, x=4→3, x=5→3, x=8→5.
이 함수가 더 쓸모 있다 — 있으면 그 위치를, 없으면 들어갈 자리를 알려 준다. 좌표 압축의 번호도 이것으로 구한다.
03 — 표준 코드

표준 코드

sortlib.c비교 함수 모음 — 통째로 외운다
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* ① 정수 오름차순 */
int cmp_int(const void *x, const void *y) {
    int a = *(const int*)x, b = *(const int*)y;
    return (a > b) - (a < b);
}

/* ② 정수 내림차순 — 항을 바꾼다 */
int cmp_int_desc(const void *x, const void *y) {
    int a = *(const int*)x, b = *(const int*)y;
    return (b > a) - (b < a);
}

/* ③ long long */
int cmp_ll(const void *x, const void *y) {
    long long a = *(const long long*)x, b = *(const long long*)y;
    return (a > b) - (a < b);
}

/* ④ 문자열 (2차원 배열) */
int cmp_str(const void *x, const void *y) {
    return strcmp((const char*)x, (const char*)y);
}

/* ⑤ 구조체 다중 기준 */
typedef struct { int score; char name[21]; int idx; } P;

int cmp_p(const void *x, const void *y) {
    const P *p = x, *q = y;
    if (p->score != q->score)
        return (q->score > p->score) - (q->score < p->score);  /* 점수 내림차순 */
    int c = strcmp(p->name, q->name);
    if (c) return c;                                        /* 이름 오름차순 */
    return (p->idx > q->idx) - (p->idx < q->idx);            /* 입력 순 */
}
uniq.c정렬 → 중복 제거 → 좌표 압축
int a[100001], b[100001];

int main(void) {
    int n;
    if (scanf("%d", &n) != 1) return 1;
    for (int i = 0; i < n; i++) {
        if (scanf("%d", &a[i]) != 1) return 1;
        b[i] = a[i];                     /* 원본을 남겨 둔다 */
    }

    qsort(b, n, sizeof(int), cmp_int);

    int k = 1;                            /* 중복 제거 */
    for (int i = 1; i < n; i++)
        if (b[i] != b[k - 1]) b[k++] = b[i];

    for (int i = 0; i < n; i++) {        /* 좌표 압축 */
        int lo = 0, hi = k;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (b[mid] < a[i]) lo = mid + 1; else hi = mid;
        }
        printf("%d ", lo);                 /* a[i]의 순위 (0부터) */
    }
    putchar('\n');
    return 0;
}
원본을 반드시 따로 보관한다 qsort는 제자리에서 정렬하므로 원래 순서가 사라진다. 좌표 압축처럼 원래 순서대로 출력해야 하는 문제에서는 복사본을 정렬한다.
구조체를 쓸 때는 idx 필드에 입력 순서를 넣어 두면 복사 없이도 복원할 수 있다(11.5절).

단계 예제

예제 1비교 함수를 검산한다

정렬이 끝난 뒤 진짜 정렬되었는지 확인하는 세 줄을 습관으로 만든다.

검산 코드
int ok = 1;
for (int i = 1; i < n; i++)
    if (cmp(&b[i-1], &b[i]) > 0) ok = 0;

printf("정렬됨? %s\n", ok ? "예" : "아니오");
왜 필요한가
뺄셈 비교로 정렬한
±2×10^9 데이터 1,000개:

200번 시도 → 200번 모두 깨짐

그런데 컴파일 경고도 없고
크래시도 없다.

검산에 비교 함수 자신을 쓴다는 점이 포인트다. 비교 함수가 틀렸으면 검산도 통과해 버리지 않을까 싶지만, 뺄셈 비교의 경우 검산에서 걸린다 — 정렬 결과가 비교 함수의 기준으로도 어긋나기 때문이다.

예제 2기준을 표로 적고 옮긴다

다중 기준은 표를 먼저 그린다(3장의 조건표와 같다). 표의 줄 수가 if의 개수다.

순위기준방향코드
1점수내림차순(q->score > p->score) - (q->score < p->score)
2이름사전순strcmp(p->name, q->name)
3입력 순서오름차순(p->idx > q->idx) - (p->idx < q->idx)
마지막 기준은 항상 달라야 한다 모든 기준이 같은 두 원소가 있으면 순서가 정해지지 않는다(11.5절). idx를 마지막 기준으로 두면 어떤 두 원소도 반드시 구분되므로, 환경이 바뀌어도 답이 같다.

예제 3이분 탐색의 경계 세 가지

함수hi의 초기값루프 조건반환
찾기 (has)n - 1lo <= hi있으면 1

lower_bound와 upper_bound의 차이는 비교 한 글자다 — v[mid] < x 대 v[mid] <= x. 그리고 upper - lower가 x의 개수다.

1 3 3 5 7 에서
x=3  lower=1  upper=3
     개수 = 3 - 1 = 2  ✓

x=4  lower=3  upper=3
     개수 = 0  ✓ (없다)
7장과 비교
7장: 카운팅 배열 cnt[x]
  → O(1), 메모리 O(V)

11장: 정렬 + upper - lower
  → O(log N), 메모리 O(N)

값의 범위가 크면 11장,
개수가 많으면 7장

예제 4구간 스케줄링 — 정렬 기준이 답을 만든다

"서로 겹치지 않게 최대한 많은 구간을 고른다"는 문제는 끝나는 시각 순으로 정렬하면 앞에서부터 욕심내어 고르는 것만으로 최적이 된다.

코드
qsort(a, n, sizeof(I), cmp_end);

int cnt = 0, last = -1;
for (int i = 0; i < n; i++)
    if (a[i].s >= last) {
        last = a[i].e;
        cnt++;
    }
검증 (11개 구간)
끝 시각 순: (1,4) (3,5) (0,6)
  (5,7) (3,9) (5,9) (6,10)
  (8,11) (8,12) (2,14) (12,16)

선택: (1,4) (5,7) (8,11) (12,16)
최대 개수 = 4
시작 시각 순으로 정렬하면 틀린다 (0,6)처럼 일찍 시작하지만 오래 끄는 구간을 먼저 고르게 되어 뒤의 여러 구간을 놓친다. 정렬 기준 하나가 답을 결정한다.
왜 끝 시각 순이 최적인지의 증명은 PART 3(그리디)에서 다룬다. 지금은 "정렬 기준을 바꿔 보는 것"이 문제 해결 수단이라는 것만 기억한다.

예제 57장과 11장 중 무엇을 고를까

상황7장 (카운팅)11장 (정렬)선택
값 ≤ 106, N = 1051MB, O(N+V)O(N log N)카운팅(더 빠르다)
값 ≤ 109, N = 105953MB — 불가O(N log N)정렬
값이 실수인덱스 불가가능정렬

7장에서 측정한 값(N = 105, V = 106)으로는 qsort 0.0132초, 카운팅 정렬 0.0045초였다. 조건이 맞으면 카운팅이 빠르고, 조건이 안 맞으면 정렬만이 답이다.

05 — 흔한 오류

흔한 오류 여섯 가지

1
비교 함수에서 뺄셈을 한다
return *(int*)x - *(int*)y;는 값이 ±2 × 109 범위면 넘쳐서 정렬이 깨진다. 측정에서 200번 중 200번 깨졌다. 작은 값으로는 멀쩡하다.
대책 (a > b) - (a < b). 네 줄짜리 비교 함수를 통째로 외운다.
2
qsort의 셋째 인자를 틀린다
배열 전체 크기나 sizeof(a)를 넘기면 엉뚱한 메모리를 정렬한다. void*라 타입 검사가 없다.
대책 "어디에, 몇 개, 하나가 몇 바이트, 어떻게". 불안하면 sizeof(a[0])으로 쓴다.
3
내림차순을 -cmp(...)로 만든다
반환값이 INT_MIN이면 부호를 뒤집을 수 없다(6장의 -n 함정). 뺄셈 비교와 겹치면 더 위험하다.
대책 두 항을 맞바꾼다 — (b > a) - (b < a).
4
안정성에 의존한다
"같은 점수면 먼저 들어온 순서"를 qsort가 알아서 해 줄 거라 믿는다. 이 환경에서는 실제로 유지되었지만 C 표준이 보장하지 않는다.
대책 idx를 마지막 기준으로 넣는다. 그러면 어떤 환경에서도 같은 답이다.
5
원본을 날린다
qsort는 제자리 정렬이라 원래 순서가 사라진다. 원래 순서대로 출력해야 하는 문제에서 되돌릴 수 없다.
대책 복사본을 정렬하거나 구조체에 idx를 담는다.
6
정렬하지 않고 이분 탐색한다
이분 탐색은 정렬된 배열에서만 옳다. 정렬 안 된 배열에 쓰면 있는 값을 "없다"고 하거나 그 반대가 된다. 크래시는 안 난다.
대책 이분 탐색 전에 정렬했는지 확인한다. 예제 1의 검산 세 줄을 쓴다.
이 장의 가장 중요한 교훈 오류 1·4·6은 전부 "작은 입력에서는 멀쩡"하다. 뺄셈 비교는 값이 작으면 맞고, 안정성은 이 환경에서 맞고, 정렬 안 된 배열도 운이 좋으면 맞는다.
정렬 문제의 표준 반례 — 값이 제약의 양 끝(±2 × 109), 같은 값이 여러 개, 원소가 1개, 이미 정렬된 입력, 역순으로 정렬된 입력. 다섯 개면 이 장의 오류가 거의 전부 걸린다.

07 — 확인 평가

정답과 해설

01
cmp_int로 qsort. 배열은 int a[1000001]을 전역에 둔다(4MB, 2장).
검증 — 양 끝 값을 포함한 다섯 개가 올바른 순서로 나온다.
지도 포인트 — N = 106이므로 출력이 100만 줄이다. 2장에서 측정했듯 printf 100만 줄이 0.047초이므로 괜찮지만, 출력량도 복잡도에 포함해야 한다. 정렬 자체는 측정상 0.167초였다.
02
return (b > a) - (b < a); — a와 b의 자리만 바꿨다.
지도 포인트 — -cmp(x,y)로 쓰면 반환값이 INT_MIN일 때 부호를 못 뒤집는다. 올바른 비교 함수는 −1/0/1만 내므로 사실 안전하지만, 뺄셈 비교와 섞이면 터진다. 항을 바꾸는 습관이 어느 경우에도 옳다.
03
예제 1의 세 줄. 올바른 비교는 "예", 뺄셈 비교는 "아니오"가 나온다.
검증 — 2000000000 -2000000000 0 1500000000 -1500000000을 뺄셈 비교로 정렬하면 0 1500000000 2000000000 -2000000000 -1500000000으로 명백히 어긋난다.
지도 포인트 — 이 세 줄을 모든 정렬 문제에서 쓰게 한다. 3장의 "경계 전수 검사", 6장의 "왕복 검사"에 이은 세 번째 자체 검산 도구다. 검산 도구를 늘려 가는 것이 PART 2의 숨은 줄기다.
04
정렬 후 if (b[i] != b[k-1]) b[k++] = b[i];
검증 — 5 3 9 3 1 9 5 5 → 정렬 1 3 3 5 5 5 9 9 → 중복 제거 1 3 5 9, 개수 4.
지도 포인트 — 제자리에서 중복을 제거하는 기법이다. k가 "지금까지 남긴 개수"이자 "다음에 쓸 자리"라는 두 역할을 한다. N = 1일 때 k = 1로 시작하는 것이 맞는지 확인시킨다.
05
정렬 후 b[n/2]와 b[K-1].
검증 — 1 3 3 5 5 5 9 9에서 b[4] = 5(중앙값), b[2] = 3(3번째).
지도 포인트 — N이 짝수일 때 "중앙값"의 정의가 문제마다 다르다(두 값의 평균인지, n/2번째인지). 문제가 정의하지 않으면 예제로 역산한다(1장). 7장 16번(카운팅 배열로 K번째)과 비교해 정렬 쪽이 훨씬 짧다는 것도 짚는다.
06
qsort(w, n, sizeof(w[0]), cmp_str), cmp_str은 strcmp를 그대로 반환.
검증 — apple banana cherry date fig kiwi.
지도 포인트 — sizeof(w[0])을 쓰면 배열 선언을 바꿔도 따라간다. 그리고 포인터 배열이었다면 비교 함수가 달라진다(역참조 한 번 더)는 것을 11.4절의 표로 확인시킨다.
07
strlen을 먼저 비교하고 같으면 strcmp.
검증 — fig date kiwi apple banana cherry (3, 4, 4, 5, 6, 6자).
지도 포인트 — 비교 함수 안에서 strlen을 부르면 비교마다 O(길이)가 든다. 8장의 "strlen은 O(N)" 교훈이다. 길이가 20 이하라 괜찮지만, 길이를 구조체에 미리 저장하는 쪽이 정석이다.
08
정렬 후 이분 탐색. 검증 — 4 1 5 2 3 정렬 1 2 3 4 5, 질의 1→1, 7→0, 5→1.
복잡도 — 정렬 O(N log N) + 질의 O(Q log N) ≈ 1.7 × 106 + 1.7 × 106.
지도 포인트 — 값의 범위가 109이라 7장의 체크 배열이 불가능하다는 것을 먼저 계산시킨다(953.7MB). 7장 01번과 같은 문제인데 제약 하나로 방법이 바뀐 것이다.
09
측정 — 뺄셈 비교로 정렬이 깨진 횟수 200 / 200. 올바른 비교는 0 / 200.
지도 포인트 — "가끔 틀린다"가 아니라 "거의 항상 틀린다"는 것이 충격적인 지점이다. 값이 큰 데이터 1,000개면 넘치는 쌍이 반드시 생기기 때문이다. 그런데도 작은 값으로만 테스트하면 영원히 안 걸린다 — 이 장 교훈의 핵심이다.
10
본문 cmp_p. 점수는 항을 바꿔 내림차순, 이름은 strcmp, 마지막에 idx.
검증 — 90점 Lee·Park(이름순), 85점 Choi·Kim(이름순), 80점 Jung.
지도 포인트 — 기준 표를 먼저 그리게 한다(예제 2). 세 기준의 방향이 제각각(내림/오름/오름)이라 헷갈리기 쉽다. 표의 줄 수와 if의 수가 같은지 확인시킨다.
11
측정 — N = 100, 2,000, 105, 106, 2 × 106의 모든 경우에서 뒤집힌 쌍 0개였다.
답 — "이 환경의 qsort는 안정적으로 동작했다. 그러나 C 표준은 보장하지 않는다." glibc는 메모리가 넉넉하면 병합 정렬을 쓰기 때문이고, 다른 구현에서는 퀵 정렬이라 깨질 수 있다.
지도 포인트 — 이 문항의 목적은 "내 환경에서 되는 것과 보장된 것은 다르다"는 태도다. 측정 결과가 "안정적"이라고 나왔는데도 의존하면 안 된다고 가르치는 드문 자리다. 1장의 "출력이 나왔다는 것은 아무것도 보장하지 않는다"와 같은 교훈이다.
12
본문 uniq.c. 원본을 복사해 두고 정렬·중복 제거한 뒤, 원본을 순서대로 훑으며 lower_bound로 순위를 찾는다.
검증 — 5 3 9 3 1 9 5 5 → 2 1 3 1 0 3 2 2.
지도 포인트 — 원본을 날리면 복구할 수 없다(오류 5). 그리고 압축 후 값의 범위가 0 ~ 3으로 줄었다는 것 — 이제 7장의 체크 배열을 쓸 수 있다. 11장이 7장의 한계를 풀어 준다는 것을 여기서 완성한다.
13
upper_bound(x) - lower_bound(x).
검증 — 1 3 3 5 7에서 x=3 → lower 1, upper 3, 개수 2. x=4 → 둘 다 3, 개수 0. x=7 → lower 4, upper 5, 개수 1.
지도 포인트 — 두 함수의 차이가 <와 <= 한 글자라는 것을 확인시킨다. 그리고 없는 값에서 둘이 같아져 0이 나온다는 점이 이 방법의 우아함이다 — 별도의 "있나" 검사가 필요 없다.
14
정렬 후 min(b[i] - b[i-1]).
검증 — 10 3 25 7 1 → 정렬 1 3 7 10 25 → 차 2, 4, 3, 15 → 2.
지도 포인트 — "가장 가까운 두 수는 정렬하면 반드시 이웃"이라는 것을 설명하게 한다. 정렬하지 않으면 모든 쌍 O(N²)을 봐야 하는데, 정렬 한 번으로 O(N)이 된다. 정렬이 만들어 주는 "순서"의 가치를 보여 주는 가장 깔끔한 예다. 차가 109를 넘을 수 있으면 long long(2장).
15
체크 배열 — 값이 109이면 char로도 953.7MB로 불가능(7장 8번).
정렬 + 이분 탐색 — 정렬한 뒤 각 a[i]마다 K - a[i]를 이분 탐색한다. 자기 자신과 짝지어지지 않도록 개수를 확인한다. 복잡도 O(N log N).
지도 포인트 — 7장 06번과 완전히 같은 문제인데 제약 하나로 방법이 바뀐다. 두 장을 나란히 펴고 비교시킨다. 그리고 "서로 다른 두 개" 조건 때문에 K - a[i] == a[i]인 경우를 따로 처리해야 한다는 것 — 7장 오류 5번이 여기서도 나온다.
16
7장의 측정 — N = 105, V = 106에서 qsort 0.0132초, 카운팅 정렬 0.0045초(약 3배). 결과는 일치.
값 범위를 109으로 바꾸면 카운팅은 메모리 초과이므로 qsort만 가능하다.
지도 포인트 — 예제 5의 표를 완성시킨다. "어느 것이 빠른가"가 아니라 "어느 것이 가능한가"를 먼저 묻는다. 가능한 것이 하나뿐이면 고민할 필요가 없고, 둘 다 가능할 때만 속도를 본다.
17
끝나는 시각 순으로 정렬한 뒤 if (a[i].s >= last) { last = a[i].e; cnt++; }.
검증 — 11개 구간에서 (1,4) (5,7) (8,11) (12,16)을 골라 4개.
지도 포인트 — last의 초기값을 −1이나 충분히 작은 값으로 둔다(4장). 그리고 s >= last인지 s > last인지는 끝점이 닿는 구간을 겹침으로 보는지에 달려 있다 — 3장 18번과 같은 질문이다. 문제가 정하지 않으면 예제로 역산한다.
18
⑴ 시작 시각 순 — (0,6)처럼 일찍 시작해 오래 끄는 구간을 먼저 골라 손해를 본다.
⑵ 길이 짧은 순 — 짧지만 가운데 끼어 있어 양쪽을 다 막는 구간을 고를 수 있다.
⑶ 끝 시각 순 — 최적이다. 가장 빨리 끝나는 것을 고르면 남는 시간이 가장 많다.
지도 포인트 — 세 기준을 모두 돌려 개수를 비교하게 한다. 정렬 기준 하나가 정답과 오답을 가른다는 것이 이 문항의 전부다. 왜 ⑶이 최적인지의 증명(교환 논법)은 PART 3에서 다루지만, "남는 시간이 가장 많다"는 직관은 지금 심어 준다.
19
⑴ O(N³) — 2,000³ = 8 × 109로 불가능(10장 17번과 같다).
⑵ 정렬 + 이분 탐색 — 두 개를 이중 루프로 고르고 K - a[i] - a[j]를 이분 탐색한다. O(N² log N) = 4 × 106 × 11 ≈ 4.4 × 107. 통과.
지도 포인트 — 10장 17번은 체크 배열로 O(N²)에 풀었고, 여기서는 이분 탐색으로 O(N² log N)에 푼다. 체크 배열이 더 빠르지만 값의 범위가 109이라 쓸 수 없다. 같은 구조의 문제에 두 도구가 어떻게 나뉘는지를 보여 주는 자리다. 합이 long long이어야 한다는 것도 짚는다.
20
⑴ 정렬 기준 표
순위기준방향코드
1국어내림(q->kor > p->kor) - (q->kor < p->kor)
2영어오름(p->eng > q->eng) - (p->eng < q->eng)
3수학내림(q->mat > p->mat) - (q->mat < p->mat)
4이름사전순strcmp(p->name, q->name)
⑵ 비교 함수 — 위 네 줄을 if (다르면) return ...;으로 쌓고 마지막은 return strcmp(...).
⑶ 반례 다섯 — ① N = 1 ② 모든 학생의 점수가 같다(이름순만 남는다) ③ 국어만 같고 영어가 다르다(2순위 확인) ④ 국어·영어가 같고 수학이 다르다(3순위, 방향이 1순위와 같은 내림이라 헷갈린다) ⑤ 점수가 0과 100인 양 끝.
⑷ 자료형과 메모리 — 점수가 0~100이므로 int로 충분. 구조체가 약 24바이트이고 N = 105이므로 2.4MB. 전역에 둔다(2장).
⑸ 복잡도 — O(N log N) = 105 × 17 ≈ 1.7 × 106. 비교 함수 안의 strcmp는 이름이 10자 이하라 상수. 통과.
⑹ 샘플 검산 — 국어 80인 sangkeun·sunyoung이 먼저이고, 둘의 영어는 60과 70이므로 오름차순으로 sangkeun(60)이 앞. 그다음 국어 50인 junkyu.
지도 포인트 — 기준이 네 개이고 방향이 내림-오름-내림-오름으로 번갈아 나온다는 점이 이 문제의 함정이다. 코드를 쓰기 전에 표를 반드시 그리게 한다. 그리고 "이름은 서로 다르다"는 제약 덕분에 idx가 필요 없다는 것 — 마지막 기준이 모든 원소를 구분하면 안정성 문제도 사라진다(11.5절).
08 — 마무리

이 장을 마치기 전 점검

  • 비교 함수는 (a > b) - (a < b) — 뺄셈을 쓰지 않는다
  • qsort의 인자는 "어디에, 몇 개, 하나가 몇 바이트, 어떻게"
  • 내림차순은 두 항을 맞바꾼다 (-cmp가 아니다)
  • 다중 기준은 표를 먼저 그리고 if로 쌓는다
  • 마지막 기준은 모든 원소를 구분하게 한다 (idx)
  • 안정성에 의존하지 않는다 — 표준이 보장하지 않는다
  • 원래 순서가 필요하면 복사본을 정렬한다
  • 이분 탐색의 mid는 lo + (hi - lo) / 2
  • 정렬 뒤에는 검산 세 줄을 붙인다
