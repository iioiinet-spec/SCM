01

문제 읽는 법과 입출력 형식 설계

PART 2는 새로운 문법을 거의 가르치지 않는다. 아는 것으로 완결된 프로그램을 만드는 절차를 훈련한다. 그 첫 번째가 문제를 읽는 법이다. 브론즈 구간에서 틀리는 이유의 상당수는 알고리즘이 아니라 입출력 형식에 있다.

학습 목표

  • 문제를 조건·제약·입출력 명세 세 덩어리로 분리해 읽을 수 있다
  • 제약 조건에서 자료형과 허용 복잡도를 먼저 결정할 수 있다
  • 입력 형식 네 가지 표준형을 구분하고 각각의 뼈대를 쓸 수 있다
  • 같은 문제를 단일 입력판과 T개 반복판 두 형태로 작성해 차이를 설명할 수 있다
  • 출력 형식 오류 다섯 가지를 제출 전에 걸러 낼 수 있다

01 — 도입 문제

같은 문제, 다른 입력 형식

아래 두 문제는 계산 내용이 완전히 같다. 두 정수를 더해 출력하는 것이다.

문제 A
두 정수 A, B가 주어진다.
A + B를 출력하라.

입력
12 25

출력
37
문제 B
첫 줄에 테스트케이스 개수 T.
이후 T개 줄에 두 정수 A, B.
각 줄의 합을 출력하라.

입력        출력
3           3
1 2         30
10 20       300
100 200

그런데 A의 코드를 B에 그대로 내면 어떻게 될까. 실행은 되고 출력도 나온다.

A용 코드에 B의 입력을 주면
$ printf '3\n1 2\n10 20\n' | ./single
4
무슨 일이 일어났나
첫 두 수 3과 1을 읽어
3 + 1 = 4 를 출력했다.

T를 A로 착각한 것이다.

프로그램은 죽지 않았고, 경고도 없었으며, 그럴듯한 숫자가 나왔다. 채점 결과만 틀린다.

브론즈 구간의 실제 오답 원인 "알고리즘을 몰라서"가 아니다. 입력 형식을 잘못 읽어서, 출력에 군더더기가 붙어서, 제약 조건을 안 봐서다. 이 세 가지를 막는 절차를 만드는 것이 이 장의 목표다.
이 장이 답할 질문 ① 문제를 어떤 순서로 읽어야 빠뜨리지 않는가?
② 입력 형식에는 몇 가지 유형이 있는가?
③ 눈에 보이지 않는 출력 차이를 어떻게 잡는가?
02 — 개념 정리

개념 정리

1.1문제는 세 덩어리다

올림피아드 문제는 길어 보이지만 구조는 항상 같다. 읽을 때 세 덩어리로 나눠 표시한다.

덩어리무엇이 적혀 있나여기서 결정하는 것
① 조건무엇을 구하는가. 규칙과 정의알고리즘의 방향
② 제약N의 범위, 값의 범위, 시간·메모리 제한자료형과 복잡도
③ 입출력 명세몇 줄에 무엇이 들어오고 무엇을 출력하나코드의 뼈대
읽는 순서를 바꾼다 대부분의 학생은 ① → ② → ③ 순으로 읽는다. 권하는 순서는 ③ → ② → ①이다.
입출력 명세를 먼저 보면 코드의 뼈대가 바로 잡히고, 제약을 보면 자료형과 알고리즘이 정해진다. 조건은 그 틀 안을 채우는 일이다. 이 순서로 읽으면 "다 풀고 나서 입력 형식이 달랐다"는 사고가 사라진다.

1.2제약 조건이 결정하는 두 가지

PART 1의 2장과 6장에서 배운 것을 하나의 절차로 묶는다. 제약 조건을 보면 코드를 쓰기 전에 두 가지가 정해진다.

① 자료형 — 최악의 경우 값을 계산한다

제약최악의 경우 값자료형
N ≤ 105, 각 값 ≤ 109, 합을 구함1014long long
두 값 ≤ 109, 곱을 구함1018long long
N ≤ 105, 각 값 ≤ 100, 합을 구함107int
N ≤ 106, 1부터 N까지의 합5 × 1011long long

2장의 교훈을 잊지 않는다. 최종 답이 아니라 계산 도중의 최댓값으로 판단한다.

② 허용 복잡도 — N을 보고 알고리즘을 고른다

N의 크기허용되는 복잡도이 파트에서 쓰는 방법
N ≤ 100O(N³)삼중 루프 완전탐색
N ≤ 5,000O(N²)모든 쌍 비교
N ≤ 106O(N) 또는 O(N log N)한 번 훑기, 정렬
N ≤ 1012O(√N) 또는 O(log N)약수 탐색, 공식

PART 2의 문제는 대부분 O(N)~O(N²)이다. 제약에 N ≤ 1000이 적혀 있으면 "이중 루프를 써도 좋다"는 출제자의 신호이고, N ≤ 100000이면 "한 번만 훑으라"는 뜻이다.

1.3입력 형식 네 가지 표준형

올림피아드 문제의 입력은 거의 전부 이 넷 중 하나다. 뼈대를 통째로 외운다.

유형 ① 단일 입력

유형 ② 개수 N이 먼저

유형 ③ 테스트케이스 T개

변수를 루프 안에서 선언한다 a, b를 루프 안에 선언하면 매 테스트케이스마다 새로 만들어진다. 밖에 두면 이전 케이스의 값이 남아, 입력이 하나 빠진 케이스에서 앞 답이 그대로 나온다. 누적 변수도 마찬가지로 매번 0으로 초기화한다(6장 오류 2).

유형 ④ 입력 끝까지(EOF)

3장에서 배운 대로 == 2로 판정한다. != EOF로 쓰면 숫자가 아닌 입력에서 무한 루프가 된다.

유형문제 서술의 신호뼈대
① 단일"두 정수가 주어진다"scanf 한 번
② N개"첫째 줄에 N", "N개의 수"for (i = 0; i < n; i++)
③ T개"테스트케이스", "첫째 줄에 T"for (t = 1; t <= T; t++)
④ EOF"입력의 끝까지", 개수 언급 없음while (scanf(...) == k)

1.4출력 형식 설계

채점은 stdout의 글자를 정답 파일과 글자 단위로 비교한다(1장 2.4절). 사람 눈에 안 보이는 차이가 오답을 만든다.

다섯 가지 출력
[A] 37
[B] 합은 37입니다
[C] 37
[D] 37
[E] 37.00
실제 바이트 (cat -A)
37$        ← 정상
37 $       ← 끝에 공백 (오답)
37         ← 줄바꿈 없음
잘못판정원인
안내문을 섞었다오답"합은 ~입니다"를 printf로
끝에 공백이 남았다오답printf("%d ", x)를 반복
마지막 줄바꿈이 없다문제에 따라\n 누락
정수를 실수로 출력오답%.2f 사용
소수 자릿수가 다르다오답문제가 요구한 자릿수 미확인

여러 값을 한 줄에 출력하는 두 가지 방법

끝 공백이 남는 방식
for (i = 0; i < n; i++) {
    printf("%d ", a[i]);
}
printf("\n");

→ "1 2 3 $"
깔끔한 방식
for (i = 0; i < n; i++) {
    if (i > 0) { printf(" "); }
    printf("%d", a[i]);
}
printf("\n");

→ "1 2 3$"
대개는 끝 공백을 허용한다 많은 채점 시스템이 줄 끝의 공백을 무시해 준다. 그러나 무시해 주지 않는 곳도 있다. 오른쪽 방식을 기본으로 쓰면 어디서든 안전하다. 습관을 들여 두면 생각할 일이 없어진다.

자신의 출력을 확인하는 명령

cat -A는 줄 끝을 $로, 탭을 ^I로 보여 준다. diff는 아무 출력이 없으면 완전히 같다는 뜻이다.

문제 첫 줄에 테스트케이스 개수 T(1 ≤ T ≤ 1000). 이후 T개 줄에 두 정수 A, B(−109 ≤ A, B ≤ 109). 각 줄마다 A + B를 출력하라.
항목적은 내용
1. 입력 유형③ T개
2. 한 케이스의 입력두 정수 A, B
3. 출력 형식케이스마다 한 줄, 정수 하나
4. 범위T ≤ 1000, |A|, |B| ≤ 109

5번에서 중요한 것이 걸렸다. INT_MAX가 약 2.147×109인데 합의 최대가 2×109이라 아슬아슬하게 들어간다. 그러나 범위가 조금만 커지면 넘치므로, 이런 경우 long long으로 쓰는 것이 안전하다.

05 — 흔한 오류

흔한 오류 여섯 가지

오류 1T를 데이터로 읽었다

도입 문제의 사고다. 첫 줄의 숫자가 개수인데 값으로 읽는다.

$ printf '3\n1 2\n10 20\n' | ./single
4            ← 3 + 1 을 출력했다

경고도 없고 죽지도 않는다. 그럴듯한 숫자가 나와서 틀렸다는 것을 알아채기 어렵다.

고치는 법 — 문제의 예시 입력을 그대로 넣어 예시 출력과 글자 단위로 비교한다. 출력 줄 수가 다르면 거의 이 오류다.
오류 2출력을 루프 밖에 두었다
for (int t = 1; t <= T; t++) {
    scanf("%d %d", &a, &b);
    sum = a + b;
}
printf("%d\n", sum);     // 마지막 케이스만 출력

출력이 한 줄만 나온다. 7장 오류 1(줄바꿈 위치)과 같은 구조다. printf가 루프 안인가 밖인가를 항상 확인한다.

고치는 법 — 케이스마다 출력하는 문제이면 printf를 루프 안에. 전체에 대해 한 번 출력하는 문제이면 밖에.
오류 3케이스 사이에 변수를 초기화하지 않았다
int sum = 0;                    // 루프 밖
for (int t = 1; t <= T; t++) {
    ...
    sum += x;                   // 이전 케이스가 누적된다
    printf("%d\n", sum);
}

첫 케이스는 맞고 두 번째부터 틀린다. 예시가 한 케이스뿐이면 발견되지 않는다.

고치는 법 — 케이스마다 쓰는 변수는 루프 안에서 선언한다. 그러면 초기화를 잊을 수가 없다.
오류 4출력에 안내문을 넣었다
printf("합은 %d입니다\n", s);      // 오답
printf("%d\n", s);                 // 올바름

디버깅하다가 넣어 둔 메시지를 지우지 않고 제출하는 경우가 많다. 1장에서 배운 대로 디버깅 출력은 stderr로 보내면 이 사고가 원천적으로 사라진다.

고치는 법 — fprintf(stderr, ...)를 쓴다. 채점에 포함되지 않으므로 지우지 않고 제출해도 안전하다.
오류 5제약 조건을 안 읽고 자료형을 정했다
// |A|, |B| ≤ 10^9 인데
int a, b;
printf("%d\n", a + b);        // 최대 2×10^9

예시 입력은 작은 수라서 통과한다. 큰 값이 들어오는 테스트에서만 틀린다. 2장 전체가 이 이야기였다.

고치는 법 — 체크리스트 5번을 반드시 적는다. 범위를 보고 최악의 값을 손으로 계산한 뒤 자료형을 정한다.
오류 6예시 출력을 글자 그대로 베끼지 않았다

고치는 법 — 문제의 예시 출력을 복사해 파일로 저장하고 diff로 비교한다. 눈으로 보지 않는다.
이 장의 가장 중요한 교훈 여섯 가지 모두 컴파일러가 아무 말도 하지 않는다. 그리고 1·2·3번은 출력이 정상적으로 나온다. 알고리즘을 아무리 잘 짜도 여기서 막히면 0점이다.
대책은 하나다. 문제의 예시 입출력을 파일로 저장하고 diff로 비교하는 것. 코드를 쓰기 전에 파일부터 만든다.

20

체크리스트 실전 — 아래 문제에 대해 체크리스트 일곱 줄을 모두 적은 뒤 코드를 작성하고, 경계 입력 세 개를 만들어 전부 통과시켜라. 각 단계에서 한 일을 기록한다.

문제 — 첫 줄에 테스트케이스 개수 T(1 ≤ T ≤ 100). 각 케이스는 첫 줄에 N(1 ≤ N ≤ 105), 둘째 줄에 N개의 정수(|값| ≤ 109). 케이스마다 합과 최댓값을 공백으로 구분해 한 줄에 출력하라.

※ T × N의 최댓값도 계산해야 한다. 전체 입력이 몇 개인지가 복잡도를 정한다.

07 — 확인 평가 해설

정답과 해설

※ 이 절은 교사용 통합본에만 수록한다. 학생 배부용에서는 제거한다.

01
합의 최대가 2×109로 INT_MAX(약 2.147×109)에 아슬아슬하게 들어간다. 정답은 int로도 되지만 long long을 권장한다. 범위가 조금만 커지면 넘치고, 판단에 시간을 쓰느니 넓게 잡는 편이 낫다.
02
합의 최대가 105 × 109 = 1014로 long long 필수. 배열에 담지 않고 읽으면서 누적한다(예제 2).
03
표준 코드 판본 2와 동일. 검증 — 출력 줄 수가 T와 같은지 세어 본다. 다르면 오류 1 또는 2다.
04
while (scanf("%d %d", &a, &b) == 2). 흔한 오답 — != EOF. 3장 오류 5를 다시 확인시킨다.
05
printf("Case #%d: %d\n", t, a + b); — #과 숫자 사이에 공백이 없고, 콜론 뒤에 공백 하나. 문제의 예시를 복사해 붙여 서식 문자열을 만들면 실수가 없다.
06
이중 구조다. 바깥 루프가 T, 안쪽이 N. 
for (int t = 0; t < T; t++) {
    int n; scanf("%d", &n);
    long long sum = 0;              // 케이스마다 0
    for (int i = 0; i < n; i++) { int x; scanf("%d", &x); sum += x; }
    printf("%lld\n", sum);
}
지도 포인트 — sum을 바깥에 선언하면 오류 3이 된다. 첫 케이스는 맞고 두 번째부터 틀리므로 예시에 케이스가 둘 이상 있어야 발견된다.
07
while (scanf("%d %d", &a, &b) == 2) {
    if (a == 0 && b == 0) { break; }
    printf("%d\n", a + b);
}
종료 신호를 먼저 검사하고 출력한다(5장 거르기 먼저). 순서를 바꾸면 0이 한 줄 더 출력된다.
08
예제 4의 방법 B. if (i > 0) printf(" ");. 지도 포인트 — 방법 A로 쓴 뒤 cat -A로 끝 공백을 확인시키면 차이를 체감한다.
09
체크리스트 5번 — N = 106이면 합은 약 5×1011. long long 필수.
printf("%lld\n", (long long)n * (n + 1) / 2); — 곱하기 전에 형변환(2장 도입 문제). n * (n+1)이 1012로 int를 넘는다.
10
long long sum으로 누적한 뒤 printf("%.2f\n", (double)sum / n);. 4장의 형변환 위치가 핵심이다. sum / n으로 쓰면 정수 나눗셈이 되어 2.00이 나온다.
11
scanf("%20s %d", name, &score)로 읽고 조건에 맞으면 바로 출력한다. 배열에 담을 필요 없다.
지도 포인트 — none 처리를 위해 출력 여부를 세는 변수가 하나 필요하다. "하나도 없을 때"를 빠뜨리는 답안이 많다.
12
scanf("%d-%d-%d", &y, &m, &d)(3장 예제 4). 출력은 printf("%d년 %d월 %d일\n", y, m, d); — 앞의 0을 붙이지 않는다(01월이 아니라 1월). 예시를 글자 그대로 본다.
13
곱의 최대가 1018로 long long이 필요하고, 곱하기 전에 형변환해야 한다. (long long)a * b. 합도 2×109이므로 함께 long long으로 처리하는 것이 간단하다.
14
출력한 개수를 세어 0이면 none. 공백 처리는 "이미 출력한 것이 있으면 앞에 공백"으로 한다. 
int cnt = 0;
for (...) { if (x > 0) { if (cnt > 0) printf(" "); printf("%d", x); cnt++; } }
if (cnt == 0) printf("none");
printf("\n");
지도 포인트 — 인덱스 i가 아니라 출력한 개수로 판단해야 한다. i > 0으로 쓰면 첫 양수 앞에 공백이 붙을 수 있다.
15
⑴ N ≤ 1,000이면 이중 루프 50만 번으로 통과한다.
⑵ N ≤ 106이면 이중 루프는 5×1011번으로 불가능하다. 가장 큰 두 수를 한 번 훑으며 찾는다(15장 연습 14번의 top2).
지도 포인트 — 답은 같은데 방법이 다르다. N이 알고리즘을 정한다는 것을 한 문제 안에서 체감시킨다. 7장 연습 20번의 재확인이다.
16
예제 5의 스크립트. 끝 공백을 넣은 버전은 diff가 즉시 다르다고 보고한다. 사람 눈으로는 구분이 안 되므로, 이 체험이 "눈으로 보지 말고 diff로 보라"는 원칙을 만든다.
17
① 단일판에 T개 입력 → 4 출력(3 + 1). T개판에 단일 입력 → 출력 없음.
② 전자는 종료 코드 0, 후자는 1(scanf 검사에서 걸림).
③ 전자가 훨씬 위험하다. 출력이 나오고 종료 코드도 0이라 정상처럼 보인다. 후자는 출력이 하나도 없어 즉시 이상을 알아챈다.
지도 포인트 — "출력이 나왔다"는 것이 아무것도 보장하지 않는다는 교훈이다. 반드시 예시 출력과 비교해야 한다.
18
세 쌍 모두 diff가 다르다고 보고한다. cat -A로 보면 37$ vs 37 $, 37$ vs 37($ 없음), YES$ vs YES $.
사람 눈으로는 구분할 수 없다. 터미널에서 공백은 보이지 않고 줄바꿈도 표시되지 않는다.
지도 포인트 — ⑵의 "마지막 줄바꿈 없음"은 채점 시스템에 따라 허용되기도 한다. 그러나 넣어서 틀리는 경우는 거의 없으므로 항상 넣는 것이 안전하다.
19
⑴ 단일 또는 N개 — 이것만으로는 알 수 없다. N 다음에 무엇이 오는지 봐야 한다. "N이 주어진다"로 끝나면 N 자체가 데이터인 단일 입력(유형 ①)이다.
⑵ 유형 ③ — for (t = 1; t <= T; t++)
⑶ 유형 ④ — while (scanf("%d %d", &a, &b) == 2)
⑷ 유형 ② — scanf("%d", &n) 후 for (i = 0; i < n; i++)
⑸ 유형 ④의 변형 — 종료 조건이 EOF가 아니라 특정 값이다. while (...) { if (a == 0 && b == 0) break; ... }
지도 포인트 — ⑴처럼 한 문장만으로는 판단할 수 없는 경우가 있다는 것이 핵심이다. 입출력 명세는 끝까지 읽는다.
20
체크리스트
1. 입력 유형 — ③ T개, 각 케이스 안에 ② N개(이중 구조)
2. 한 케이스 — N과 N개의 정수
3. 출력 — 케이스마다 한 줄, 합 최댓값
4. 범위 — T ≤ 100, N ≤ 105, |값| ≤ 109
5. 최악의 값 — 한 케이스 합이 105 × 109 = 1014 → long long
6. 복잡도 — 전체 입력 개수가 T × N = 107. 한 번 훑으므로 O(T·N)으로 통과
7. 경계 입력 — N = 1 / 모두 음수 / 모든 값이 109이고 N = 105

코드 — 이중 루프, sum과 mx를 케이스마다 초기화, mx는 첫 값으로.
지도 포인트 — 6번이 이 문제의 핵심이다. T와 N을 각각만 보면 작아 보이지만 곱하면 107이다. 전체 입력 개수를 계산하는 습관을 여기서 만든다. 그리고 "모두 음수"가 mx 초기값 오류를 잡는다.
08 — 마무리

이 장을 마치기 전 점검

  • 문제를 입출력 명세 → 제약 → 조건 순으로 읽는다
  • 코드를 쓰기 전에 체크리스트 일곱 줄을 적는다
  • 제약에서 자료형과 허용 복잡도를 먼저 결정한다
  • 입력 유형 네 가지의 뼈대를 외워서 쓴다
  • 케이스마다 쓰는 변수는 루프 안에서 선언한다
  • printf가 루프 안인지 밖인지 확인한다
  • 예시 입출력을 파일로 저장하고 diff로 비교한다
  • 디버깅 메시지는 stderr로 보낸다
다음 장 예고 — 02장 제약 조건과 시간복잡도 감각 이 장에서 "N을 보고 알고리즘을 고른다"고 했다. 다음 장에서는 그 판단을 표로 만들어 몸에 붙인다. 1초에 몇 번을 돌 수 있는지, 어떤 N에서 어떤 방법이 허용되는지를 직접 측정하고, 제약 조건만 보고 알고리즘을 말하는 훈련을 반복한다.
