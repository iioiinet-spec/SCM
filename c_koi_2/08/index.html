08

문자열 기초 처리

7장에서 값을 인덱스로 썼다. 이 장에서는 문자를 인덱스로 쓴다. 알파벳은 26칸이면 충분하니 카운팅 배열이 가장 잘 맞는 자리다. 그런데 그 전에, C의 문자열에는 보이지 않는 글자가 하나 있다는 것부터 알아야 한다.

학습 목표

  • '\0'의 역할을 설명하고 배열 크기를 N+1로 잡을 수 있다
  • strlen이 O(N)임을 알고 루프 조건에 쓰지 않는다
  • scanf("%s")와 fgets의 차이를 알고 상황에 맞게 고를 수 있다
  • 아스키 코드로 문자 분류와 대소문자 변환을 할 수 있다
  • 문자를 인덱스로 써서 26칸 카운팅 배열을 만들 수 있다
  • 문자열 비교에 == 대신 strcmp를 쓰는 이유를 설명할 수 있다

01 — 도입 문제

대문자로 바꾸는 데 0.4초

문제
문자열을 모두 대문자로 바꿔 출력하라.

제약
문자열의 길이 ≤ 200,000
자연스러운 코드
for (int i = 0; i < strlen(s); i++)
    s[i] = toupper(s[i]);

printf("%s\n", s);

길이 20만인 문자열로 돌려 보면,

측정
조건에 strlen        0.417초
길이를 미리 저장     0.00009초

배수 = 4,537배
고친 코드 — 한 줄 차이
int len = strlen(s);        /* 한 번만 */
for (int i = 0; i < len; i++)
    s[i] = toupper(s[i]);
왜 그렇게 느린가 strlen(s)은 문자열의 길이를 어딘가에서 꺼내 오는 것이 아니다. 맨 앞부터 한 글자씩 보며 '\0'을 찾을 때까지 세는 O(N) 함수다.
그것을 루프 조건에 두면 매 반복마다 처음부터 끝까지 다시 센다. 전체는 N + (N−1) + … ≈ N²/2 = 2 × 1010번이다. 2장의 표로 보면 확실한 시간 초과다.

이 한 줄짜리 버그의 뿌리는 '\0'이라는 보이지 않는 글자에 있다. C는 문자열의 길이를 따로 저장하지 않는다. 대신 끝에 0을 하나 놓아 두고 거기까지가 문자열이라고 약속한다. 이 장의 거의 모든 오류가 그 약속에서 나온다.

이 장이 답할 질문 ① 문자열을 담을 배열은 몇 칸이어야 하는가?
② 공백이 포함된 한 줄은 어떻게 읽는가?
③ 문자를 어떻게 배열의 인덱스로 쓰는가?
02 — 개념 정리

개념 정리

8.1'\0' — 보이지 않는 마지막 글자

실제 메모리
char s[20] = "abc";

s[0] = 97  ('a')
s[1] = 98  ('b')
s[2] = 99  ('c')
s[3] = 0   ('\0')  ← 끝 표시
s[4] = 0
...
두 가지 "크기"
sizeof(s) = 20   배열의 칸 수
strlen(s) = 3    '\0' 전까지의 글자 수

둘은 전혀 다른 것이다.
길이 N인 문자열은 N+1칸이 필요하다 char t[4] = "abc";는 딱 맞는다 — 글자 3개 + '\0' 하나.
문제에 "문자열의 길이 ≤ 100"이라고 적혀 있으면 char s[101]로 선언한다. 100으로 잡으면 가장 긴 입력에서 '\0'이 들어갈 자리가 없어 옆 메모리를 덮어쓴다.
습관 — 제약의 길이에 항상 +1, 불안하면 넉넉하게 +10.

8.2문자 하나와 문자열은 다르다

표기무엇인가크기비고
'a'문자 하나값 97작은따옴표. C에서는 int로 다룬다
"a"문자열2바이트큰따옴표. 'a'와 '\0'
'\0'값이 0인 문자값 0'0'(값 48)과 전혀 다르다

s[i] == "a"라고 쓰면 컴파일 오류이거나 엉뚱한 비교가 된다. 한 글자를 비교할 때는 반드시 작은따옴표다.

8.3strlen은 O(N)이다

도입 문제의 원인이다. 올바른 루프 조건은 두 가지다.

① 길이를 미리 저장
int len = strlen(s);
for (int i = 0; i < len; i++)
    ...

루프 안에서 길이가 바뀌지 않을 때
② '\0'까지 (더 간결)
for (int i = 0; s[i]; i++)
    ...
         ↑
  s[i] 가 '\0'(=0)이면 거짓

strlen 을 아예 안 쓴다
②를 기본으로 쓴다 for (int i = 0; s[i]; i++)는 한 번만 훑고 길이를 따로 구할 필요도 없다. 6장의 while (n)과 같은 관용구다 — 0이면 거짓이라는 C의 성질을 쓴 것이다.
길이 자체가 필요할 때만 strlen을 부르고, 그 결과를 변수에 담아 쓴다.

8.6문자를 인덱스로 — 26칸

7장의 카운팅 배열이 문자열에서 가장 잘 맞는다. 값의 범위가 26(또는 128)밖에 안 되기 때문이다.

알파벳 카운팅7장 기법의 문자열판
int cnt[26] = {0};

for (int i = 0; s[i]; i++) {
    char x = tolower((unsigned char)s[i]);
    if (x >= 'a' && x <= 'z')
        cnt[x - 'a']++;          /* ← 문자를 인덱스로 */
}
검증: "Mississippi"
i:4  m:1  p:2  s:4

합 = 11 = 문자열 길이
(자체 검산)
범위에 따른 배열 크기
알파벳만        26칸
알파벳 대소 구분  52칸
숫자까지         62칸
아스키 전체     128칸

전부 아주 작다 — 7장의
"값의 범위" 걱정이 없다
가장 단순한 방법은 128칸 문자 종류를 구분하기 귀찮으면 int cnt[128] = {0};에 cnt[(unsigned char)s[i]]++ 한 줄이면 끝난다. 알파벳·숫자·기호가 전부 제자리에 세어진다. 메모리는 512바이트다.
(unsigned char) 캐스팅은 한글이나 특수문자가 음수가 되는 것을 막는다. C의 char는 부호가 있을 수 있어서 128 이상의 바이트가 음수로 읽힌다.

8.7비교는 strcmp로

==는 내용을 비교하지 않는다
char s1[] = "abc";
char s2[] = "abc";

s1 == s2            → 거짓
  (주소를 비교한다)

strcmp(s1, s2) == 0 → 참
  (내용을 비교한다)
strcmp의 반환값
strcmp("apple","banana")  = -1
strcmp("banana","apple")  =  1
strcmp("abc","abc")       =  0
strcmp("abc","abcd")      = -100
strcmp("ABC","abc")       = -32
strcmp("Z","a")           = -7
반환값은 부호만 본다 측정 결과에서 보듯 -1이 아니라 -100이나 -32가 나오기도 한다. 구체적인 값은 보장되지 않는다. 반드시 < 0, == 0, > 0으로만 판정한다.
그리고 사전 순 비교는 아스키 코드 순이므로 대문자가 소문자보다 앞이다('Z'=90 < 'a'=97). 대소문자를 구분하지 않고 비교해야 한다면 양쪽을 모두 tolower한 뒤 비교한다.

03 — 표준 코드

표준 코드

readline.c공백 포함 한 줄 읽기 — 가장 많이 쓰는 뼈대
#include <stdio.h>
#include <string.h>

char line[1000001];              /* 길이 10^6 + '\0' + 여유 */

int main(void) {
    if (!fgets(line, sizeof line, stdin)) return 1;

    size_t L = strlen(line);
    if (L > 0 && line[L - 1] == '\n')
        line[--L] = '\0';          /* 개행 제거 + 길이도 줄인다 */

    printf("[%s] 길이 %zu\n", line, L);
    return 0;
}
L > 0 검사가 왜 필요한가 빈 입력이면 L이 0이고, line[L-1]은 line[-1]이 되어 배열 밖이다. 8.1절의 "+1"과 더불어 문자열의 양 끝을 늘 조심한다.
그리고 L을 size_t로 받았다면 L - 1이 0에서 엄청나게 큰 값이 된다(부호 없는 정수). 그래서 L > 0을 먼저 쓰거나, 아예 int로 받는다.
strlib.c문자열 처리 모음
#include <stdio.h>
#include <string.h>
#include <ctype.h>

/* ① 뒤집기 — j는 반드시 int */
void reverse(char *s) {
    int i = 0, j = (int)strlen(s) - 1;
    while (i < j) {
        char t = s[i]; s[i] = s[j]; s[j] = t;
        i++; j--;
    }
}

/* ② 회문 판정 */
int is_palindrome(const char *s) {
    int i = 0, j = (int)strlen(s) - 1;
    while (i < j) {
        if (s[i] != s[j]) return 0;
        i++; j--;
    }
    return 1;
}

/* ③ 알파벳 세기 (대소문자 구분 없이) */
void count_alpha(const char *s, int cnt[26]) {
    for (int k = 0; k < 26; k++) cnt[k] = 0;
    for (int i = 0; s[i]; i++) {
        int x = tolower((unsigned char)s[i]);
        if (x >= 'a' && x <= 'z') cnt[x - 'a']++;
    }
}

/* ④ 단어 세기 — 공백이 여러 개여도 된다 */
int count_words(const char *s) {
    int w = 0, in = 0;
    for (int i = 0; s[i]; i++) {
        if (s[i] != ' ') { if (!in) { w++; in = 1; } }
        else in = 0;
    }
    return w;
}
④의 in이 핵심이다 "공백을 세면 단어 수"라고 생각하면 공백이 연속하거나 앞뒤에 붙은 입력에서 틀린다. "공백이 아닌 글자가 나왔는데 직전이 공백이었으면 새 단어"로 세어야 한다.
검증 — "The Curious Case of Benjamin Button" → 6, " hello world " → 2, " " → 0, "a" → 1.

예제 2아나그램 — 카운팅 배열 두 번

"두 문자열이 같은 글자로 이루어졌는가"는 한 쪽은 더하고 다른 쪽은 빼서 전부 0인지 보면 된다.

예제 3최빈 알파벳 — 동점 처리

7장 예제 3의 문자열판이다. 동점일 때 무엇을 출력할지가 문제의 핵심이 된다.

측정
"Mississippi" → i:4, s:4  동점!
"Zbaba"       → a:2, b:2  동점!

동점 판정
int mx = 0, best = -1, dup = 0;
for (k = 0; k < 26; k++) {
    if (cnt[k] > mx) {
        mx = cnt[k]; best = k; dup = 0;
    } else if (cnt[k] == mx && mx > 0)
        dup = 1;
}
/* dup 이면 '?' 출력 */
mx > 0 조건이 필요한 이유 등장하지 않은 알파벳은 전부 0이다. mx가 0인 상태에서 cnt[k] == mx를 만나면 나오지도 않은 글자끼리 동점이 되어 버린다. 초기값과 비교하는 순간을 조심하는 것은 4장에서 배운 그대로다.

예제 4size_t의 함정

strlen의 반환형은 size_t인데, 이것은 부호 없는 정수다. 0에서 1을 빼면 음수가 아니라 엄청나게 큰 수가 된다.

빈 문자열에서
char s[8] = "";

int    j = strlen(s) - 1;
  → -1            (정상)

size_t j = strlen(s) - 1;
  → 18446744073709551615
무슨 일이 일어나나
뒤집기 코드의
  while (i < j)
에서 j 가 거대한 값이면
배열 밖을 마구 건드린다.

→ 즉시 크래시하거나
  조용히 메모리를 망가뜨린다
규칙 한 줄 인덱스로 쓸 값은 int로 받는다. strlen의 결과를 바로 빼서 쓰지 말고 int len = (int)strlen(s);처럼 한 번 담는다.
이것은 2장에서 다룬 오버플로와 같은 종류의 문제다 — 자료형의 경계에서 조용히 깨진다.

코드
for (int i = 0; s[i]; i++) {
    unsigned char c = s[i];
    s[i] = isupper(c) ? tolower(c)
                      : toupper(c);
}

알파벳이 아닌 글자는
toupper 가 그대로 두므로

직접 32를 더하고 빼는 방법으로 쓰면 if가 두 번 필요하고, 알파벳이 아닌 글자에서 깨진다. ctype.h를 쓰는 편이 짧고 안전하다.

05 — 흔한 오류

흔한 오류 여섯 가지

1
배열 크기를 길이와 똑같이 잡는다
"길이 ≤ 100"인데 char s[100]으로 선언하면 가장 긴 입력에서 '\0'이 들어갈 자리가 없어 옆 메모리를 덮어쓴다. 짧은 입력으로는 멀쩡하다.
대책 항상 +1, 불안하면 +10. 그리고 최대 길이 입력으로 반드시 테스트한다.
2
strlen을 루프 조건에 둔다
strlen은 O(N)이므로 전체가 O(N²)가 된다. 길이 20만에서 0.417초, 짧은 입력으로는 안 보인다.
대책 for (int i = 0; s[i]; i++)를 기본으로. 길이가 필요하면 변수에 담아 쓴다.
3
scanf 뒤에 바로 fgets를 쓴다
scanf가 남긴 개행을 fgets가 읽어 빈 줄이 들어온다. 길이 1짜리 "\n"이 되어 모든 처리가 어긋난다.
대책 사이에 while ((ch=getchar()) != '\n' && ch != EOF);를 넣거나 한 가지만 쓴다.
4
문자열을 ==로 비교한다
s1 == s2는 주소를 비교하므로 내용이 같아도 거짓이다. 컴파일 경고(-Warray-compare)가 나오지만 그냥 지나치기 쉽다.
대책 strcmp(s1, s2) == 0. 반환값은 부호만 본다(-1이 아니라 -100이 나올 수 있다).
5
strlen(s) - 1을 size_t로 받는다
빈 문자열에서 -1이 아니라 18446744073709551615가 된다. 뒤집기·회문 코드가 배열 밖을 휘젓는다.
대책 인덱스는 int로. int j = (int)strlen(s) - 1;
6
이미 대문자인 글자에 32를 뺀다
'A' - 32는 '!'(코드 33)이다. 알파벳이 아닌 글자(숫자·공백)에서도 깨진다.
대책 toupper/tolower를 쓴다. 직접 계산하려면 조건 검사를 반드시 같이 한다.
이 장의 가장 중요한 교훈 오류 1·2·5는 전부 '\0'에서 나온다. 끝을 표시하는 글자가 하나 있기 때문에 칸이 하나 더 필요하고(1), 길이를 세려면 끝까지 훑어야 하고(2), 길이가 0일 때 "마지막 글자의 위치"가 존재하지 않는다(5).
문자열 문제의 반례는 넷이다 — 빈 문자열 / 한 글자 / 최대 길이 / 공백이 섞인 입력. 네 개를 넣으면 이 장의 오류가 거의 전부 걸린다.

07 — 확인 평가

정답과 해설

01
fgets로 읽고 개행을 제거한 뒤 strlen. 배열은 char line[1000002](길이 106 + 개행 + '\0').
검증 — "hello world" → 11. 빈 줄 → 0.
지도 포인트 — scanf("%s")로 읽으면 hello만 읽혀 5가 나온다. 공백이 포함된 한 줄은 fgets라는 원칙을 여기서 못 박는다. 그리고 배열 크기가 왜 +2인지 설명하게 한다.
02
for (int i = 0; s[i]; i++) s[i] = toupper((unsigned char)s[i]);
검증 — "Hello, World 123!" → "HELLO, WORLD 123!". 쉼표·공백·숫자가 그대로다.
지도 포인트 — toupper가 알파벳이 아닌 글자를 그대로 둔다는 것이 핵심이다. s[i] - 32로 쓰면 쉼표가 '\f'가 되고 공백이 '\0'이 되어 문자열이 거기서 끊긴다. 실연해 보이면 강렬하다.
03
본문 reverse. int i = 0, j = (int)strlen(s) - 1;로 받는 것이 핵심.
검증 — "abcde"→"edcba", "ab"→"ba", "a"→"a", ""→"".
지도 포인트 — 빈 문자열에서 j = -1이 되어 i < j가 처음부터 거짓이 되는 것이 정상 동작이다. size_t로 받으면 여기서 터진다(15번). 두 경계(""와 "a")를 반드시 넣게 한다.
04
본문 is_palindrome. 양 끝에서 좁혀 오며 비교.
검증 — "level"→YES, "abba"→YES, "abc"→NO, "a"→YES, ""→YES, "Able"→NO.
지도 포인트 — 6장에서 수를 뒤집어 비교했던 것과 목적은 같고 방법이 다르다. 문자열판은 오버플로가 없고 길이 제한도 없다는 점을 짚는다. 6장 예제 1의 "수로 풀까 문자열로 풀까" 표를 다시 편다.
05
본문 count_alpha. cnt[tolower(s[i]) - 'a']++.
검증 — "Mississippi" → i:4, m:1, p:2, s:4. 합이 11로 문자열 길이와 일치한다.
지도 포인트 — 합으로 자체 검산하는 습관(4장 6번, 6장 8번)을 또 쓴다. 다만 알파벳이 아닌 글자가 섞이면 합이 길이보다 작아진다는 점도 짚는다 — 검산식은 "합 ≤ 길이"다.
06
본문 count_words. in 상태 변수로 "새 단어의 시작"만 센다.
검증 — "The Curious Case of Benjamin Button"→6, " hello world "→2, " "→0, "a"→1.
지도 포인트 — "공백 개수 + 1"로 세면 " hello world "에서 8이 나온다. 앞뒤 공백과 연속 공백이 표준 반례다. 문제에 "공백이 연속할 수 있다"는 말이 없어도 넣어 봐야 한다.
07
islower, isupper, isdigit, c == ' ', 나머지로 분류한다.
검증 — "aZ3 !" → 1, 1, 1, 1, 1.
지도 포인트 — 다섯 분류가 빠짐없이·겹치지 않게 되어 있는지 확인시킨다(3장). 개수의 합이 문자열 길이와 같아야 한다. 그리고 ctype.h 함수에 (unsigned char) 캐스팅을 붙이는 이유(음수 입력 방지)도 함께 다룬다.
08
int r = strcmp(a, b); if (r < 0) puts(a); else if (r > 0) puts(b); else puts("SAME");
검증 — strcmp("apple","banana") = −1, strcmp("abc","abcd") = −100, strcmp("ABC","abc") = −32.
지도 포인트 — 반환값이 −1이 아닐 수 있다는 것이 핵심이다. if (strcmp(a,b) == -1)로 쓰면 "abc"와 "abcd"에서 틀린다. 부호만 본다. 그리고 대문자가 소문자보다 앞선다는 것('Z'=90 < 'a'=97)도 확인시킨다.
09
측정 (길이 200,000) — strlen을 조건에 둔 판 0.417초 / 미리 저장한 판 0.00009초 → 약 4,537배.
연산 횟수로는 N²/2 = 2 × 1010 대 2 × 105이다.
지도 포인트 — 루프 안에서 문자열을 바꾸지 않으면 컴파일러가 strlen을 밖으로 빼 버려 차이가 안 보일 수 있다. 대문자 변환처럼 문자열을 수정하는 루프로 측정해야 한다. 2장 3.1절의 "volatile을 빼면 0초가 나온다"와 같은 종류의 함정이다.
10
예제 3의 동점 판정. 검증 — "Mississippi"는 i:4, s:4로 동점이라 ?. "Zbaba"도 a:2, b:2로 ?. "aAbB"도 ?.
지도 포인트 — 예제로 주어진 유명한 단어들이 대부분 동점이라는 것이 이 문제의 함정이다. 동점 처리를 빼먹으면 예제조차 통과하지 못한다. 그리고 mx > 0 조건 없이 짜면 알파벳이 하나도 없는 입력에서 엉뚱한 답이 나온다.
11
예제 2. 길이를 먼저 비교하고, 26칸 배열에 한쪽은 +1 다른 쪽은 −1.
검증 — listen/silent→YES, abc/cab→YES, abc/abd→NO, aab/abb→NO.
지도 포인트 — "aab"와 "abb"는 길이가 같고 글자 종류도 같지만 개수가 다르다. 체크 배열(있나)이 아니라 카운팅 배열(몇 개)이어야 하는 이유다. 7장 7.1절의 표를 다시 편다.
12
s[i] = isupper(c) ? tolower(c) : toupper(c);
검증 — "StuDY 2026!" → "sTUdy 2026!".
지도 포인트 — 삼항 연산자 한 줄로 끝난다. 직접 ±32로 쓰려면 if (islower) +32 else if (isupper) -32로 조건이 둘 필요하고, 조건을 빠뜨리면 숫자와 기호가 깨진다. 라이브러리가 경계 처리를 대신해 준다.
13
if (isdigit(c)) sum += c - '0'; — 6장의 관용구.
검증 — "a1b22c333" → 1+2+2+3+3+3 = 14.
지도 포인트 — c - '0'이 왜 숫자가 되는지(아스키 연속) 다시 설명하게 한다. 그리고 여러 자리 수로 읽는 것이 아니라 자릿수 하나씩 더한다는 점 — 문제가 "22를 22로 볼지 2+2로 볼지"를 명시했는지 확인시킨다(1장).
14
int i = 0;
while (s[i]) {
    while (s[i] == ' ') i++;              /* 공백 건너뛰기 */
    if (!s[i]) break;
    while (s[i] && s[i] != ' ') putchar(s[i++]);
    putchar('\n');
}
검증 — " the quick brown " → the / quick / brown 세 줄.
지도 포인트 — "공백 건너뛰기 → 단어 출력"의 반복이라는 구조를 잡는 것이 전부다. 06번의 in 변수 방식과 다른 접근인데 둘 다 맞다. 끝의 if (!s[i]) break;를 빼면 마지막 공백 뒤에 빈 줄이 하나 더 나온다 — 1장의 출력 형식 오류다.
15
size_t j = strlen(s) - 1;로 빈 문자열을 넣으면 j = 18446744073709551615. while (i < j)가 참이 되어 s[j], 즉 배열에서 한참 떨어진 메모리를 읽고 쓴다.
sanitizer 메시지 — AddressSanitizer: ... buffer-overflow 또는 SEGV.
지도 포인트 — 부호 없는 정수에서 0 − 1이 어떤 값이 되는지를 2장의 오버플로와 연결해 설명한다. 같은 원리이고 방향만 반대다. 그리고 -Wall로는 안 잡히지만 sanitizer로는 잡힌다는 점 — 도구마다 잡는 것이 다르다.
16
첫 루프에서 cnt[c]++, 둘째 루프에서 if (cnt[s[i]] == 1) { 출력; break; }.
검증 — "baabcd" → b는 2번, a는 2번, c가 1번 → c. 모두 중복이면 -1.
지도 포인트 — 두 번 훑어야 하는 전형적인 문제다(4장 8.4절의 판별 질문: "뒤에 올 입력이 필요한가" → 필요하다). 그리고 둘째 루프를 원래 순서대로 돌아야 "첫 번째"가 나온다 — 카운팅 배열을 훑으면 알파벳 순이 되어 틀린다.
17
양 끝 포인터를 쓰되 알파벳이 아니면 건너뛴다. 
int i = 0, j = (int)strlen(s) - 1;
while (i < j) {
    while (i < j && !isalpha((unsigned char)s[i])) i++;
    while (i < j && !isalpha((unsigned char)s[j])) j--;
    if (tolower(s[i]) != tolower(s[j])) return 0;
    i++; j--;
}
return 1;
검증 — "A man, a plan, a canal: Panama" → YES.
지도 포인트 — 안쪽 while에도 i < j 조건이 들어가야 한다. 빼면 알파벳이 하나도 없는 입력에서 양 포인터가 서로를 지나쳐 배열 밖으로 나간다. 중첩된 루프의 경계를 조심하는 문항이다.
18
⑴ 복잡도 — 시작 위치마다 P를 비교하므로 O(|S| × |P|) = 104 × 100 = 106. 2장의 기준으로 여유롭다.
⑵ 코드 — for (i = 0; i + plen <= slen; i++) if (strncmp(s+i, p, plen) == 0) cnt++;
⑶ 검증 — S = "aaaa", P = "aa" → 위치 0, 1, 2에서 모두 일치하므로 3.
지도 포인트 — 루프 조건이 i + plen <= slen인 것이 핵심이다. i < slen으로 쓰면 끝부분에서 배열 밖을 비교한다. 그리고 "겹치는 것도 센다"는 조건 때문에 찾은 뒤 i를 plen만큼 건너뛰면 안 된다 — 1장의 "문제를 끝까지 읽는다"다. |S|가 106급이면 이 방법으로는 부족하고 PART 3의 KMP가 필요하다.
19
14번처럼 단어의 시작과 끝을 찾은 뒤, 그 구간만 뒤집어 출력한다. 또는 단어를 임시 배열에 담아 reverse를 부른다.
검증 — "the quick brown" → "eht kciuq nworb".
지도 포인트 — "문자열 전체를 뒤집는 것"과 "각 단어를 뒤집는 것"이 완전히 다르다는 것을 먼저 확인시킨다(전체를 뒤집으면 "nworb kciuq eht"). 그리고 구간 [l, r]을 제자리에서 뒤집는 함수를 따로 만들면 03번 코드를 그대로 재사용할 수 있다 — 도구를 함수로 떼어 내는 연습이다(PART 1 10장).
20
⑴ 배열과 입력 — 길이 ≤ 105이고 공백이 포함되므로 fgets, 배열은 char line[100002](105 + 개행 + '\0'). 전역에 둔다(2장).
첫 줄의 T는 scanf("%d", &T)로 읽으므로 그 뒤에 남은 개행을 비워야 한다(오류 3). 아니면 T도 fgets로 읽는다.
⑵ 반례 목록 — ① 빈 줄(길이 0, 단어 0, 최빈 -, 회문 YES) ② 공백만 있는 줄 ③ 알파벳이 없는 줄("123 !") ④ 한 글자 ⑤ 최대 길이 105 ⑥ 최빈 알파벳 동점
⑶ 네 가지를 한 번씩 훑어 구한다 — 길이(strlen 한 번), 단어 수, 알파벳 카운팅, 회문 판정. 각각 O(길이)이므로 줄마다 O(4 × 길이)다.
⑷ 복잡도 — T × 길이 = 100 × 105 = 107. 통과.
⑸ 샘플 검산 — "banana": 길이 6, 단어 1, a가 3번으로 최빈 A, 회문 NO. "Mississippi": 길이 11, 단어 1, i와 s가 4번씩이라 동점 ?, 회문 NO. 세 번째 줄: 길이 30, 단어 7, a가 10번으로 최빈 A, 기호·대소문자를 무시하면 회문 YES.
참고로 "level"을 넣으면 l과 e가 둘 다 2번이라 답이 ?다 — 회문은 글자가 쌍으로 나타나므로 동점이 되기 쉽다. 동점 처리를 빼면 회문 예제부터 틀린다.
지도 포인트 — 이 문제는 이 장의 다섯 도구를 한 줄 입력에 전부 적용한다. 특히 ⑴의 "T를 읽은 뒤 개행 비우기"를 빠뜨리면 첫 줄이 빈 줄로 읽혀 전부 어긋난다 — 오류 3번이 실전에서 어떻게 나타나는지 보여 주는 자리다. 그리고 "알파벳이 없으면 -"라는 조건 한 줄이 mx > 0 검사를 강제한다는 것도 짚어 준다.
08 — 마무리

이 장을 마치기 전 점검

  • 배열 크기는 최대 길이 + 1 이상 (개행까지 받으면 +2)
  • 루프는 for (int i = 0; s[i]; i++)를 기본으로
  • strlen은 O(N) — 조건에 두지 않는다
  • 공백 포함 한 줄은 fgets, 단어 하나는 scanf("%s")
  • fgets 뒤에는 개행을 제거한다
  • scanf와 fgets를 섞어 쓸 때 남은 개행을 비운다
  • 인덱스로 쓸 값은 int로 받는다 (size_t 금지)
  • 문자 변환은 toupper/tolower, 비교는 strcmp
  • 반례 — 빈 문자열 / 한 글자 / 최대 길이 / 공백 섞인 입력
다음 장 예고 — 09장 2차원 격자 시뮬레이션 지금까지 다룬 것은 한 줄짜리 데이터였다. 다음 장은 평면으로 간다. PART 1 9장에서 배운 델타 배열이 본격적으로 쓰이고, 격자 바깥으로 나가는 것을 막는 경계 검사 한 줄이 모든 문제의 공통 뼈대가 된다. 좌표계가 뒤집히는 문제, 테두리를 한 칸 더 두는 기법도 함께 다룬다.
