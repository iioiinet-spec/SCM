06

진법 변환과 자릿수 처리

5장에서 %와 /로 수를 약수로 분해했다. 이 장은 같은 두 연산으로 수를 자릿수로 분해한다. 놀라운 것은, 10으로 나누고 남기는 두 줄이 모든 진법에 그대로 통한다는 점이다. 10을 b로 바꾸기만 하면 된다.

학습 목표

  • n % 10과 n / 10 두 줄로 수를 자릿수로 분해할 수 있다
  • 0과 음수라는 두 경계를 올바르게 처리할 수 있다
  • 10진수를 임의의 b진법으로 바꾸고, 결과가 역순으로 나오는 이유를 설명할 수 있다
  • 호너의 방법으로 b진법 문자열을 10진수로 되돌릴 수 있다
  • 숫자와 문자를 '0', 'A' 기준으로 변환할 수 있다
  • 역순 수·회문수에서 생기는 오버플로를 예상할 수 있다

01 — 도입 문제

두 줄이면 되는데 두 군데가 틀린다

문제
정수 N의 각 자릿수의 합을 출력하라.

제약
-1,000,000,000 ≤ N ≤ 1,000,000,000
정석 코드
int s = 0;
while (n) {
    s += n % 10;   /* 맨 뒷자리 */
    n /= 10;       /* 한 자리 버리기 */
}
printf("%d\n", s);

123을 넣으면 6이 나온다. 999는 27, 1000은 1. 전부 맞다. 그런데 이 두 입력을 넣어 보자.

입력 두 개
N = 0     → 합 0   (맞다)
N = -123  → 합 ?
실행 결과
-123 % 10 = -3    ← 음수다
-123 / 10 = -12

digit_sum(-123) = -6
                  ↑ 정답은 6

자릿수 합이 음수로 나왔다. C의 나머지 연산은 피연산자가 음수면 결과도 음수이기 때문이다(4장 4.7절에서 본 "0 방향 절삭"의 결과다). 그리고 "자릿수 개수"를 세는 코드에서는 더 조용한 오류가 난다.

이 장의 두 경계 ① n = 0 — while (n)이 한 번도 돌지 않는다. 합은 우연히 맞지만(0), 개수·변환·출력은 전부 틀린다.
② n < 0 — %의 결과가 음수가 된다. 부호를 먼저 떼어 내야 한다.

6.6b진법 → 10진수 — 호너의 방법

반대 방향은 더 쉽다. 역순 수를 만들 때 쓴 r = r * 10 + d에서 10을 b로 바꾼 것이다.

호너의 방법앞자리부터 읽으며 밀어 올린다
long long v = 0;
for (int i = 0; s[i]; i++) {
    int d = digit_of(s[i]);   /* 문자 → 숫자 */
    v = v * b + d;             /* 밀어 올리고 더한다 */
}
"FF"를 16진법으로 읽기
v = 0
'F' → d=15 : v = 0*16+15 = 15
'F' → d=15 : v = 15*16+15 = 255

→ 255
검증

"FF"       (16진법) → 255
"777"      ( 8진법) → 511

6.7숫자와 문자 사이

10진법을 넘어가면 자릿수가 10 이상이 되어 문자로 표현해야 한다. 변환식은 두 줄이다.

숫자 → 문자
char c = (d < 10)
       ? ('0' + d)
       : ('A' + d - 10);

d=7  → '7'
d=10 → 'A'
d=35 → 'Z'
문자 → 숫자
int d = (c >= '0' && c <= '9')
      ? (c - '0')
      : (c - 'A' + 10);

'7' → 7
'A' → 10
'Z' → 35
왜 - '0'인가 문자 '0'부터 '9'까지는 아스키 코드에서 연속한 값이다(48~57). 그래서 '7' - '0'은 55 − 48 = 7이 된다. 'A'~'Z'도 연속(65~90)이므로 같은 방식이 통한다.
숫자 48을 외울 필요는 없다. '0'이라고 쓰면 컴파일러가 알아서 48로 바꾼다. 14장 문자열에서 이 관용구를 본격적으로 쓴다.

읽을 때는 scanf("%x", &v)나 strtol(s, NULL, b)를 쓸 수 있다. strtol은 b를 2~36까지 받으므로 검산용으로 유용하다 — strtol("ZZ", NULL, 36)은 1295다.
03 — 표준 코드

표준 코드

digitlib.c자릿수 처리 모음
#include <stdio.h>

/* ① 자릿수의 합 (음수 대응) */
int digit_sum(long long n) {
    if (n < 0) n = -n;
    int s = 0;
    while (n) { s += n % 10; n /= 10; }
    return s;
}

/* ② 자릿수의 개수 (0 대응) */
int digit_count(long long n) {
    if (n < 0) n = -n;
    if (n == 0) return 1;        /* ← 이 줄이 없으면 0을 반환한다 */
    int c = 0;
    while (n) { c++; n /= 10; }
    return c;
}

/* ③ 역순 수 (반환형은 long long) */
long long reverse_num(long long n) {
    long long r = 0;
    while (n) { r = r * 10 + n % 10; n /= 10; }
    return r;
}

/* ④ 회문수 판정 */
int is_palindrome(long long n) {
    return reverse_num(n) == n;
}
base.c진법 변환 양방향 — 2 ≤ b ≤ 36
#include <stdio.h>
#include <string.h>

/* 10진수 n → b진법 문자열 out */
void to_base(long long n, int b, char *out) {
    char tmp[80];
    int len = 0;

    if (n == 0) { strcpy(out, "0"); return; }   /* ← 0 처리 */

    while (n) {
        int d = n % b;
        tmp[len++] = (d < 10) ? ('0' + d) : ('A' + d - 10);
        n /= b;
    }
    for (int i = 0; i < len; i++)
        out[i] = tmp[len - 1 - i];      /* ← 뒤집는다 */
    out[len] = '\0';
}

/* b진법 문자열 s → 10진수 */
long long from_base(const char *s, int b) {
    long long v = 0;
    for (int i = 0; s[i]; i++) {
        int d = (s[i] >= '0' && s[i] <= '9')
              ? (s[i] - '0') : (s[i] - 'A' + 10);
        v = v * b + d;                   /* ← 호너 */
    }
    return v;
}
tmp[80]이면 충분한 이유 가장 자릿수가 많아지는 경우는 b = 2다. long long의 최댓값 9.2 × 1018을 2진법으로 쓰면 63자리다. 측정해 보면 1018은 2진법으로 60자리(1이 24개)다.
그러므로 80칸이면 넉넉하다. 이렇게 최악의 길이를 먼저 계산하고 배열 크기를 정하는 것이 2장의 습관이다.
재귀판뒤집는 과정이 사라진다
void print_base(long long n, int b) {
    if (n == 0) return;                 /* 바닥 */
    print_base(n / b, b);                /* 윗자리를 먼저 */
    int d = n % b;
    putchar((d < 10) ? ('0' + d) : ('A' + d - 10));
}

/* 호출할 때 0을 따로 처리한다 */
if (n == 0) putchar('0');
else print_base(n, b);
putchar('\n');
재귀가 뒤집기를 대신한다 print_base(n/b, b)를 출력보다 먼저 부르므로, 가장 깊이 들어간 호출(맨 윗자리)이 가장 먼저 출력된다. 배열도 뒤집기도 필요 없다.
재귀 깊이는 자릿수만큼이므로 최대 63이다 — 전혀 위험하지 않다(PART 1 11장). 다만 n == 0일 때 아무것도 출력하지 않는다는 점은 똑같으므로 호출부에서 처리한다.

예제 1회문수 판정 — 뒤집어서 비교

역순 수를 만들 줄 알면 회문수는 한 줄이다.

코드
int is_pal(long long n) {
    return reverse_num(n) == n;
}
검증
  0 → 회문      7 → 회문

123 → 아님   1221 → 회문

수로 풀까, 문자열로 풀까 수로 — 코드가 짧다. 단, 뒤집은 값이 오버플로할 수 있다.
문자열로 — 양 끝에서 안쪽으로 좁혀 오며 비교한다. 오버플로가 없고 자릿수가 아무리 많아도 된다.
판단 기준 — 제약의 자릿수가 19를 넘으면 반드시 문자열이다. 그 안이면 둘 다 되고, 수 쪽이 짧다. 14장에서 문자열판을 다룬다.

예제 2왕복 검사로 변환 코드를 검증한다

진법 변환은 스스로 검산할 수 있는 드문 유형이다. 바꿨다가 되돌려서 원래 값이 나오면 맞는 것이다.

왕복 검사3장의 전수 비교를 변환에 적용
char buf[80];
int bad = 0;
for (long long n = 0; n <= 200000; n++)
    for (int b = 2; b <= 36; b++) {
        to_base(n, b, buf);
        if (from_base(buf, b) != n) bad++;
    }
printf("불일치 %d건\n", bad);

실제로 돌린 결과 7,000,035회 중 불일치 0건이었다. 2장의 복잡도 표로 보면 7 × 106이므로 몇 초 안에 끝난다.

왕복 검사가 못 잡는 것 두 함수가 똑같이 틀리면 왕복은 통과한다. 예를 들어 문자 변환에서 'A' 대신 'a'를 썼다면 양쪽이 일관되므로 왕복은 맞는다. 그래서 strtol로 몇 개를 교차 검증한다 — strtol("FF", NULL, 16) = 255, strtol("ZZ", NULL, 36) = 1295.

한 자리·두 자리 수는 항상 한수다. 루프가 i = 2부터이므로 c가 1이나 2면 아예 돌지 않고 ok가 1로 남는다 — 코드가 저절로 맞는다. 이런 구조를 만들면 예외 처리가 줄어든다.

예제 4디지털 루트 — 성질을 찾으면 루프가 사라진다

"자릿수의 합을 한 자리가 될 때까지 반복"한 값을 디지털 루트라 한다. 반복문으로 구할 수 있지만,

n디지털 루트n을 9로 나눈 나머지관계
000같다
990나머지 0 → 9
9990나머지 0 → 9
1234566같다
999999999990나머지 0 → 9

즉 n이 0이면 0, 9의 배수면 9, 아니면 n mod 9다. 반복문이 한 줄의 나머지 연산으로 바뀐다. 5장 17번(약수 개수가 홀수인 수 = 제곱수)과 같은 종류의 발견이다.

예제 52진법에서 1의 개수

진법 분해의 b = 2 특수형이다. % 2와 / 2를 비트 연산으로 쓰면 더 빠르고 짧다.

두 가지 표기
/* 나눗셈 */
while (n) { c += n % 2; n /= 2; }

/* 비트 연산 — 같은 뜻 */
while (n) { c += n & 1;  n >>= 1; }
측정
  n : 1의 개수 / 2진 자릿수
  1 →  1 /  1
  7 →  3 /  3
255 →  8 /  8
256 →  1 /  9
1023 → 10 / 10
10^18 → 24 / 60
비트 연산은 음수에서 다르게 동작한다 n >>= 1은 음수에서 부호를 유지하며 밀기 때문에 무한 루프가 될 수 있다. 비트 연산으로 자릿수를 셀 때는 반드시 n이 0 이상인지 확인하거나 unsigned long long으로 받는다.
PART 3의 비트마스크에서 이 연산을 본격적으로 쓴다. 지금은 %2·/2와 &1·>>1이 같은 일이라는 것만 알아 둔다.
05 — 흔한 오류

흔한 오류 여섯 가지

1
n = 0에서 아무것도 하지 않는다
while (n)이 한 번도 돌지 않아 자릿수 개수가 0, 진법 변환 결과가 빈 문자열이 된다. 합과 역순 수는 우연히 맞아서 더 안 보인다.
대책 while (n)을 쓰는 즉시 n = 0을 넣어 본다. 필요하면 if (n == 0)을 맨 위에 둔다.
2
음수를 그대로 분해한다
-123 % 10은 −3이다. 자릿수 합이 −6이 된다. 제약에 음수가 있는지 보지 않으면 놓친다.
대책 if (n < 0) n = -n;을 맨 위에. 그리고 long long으로 받아 INT_MIN 문제를 피한다.
3
진법 변환 결과를 뒤집지 않는다
나머지는 맨 아랫자리부터 나온다. 그대로 출력하면 1000의 2진수가 0001011111로 나온다(정답 1111101000).

4
역순 수를 int로 받는다
입력 1000000003은 int에 들어가지만 뒤집은 3000000001은 안 들어간다. 측정 결과 −1294967295가 나왔다.

5
10 이상의 자릿수를 숫자로 출력한다
16진법에서 d = 10일 때 printf("%d", d)로 쓰면 10이라는 두 글자가 나온다. 255가 1515가 된다.

자릿수 배열의 방향을 헷갈린다
while로 담으면 d[0]이 1의 자리이고 d[c-1]이 맨 앞자리다. 문제에서 "첫 번째 자리"라고 하면 보통 맨 앞을 뜻하므로 방향이 반대다.
대책 배열에 담은 직후 주석으로 방향을 적는다. 또는 담자마자 뒤집어 놓고 시작한다.
이 장의 가장 중요한 교훈 오류 1·2·4는 제약을 읽을 때 결정된다. "N은 0일 수 있는가", "음수일 수 있는가", "뒤집으면 몇 자리인가" — 세 질문을 코드 쓰기 전에 던지면 세 오류가 모두 사라진다. 1장의 체크리스트 5번(최악의 값)과 7번(경계 입력)이 그것이다.

지도 포인트 — 10진 회문은 reverse_num으로, 2진 회문은 문자열로 바꾼 뒤 양 끝 비교로 판정하는 것이 자연스럽다. 같은 "회문"이라도 진법이 다르면 다른 코드가 필요하다는 점, 그리고 06번·07번 함수를 조합하면 새 코드를 거의 안 써도 된다는 점(도구가 쌓인다)을 짚는다.
15
b를 2부터 36까지 돌며 from_base(S, b) == N인 첫 b를 찾는다. 단 S의 각 글자가 b보다 작은지 먼저 확인해야 한다 — "FF"는 b = 10에서 유효하지 않다.
검증 — 255 FF → 16. 255 11111111 → 2. 10 10 → 10.
지도 포인트 — 유효성 검사를 빠뜨리면 작은 b에서 엉뚱한 값이 나와 더 작은 b가 답으로 선택될 수 있다. "입력이 그 진법에서 가능한가"를 묻는 것이 이 문항의 핵심이고, 1장의 "제약을 끝까지 읽는다"와 같은 종류다.
16
int판 — 1000000003 → −1294967295.
long long판 — 3000000001. INT_MAX = 2147483647.
지도 포인트 — 입력이 int에 들어가는데 결과가 안 들어간다는 구조를 다시 짚는다. 3장 9번(삼각형 성립 조건)과 완전히 같은 함정이다. 모양만 다를 뿐 "중간값·결과값의 자릿수를 세라"는 교훈이 같다.
17
어긋나는 쌍이 존재한다. N = 1..100,000 / b = 2..36의 3,500,000쌍을 전수 비교하면 정확히 7쌍이 어긋나고, 모두 N이 b의 거듭제곱일 때다. 
n=  243  b= 3   변환 6자리 / 로그 5자리   log값 4.99999999999999911
n= 1000  b=10   변환 4자리 / 로그 3자리   log값 2.99999999999999956
n= 4913  b=17   변환 4자리 / 로그 3자리   (17^3)
n=29791  b=31   변환 4자리 / 로그 3자리   (31^3)
n=39304  b=34   변환 4자리 / 로그 3자리   (34^3)
n=59049  b= 3   변환 11자리 / 로그 10자리  (3^10)
log(1000)/log(10)은 수학적으로 정확히 3인데 double로는 2.99999999999999956이 되고, floor가 2를 주어 자릿수를 3으로 계산한다(정답 4).
대책 — ① 변환해서 세는 것이 가장 안전하다 ② 로그로 어림한 뒤 정수로 검산한다(5장 14번의 제곱근 보정과 같은 패턴).
지도 포인트 — 3장의 실수 비교 함정이 또 다른 모습으로 나타난 것이다. sqrt, log, pow는 전부 같은 위험을 가진다. "실수 함수의 결과를 정수로 쓸 때는 반드시 검산"을 규칙으로 만든다.
18
방법 ① — to_base(from_base(A,b) + from_base(B,b), b). 세 줄로 끝나지만 합이 long long을 넘으면 불가능하다.
방법 ② — 뒤에서부터 자릿수를 더하며 올림을 전파한다. 
int carry = 0;
for (i = 뒤에서부터) {
    int s = da[i] + db[i] + carry;
    out[k++] = s % b;      /* 자리 */
    carry    = s / b;      /* 올림 */
}
if (carry) out[k++] = carry;
검증 — FF + 1 (16진법) → 100. 1 1 (2진법) → 10.
지도 포인트 — 올림 처리 s % b와 s / b가 6.1절의 분해 두 줄과 같은 식이라는 것을 발견하게 한다. 그리고 방법 ②는 자릿수가 아무리 많아도 되므로 PART 3의 큰 수 연산으로 이어진다. 3장 예제 5의 자리 넘김(알람 시계)과도 같은 구조다.
19
각 수마다 자릿수 합을 구해 최댓값을 갱신한다. 초기값은 a[1]에 해당하는 첫 값(4장).
N = 100 → 99(합 18). N = 1,000 → 999(합 27). N = 106 → 999999(합 54).
복잡도 — 각 수의 자릿수는 최대 7자리이므로 N × 7 = 7 × 106. 2장의 기준으로 여유롭게 통과한다.
지도 포인트 — 자릿수 분해의 비용이 O(log N)이라는 것을 수치로 체감시킨다. "루프 안에 루프가 있으니 O(N²)인가?" 하는 오해를 여기서 푼다 — 안쪽은 자릿수만큼이므로 상수에 가깝다. 2장의 복잡도 세기를 다시 적용하는 문항이다.
20
⑴ 질의별 경계 입력
질의경계 입력이유
1 (자릿수 합)0, -123, -10^180 / 음수 / n = -n 안전성
2 (b진법 출력)0 아무 b, b=2 최댓값, b=16빈 출력 / 60자리 / 문자 자릿수
3 (10진수 복원)"0", "ZZ" b=36, 60자 문자열0 / 문자 변환 / 오버플로
⑵ 자료형 — N과 결과 모두 long long. 문자열 버퍼는 80칸(2진 63자리 + 여유). 질의가 105개이므로 버퍼는 재사용한다(매번 선언해도 되지만 전역이 안전하다).
⑶ 복잡도 — 질의 하나가 O(자릿수) = 최대 60. 전체 105 × 60 = 6 × 106. 통과.
⑷ 검증 — 질의 2와 3이 서로 역함수이므로 왕복 검사가 그대로 가능하다. 무작위 N과 b를 10만 쌍 만들어 3(2(N, b), b) == N을 확인한다.
지도 포인트 — 이 문제의 핵심은 질의 2와 3이 서로의 정답지라는 점이다. 5장 20번이 "미리 표를 만든다"였다면 여기는 "서로 검산한다"이다. 문제 구조 안에 검증 수단이 들어 있는지를 살피는 눈을 기르는 것이 목적이다. 그리고 2 0 16이 0을 출력해야 한다는 샘플 한 줄이 오류 1번을 정조준하고 있다는 것도 짚어 준다.
08 — 마무리

이 장을 마치기 전 점검

  • 분해는 n % b와 n /= b 두 줄이다 (10도 b의 하나다)
  • while (n)을 쓰면 그 자리에서 n = 0을 넣어 본다
  • 음수는 if (n < 0) n = -n;으로 부호를 먼저 뗀다
  • 역순 수·회문 판정은 항상 long long
  • 진법 변환 결과는 반드시 뒤집는다 (또는 재귀)
  • 10 이상의 자릿수는 'A' + d - 10
  • b진법 → 10진수는 호너 v = v * b + d
  • 변환 코드는 왕복 검사로 스스로 검증한다
  • 반례 — n = 0, 한 자리, 음수, b = 2, b = 16, 최댓값
다음 장 예고 — 07장 배열 카운팅과 체크 배열 4장에서 자릿수를, 5장에서 소수를 배열에 담아 세었다. 다음 장은 그 기법에 이름을 붙이고 본격적으로 쓴다. 값을 인덱스로 쓴다는 한 줄의 발상이 O(N²)를 O(N)으로 바꾸는 장면을 여러 번 보게 된다. 2장 예제 2에서 미뤄 둔 "두 수의 합" 문제가 여기서 제대로 풀린다.
