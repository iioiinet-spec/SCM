09

2차원 격자 시뮬레이션

지금까지 다룬 것은 한 줄짜리 데이터였다. 이 장은 평면으로 간다. PART 1 9장에서 배운 델타 배열이 본격적으로 쓰이고, 경계 검사 한 줄이 거의 모든 격자 문제의 공통 뼈대가 된다. 그 한 줄을 빠뜨리면 어떻게 되는지부터 본다.

학습 목표

  • 문자 격자와 정수 격자를 올바르게 입력할 수 있다
  • 델타 배열을 시계 방향으로 외워 쓰고 회전을 (d+1)%4로 처리할 수 있다
  • 경계 검사 한 줄을 모든 이웃 탐색에 붙일 수 있다
  • 패딩으로 경계 검사를 아예 없애는 기법을 쓸 수 있다
  • 행 우선 순회가 왜 빠른지 측정으로 설명할 수 있다
  • 전치·반전·90도 회전의 인덱스 식을 유도할 수 있다

02 — 개념 정리

개념 정리

9.1격자를 읽는 두 가지

정수가 공백으로 구분될 때
int a[102][102];

for (int i = 0; i < n; i++)
    for (int j = 0; j < m; j++)
        scanf("%d", &a[i][j]);
숫자나 기호가 붙어 있을 때
char g[102][102];

for (int i = 0; i < n; i++)
    scanf("%101s", g[i]);
            ↑ 한 줄이 문자열 하나

a[i][j] = g[i][j] - '0';   /* 필요하면 */

입력이 1234 / 5678 / 9012처럼 붙어서 들어오면 %d로는 1234를 통째로 읽어 버린다. 이럴 때는 한 줄을 문자열로 읽은 뒤 8장의 - '0' 관용구로 숫자를 꺼낸다. 검증 — 위 입력에서 g[1][2]는 '7'이고, 정수로 바꾼 첫 행은 1 2 3 4다.

배열 크기는 넉넉하게 +2 문자열로 읽으면 '\0' 자리가 필요하고(8장), 패딩을 쓰면 테두리 자리도 필요하다. 제약이 100이면 [102][102]로 잡는다. 메모리는 어차피 작다 — char면 10KB, int여도 41KB다.

9.2델타 배열 — 시계 방향으로 외운다

4방향상 → 우 → 하 → 좌 (시계 방향)
int dr[4] = {-1, 0, 1, 0};   /* 행 변화 */
int dc[4] = { 0, 1, 0, -1};   /* 열 변화 */
d방향(dr, dc)행이 줄면 위, 열이 늘면 오른쪽
0상(−1, 0)행 번호는 아래로 갈수록 커진다. 수학의 y축과 반대이므로 "위 = −1"이다
1우(0, +1)
2하(+1, 0)
3좌(0, −1)
시계 방향으로 적는 이유 — 회전이 공짜가 된다
회전식검증
오른쪽 90°d = (d + 1) % 4상→우, 우→하, 하→좌, 좌→상
왼쪽 90°d = (d + 3) % 4상→좌, 좌→하, 하→우, 우→상
반대 방향d = (d + 2) % 4상→하, 우→좌
왼쪽 90°를 (d - 1) % 4로 쓰면 d = 0에서 −1이 된다(4장에서 본 C의 음수 나머지). +3을 더하는 것이 안전하다.

9.38방향

8방향상 → 우상 → 우 → 우하 → 하 → 좌하 → 좌 → 좌상
int dr8[8] = {-1, -1, 0, 1, 1,  1,  0, -1};
int dc8[8] = { 0,  1, 1, 1, 0, -1, -1, -1};
델타 배열은 반드시 검산한다 8방향은 숫자가 16개라 하나만 틀려도 어떤 칸을 두 번 보거나 한 칸을 빠뜨린다. 두 가지로 검산한다.
① 합이 0인가 — 대칭이므로 dr의 합도 dc의 합도 0이어야 한다. 측정 결과 둘 다 0.
② 3×3을 덮는가 — 중앙 (0,0)을 뺀 8칸이 정확히 한 번씩 나오는지 세어 본다. 측정 결과 일치.
이 두 줄짜리 검산을 하면 델타 오타로 몇 시간을 잃는 일이 사라진다.

9.4경계 검사 — 네 조건을 한 줄로

이웃 탐색의 표준형이 모양을 통째로 외운다
for (int d = 0; d < 4; d++) {
    int nr = r + dr[d];
    int nc = c + dc[d];
    if (nr < 0 || nr >= n || nc < 0 || nc >= m) continue;
    /* 여기서부터 (nr, nc)는 안전하다 */
}
세 가지를 같이 기억한다 ① 조건은 ||로 네 개다. 3장에서 배운 대로 0 <= nr < n처럼 쓰면 안 된다.
② 행의 한계는 n, 열의 한계는 m이다. 정사각형이 아닐 때 둘을 바꿔 쓰는 실수가 가장 많다.
③ continue로 건너뛰는 형태가 기본이다. 뒤집어서 if (안쪽이면) { ... }로 써도 되지만, 조건이 길어지면 들여쓰기가 깊어진다.

9.5패딩 — 경계 검사를 아예 없앤다

격자의 사방에 한 칸씩 테두리를 두고 그 자리를 "아무것도 없음"으로 채우면, 밖으로 나가도 테두리에 떨어지므로 검사가 필요 없어진다.

검사판
char m[N][N];
/* 데이터는 [0..N-1] */

for (d = 0; d < 8; d++) {
    ni = i+dr8[d]; nj = j+dc8[d];
    if (ni<0||ni>=N||nj<0||nj>=N)
        continue;
    if (m[ni][nj]=='*') c++;
}
패딩판
char m[N+2][N+2];
/* 데이터는 [1..N], 테두리는 '.' */

for (d = 0; d < 8; d++)
    if (m[i+dr8[d]][j+dc8[d]]=='*') c++;

           ↑ if 가 사라졌다
방법 (1000×1000, 20회 반복)시간결과
경계 검사판0.116초합이 79,920,000으로 동일
패딩판0.075초 (약 1.5배)
패딩의 진짜 이득은 속도가 아니라 코드다 1.5배는 큰 차이가 아니다. 진짜 이득은 경계 검사를 빠뜨릴 수 없게 된다는 것이다. 이 장 오류의 절반이 "검사를 한 군데 빠뜨림"에서 나온다.
쓸 수 있는 조건 — 테두리 값이 답에 영향을 주지 않아야 한다. 지뢰 세기에서 테두리를 '.'로 두면 안전하고, 합을 구할 때 테두리를 0으로 두면 안전하다. 반대로 최솟값을 구하는데 테두리가 0이면 틀린다(4장의 초기값 판단과 같은 질문).
그리고 인덱스가 1부터가 된다. 2장의 누적합에서 1부터 쓴 것과 같은 이유다.

9.6행 우선으로 훑는다

C의 2차원 배열은 메모리에 한 행씩 이어서 놓인다. 그래서 순회 순서가 속도를 바꾼다. 4000×4000 격자(61MB)로 측정했다.

순회 순서시간비고
for i: for j: a[i][j] (행 우선)0.010초메모리 순서대로 읽는다
for j: for i: a[i][j] (열 우선)0.112초11.2배 느리다

더한 합은 같다(48,000,006). 같은 칸을 전부 더하므로 당연하다. 답은 같고 시간만 11배 차이라는 점이 핵심이다.

2장의 "상수 최적화"에 해당한다 복잡도는 양쪽 다 O(N²)다. 바뀐 것은 상수인데 11배다. 2장에서 "상수 최적화는 최대 4배"라고 했지만, 캐시가 걸린 경우에는 10배를 넘기도 한다.
습관 — 2차원 배열은 항상 i를 바깥, j를 안쪽에 둔다. 특별한 이유가 없으면 순서를 바꾸지 않는다.

9.7격자 변환 — 식을 외우지 말고 유도한다

변환식유도
전치t[j][i] = a[i][j]행과 열을 바꾼다
상하 반전t[n-1-i][j] = a[i][j]행 번호만 뒤집는다
좌우 반전t[i][m-1-j] = a[i][j]열 번호만 뒤집는다
90° 시계t[j][n-1-i] = a[i][j]전치 + 좌우 반전
90° 반시계t[m-1-j][i] = a[i][j]전치 + 상하 반전
검증: 90° 시계
원본        회전
1 2 3   →   7 4 1
4 5 6   →   8 5 2
7 8 9   →   9 6 3

1행이 마지막 열이 된다.
검산법
"전치 후 좌우 반전"으로 두 번
돌린 결과와, 식 하나로 직접
돌린 결과를 비교한다.

4×4로 확인 → 완전히 일치
식을 외우지 말고 한 칸으로 확인한다 다섯 식을 외우면 반드시 헷갈린다. 왼쪽 위 a[0][0]이 어디로 가는지 한 칸만 따져 본다. 90° 시계면 a[0][0]은 오른쪽 위, 즉 t[0][n-1]로 간다. 식 t[j][n-1-i]에 i=0, j=0을 넣으면 t[0][n-1]이다. 맞다.
정사각형이 아니면 결과의 크기가 n×m에서 m×n으로 바뀐다는 것도 잊지 않는다.

9.8(행, 열)과 (x, y)를 섞지 않는다

표기첫 번째두 번째위쪽은?
(행, 열) — 배열행 r (세로)열 c (가로)r이 작은 쪽
(x, y) — 수학x (가로)y (세로)y가 큰 쪽
문제가 (x, y)로 말하면 종이에 적는다 "좌표 (3, 5)에 있다"는 문장이 a[3][5]인지 a[5][3]인지는 문제가 정한다. 예제 입출력으로 확인하고 종이에 변환 규칙을 적은 뒤 코드를 쓴다.
권장 — 코드 안에서는 무조건 (행, 열)로 통일한다. 입력을 받는 순간 변환하고, 그 뒤로는 r, c라는 이름만 쓴다. 변수 이름을 x, y로 두면 반드시 어느 순간 헷갈린다.
03 — 표준 코드

표준 코드

minesweeper.c8방향 세기 — 경계 검사판
#include <stdio.h>

char g[102][102];
int n, m;
int dr8[8] = {-1,-1,0,1,1, 1, 0,-1};
int dc8[8] = { 0, 1,1,1,0,-1,-1,-1};

int main(void) {
    if (scanf("%d %d", &n, &m) != 2) return 1;
    for (int i = 0; i < n; i++)
        if (scanf("%101s", g[i]) != 1) return 1;

    for (int i = 0; i < n; i++) {          /* 행 우선 */
        for (int j = 0; j < m; j++) {
            if (g[i][j] == '*') { putchar('*'); continue; }
            int c = 0;
            for (int d = 0; d < 8; d++) {
                int ni = i + dr8[d], nj = j + dc8[d];
                if (ni < 0 || ni >= n || nj < 0 || nj >= m) continue;
                if (g[ni][nj] == '*') c++;
            }
            putchar('0' + c);
        }
        putchar('\n');
    }
    return 0;
}

5 5
*....
.....
.*...
.....
....*
출력 (검증 완료)

22100
1*100
11111
0001*
minesweeper_pad.c같은 문제 — 패딩판
char m2[102][102];                  /* 데이터는 [1..n][1..m] */

memset(m2, '.', sizeof m2);          /* 테두리까지 전부 '.' */
for (int i = 1; i <= n; i++)
    scanf("%101s", m2[i] + 1);         /* 1번 칸부터 채운다 */

for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= m; j++) {
        if (m2[i][j] == '*') { putchar('*'); continue; }
        int c = 0;
        for (int d = 0; d < 8; d++)
            if (m2[i + dr8[d]][j + dc8[d]] == '*') c++;   /* 검사 없음 */
        putchar('0' + c);
    }
    putchar('\n');
}

두 판의 출력이 완전히 같다는 것을 확인했다. 패딩판은 if가 하나 사라졌고, scanf에 m2[i] + 1을 넘기는 것이 요령이다.

walk.c이동 시뮬레이션 — 벽에 부딪히면 제자리
const char *ds = "UDLR";             /* 명령 문자 */
int mr[4] = {-1, 1, 0, 0};
int mc[4] = { 0, 0, -1, 1};

int r = 0, c = 0;
for (int k = 0; cmd[k]; k++) {
    int d = 0;
    for (int t = 0; t < 4; t++) if (ds[t] == cmd[k]) d = t;

    int nr = r + mr[d], nc = c + mc[d];
    if (nr < 0 || nr >= n || nc < 0 || nc >= m) continue;  /* 제자리 */
    r = nr; c = nc;
}
"벽이면 제자리"와 "벽이면 무시"는 다르다 위 코드는 이동만 취소하고 다음 명령으로 넘어간다. 문제에 따라 그 자리에서 멈춘다(남은 명령을 버린다)일 수도 있다. 1장에서 배운 대로 문제 문장을 끝까지 읽고 어느 쪽인지 확인한다.
검증 — 5×5 격자에서 (0,0) 시작, 명령 RRDDLU → (0,1) → (0,2) → (1,2) → (2,2) → (2,1) → (1,1).

예제 2경계 검사를 뒤집어 쓰기

같은 조건을 두 가지로 쓸 수 있다. 3장의 드모르간이 여기서 쓰인다.

밖이면 건너뛴다 (권장)
if (nr < 0 || nr >= n ||
    nc < 0 || nc >= m) continue;

/* 본문 */
안이면 처리한다
if (0 <= nr && nr < n &&
    0 <= nc && nc < m) {
    /* 본문 */
}

둘은 완전히 같다. 다만 본문이 길어지면 왼쪽이 읽기 쉽다 — 들여쓰기가 늘지 않기 때문이다. 그리고 &&를 ||로 바꾸는 것을 잊지 않는 것이 3장의 교훈이다.

자주 나오는 오타 nr >= n을 nr > n으로 쓰면 마지막 행 바로 밖을 읽는다. 3장의 경계 판단 그대로다. 1×1 격자를 넣어 보면 즉시 드러난다.

예제 3지뢰찾기를 두 판으로 만들어 비교한다

05 — 흔한 오류

흔한 오류 여섯 가지

1
경계 검사를 빠뜨린다
격자 밖을 읽어도 크래시하지 않고 0이 나온다. 쓰기라면 옆 변수가 조용히 망가진다. 안쪽 칸만 테스트하면 절대 안 걸린다.
대책 이웃 탐색 세 줄을 통째로 외운다. -fsanitize=address로 한 번 돌려 본다. 또는 패딩으로 검사 자체를 없앤다.
2
행과 열의 한계를 바꿔 쓴다
nr >= m, nc >= n처럼 쓰면 정사각형에서는 멀쩡하고 직사각형에서만 틀린다. 예제가 정사각형이면 끝까지 안 보인다.
대책 n은 행, m은 열로 고정한다. 그리고 n ≠ m인 격자(예: 3×5)를 반드시 테스트한다.
3
델타 배열에 오타가 있다
8방향은 숫자가 16개다. 하나만 틀려도 어떤 칸을 두 번 보거나 한 칸을 빠뜨린다. 결과가 미묘하게만 달라 찾기 어렵다.
대책 예제 1의 검산 두 줄(합이 0 / 3×3을 덮는가)을 코드 쓰기 전에 돌린다.
4
왼쪽 회전을 (d-1)%4로 쓴다
d = 0일 때 -1 % 4는 C에서 −1이다(4장). 배열 인덱스로 쓰면 격자 밖이다.
대책 (d + 3) % 4. 음수 나머지가 나올 수 있는 모든 자리에서 법만큼 더하고 나눈다.
5
열 우선으로 훑는다
for j: for i: 순서면 답은 같은데 11.2배 느리다. 작은 격자에서는 안 보이고 큰 격자에서만 시간 초과가 난다.
대책 i를 바깥, j를 안쪽으로 고정한다. 특별한 이유 없이 바꾸지 않는다.
6
회전을 제자리에서 한다
a[j][n-1-i] = a[i][j]는 아직 읽지 않은 칸을 먼저 덮어쓴다. 결과가 뒤죽박죽이 되는데 작은 격자에서는 우연히 맞기도 한다.
대책 새 배열에 담는다. 메모리는 충분하다(1000×1000 int가 4MB).
이 장의 가장 중요한 교훈 오류 1·2·3은 전부 "안쪽 칸만 보면 멀쩡"하다. 격자 문제의 반례는 항상 테두리에 있다.
격자 문제의 표준 반례 다섯 개 — ① 1×1 ② 1×m(한 줄짜리) ③ n×1(한 열짜리) ④ n ≠ m인 직사각형 ⑤ 네 모서리. 다섯 개를 넣으면 이 장의 오류가 거의 전부 걸린다.

07 — 확인 평가

정답과 해설

01
한 번 훑으며 전체 합, 행별 합, 열별 합을 동시에 모은다(4장 8.4절).
검증 — 1 2 3 / 4 5 6 → 전체 21, 행별 6 15, 열별 5 7 9.
지도 포인트 — 값이 109이고 칸이 106개이므로 전체 합은 최대 1015다. long long이 필요하다(2장·4장). 그리고 행 우선으로 훑으면 세 가지를 한 번에 모을 수 있다는 점도 짚는다.
02
scanf("%s", g[i])로 한 줄씩 읽는다. 배열은 char g[1002][1002].
검증 — 예제에서 #이 5개.
지도 포인트 — %d로 읽으려 하면 .#..에서 막힌다. 붙어 있는 격자는 문자열이라는 것을 여기서 못 박는다. 그리고 각 행의 길이가 m과 같은지 strlen으로 확인하는 것도 좋은 검산이다(8장).
03
예제 1의 두 검산. 4방향은 합이 (0, 0), 8방향도 (0, 0). 3×3 덮기는 8방향에서만 의미가 있고 가운데를 뺀 8칸이 한 번씩 나온다.
지도 포인트 — 이 두 줄을 습관으로 만드는 것이 목적이다. 학생에게 일부러 델타 하나를 틀리게 적은 뒤 검산이 잡아내는지 보여 주면 효과가 크다. 3장의 "전수 검사"가 델타 배열에 적용된 형태다.
04
4방향 델타 + 경계 검사.
검증 — 3×3 격자 1..9에서 (0,0)의 이웃은 2와 4이므로 6, (0,1)은 1+3+5 = 9, (1,1)은 2+4+6+8 = 20, (2,1)은 7+9+5 = 21. 전체 출력은 6 9 8 / 13 20 17 / 12 21 14.
지도 포인트 — 모서리 칸은 이웃이 2개, 변 위의 칸은 3개, 안쪽은 4개다. 출력을 보며 이것을 확인시키면 경계 검사가 실제로 동작하는지 눈으로 검산할 수 있다.
05
본문 minesweeper.c.
검증 — 출력 *1000 / 22100 / 1*100 / 11111 / 0001*.
지도 포인트 — 지뢰 칸은 세지 말고 그대로 *를 출력해야 한다. 지뢰 칸에도 숫자를 쓰면 틀린다. 그리고 putchar('0' + c)가 6장의 숫자→문자 변환이라는 점을 연결한다.
06
for (i=0;i<n;i++) { d1 += a[i][i]; d2 += a[i][n-1-i]; }
검증 — 4×4 격자 1..16에서 주대각선 1+6+11+16 = 34, 반대각선 4+7+10+13 = 34.
지도 포인트 — a[i][n-1-i]가 반대각선이라는 것을 i=0과 i=n-1을 넣어 확인시킨다. i=0이면 a[0][n-1](오른쪽 위), i=n-1이면 a[n-1][0](왼쪽 아래)다. 9.7절의 "한 칸으로 확인" 습관이다.
07
t[j][n-1-i] = a[i][j], 결과는 M×N.
검증 — 1 2 3 / 4 5 6 / 7 8 9 → 7 4 1 / 8 5 2 / 9 6 3.
지도 포인트 — 결과의 크기가 바뀐다는 것을 반드시 짚는다. N≠M인 입력(3×4)을 넣어 결과가 4×3이 되는지 확인시킨다. 정사각형만 테스트하면 이 오류가 안 보인다(오류 2와 같은 성질).
08
명령 문자를 방향 번호로 바꾼 뒤 이동, 격자 밖이면 continue.
검증 — 5×5에서 RRDDLU → (0,1) → (0,2) → (1,2) → (2,2) → (2,1) → (1,1).
지도 포인트 — "무시"와 "멈춤"의 차이를 다시 묻는다(본문 walk.c). 그리고 1×1 격자를 넣으면 모든 명령이 무시되어 (0,0)이 나와야 한다 — 표준 반례 ①이다.
09
본문 minesweeper_pad.c. 세 가지가 핵심 — memset으로 테두리를 '.'로, 입력을 m2[i] + 1로, 루프를 1부터.
두 판의 출력이 완전히 일치함을 확인했다.
지도 포인트 — 패딩의 이득이 1.5배의 속도가 아니라 "검사를 빠뜨릴 수 없게 되는 것"임을 강조한다. 그리고 테두리 값이 답에 영향을 주지 않는지 따져 보게 한다 — 여기서는 '.'이라 안전하지만, 최솟값 문제였다면 테두리를 0으로 두면 틀린다.
10
측정 (4000×4000, 61MB) — 행 우선 0.010초 / 열 우선 0.112초 → 11.2배. 합은 둘 다 48,000,006으로 동일.
지도 포인트 — 답은 같고 시간만 11배라는 점이 전부다. 복잡도는 둘 다 O(N²)이므로 2장의 표로는 구분되지 않는다. 복잡도가 같아도 상수가 다르다는 것을 캐시로 설명한다(PART 1 9장). 작은 격자에서는 차이가 안 나므로 큰 격자로 재야 한다는 것도 짚는다.
11
경계 검사를 빼면 (0,0)에서 g[-1][0]과 g[0][-1]을 읽는다. 측정에서는 0이 나오고 크래시하지 않았다.
sanitizer 메시지 — AddressSanitizer: global-buffer-overflow, READ of size 4.
지도 포인트 — "오류가 안 난다"가 "맞다"가 아니다. 7장 15번과 같은 교훈이다. 그리고 g[-1][0]이 왜 g[0][-1]과 같은 자리를 가리키는지(2차원 배열이 메모리에 한 줄로 놓이므로) 설명하면 9.6절의 캐시 이야기와 자연스럽게 이어진다.
12
R이면 d = (d+1)%4, L이면 d = (d+3)%4, F면 전진하되 밖이면 무시.
검증 — 5×5, (0,0) 방향 1(우)에서 FFRFFL → F:(0,1), F:(0,2), R:d=2(하), F:(1,2), F:(2,2), L:d=1(우) → 2 2 1.
지도 포인트 — (d-1)%4로 쓰면 d=0에서 −1이 되어 dr[-1]을 읽는다(오류 4). 이것도 크래시 없이 쓰레기가 나온다. 음수 나머지는 4장에서 이미 다뤘으므로 학생이 스스로 떠올리게 유도한다.
13
if (i == 0 || i == n-1 || j == 0 || j == m-1) sum += a[i][j];
검증 — 3×3 1..9에서 가운데 5를 뺀 나머지 합 = 45 − 5 = 40.
지도 포인트 — 1×1이면 유일한 칸이 가장자리이므로 그 값이 답이다. 1×M이면 모든 칸이 가장자리다. "네 변을 따로 더하기"로 짜면 모서리를 두 번 세거나 1×M에서 틀린다. 조건 하나로 판정하는 쪽이 경계를 자동으로 처리한다 — 3장의 "빠짐없이·겹치지 않게"다.
14
변환식결과 크기
전치t[j][i] = a[i][j]M×N
상하 반전t[n-1-i][j] = a[i][j]N×M
좌우 반전t[i][m-1-j] = a[i][j]N×M
90° 반시계t[m-1-j][i] = a[i][j]M×N
지도 포인트 — 크기가 바뀌는 둘(전치·회전)과 안 바뀌는 둘(반전)을 구분시킨다. 그리고 각 식을 a[0][0] 한 칸으로 검산하게 한다(예제 4). 4×4로 "전치 후 좌우 반전 = 90° 시계"를 확인한 결과와 맞춰 보면 식 사이의 관계가 보인다.
15
0도(그대로)부터 시작해 90도씩 네 번 돌리며 매번 비교한다. 돌릴 때마다 크기가 바뀌므로 크기가 다르면 바로 건너뛴다.
지도 포인트 — 크기 비교를 먼저 하는 것이 요령이다. N≠M이면 90도와 270도는 크기가 달라 애초에 비교할 필요가 없다. 1장의 "먼저 걸러 내기"이고, 8장 아나그램의 길이 비교와 같은 발상이다.
16
P[i][j] = a[i][j] + P[i-1][j] + P[i][j-1] - P[i-1][j-1], 질의는
P[r2][c2] - P[r1-1][c2] - P[r2][c1-1] + P[r1-1][c1-1].
검증 — 3×3 1..9에서 (1,1)~(2,2) → 1+2+4+5 = 12, (2,2)~(3,3) → 5+6+8+9 = 28.
복잡도 — 전처리 O(N·M) = 106, 질의마다 O(1). 전체 통과.
지도 포인트 — 2장 18번에서 식만 보았던 것을 여기서 직접 작성한다. 인덱스를 1부터 쓰면 P[0][*]와 P[*][0]이 전부 0이라 경계 검사가 사라진다 — 9.5절의 패딩과 같은 발상이다. P는 long long이어야 한다.
17
방문 배열을 두고, 격자 밖이거나 이미 방문했으면 d = (d+1)%4로 꺾는다. N×M번 반복한다. 
int r=0, c=0, d=1;              /* 오른쪽부터 */
for (int k = 0; k < n*m; k++) {
    출력(a[r][c]); vis[r][c] = 1;
    int nr = r+dr[d], nc = c+dc[d];
    if (nr<0||nr>=n||nc<0||nc>=m||vis[nr][nc]) {
        d = (d+1)%4;
        nr = r+dr[d]; nc = c+dc[d];
    }
    r = nr; c = nc;
}
검증 — 3×4 격자 → 1 2 3 4 8 12 11 10 9 5 6 7.
지도 포인트 — PART 1 7장에서는 닫힌 식으로 달팽이를 풀었다. 여기서는 시뮬레이션으로 푼다. 같은 문제를 두 방법으로 풀어 본 셈인데, 시뮬레이션이 훨씬 쉽고 변형에 강하다는 것을 체감시킨다. 방향 전환 조건이 "밖 또는 방문함" 두 가지라는 점이 핵심이다.
18
8방향 이웃을 세어 규칙을 적용한다. 반드시 새 배열에 쓴다.
검증 — 세로 막대 3개 → 가로 막대 3개(점멸기).
왜 새 배열인가 — 제자리에 쓰면 이미 바뀐 칸을 이웃으로 세게 된다. (1,2)를 갱신한 뒤 (2,2)를 계산할 때 (1,2)의 새 값을 보게 되어, "한 세대 뒤"가 아니라 뒤죽박죽이 된다.
지도 포인트 — 오류 6번(제자리 회전)과 같은 원리다. "읽는 배열과 쓰는 배열을 분리"는 시뮬레이션의 기본 규칙이다. 여러 세대를 돌릴 때는 두 배열을 번갈아 쓰거나 매번 복사한다.
19
⑴ 단순 방법 — 시작 위치 N·M개마다 K²칸을 더하면 O(N·M·K²). N=M=K/2=1,000이면 106 × 106으로 불가능하다.
⑵ 누적합 — 16번의 2차원 누적합을 만든 뒤, 각 시작 위치마다 O(1)로 합을 구한다. 전체 O(N·M) = 106.
for (i = K; i <= n; i++)
  for (j = K; j <= m; j++) {
    long long s = P[i][j] - P[i-K][j] - P[i][j-K] + P[i-K][j-K];
    if (s > best) best = s;
  }
지도 포인트 — 2장 도입(구간 합)의 2차원판이다. 질의가 미리 주어지지 않아도 누적합이 쓰인다는 것 — "모든 위치를 다 보는 것"이 곧 106개의 질의다. 그리고 best의 초기값은 4장대로 첫 정사각형의 합으로 둔다(값이 음수일 수 있다면 0은 틀린다).
20
⑴ 좌표계 — 문제가 (행, 열)로 말하고 방향도 0=상, 1=우, 2=하, 3=좌로 시계 방향이다. 본문 9.2절의 델타를 그대로 쓸 수 있다. 종이에 dr = {-1,0,1,0}, dc = {0,1,0,-1}을 적고 시작한다.
⑵ 배열과 패딩 — char vis[1001][1001] = 1MB. 패딩은 쓰지 않는다 — 전진을 "무시"해야 하므로 경계를 명시적으로 판정해야 하기 때문이다(패딩은 "밖을 읽어도 안전"일 뿐 "밖인지 알려 주지" 않는다). 방문 배열은 전역(2장).
⑶ 반례 다섯 — ① 1×1(모든 F가 무시, 지나간 칸 1) ② 1×M(상하 이동이 전부 무시) ③ N×1 ④ N≠M인 직사각형 ⑤ 네 모서리에서 시작. 추가로 명령이 회전뿐인 경우(지나간 칸 1)와 같은 칸을 여러 번 지나는 경우(중복으로 세면 안 된다).
⑷ 복잡도 — 명령마다 O(1)이므로 105. 통과.
⑸ 샘플 검산 — 5×5, (0,0) 방향 1에서 FFRFFL: F→(0,1), F→(0,2), R→d=2, F→(1,2), F→(2,2), L→d=1. 지나간 칸은 (0,0),(0,1),(0,2),(1,2),(2,2)로 5개, 최종 2 2 1.
지도 포인트 — ⑵의 판단이 이 문제의 함정이다. 패딩이 항상 좋은 것이 아니라 "밖인지 알아야 하는 문제"에서는 쓸 수 없다는 것을 깨닫는 자리다. 그리고 지나간 칸을 세는 데 방문 배열이 필요하다는 것은 7장의 체크 배열이 2차원으로 확장된 것이다 — 도구가 차원을 넘어 따라온다.
08 — 마무리

이 장을 마치기 전 점검

  • 델타는 시계 방향으로 적고 회전은 (d+1)%4, (d+3)%4
  • 델타 배열은 합이 0인지 / 3×3을 덮는지 검산한다
  • 이웃 탐색에 경계 검사 한 줄을 반드시 붙인다
  • 행의 한계는 n, 열의 한계는 m — 바꿔 쓰지 않는다
  • 테두리 값이 답에 영향이 없으면 패딩으로 검사를 없앤다
  • 순회는 i 바깥, j 안쪽 (11.2배)
  • 변환 식은 a[0][0]이 어디로 가는지로 확인한다
  • 시뮬레이션은 읽는 배열과 쓰는 배열을 분리한다
  • 반례 — 1×1 / 1×m / n×1 / 직사각형 / 네 모서리
다음 장 예고 — 10장 완전탐색 입문 2장에서 "N ≤ 20이면 O(2N), N ≤ 10이면 O(N!)"이라고 했다. 다음 장은 그 허락을 실제로 쓰는 법을 다룬다. 모든 부분집합을 만드는 두 가지 방법(재귀와 비트), 모든 순열을 만드는 법, 그리고 중복을 어떻게 피하는가가 핵심이다. PART 1 11장의 재귀가 여기서 제값을 한다.
