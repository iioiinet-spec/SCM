10

완전탐색 입문

2장에서 "N ≤ 20이면 O(2N), N ≤ 10이면 O(N!)"이라고 판정만 했다. 이 장은 그 허락을 실제로 쓰는 법을 다룬다. 그리고 허락 범위를 넘어선 N에서도, 한 줄만 넣으면 돌아가는 경우가 있다는 것을 본다.

학습 목표

  • 완전탐색의 두 모양(부분집합 2N / 순열 N!)을 구분할 수 있다
  • 모든 부분집합을 재귀와 비트마스크 두 가지로 만들 수 있다
  • 모든 순열을 used 배열과 되돌리기로 만들 수 있다
  • 조합에서 중복을 피하는 두 가지 기법을 쓸 수 있다
  • 가지치기 한 줄로 탐색을 수만 배 줄일 수 있다
  • 되돌리기를 빠뜨리면 생기는 증상을 알아볼 수 있다

2차시순열 · 조합 · 중복 처리 · 가지치기

01 — 도입 문제

한 줄이 14만 배

문제
N개의 수에서 일부를 골라
합이 S가 되게 하는 경우의 수는?

제약
1 ≤ N ≤ 30
1 ≤ A[i] ≤ 100,000
1 ≤ S ≤ 100,000
시간 제한 1초
완전탐색 — 넣거나 안 넣거나
void rec(int i, int s) {
    if (i == n) {
        if (s == S) cnt++;
        return;
    }
    rec(i+1, s);          /* 안 넣는다 */
    rec(i+1, s + a[i]);   /* 넣는다 */
}

2장의 표로 보면 N ≤ 20이면 통과, N = 30이면 230 ≈ 10억으로 불가능이다. 실제로 재 보면 그렇다.

왜 그렇게 줄어드는가 합이 이미 S를 넘었다면 뒤에 무엇을 더 넣어도 S가 될 수 없다(값이 모두 양수이므로). 그 아래 가지 전체가 볼 필요 없는 가지다. 하나를 잘라 내면 그 밑에 달린 수천·수만 개가 통째로 사라진다.
이것을 가지치기라고 한다. 완전탐색은 "모든 경우를 다 해 보는 것"이지만, 해 보지 않아도 아는 경우를 빼는 것까지가 한 세트다.

② 같은 경우를 두 번 세지 않으려면?
③ 어떤 조건이면 가지를 잘라도 되는가?

10.1완전탐색의 두 모양

모양가짓수허용 N (2장)문제의 신호
부분집합2NN ≤ 20"일부를 고른다", "뽑는다", "켜거나 끈다"
순열N!N ≤ 10"순서를 정한다", "줄을 세운다", "방문 순서"
조합C(N, M)경우 수를 계산"M개를 고른다" (순서 무관)
중복 순열MNMN ≤ 108"각 칸에 M가지 중 하나"

측정값 — 순열은 N=10에서 362만 가지에 0.10초, N=11에서 3,992만 가지에 1.27초다. 2장에서 계산한 "N ≤ 10"이라는 기준이 그대로 확인된다.

먼저 가짓수를 센다 코드를 쓰기 전에 "몇 가지가 나오는가"를 계산한다. 2N인가 N!인가 C(N,M)인가. 그 수가 2장의 표에서 통과 구간에 있으면 완전탐색을 쓰고, 아니면 가지치기로 줄일 수 있는지 본다. 그래도 안 되면 다른 알고리즘이다(PART 3).

10.2부분집합 ① 재귀 — 넣거나 안 넣거나

부분집합 재귀가장 중요한 뼈대
void rec(int i, int s) {
    if (i == n) {              /* 바닥: 모든 원소를 결정했다 */
        /* s 로 할 일 */
        return;
    }
    rec(i + 1, s);             /* i번째를 안 넣는다 */
    rec(i + 1, s + a[i]);      /* i번째를 넣는다 */
}
호출 구조 (N=3)
            rec(0)
          /        \
      rec(1)        rec(1)
      /   \         /   \
   rec(2) rec(2) rec(2) rec(2)
    / \    / \    / \    / \
   8개의 잎 = 2^3
호출 수
잎 = 2^N
전체 호출 = 2^(N+1) - 1

N=20 → 2,097,151
N=24 → 33,554,431
N=30 → 2,147,483,647
합을 인자로 들고 다닌다 s + a[i]를 인자로 넘기면 합을 매번 다시 계산할 필요가 없다. 이것이 다음 절의 비트마스크보다 빠른 이유다. 재귀의 인자는 "여기까지 결정한 상태"를 담는 자리다.

10.3부분집합 ② 비트마스크

N개의 원소를 "넣음/안 넣음"으로 표시하면 N자리 2진수가 된다. 0부터 2N−1까지 세면 모든 부분집합이 한 번씩 나온다.

N=4일 때
mask  2진   집합
  0  0000   {}
  5  0101   {0, 2}
 10  1010   {1, 3}
 15  1111   {0,1,2,3}
코드
for (int mask = 0; mask < (1 << n); mask++) {
    int s = 0;
    for (int i = 0; i < n; i++)
        if (mask & (1 << i))
            s += a[i];
    /* s 로 할 일 */
}
식뜻예 (mask = 10, 2진 1010)
1 << ii번 비트만 켜진 수1<<0=1, 1<<3=8
(mask >> i) & 1i번이 켜져 있나i=1 → 1, i=2 → 0
mask | (1 << i)i번을 켠다i=0 → 11
mask & ~(1 << i)i번을 끈다i=1 → 8
1 << n부분집합의 개수n=4 → 16
비트마스크가 더 빠를 거라는 오해 같은 문제(합이 S인 부분집합 세기)를 두 방법으로 측정했다.
N재귀비트마스크비율
200.005초0.074초14.8배
220.020초0.311초15.6배
240.087초1.270초14.6배
재귀가 훨씬 빠르다. 비트마스크는 mask마다 안쪽 루프를 N번 돌아 합을 처음부터 다시 계산하므로 O(N · 2N)이고, 재귀는 합을 들고 다니므로 O(2N)이다.
그럼 비트마스크는 언제 쓰나 — 코드가 짧고 재귀 없이 쓸 수 있으며, 가지치기가 불가능한 경우(부분집합마다 독립적인 계산)에 편하다. 그리고 mask 자체를 다른 자료의 인덱스로 쓸 수 있다(PART 3의 비트마스크 DP).

10.4순열 — used와 되돌리기

순열 생성N! 가지
int used[12], pick[12];

void perm(int d) {
    if (d == n) { /* pick[0..n-1]이 완성된 순열 */ return; }

    for (int i = 0; i < n; i++) {
        if (used[i]) continue;      /* 이미 쓴 원소는 건너뛴다 */
        used[i] = 1;
        pick[d] = a[i];
        perm(d + 1);
        used[i] = 0;              /* ← 되돌리기 */
    }
}

(123) (132) (213)
(231) (312) (321)

작은 인덱스부터 보므로
사전 순으로 나온다.
되돌리기를 빠뜨리면
(123)

→ 한 가지만 나온다.

한 번 쓴 원소가 영원히
"쓴 것"으로 남기 때문이다.
되돌리기는 "다음 형제를 위한 것"이다 perm(d+1)이 끝나고 돌아오면, 같은 자리에 다른 원소를 넣어 봐야 한다. 그러려면 방금 쓴 원소를 다시 쓸 수 있게 돌려놓아야 한다.
규칙 — 바꾼 것은 반드시 되돌린다. used[i] = 1과 used[i] = 0은 항상 짝으로 쓴다. 재귀 호출을 사이에 두고 위아래로.

10.5조합 — 시작 인덱스로 중복을 막는다

조합은 순서를 따지지 않는다. {1,2}와 {2,1}은 같은 것이다. 순열처럼 짜면 같은 조합이 여러 번 나온다. 해법은 "항상 뒤쪽에서만 고른다"는 규칙이다.

조합 생성N개 중 M개
void comb(int start, int d) {
    if (d == m) { /* pick[0..m-1]이 완성된 조합 */ return; }

    for (int i = start; i < n; i++) {   /* start 부터! */
        pick[d] = a[i];
        comb(i + 1, d + 1);            /* 자기 다음부터 */
    }
}
C(n, m)측정 개수공식값시간
C(10, 3)1201200.0000초
C(20, 5)15,50415,5040.0001초
C(20, 10)184,756184,7560.0016초
C(24, 12)2,704,1562,704,1560.0298초
used 배열이 필요 없다 start부터만 고르므로 이미 고른 원소를 다시 고를 수 없다. 되돌릴 것도 없다. 조합이 순열보다 코드가 짧은 이유다.
부분집합도 조합의 합이다 — C(n,0) + C(n,1) + … + C(n,n) = 2n. 그래서 m을 0부터 n까지 바꿔 가며 comb을 부르면 모든 부분집합이 나온다.

10.6중복 원소가 있을 때

입력에 같은 값이 섞여 있으면 같은 결과가 여러 번 나온다. {1, 1, 2}에서 2개를 고르면,

그냥 하면
(11) (12) (12)
            ↑
     같은 조합이 두 번

첫 번째 1과 짝지은 2,
두 번째 1과 짝지은 2
정렬한 뒤 한 줄 추가
for (int i = start; i < n; i++) {
    if (i > start && b[i] == b[i-1])
        continue;      /* ← 추가 */
    ...
}

→ (11) (12)
두 가지가 모두 필요하다 ① 정렬 — 같은 값이 붙어 있어야 b[i] == b[i-1]로 판별할 수 있다.
② i > start 조건 — 이 자리의 첫 번째 후보는 써야 한다. 조건이 없으면 같은 값을 아예 한 번도 못 쓴다.
읽는 법은 "이 자리에서 같은 값은 한 번만"이다. 중복 원소 처리가 필요한지는 제약에 "서로 다른"이라는 말이 있는지로 판단한다.

10.7가지치기 — 이 장의 핵심

도입에서 본 한 줄이다. 조건을 일반화하면 이렇다.

가지치기의 종류조건예
불가능지금 상태로는 답이 될 수 없다if (s > S) return; (값이 모두 양수)
이미 졌다최선을 다해도 현재 답보다 나쁘다if (cost >= best) return;
중복같은 경우를 이미 봤다10.6절의 b[i] == b[i-1]
대칭좌우·회전이 같은 경우첫 선택을 절반으로 제한
가지치기가 틀리면 답이 바뀐다 if (s > S) return;은 값이 모두 양수일 때만 옳다. 음수가 섞여 있으면 합이 S를 넘었다가 다시 내려올 수 있으므로 정답을 잘라 버린다.
검증 방법 — 가지치기 없는 판과 있는 판을 모두 만들어 작은 N에서 답이 같은지 비교한다. 도입의 측정에서도 양쪽 답이 64가지로 같음을 확인했다. 3장·6장에서 쓴 "두 판 비교"가 여기서도 검증 도구다.
얼마나 줄어드는지는 입력에 달려 있다 도입의 측정은 S = 20이고 값이 1..30이라 대부분의 가지가 금방 S를 넘는다. S가 매우 크면(전체 합에 가까우면) 가지치기가 거의 효과가 없다.
그래서 가지치기는 "최악의 경우 복잡도를 줄이지 못한다". 2장의 표로는 여전히 O(2N)이다. 그런데도 실전에서 통과시키는 일이 많다 — 이론과 실측을 둘 다 봐야 하는 대표적인 자리다.
03 — 표준 코드

표준 코드

subsum.c부분집합의 합 — 가지치기 포함
#include <stdio.h>

int n, S, a[31];
long long cnt;

void rec(int i, int s) {
    if (s > S) return;                  /* 가지치기 (값이 모두 양수일 때) */
    if (i == n) { if (s == S) cnt++; return; }
    rec(i + 1, s);
    rec(i + 1, s + a[i]);
}

int main(void) {
    if (scanf("%d %d", &n, &S) != 2) return 1;
    for (int i = 0; i < n; i++)
        if (scanf("%d", &a[i]) != 1) return 1;
    rec(0, 0);
    printf("%lld\n", cnt);
    return 0;
}
perm.c모든 순열 — 되돌리기를 짝으로
int n, a[11], used[11], pick[11];

void perm(int d) {
    if (d == n) {
        for (int i = 0; i < n; i++) {
            if (i) putchar(' ');
            printf("%d", pick[i]);
        }
        putchar('\n');
        return;
    }
    for (int i = 0; i < n; i++) {
        if (used[i]) continue;
        used[i] = 1; pick[d] = a[i];
        perm(d + 1);
        used[i] = 0;
    }
}
comb.cN개 중 M개 — 중복 원소 대응판
int n, m, a[25], pick[25];

void comb(int start, int d) {
    if (d == m) {
        for (int i = 0; i < m; i++) {
            if (i) putchar(' ');
            printf("%d", pick[i]);
        }
        putchar('\n');
        return;
    }
    for (int i = start; i < n; i++) {
        if (i > start && a[i] == a[i - 1]) continue;  /* 중복 (정렬 전제) */
        pick[d] = a[i];
        comb(i + 1, d + 1);
    }
}
세 코드의 공통 구조 ① 바닥 조건(if (d == n) 또는 i == n)이 맨 위에 있다.
② 선택을 하고 ③ 재귀를 부르고 ④ 되돌린다(조합은 되돌릴 것이 없다).
⑤ 가지치기는 바닥 조건보다 앞에 둔다. 먼저 걸러야 효과가 크다.
PART 1 11장의 재귀 구조가 여기서 전부 쓰인다. 깊이는 최대 N(≤ 30)이므로 스택 걱정은 없다.

가지치기는 답을 바꿀 수 있는 위험한 최적화다. 반드시 두 판을 만들어 비교한다.

검증 절차

② 작은 N(≤ 15)으로 답을 구한다
③ 가지치기 판을 만든다
④ 같은 입력으로 답이 같은지 본다
⑤ 여러 입력으로 반복한다

N=20  없음 64 / 있음 64
N=24  없음 64 / 있음 64

N=30  없음 64 / 있음 64

호출 수는 21억 → 15,303
반례를 만들어 본다 값에 음수가 섞인 입력({5, -3, 2}, S=4)으로 두 판을 돌려 보면 답이 달라진다. 5를 넣은 순간 s = 5 > 4라 잘리는데, -3을 더하면 2가 되고 거기에 2를 더하면 4가 되기 때문이다.
가지치기의 전제 조건을 코드 주석에 적는다. "값이 모두 양수일 때만 유효" 같은 한 줄이 나중의 자신을 구한다.

예제 3되돌리기가 빠졌는지 알아보는 법

증상
되돌리기 있음:
(123) (132) (213) (231) (312) (321)
→ 6가지

되돌리기 없음:
(123)
→ 1가지
알아보는 법
① 결과가 "첫 한 줄"만 나온다
② 또는 개수가 N!보다 훨씬 적다

→ used[i] = 0 을 찾아본다

바꾼 것은 반드시 되돌린다.

반대로 되돌리기를 재귀 호출 앞에 두면 아예 아무 제약이 없어져 NN가지가 나온다(중복 순열). 개수를 세어 보면 어느 쪽 실수인지 바로 알 수 있다.

예제 4두 팀으로 나누기

부분집합 완전탐색의 전형이다. N명을 두 팀으로 나눠 능력치 합의 차이를 최소로 만든다.

코드
void rec(int i, int s1, int c1) {
    if (i == n) {
        if (c1 == 0 || c1 == n) return;  /* 한쪽이 비면 안 됨 */
        int d = abs(s1 - (total - s1));
        if (d < best) best = d;
        return;
    }
    rec(i+1, s1 + a[i], c1 + 1);   /* 1팀 */
    rec(i+1, s1,        c1);       /* 2팀 */
}
검증
10 20 30 40 50 60
  합 210 → 최소 차이 10
  ({10,20,30,40}=100 vs 110)

1 2 3
  합 6 → 최소 차이 0
  ({1,2}=3 vs {3}=3)

100 (한 명)
  → 나눌 수 없다
세 가지를 짚는다 ① c1 == 0 || c1 == n 검사가 없으면 한쪽이 빈 팀이 되어 차이가 전체 합이 된다. 그런데 그것이 최소일 리 없으므로 답에는 영향이 없다 — 다만 N=1일 때는 답이 없음을 알려야 한다.
② best의 초기값은 4장대로 충분히 큰 값(1<<30)이거나 첫 경우의 값이다.
③ 1번 사람을 항상 1팀에 고정하면 가짓수가 절반(2N−1)이 된다. 대칭 가지치기다.

예제 5부분집합을 조합으로 쪼개기

"N개 중 정확히 M개를 고른다"와 "N개 중 일부를 고른다"는 다르다. 후자는 전자를 M=0부터 N까지 합친 것이다.

NC(N,0)+…+C(N,N)2N일치
41+4+6+4+1 = 1616일치
51+5+10+10+5+1 = 3232일치
20합 = 1,048,5761,048,576일치

그래서 "합이 S인 부분집합"을 구할 때 크기별로 나눌 필요가 없다. 반대로 "정확히 M명을 뽑는다"는 제약이 있으면 조합으로 짜는 쪽이 가짓수가 훨씬 적다 — C(20,3)은 1,140가지로 220의 1,000분의 1이다.

05 — 흔한 오류

흔한 오류 여섯 가지

1
되돌리기를 빠뜨린다
used[i] = 0;이 없으면 첫 한 줄만 나온다. N=3이면 6가지 대신 1가지다.
대책 used[i] = 1과 used[i] = 0을 항상 짝으로 쓴다. 결과 개수가 N!인지 세어 확인한다.
2
조합에서 start 대신 0부터 돈다
같은 조합이 여러 번 나온다. {1,2}와 {2,1}을 둘 다 세므로 개수가 C(n,m)이 아니라 순열 수가 된다.
대책 for (i = start; ...), 재귀는 comb(i+1, d+1). 개수를 C(n,m) 공식과 비교한다.
3
가지치기가 정답을 자른다
if (s > S) return;은 값이 모두 양수일 때만 옳다. 음수가 섞이면 {5,-3,2}, S=4에서 답을 놓친다.
대책 가지치기 없는 판과 작은 N에서 비교한다. 전제 조건을 주석에 적는다.
4
비트마스크가 더 빠를 거라고 생각한다
mask마다 합을 다시 계산하면 O(N · 2N)이다. N=24에서 재귀 0.087초 대 비트마스크 1.270초로 14.6배 느렸다.
대책 합이나 상태를 인자로 들고 다닌다. 비트마스크는 코드가 짧을 때, 또는 mask를 인덱스로 쓸 때 고른다.
5
중복 원소를 처리하지 않는다
{1,1,2}에서 2개를 고르면 (11) (12) (12)로 같은 조합이 두 번 나온다. 제약에 "서로 다른"이 없으면 중복이 있을 수 있다.
대책 정렬한 뒤 if (i > start && a[i] == a[i-1]) continue;. 두 조건이 모두 필요하다.
6
가짓수를 세지 않고 코드부터 쓴다
N=25에서 순열을 만들려 하면 25!은 1.5 × 1025로 우주가 끝나도 안 끝난다. 코드는 멀쩡해 보인다.
대책 코드를 쓰기 전에 가짓수를 계산한다. 2장의 표에서 통과 구간인지 확인한 뒤 손을 댄다.
이 장의 가장 중요한 교훈 오류 1·2·5는 개수를 세어 보면 전부 잡힌다. 순열은 N!, 조합은 C(n,m), 부분집합은 2n이어야 한다. 작은 N(3~5)으로 돌려 개수를 세는 것이 완전탐색의 기본 검산법이다.
오류 3은 더 위험하다 — 개수가 맞아도 답이 틀릴 수 있다. 가지치기를 넣을 때는 반드시 없는 판과 비교한다.

01
재귀로 "안 넣는다 / 넣는다"를 하되 pick 배열에 담아 바닥에서 출력한다. 또는 비트마스크로 0부터 2N−1까지.

02
본문 subsum.c에서 가지치기를 뺀 판(제약에 음수가 있을 수 있으므로). 빈 집합 제외를 위해 고른 개수를 함께 들고 다니거나, 마지막에 S가 0이면 1을 뺀다.
검증 — -7 -3 -2 5 8, S=0 → {-7,-3,2...} 중 합이 0인 것은 1가지(−7−3−2+5+8 = 1이 아니라, −3−2+5 = 0).
지도 포인트 — "빈 집합을 세지 않는다"는 한 줄이 S=0일 때만 영향을 준다. 1장대로 문제를 끝까지 읽어야 보이는 조건이고, S=0이 아닌 예제로는 절대 안 걸린다.
03
측정 (합이 S인 부분집합 세기, 값은 1..N) —
N재귀비트마스크비율
200.005초0.074초14.8배
220.020초0.311초15.6배
240.087초1.270초14.6배
두 방법의 답은 모두 같았다(N=24에서 2,755가지).
지도 포인트 — 비율이 약 N배라는 점을 짚는다. 비트마스크가 O(N · 2N)이기 때문이다. "짧은 코드가 빠른 코드는 아니다"를 숫자로 보여 주는 자리다.

본문 perm.c. 작은 인덱스부터 보므로 사전 순으로 나온다.
검증 — N=3 → 6가지, N=5 → 120, N=8 → 40,320(0.0009초), N=10 → 3,628,800(0.1006초), N=11 → 39,916,800(1.2677초).
지도 포인트 — N=11에서 1.27초라는 측정값이 2장의 "N ≤ 10이면 순열"이라는 기준의 근거다. 출력까지 하면 훨씬 느려지므로 N ≤ 8 정도가 출력 가능한 한계라는 것도 짚는다.
05
본문 comb.c. for (i = start; ...)와 comb(i+1, d+1).
검증 — C(4,2) = 6가지. C(10,3) = 120, C(20,10) = 184,756, C(24,12) = 2,704,156 모두 공식과 일치.
지도 포인트 — start를 0으로 두면 순열이 나와 12가지가 된다. 개수를 C(n,m) 공식과 비교하는 것이 이 유형의 표준 검산법이다.
06
used도 start도 쓰지 않는다. 매번 1부터 N까지 전부 시도한다. 
void rep(int d) {
    if (d == m) { 출력; return; }
    for (int i = 1; i <= n; i++) { pick[d] = i; rep(d+1); }
}
검증 — N=2, M=2 → 4가지(2² = 4).
지도 포인트 — 세 코드(순열·조합·중복순열)의 차이가 딱 한 군데라는 것을 표로 정리시킨다 — 순열은 used, 조합은 start, 중복순열은 아무 제약 없음. 이 비교가 완전탐색의 뼈대를 굳힌다.
07
⑴ used[i] = 0;을 지우면 → 1가지((123)만). 한 번 쓴 원소가 영원히 막혀 되돌아온 뒤 쓸 것이 없다.
⑵ 재귀 호출 앞으로 옮기면 → 제약이 사라져 NN가지(N=3이면 27가지, 중복 순열).
지도 포인트 — 두 실수의 증상이 정반대라는 것이 이 문항의 핵심이다. 너무 적게 나오면 ⑴, 너무 많이 나오면 ⑵다. 개수만 세어도 어느 실수인지 안다.
08
(mask>>i)&1, mask|(1<<i), mask&~(1<<i), while(t){c+=t&1;t>>=1;}.
검증 — mask=10(1010), i=1 → 켜짐 1, 켜기 10(이미 켜져 있음), 끄기 8, 개수 2.
지도 포인트 — "이미 켜진 비트를 또 켜도 그대로"라는 점을 확인시킨다(|의 성질). 그리고 6장 13번의 "1의 개수 세기"와 같은 코드라는 것 — 진법 분해와 비트 연산이 같은 일이다.

지도 포인트 — N이 커질수록 비율이 더 커진다는 점을 짚는다. 가지치기 판의 호출 수는 거의 늘지 않는데(7,883 → 15,303) 없는 판은 2배씩 늘기 때문이다. 그리고 답이 네 경우 모두 64로 같다는 것을 반드시 확인시킨다.
10
반례 — {5, -3, 2}, S = 4. 정답은 {5, -3, 2} 전체(5−3+2 = 4)로 1가지인데, 가지치기 판은 5를 넣은 순간 s = 5 > 4라 그 아래를 전부 잘라 0가지를 낸다.
이유 — 음수가 있으면 합이 올라갔다 내려올 수 있다. "지금 넘었으면 영영 못 돌아온다"는 전제가 깨진다.
지도 포인트 — 가지치기는 성능 최적화가 아니라 "논리적 추론"이다. 추론의 전제가 틀리면 답이 틀린다. 코드 주석에 전제를 적는 습관을 여기서 만든다.
11
예제 4의 코드. best의 초기값은 1<<30.
검증 — 10 20 30 40 50 60(합 210) → 10. 1 2 3(합 6) → 0. N=1이면 나눌 수 없다.
지도 포인트 — abs(s1 - (total - s1))이 abs(2*s1 - total)과 같다는 것도 보여 준다. 2*s1이 109을 넘을 수 있으면 long long이 필요하다(2장). 그리고 한쪽이 빈 경우를 걸러야 하는지는 문제가 정한다.
12
정렬한 뒤 if (i > start && a[i] == a[i-1]) continue;
검증 — {1,1,2}에서 2개 → 1 1, 1 2 두 가지. 처리하지 않으면 1 1, 1 2, 1 2 세 가지.
지도 포인트 — i > start 조건을 빼면 1 1이 사라진다(같은 값을 아예 못 쓰게 되므로). 두 조건이 모두 필요한 이유를 직접 돌려 확인시킨다. 그리고 정렬이 전제라는 것도 — 정렬하지 않으면 같은 값이 떨어져 있어 판별이 안 된다.
13
음수가 있으므로 if (s > M) return;은 쓸 수 없다(10번의 반례와 같은 이유). 전부 탐색한 뒤 s <= M인 것 중 최대를 취한다.
검증 — 3 5 7 -2 9, M=10 → 10(3+5+9−7 = 10 또는 3+7 = 10).
지도 포인트 — "가지치기를 쓸 수 없다"고 판단하는 것도 실력이다. 220 = 106이라 가지치기 없이도 통과하므로 억지로 넣을 이유가 없다. 필요 없는 최적화는 버그만 만든다.
14
모든 순열(최대 8! = 40,320가지)을 만들어 이웃 차의 합을 구하고 최소를 취한다.
검증 — 1 5 2 8 → 정렬한 1 2 5 8일 때 1+3+3 = 7이 최소다.
지도 포인트 — 답이 정렬한 순서라는 것을 학생이 발견하면, "그럼 순열을 다 만들 필요가 없지 않나?"라는 질문이 나온다. 맞는 질문이다. 그러나 증명하기 전까지는 완전탐색이 안전하고, N ≤ 8이면 충분하다. 완전탐색은 추측을 검증하는 도구이기도 하다.
15
⑴ 218 = 262,144 → 여유
⑵ 12! = 479,001,600 → 측정상 약 13초, 불가능(2장 15번)
⑶ C(30,4) = 27,405 → 여유
⑷ 410 = 1,048,576 → 여유
⑸ 225 = 33,554,432 → 가능하나 각 경우의 처리가 가벼워야 한다
지도 포인트 — ⑶이 핵심이다. N = 30이면 230은 불가능한데 C(30,4)는 2만 7천이다. "N개 중 몇 개"라는 제약이 가짓수를 극적으로 줄인다. 문제에 M이 명시되어 있는지 반드시 확인한다(예제 5).
16
1번 사람을 1팀에 고정하면 나머지 N−1명만 선택하므로 2N−1가지다. 답은 같다 — {A,B}와 {B,A}는 같은 분할이고, 1번이 어느 쪽에 있든 차이는 같기 때문이다.
지도 포인트 — 대칭 가지치기의 가장 단순한 형태다. 호출 수가 정확히 절반인지 세어 확인시킨다. 그리고 "왜 답이 안 바뀌는가"를 말로 설명하게 한다 — 가지치기는 언제나 근거를 말할 수 있어야 한다(10번).
17
각 행에 퀸을 하나씩 놓으므로 열 번호의 순열이다. 같은 열은 used로 막고, 대각선은 abs(행차) == abs(열차)로 검사한다. 
void go(int r) {
    if (r == n) { cnt++; return; }
    for (int c = 0; c < n; c++) {
        if (used[c]) continue;
        int ok = 1;
        for (int k = 0; k < r; k++)
            if (abs(r - k) == abs(c - col[k])) { ok = 0; break; }
        if (!ok) continue;                    /* ← 가지치기 */
        used[c] = 1; col[r] = c;
        go(r + 1);
        used[c] = 0;
    }
}
검증 — N=4 → 2, N=5 → 10, N=6 → 4, N=7 → 40, N=8 → 92. (N=6이 N=5보다 적다는 것이 재미있는 지점이다 — 가짓수가 N에 대해 단조롭지 않다.)
지도 포인트 — 가지치기가 없으면 8! = 40,320가지를 다 만들어 끝에서 검사해야 한다. 있으면 중간에 잘려 훨씬 적다. "판정을 마지막이 아니라 가능한 한 일찍"이 가지치기의 본질이다. 대각선 검사를 배열로 바꾸면 더 빨라지는데, 그것은 PART 3에서 다룬다.
18
연산자 개수를 배열로 들고 다니며 남은 것을 하나씩 써 본다. 가짓수는 최대 310 = 59,049(연산자 자리가 N−1개). 
void go(int i, long long cur) {
    if (i == n) { if (cur > mx) mx = cur; if (cur < mn) mn = cur; return; }
    for (int op = 0; op < 3; op++) {
        if (!left[op]) continue;
        left[op]--;
        go(i+1, op==0 ? cur+a[i] : op==1 ? cur-a[i] : cur*a[i]);
        left[op]++;                      /* 되돌리기 */
    }
}
검증 — 1 2 3에 + 1개, × 1개를 끼우면 가능한 식이 둘뿐이다 — (1+2)×3 = 9와 (1×2)+3 = 5. 따라서 최대 9, 최소 5.
지도 포인트 — left[op]--와 left[op]++가 짝이라는 것이 핵심이다. 순열의 used와 완전히 같은 구조다. 그리고 앞에서부터 순서대로 계산하므로 곱셈 우선순위가 없다는 조건을 빠뜨리면 안 된다 — 1장의 "문제를 끝까지 읽는다".
19
S를 전체 합에 가깝게 잡으면 가지치기가 거의 걸리지 않는다. 값이 1..30이면 전체 합은 465이므로 S = 465로 두면 s > S가 거의 참이 되지 않아 호출 수가 가지치기 없는 판과 비슷해진다.
지도 포인트 — 이것이 10.7절의 "가지치기는 최악 복잡도를 줄이지 못한다"의 실증이다. 이론(2장의 O 표기)과 실측이 둘 다 필요한 이유이기도 하다. 제출 전에 최악의 입력을 직접 만들어 재 보는 2장 예제 4의 습관이 여기서도 유효하다.
20
⑴ 가짓수 — 각 물건을 "넣거나 안 넣거나"이므로 220 = 1,048,576. 2장의 표에서 여유롭게 통과.
⑵ 모양 — 부분집합. M이 정해져 있지 않으므로 조합이 아니다.
⑶ 가지치기 — 무게가 모두 양수이므로 if (w > K) return;이 유효하다. 10번의 반례(음수)가 여기서는 생기지 않는다. 전제를 주석에 적는다.
⑷ 자료형 — 가치의 합은 최대 20 × 10,000 = 200,000으로 int로 충분하지만, 무게의 합도 200,000이라 K와 비교할 때 문제없다. best의 초기값은 0이 안전하다(아무것도 안 고르면 가치 0이고, 가치가 모두 양수이므로).
⑸ 검산 — 샘플에서 (무게 4, 가치 8)과 (무게 3, 가치 6)을 고르면 무게 7 ≤ 7, 가치 14. (무게 6, 가치 13) 하나만 고르면 13, (무게 3,6)+(무게 5,12)는 무게 8로 초과. 따라서 14가 최대다.
지도 포인트 — 이것이 배낭 문제의 가장 작은 형태다. N ≤ 20이라 완전탐색으로 풀리지만, N이 100이면 2100으로 불가능하고 동적 계획법이 필요하다(PART 3). 같은 문제가 제약 하나로 완전히 다른 알고리즘을 요구한다는 것을 보여 주는 자리다. 2장의 "제약은 힌트다"가 여기서 완성된다.
08 — 마무리

이 장을 마치기 전 점검

  • 코드를 쓰기 전에 가짓수를 센다 (2N / N! / C(N,M))
  • 부분집합은 "넣거나 안 넣거나" 재귀, 상태는 인자로 들고 다닌다
  • 순열은 used와 되돌리기를 짝으로
  • 조합은 start부터, 되돌릴 것이 없다
  • 중복 원소는 정렬 + i > start && a[i]==a[i-1]
  • 가지치기는 바닥 조건보다 앞에 둔다
  • 가지치기의 전제를 주석에 적고, 없는 판과 답을 비교한다
  • 작은 N으로 개수를 세어 공식과 맞춰 본다
  • 비트마스크가 항상 빠른 것은 아니다 (14.6배 느릴 수 있다)
다음 장 예고 — 11장 qsort와 정렬 기반 문제 7장에서 "값의 범위가 크면 체크 배열을 포기한다"고 했고, 그때 미뤄 둔 답이 정렬이었다. 다음 장은 C의 qsort를 쓰는 법, 특히 비교 함수를 쓰는 요령을 다룬다. 구조체를 여러 기준으로 정렬하는 법, 그리고 정렬해 두면 저절로 풀리는 문제 유형을 정리한다.
