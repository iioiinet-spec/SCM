03

조건 분기형 문제

브론즈 구간에서 가장 많이 나오는 유형이다. 어려운 알고리즘은 없다. 그런데 조건을 한 줄 빠뜨리거나 순서를 바꾸면 조용히 틀린다. 이 장은 경우를 빠짐없이, 겹치지 않게 나누는 절차와, 그것을 기계로 확인하는 방법을 만든다.

학습 목표

  • if 연쇄와 else if 연쇄의 차이를 설명할 수 있다
  • 경우를 빠짐없이·겹치지 않게 나누고 조건의 순서를 정할 수 있다
  • 경계 전수 검사로 빠진 구간과 어긋난 경계를 찾아낼 수 있다
  • &&·||의 단축 평가와 드모르간 법칙을 활용할 수 있다
  • 조건식 안에서 일어나는 오버플로를 예상하고 피할 수 있다
  • 실수를 ==나 >=로 비교하면 안 되는 이유를 측정으로 설명할 수 있다
1차시도입 문제 · 체인의 규칙 · 빠짐없이 겹치지 않게
2차시경계 전수 검사 · 복합 조건 · 오버플로와 실수 비교
3차시표준 코드 · 단계 예제 · 흔한 오류 6종 · 연습 문제
01 — 도입 문제

조건은 같은데 답이 다르다

윤년의 규칙은 셋이다. 4의 배수면 윤년, 단 100의 배수면 평년, 단 400의 배수면 윤년. 이 셋을 그대로 else if로 옮겨 적은 두 코드를 보자.

코드 ㉮ — 규칙을 적힌 순서대로
if      (y % 4   == 0) return 1;
else if (y % 100 == 0) return 0;
else if (y % 400 == 0) return 1;
else                   return 0;
코드 ㉯ — 순서를 거꾸로
if      (y % 400 == 0) return 1;
else if (y % 100 == 0) return 0;
else if (y % 4   == 0) return 1;
else                   return 0;

세 조건의 집합은 완전히 같다. 부등호도 숫자도 같다. 순서만 다르다. 실행 결과는 이렇다.

연도정답㉮ 적힌 순서㉯ 거꾸로판정
1900평년윤년평년㉮ 오답
2000윤년윤년윤년일치
2023평년평년평년일치
2024윤년윤년윤년일치
2100평년윤년평년㉮ 오답
100평년윤년평년㉮ 오답
왜 ㉮가 틀리는가 else if 연쇄는 위에서부터 내려가다 처음 참인 하나에서 멈춘다. 1900은 4의 배수이므로 첫 줄에서 잡혀 버리고, 아래의 100·400 조건은 아예 검사되지 않는다.
규칙이 "4의 배수다. 단 100의 배수면 예외다"라고 말했다면, 코드에서는 예외를 먼저 써야 한다. 좁은 조건이 위로, 넓은 조건이 아래로.

2023년과 2024년만 넣어 보고 "맞네"라고 판단하면 이 오류는 영원히 발견되지 않는다. 틀리는 입력은 1900, 2100, 100처럼 드문 값이다. 이 장의 후반에서 그런 입력을 사람이 찾지 않고 기계가 찾게 만든다.

이 장이 답할 질문 ① 조건의 순서는 무엇을 기준으로 정하는가?
② 빠진 경우가 없다는 것을 어떻게 확인하는가?
③ 조건식 자체가 틀리는 경우(오버플로·실수 비교)는 어떻게 막는가?
02 — 개념 정리

개념 정리

3.1if 연쇄와 else if 연쇄는 다르다

겉보기에 비슷하지만 의미가 완전히 다르다. 95점을 넣어 보면 바로 드러난다.

if 를 연달아 — 전부 검사한다
if (s >= 90) printf("A");
if (s >= 80) printf("B");
if (s >= 70) printf("C");

s = 95 →  ABC
          ↑ 세 번 다 출력
else if — 처음 참 하나만
if      (s >= 90) printf("A");
else if (s >= 80) printf("B");
else if (s >= 70) printf("C");

s = 95 →  A
          ↑ 한 번만
쓰는 경우문법판단 기준
경우가 서로 배타적else if 연쇄등급, 사분면, 삼각형 종류 — 하나만 해당된다
조건이 독립적if 연쇄여러 개가 동시에 참일 수 있고 각각 처리한다
판별 질문 한 줄 "두 조건이 동시에 참일 수 있는가?" 있을 수 없다면 else if, 있을 수 있는데 둘 다 처리해야 한다면 if 연쇄다. 헷갈리면 배타적인 쪽이 기본이다. 브론즈 분기 문제는 거의 모두 배타적이다.

3.2빠짐없이, 겹치지 않게

경우를 나눌 때 지켜야 할 조건은 두 가지뿐이다.

조건어기면 생기는 일확인 방법
빠짐없이어떤 입력에서 아무 가지도 실행되지 않거나, 엉뚱한 else로 떨어진다마지막을 반드시 else로 닫는다
겹치지 않게여러 가지가 동시에 참이 되어 순서가 답을 결정한다좁은 조건을 위로 올린다

삼각형 종류 판정이 전형적인 예다. "세 변이 모두 같다"는 "두 변이 같다"에 포함된다. 겹치는 두 조건 중 좁은 쪽(정삼각형)을 위에 두어야 한다.

넓은 조건을 위에 두면
if      (a==b || b==c || a==c)
    printf("Isosceles");
else if (a==b && b==c)
    printf("Equilateral");
else
    printf("Scalene");

3 3 3 → Isosceles   ← 오답
좁은 조건을 위에 두면
if      (a==b && b==c)
    printf("Equilateral");
else if (a==b || b==c || a==c)
    printf("Isosceles");
else
    printf("Scalene");

3 3 3 → Equilateral  ← 정답
정삼각형 가지는 영원히 실행되지 않는다 왼쪽 코드에서 Equilateral 줄은 어떤 입력으로도 도달할 수 없다. 정삼각형이면 이미 윗줄에서 잡히기 때문이다. 이런 줄을 죽은 가지라고 한다. 컴파일러는 경고하지 않는다.
점검법 — 각 가지마다 "이 가지로만 들어오는 입력을 하나 말해 보라". 말할 수 없으면 죽은 가지다.

3.3경계 전수 검사 — 이 장의 도구

조건 분기의 오류는 거의 전부 경계에서 난다. 그렇다면 경계만 뽑아서 보면 된다. 입력 범위가 좁을 때(점수 0~100, 월 1~12 등) 쓸 수 있는 강력한 방법이다.

경계 전수 검사결과가 바뀌는 지점만 출력한다
const char* prev = "";
for (int s = 0; s <= 100; s++) {
    const char* now = grade(s);
    if (now != prev) {               /* 결과가 바뀐 지점만 */
        printf("  s=%3d 부터 %s\n", s, now);
        prev = now;
    }
}

100줄이 아니라 경계의 개수만큼만 출력된다. 아래는 s > 70을 s >= 70 대신 쓴 코드를 검사한 결과다.

출력
  s=  0 부터 F
  s= 60 부터 D
  s= 71 부터 C     ← 70이어야 한다
  s= 80 부터 B
  s= 90 부터 A
문제의 등급표와 대조
90 이상 A   ✓ 90
80 이상 B   ✓ 80
70 이상 C   ✗ 71
60 이상 D   ✓ 60
그 외   F   ✓  0

→ 70점이 D로 떨어진다
왜 이것이 강력한가 ① 출력이 다섯 줄이라 눈으로 전부 확인할 수 있다.
② 문제에 적힌 표와 숫자 대 숫자로 비교된다. "느낌"이 개입하지 않는다.
③ 조건을 고친 뒤 다시 돌리면 1초다. 손으로 테스트케이스를 만들 필요가 없다.
입력 범위가 넓어 전수가 불가능할 때는 경계 후보만 넣는다. 각 경계값의 −1, 그 값, +1 세 개씩이면 충분하다.

3.4경계값: >= 와 >

"90점 이상이면 A"는 s >= 90이다. s > 90이면 90점이 A에서 빠진다. 전수 검사 결과로 보면 이렇다.

점수> 를 쓴 경우>= 를 쓴 경우판정
100AA일치
90BA다름
89BB일치
80CB다름
79CC일치
60FD다름

경계값 딱 그 값에서만 틀린다. 100점과 89점으로 테스트하면 절대 발견되지 않는다. 테스트 입력은 항상 경계값으로 만든다.

3.5복합 조건 — &&, ||, 단축 평가

C는 &&와 ||를 왼쪽부터 평가하다 결과가 정해지면 멈춘다. 이것을 단축 평가라 한다. 측정으로 확인하면,

호출 횟수 측정
0 && f()  → f 호출 0번
1 || f()  → f 호출 0번
1 && f()  → f 호출 1번
이것을 안전장치로 쓴다
if (i < n && a[i] == x) ...
      ↑        ↑
   먼저 검사   i가 범위 안일 때만 읽음

순서를 바꾸면 a[n]을 읽는다
→ 미정의 동작
수학 기호를 그대로 쓰면 안 된다 "1 ≤ x ≤ 10"을 if (1 <= x <= 10)으로 쓰면 항상 참이 된다. C는 (1 <= x)를 먼저 계산해 0이나 1을 만들고, 그 다음 0 <= 10 또는 1 <= 10을 계산하기 때문이다. 둘 다 참이다.
반드시 if (1 <= x && x <= 10)으로 쓴다. gcc -Wall을 켜면 경고가 나온다 — comparisons like 'X<=Y<=Z' do not have their mathematical meaning.

조건을 뒤집을 때는 드모르간 법칙을 쓴다. 네 가지 경우를 전수 검사해 확인했다.

원래 조건부정한 조건검증
!(A && B)!A || !B모든 경우 일치
!(A || B)!A && !B모든 경우 일치
1 <= x && x <= 10 (안)x < 1 || x > 10 (밖)안 10개 + 밖 7개 = 17개 (−3~13)

부정할 때 &&는 ||로 바뀐다는 것이 핵심이다. &&를 그대로 두고 부등호만 뒤집는 것이 가장 흔한 실수다.

3.6조건식 안에서도 오버플로가 난다

2장에서 "답이 10자리를 넘으면 long long"이라고 했다. 그런데 출력하지 않는 중간 계산에서도 넘칠 수 있다. 삼각형 성립 조건이 대표적이다.

제약: 1 ≤ a, b, c ≤ 2×10⁹
int a = 2000000000;
int b = 2000000000;
int c = 1;

a + b      = -294967296   ← 넘침
a + b > c  = 거짓

삼각형인데 "아니다"라고 한다.
두 가지 해결책
/* ① long long 으로 올린다 */
if ((long long)a + b > c)

/* ② 뺄셈으로 바꾼다 */
if (c - b < a)
   ← 양수끼리의 뺄셈은
     넘치지 않는다
제약이 109이어도 안심할 수 없다 세 변의 둘레를 구하면 109 × 3 = 3 × 109으로 int를 넘는다. 실제 측정값은 -1294967296이었다.
규칙 — 조건식이든 중간 계산이든, 더하거나 곱하는 순간 자릿수를 센다. 변수 하나하나가 int에 들어간다는 것은 아무것도 보장하지 않는다.

3.7실수는 ==로도 >=로도 비교하지 않는다

0.1 + 0.2 != 0.3은 잘 알려져 있다. 그런데 >=도 틀린다는 것이 실전에서 더 위험하다.

측정 결과
0.1 + 0.2 = 0.30000000000000004441
  == 0.3  → 거짓

0.7 + 0.1 = 0.79999999999999993339
  == 0.8  → 거짓
  >= 0.8  → 거짓   ← 이것이 터진다
대책
/* ① 정수로 비교한다 (최선) */
if (a + b + c >= 270)     /* 평균 90 이상 */

/* ② 꼭 실수여야 하면 오차 허용 */
if (fabs(x - 0.3) < 1e-9)
if (x >= 0.8 - 1e-9)
나누지 말고 곱한다 "평균이 90 이상인가"를 (a+b+c)/3.0 >= 90.0으로 쓰지 말고 a+b+c >= 270으로 쓴다. 양변에 3을 곱한 것이다. 나눗셈을 곱셈으로 바꾸면 실수가 사라진다. 2장에서 배운 double의 한계가 여기서 실제 오답이 된다.

3.8switch는 값이 띄엄띄엄할 때만

switch는 정수 하나를 값으로 분기할 때만 쓸 수 있다. 범위 조건(s >= 90)에는 쓸 수 없다. 그리고 break를 빠뜨리면 아래로 흘러내린다.

break 를 빠뜨리면
switch (m) {
    case 1: printf("31일");
    case 2: printf("28일");
    case 3: printf("31일");
    default: printf("(끝)");
}
m = 1 →  31일28일31일(끝)
일부러 흘려보내기도 한다
switch (m) {
    case 1: case 3: case 5:
    case 7: case 8: case 10:
    case 12: d = 31; break;
    case 2:  d = 28; break;
    default: d = 30;
}
← 같은 처리를 묶을 때는 유용
03 — 표준 코드

표준 코드

leap.c윤년 — 예외를 먼저 쓴다
#include <stdio.h>

int main(void) {
    int y;
    if (scanf("%d", &y) != 1) return 1;

    /* 방법 ① 체인 — 좁은 조건부터 */
    if      (y % 400 == 0) printf("1\n");
    else if (y % 100 == 0) printf("0\n");
    else if (y % 4   == 0) printf("1\n");
    else                  printf("0\n");

    /* 방법 ② 한 줄 — 순서를 걱정할 필요가 없다 */
    /* printf("%d\n", (y%4==0 && y%100!=0) || y%400==0); */
    return 0;
}
두 방법 중 무엇을 쓸까 둘 다 정답이다. 방법 ②는 순서가 아예 상관없다는 장점이 있다. 조건이 세 개 이하이고 한 줄에 담기면 ②를, 네 개 이상이거나 가지마다 할 일이 다르면 ①을 쓴다.
triangle.c삼각형 — 정렬 → 성립 → 종류
#include <stdio.h>

int main(void) {
    long long a, b, c, t;        /* 더할 것이므로 long long */
    if (scanf("%lld %lld %lld", &a, &b, &c) != 3) return 1;

    /* ① 가장 긴 변을 c로 보낸다 — 조건이 하나로 줄어든다 */
    if (a > b) { t = a; a = b; b = t; }
    if (b > c) { t = b; b = c; c = t; }
    if (a > b) { t = a; a = b; b = t; }

    /* ② 성립 검사: 가장 긴 변보다 나머지 둘의 합이 커야 한다 */
    if (a + b <= c) { printf("Invalid\n"); return 0; }

    /* ③ 종류: 좁은 조건부터 */
    if      (a == b && b == c) printf("Equilateral\n");
    else if (a == b || b == c) printf("Isosceles\n");
    else                      printf("Scalene\n");
    return 0;
}
정렬이 조건을 세 개에서 한 개로 줄인다 정렬하지 않으면 성립 검사에 a+b>c && b+c>a && a+c>b 세 개가 필요하고, 종류 판정에서도 a==c까지 따져야 한다. 가장 긴 변을 맨 뒤로 보내는 세 줄이 그 모두를 지운다.
이 기법은 반복해서 쓰인다 — 입력을 정렬해 두면 분기가 줄어든다. 11장 정렬 기반 문제에서 다시 만난다.

검증 결과 — 3 3 3 → Equilateral, 5 3 3 → Isosceles, 3 4 5 → Scalene, 1 2 3 → Invalid(a+b == c는 삼각형이 아니다), 2000000000 2000000000 1 → Isosceles(long long 덕분에 성립 판정 통과).

grade.c등급 — 경계는 >=, 마지막은 else
#include <stdio.h>

char grade(int s) {
    if      (s >= 90) return 'A';
    else if (s >= 80) return 'B';
    else if (s >= 70) return 'C';
    else if (s >= 60) return 'D';
    else              return 'F';   /* 반드시 else 로 닫는다 */
}

int main(void) {
    int s;
    if (scanf("%d", &s) != 1) return 1;
    printf("%c\n", grade(s));
    return 0;
}
내림차순으로 쓰면 아래 조건이 저절로 줄어든다 s >= 80 줄에 도달했다는 것은 이미 s < 90이라는 뜻이다. 그래서 80 <= s && s < 90이라고 쓸 필요가 없다. 내림차순 정렬된 체인은 조건을 절반으로 줄인다. 올림차순으로 쓰면 반대로 s < 60부터 시작한다 — 둘 다 되지만 한 방향으로만 쓰는 습관을 들인다.
04 — 단계 예제

단계 예제

예제 1조건표부터 그린다

코드를 쓰기 전에 표를 먼저 그린다. 표의 줄 수가 else if의 개수다.

조건결과겹침 검사
x > 0, y > 01사분면네 경우가 서로 배타적이고, x·y가 0이 아니면 반드시 하나에 해당한다 → 빠짐없이·겹치지 않게 만족
x < 0, y > 02사분면
x < 0, y < 03사분면
x > 0, y < 04사분면
표를 그대로 옮기면
if      (x>0 && y>0) q=1;
else if (x<0 && y>0) q=2;
else if (x<0 && y<0) q=3;
else                  q=4;
중첩으로 줄이면
if (x > 0) q = (y > 0) ? 1 : 4;
else       q = (y > 0) ? 2 : 3;

검증 (1,1)=1 (-1,1)=2
     (-1,-1)=3 (1,-1)=4

오른쪽이 짧지만, 표와 한 줄씩 대응하지 않는다. 처음에는 왼쪽처럼 표를 그대로 옮겨 쓰고, 맞는 것을 확인한 뒤에 줄이는 순서를 권한다.

예제 2경계 전수 검사로 버그 잡기

등급 함수를 작성했다면 제출하기 전에 다음을 돌린다. 열 줄짜리 main이면 된다.

검사 코드
char prev = 0;
for (int s = 0; s <= 100; s++) {
    char now = grade(s);
    if (now != prev) {
        printf("%3d → %c\n", s, now);
        prev = now;
    }
}
정상일 때의 출력
  0 → F
 60 → D
 70 → C
 80 → B
 90 → A

문제의 표와 숫자가 모두 일치

다섯 줄이 문제의 등급표 다섯 줄과 정확히 같은지만 보면 된다. 하나라도 어긋나면 그 경계의 부등호를 고친다.

예제 3조건을 뒤집기

"시각이 영업시간(9시 이상 18시 미만) 안에 있으면 OPEN, 아니면 CLOSED"를 두 가지로 쓸 수 있다.

안쪽을 쓰면
if (9 <= h && h < 18)
    printf("OPEN");
else
    printf("CLOSED");
바깥쪽을 쓰면 (드모르간)
if (h < 9 || h >= 18)
    printf("CLOSED");
else
    printf("OPEN");
뒤집을 때 &&가 ||로 바뀌는 것을 빠뜨린다 h < 9 && h >= 18로 쓰면 어떤 h도 만족하지 않는다(9보다 작으면서 18 이상일 수는 없다). 그 결과 모든 입력이 OPEN이 된다. 전수 검사(h = 0~23)를 돌리면 즉시 보인다.

예제 4조건을 줄이는 세 가지 방법

방법쓰기 전쓴 뒤
정렬a+b>c && b+c>a && a+c>b가장 긴 변을 c로 → a+b>c
내림차순 체인80<=s && s<90위에서 90을 걸렀으므로 → s>=80
표 만들기switch로 월별 일수 12가지int d[]={0,31,28,31,...} 배열 하나

세 번째가 특히 중요하다. 분기가 다섯 개를 넘으면 배열을 의심한다. 월별 일수를 if 열두 개로 쓰면 오타 하나를 찾기 어렵지만, 배열이면 숫자 열두 개를 한눈에 대조할 수 있다.

분기 대신 배열
int d[] = {0,31,28,31,30,31,30,
               31,31,30,31,30,31};

int days(int y, int m) {
    if (m == 2 && leap(y)) return 29;
    return d[m];
}
검증
2024/2 → 29   (윤년)
2023/2 → 28
1900/2 → 28   (100의 배수)
2000/2 → 29   (400의 배수)
2024/4 → 30

예제 5자리 넘김이 있는 분기 — 알람 시계

"H시 M분의 45분 전"을 구한다. 분이 음수가 되면 시를 하나 줄이고, 시가 음수가 되면 23시로 돌아간다. 두 단계의 자리 넘김이 있다.

코드
m -= 45;
if (m < 0) {
    m += 60;
    h -= 1;
    if (h < 0) h = 23;
}
printf("%d %d\n", h, m);
경계 입력으로 검증
10:10 → 9 25
 0:30 → 23 45    ← 날짜 넘김
 0:00 → 23 15    ← 둘 다 넘김
23:59 → 23 14
경계 입력을 고르는 법 자리 넘김 문제의 경계는 "넘기 직전, 넘는 순간, 두 번 넘는 경우"다. 여기서는 0:45(정확히 0이 되는 순간), 0:44(처음 음수), 0:00(시까지 넘침) 셋을 반드시 넣는다.
05 — 흔한 오류

흔한 오류 여섯 가지

1
넓은 조건을 위에 두어 아래 가지가 죽는다
윤년에서 y%4==0을 맨 위에 두면 1900·2100·100이 전부 윤년이 된다. 삼각형에서 a==b||b==c를 위에 두면 Equilateral은 영원히 출력되지 않는다.
대책 좁은 조건을 위로. 그리고 각 가지마다 "이 가지로만 오는 입력"을 하나씩 말해 본다.
2
경계에서 >= 대신 >를 쓴다
"90점 이상 A"를 s > 90으로 쓰면 딱 90점만 B가 된다. 100점·89점 테스트로는 절대 안 걸린다.
대책 경계 전수 검사를 돌려 출력된 경계 숫자를 문제의 표와 대조한다.
3
마지막을 else로 닫지 않는다
else if (s >= 0) return 'F';로 끝내면 음수 입력에서 아무것도 반환하지 않는다. 쓰레기 값이 나오고 컴파일 경고는 -Wall을 켜야 보인다.
대책 체인의 마지막은 조건 없는 else로 닫는다. 거기로 떨어지는 입력이 없어도 쓴다.
4
1 <= x <= 10으로 쓴다
문법 오류가 아니라 항상 참인 식이 된다. 범위 밖 입력이 전부 통과한다.
대책 1 <= x && x <= 10. 그리고 gcc -Wall로 컴파일하면 경고가 뜬다. -Wall을 항상 켠다.
5
조건식 안에서 오버플로가 난다
if (a + b > c)에서 a, b가 각각 20억이면 합이 음수가 되어 조건이 거짓이 된다. 변수는 멀쩡히 int에 들어 있었다.
대책 (long long)a + b > c로 올리거나 c - b < a로 뺄셈으로 바꾼다. 출력하지 않는 중간값도 자릿수를 센다.
6
실수를 ==나 >=로 비교한다
0.7 + 0.1은 0.79999999999999993이라 >= 0.8이 거짓이다. 평균·비율 문제에서 경계값만 틀리는 증상으로 나타난다.
대책 나눗셈을 곱셈으로 바꿔 정수로 비교한다. 꼭 실수여야 하면 fabs(x-y) < 1e-9를 쓴다.
이 장의 가장 중요한 교훈 여섯 가지 모두 예제 입력으로는 통과한다. 문제에 적힌 예시는 보통 가운데 값이기 때문이다. 1·2·3번은 경계 전수 검사 한 번이면 전부 드러나고, 4번은 -Wall이 잡아 주며, 5·6번은 제약을 읽을 때 자릿수를 세는 습관이 막는다.

07 — 확인 평가

정답과 해설

01
본문 grade.c와 동일. 전수 검사 출력은 0→F / 60→D / 70→C / 80→B / 90→A 다섯 줄이어야 한다.
지도 포인트 — 다섯 줄의 숫자가 문제의 표와 하나씩 대응하는지 손가락으로 짚어 가며 확인시킨다. 이 습관이 이 장 전체의 목표다.
02
체인판은 400 → 100 → 4 순서. 한 줄판은 (y%4==0 && y%100!=0) || y%400==0.
확인값 — 1900→0, 2000→1, 2100→0, 100→0, 400→1, 2024→1, 2023→0.
지도 포인트 — 4의 배수를 먼저 쓴 코드는 1900·2100·100에서만 틀린다. 2023·2024만 넣어 보면 통과한다는 사실을 반드시 실연해 보인다. 도입 문제의 표를 다시 펴게 한다.
03
if (x>0) q = (y>0) ? 1 : 4; else q = (y>0) ? 2 : 3;
검증 — (1,1)→1, (−1,1)→2, (−1,−1)→3, (1,−1)→4.
지도 포인트 — "둘 다 0이 아님"이라는 제약이 있어서 네 경우로 빠짐없이 나뉜다. 제약이 없었다면 축 위의 점을 따로 처리해야 한다. 제약이 경우의 수를 결정한다는 것을 짚는다.
04
if ((a<=b&&b<=c)||(c<=b&&b<=a)) return b; 식으로 세 경우를 쓰거나, 세 수를 정렬한 뒤 가운데를 출력한다.
검증 — (1,2,3)→2, (3,1,2)→2, (5,5,1)→5, (2,2,2)→2, (1,3,2)→2.
지도 포인트 — 등호를 <로 쓰면 (2,2,2)에서 아무 가지에도 걸리지 않는다. 값이 같은 입력이 이 문제의 경계값이다. 정렬로 푸는 쪽이 짧고 안전하다는 것도 보여 준다.
05
m -= 45; if (m < 0) { m += 60; h -= 1; if (h < 0) h = 23; }
검증 — 10:10→9 25, 0:30→23 45, 0:00→23 15, 23:59→23 14, 0:45→0 0.
지도 포인트 — 0:45가 숨은 경계다. m이 정확히 0이 되므로 if (m < 0)에 걸리지 않는다. if (m <= 0)으로 잘못 쓰면 여기서 틀린다. "0이 되는 순간"을 항상 경계 목록에 넣게 한다.
06
int d[] = {0,31,28,31,30,31,30,31,31,30,31,30,31}; 를 두고
if (m == 2 && leap(y)) return 29; return d[m];
검증 — 2024/2→29, 2023/2→28, 1900/2→28, 2000/2→29, 2024/4→30.
지도 포인트 — d[0]=0을 넣어 인덱스를 1부터 맞추는 기법이 핵심이다(2장 누적합과 같은 발상). 분기 열두 개가 배열 한 줄이 되었다는 점을 숫자로 짚는다.
07
안쪽 — 9 <= h && h < 18. 바깥쪽 — h < 9 || h >= 18.
전수 검사 결과 두 판이 0~23 전부에서 일치한다. OPEN은 9~17의 9개, CLOSED는 15개, 합 24.
지도 포인트 — h < 9 && h >= 18로 잘못 쓰면 CLOSED가 0개가 된다. 전수 검사에서 개수를 세게 하면 즉시 드러난다. 뒤집을 때 &&↔||를 반복 강조한다.
08
본문 triangle.c와 동일. 정렬 → 성립(a+b <= c면 Invalid) → 종류(좁은 조건부터).
검증 — 3 3 3→Equilateral, 5 3 3→Isosceles, 3 4 5→Scalene, 1 2 3→Invalid, 1 1 3→Invalid.
지도 포인트 — 1 2 3처럼 합이 정확히 같은 경우가 경계다. a+b < c로 쓰면 이것이 삼각형으로 통과한다. 세 점이 일직선이면 삼각형이 아니라는 것을 그림으로 보인다.
09
int판 — a+b가 -294967296이 되어 a+b > c가 거짓, 결과는 Invalid. 오답이다.
long long판 — 정상적으로 Isosceles.
지도 포인트 — 입력값 하나하나는 int에 들어간다는 점이 이 함정의 핵심이다. scanf("%d")도 성공하고 경고도 없다. "변수에 들어간다"와 "계산이 안전하다"는 다른 말이다. 2장에서 계산한 자릿수가 조건식에도 적용된다.
10
if (a + b + c >= 180) printf("PASS"); else printf("FAIL"); — 양변에 3을 곱했다.
지도 포인트 — (a+b+c)/3.0 >= 60.0으로 써도 이 경우에는 우연히 맞는다(180/3이 정확히 나누어떨어지므로). 그러나 기준이 18.5처럼 소수이면 즉시 틀린다(20번 참조). 나눗셈이 보이면 양변에 분모를 곱한다는 변형을 손에 익힌다.
11
죽은 줄 — else if (n % 4 == 0) printf("4의 배수");
이유 — 4의 배수는 모두 짝수이므로 첫 줄에서 잡힌다. 윗줄의 조건(짝수)이 아랫줄의 조건(4의 배수)을 포함한다.
수정 — n%4==0을 맨 위로 올린다. 좁은 조건이 위다.
지도 포인트 — 도입 문제의 윤년과 똑같은 구조다. 4의 배수 ⊂ 짝수는 400의 배수 ⊂ 100의 배수 ⊂ 4의 배수와 같다. 학생이 이 대응을 스스로 말하게 한다.
12
void scan(const char* (*f)(int), int lo, int hi) {
    const char* prev = "";
    for (int v = lo; v <= hi; v++) {
        const char* now = f(v);
        if (now != prev) { printf("%d → %s\n", v, now); prev = now; }
    }
}
함수 포인터가 어렵다면 함수마다 검사용 main을 따로 써도 된다.
지도 포인트 — 문자열 포인터를 !=로 비교하는 것이 가능한 이유는 같은 문자열 상수를 반환하기 때문이다. 안전하게 하려면 strcmp를 쓰거나 결과를 int로 반환하게 바꾼다. 14장 문자열에서 다시 다룬다. 지금은 검사기를 손에 쥐는 것이 목적이다.
13
if (u <= 100) 100; else if (u <= 200) 200; else if (u <= 300) 300; else 400;
전수 검사(0~400) 출력 — 0→100 / 101→200 / 201→300 / 301→400 네 줄.
지도 포인트 — 이 문제는 오름차순 체인이 자연스럽다. 등급(내림차순)과 반대 방향이지만 원리는 같다 — 이미 걸러진 범위는 다시 쓰지 않는다. 101 <= u && u <= 200이라고 쓰는 학생이 많은데, 틀리지는 않지만 조건이 두 배다.
14
if(a>b)swap; if(b>c)swap; if(a>b)swap; — 비교 3번이면 충분하다.
왜 3번인가 — 두 번째까지 하면 c가 최댓값이 된다. 남은 a, b만 비교하면 끝이다.
지도 포인트 — 본문 triangle.c의 정렬 세 줄과 같은 코드다. 그곳에서는 "가장 긴 변을 c로" 보내는 것이 목적이었고 여기서는 출력이 목적이다. 같은 도구가 다른 문제에 쓰인다는 경험을 만든다.
15
0.7 + 0.1 = 0.79999999999999993339, >= 0.8은 거짓.
정수판 — 0.1 단위이므로 10을 곱해 7 + 1 >= 8로 쓴다. 참이다.
지도 포인트 — ==가 위험하다는 것은 대부분 알지만 >=도 위험하다는 것은 모른다. "실수는 비교 자체를 피한다"로 기억시킨다. 그리고 2장의 double 정밀도 실험과 연결해 "같은 원인, 다른 증상"임을 짚는다.
16
식f 호출 횟수이유
0 && f()0왼쪽이 거짓이면 전체가 거짓
1 || f()0왼쪽이 참이면 전체가 참
1 && f()1오른쪽을 봐야 결정된다
0 || f()1오른쪽을 봐야 결정된다
지도 포인트 — 이것이 if (i < n && a[i] == x)를 안전하게 만드는 원리다. 순서를 바꾸면 a[n]을 읽어 미정의 동작이 된다. 조건의 순서가 안전성을 결정하는 사례로 묶어 설명한다.
17
d++;
if (d > days(y, m)) { d = 1; m++; }
if (m > 12)         { m = 1; y++; }
printf("%d %d %d\n", y, m, d);
검증 — 2023-12-31→2024 1 1, 2024-02-28→2024 2 29, 2023-02-28→2023 3 1, 1900-02-28→1900 3 1.
지도 포인트 — 예제 5의 알람 시계와 구조가 같다. 자리 넘김이 두 단계(일→월, 월→년)이고, 두 번째 if는 첫 번째 안에 넣어도 되고 밖에 두어도 된다(m이 13이 되는 경우는 첫 if가 실행된 때뿐이므로). 1900-02-28이 윤년 판정까지 묶어서 검사하는 입력이다.
18
먼저 정의를 고정한다. 끝점만 닿는 경우(b == c)를 겹침으로 볼지 말지는 문제가 정해야 하며, 정하지 않았다면 겹침으로 본다고 적고 푼다.
if (b < c || d < a)                 Disjoint;
else if ((a <= c && d <= b) ||
         (c <= a && b <= d))        Contain;
else                                Overlap;
검증 — (1 5, 3 9)→Overlap, (1 9, 3 5)→Contain, (1 2, 5 9)→Disjoint, (1 5, 5 9)→Overlap(끝점 접촉), (1 5, 1 5)→Contain.
지도 포인트 — Disjoint를 먼저 거르는 것이 요령이다. 겹치지 않는 경우를 빼고 나면 남은 것은 포함이거나 부분 겹침 둘뿐이라 조건이 단순해진다. 그리고 문제가 정의하지 않은 경계는 스스로 정의하고 명시하는 훈련을 시킨다 — 실전에서는 예제 입출력을 보고 추론한다.
19
원래 코드를 switch로 쓰면 case가 12개 + 윤년 조건 2~3개 = 14~15개. 배열판은 if가 3개(윤년 1 + 자리 넘김 2)로 줄어든다.
전수 비교 — 2000년 1월 1일부터 2100년 12월 31일까지 36,890일을 모두 돌려 두 판의 출력이 전부 일치함을 확인한다.
지도 포인트 — "줄였으니 맞겠지"가 아니라 두 판을 모두 돌려 전수 비교하는 절차가 핵심이다. 이것이 16장에서 배운 검증 방법의 분기 버전이다. 느린 판을 정답지로 삼아 빠른 판을 검사하는 방식은 PART 2 내내 반복된다.
20
⑴ 조건표 — BMI = w / (h/100)² 이므로 양변을 정리하면 BMI = w × 10000 / (h × h).
실수를 피하려면 양변에 h×h를 곱한다. 기준 18.5는 소수이므로 다시 2를 곱해 정수로 만든다.
long long L = (long long)w * 10000 * 2;   /* 왼쪽: BMI × h² × 2 */
long long H = (long long)h * h;
if      (L <  37 * H) printf("Under");    /* 18.5 × 2 = 37  */
else if (L <  46 * H) printf("Normal");   /* 23   × 2 = 46  */
else if (L <  50 * H) printf("Over");     /* 25   × 2 = 50  */
else                  printf("Obese");
⑵ 겹침·누락 — 네 구간이 <로 이어져 겹치지 않고, 마지막이 else라 누락이 없다.
⑶ 경계 입력 — 각 기준을 정확히 맞추는 (h, w) 쌍. h = 100이면 h² = 10000이므로 L = 20000w, 37H = 370000 → w = 18.5에서 갈린다. 정수 w이므로 w = 18(Under) / w = 19(Normal)이 경계다.
⑷ 최댓값 — w × 10000 × 2 ≤ 300 × 20000 = 6,000,000, 50 × h² ≤ 50 × 62,500 = 3,125,000. int로도 되지만 long long으로 쓰는 것이 안전하다.

⑸ 전수 비교 — 실수판은 실제로 틀린다
위의 정수판과, 같은 판정을 double로 쓴 판을 제약 안의 모든 (h, w) 42,431쌍에 대해 비교했다. 결과는 2쌍에서 불일치했고, 두 번 모두 정수판이 맞았다. 
h=160 w= 64  정수=Obese  실수=Over   BMI=24.999999999999996
h=220 w=121  정수=Obese  실수=Over   BMI=24.999999999999996
64 ÷ 1.62은 수학적으로 정확히 25다. 그런데 1.6은 2진법으로 딱 떨어지지 않아 1.6*1.6이 2.5600000000000005가 되고, 나눈 결과가 25보다 아주 조금 작아진다. 그래서 b < 25.0이 참이 되어 Over로 떨어진다.
지도 포인트 — 이 두 줄이 이 장 전체의 결론이다. 42,431개 중 2개, 비율로 0.005%다. 예제 입출력으로도, 손으로 만든 테스트로도, 무작위 입력으로도 거의 절대 걸리지 않는다. 그런데 출제자는 BMI가 정확히 25가 되는 입력을 반드시 넣는다. "드물어서 안전한 것이 아니라, 드물어서 못 찾는 것"임을 여기서 못 박는다.
나머지 교훈 네 가지 — ① 실수를 정수로 바꾸는 변형(양변에 곱하기) ② 소수 기준 18.5를 정수로 만들기 위해 2를 더 곱하기 ③ 곱한 뒤 자릿수 세기 ④ 오름차순 < 체인으로 쓰면 조건이 하나씩만 필요하다는 점. "실수 연산을 쓰지 말 것"이라는 한 줄이 문제의 난이도를 전부 결정한다.
08 — 마무리

이 장을 마치기 전 점검

  • 코드를 쓰기 전에 조건표를 그린다
  • 경우가 배타적이면 else if, 독립적이면 if 연쇄를 쓴다
  • 좁은 조건을 위로 올린다 (죽은 가지가 생기지 않도록)
  • 체인의 마지막은 조건 없는 else로 닫는다
  • 경계는 >=인지 >인지 문제의 표와 글자 단위로 맞춘다
  • 경계 전수 검사를 돌려 경계 숫자를 표와 대조한다
  • 범위 조건은 1 <= x && x <= 10으로 쓴다 (-Wall을 켠다)
  • 조건식 안의 덧셈·곱셈도 자릿수를 센다
  • 실수 비교는 양변에 곱해 정수로 바꾼다
다음 장 예고 — 04장 누적·집계형 문제 조건 분기가 "하나를 고르는" 문제였다면, 다음은 "전부를 훑으며 모으는" 문제다. 합·최댓값·개수·평균을 구할 때 초기값을 무엇으로 두는가가 거의 모든 오답의 원인이다. 2장에서 계산한 누적합이 여기서 본격적인 도구가 되고, "모두 음수인 입력"이 왜 단골 반례인지를 다룬다.
